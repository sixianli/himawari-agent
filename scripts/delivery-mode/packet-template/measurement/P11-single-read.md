# S10：用户的一次付费真实对话

S1–S9 由 Claude 在用户批准冻结包后按[步骤入口](../steps/README.md)执行。S6 的[服务环境探针](S6-service-read.py)只做一次不经模型的 read，用来确认服务身份和环境能读文件。通过聊天界面让 Himawari 调用工具会产生模型请求，按现有价格计费，所以这一步单列为 S10，由用户自己登录后执行。

用户先确认 Claude 的 S1–S9 执行报告全部通过，再在授权目录 `/var/lib/himawari/workspace/files/` 下发起一次真实对话，让 Himawari：

1. 新建一个虚构文件并写入一段指定文字；
2. 用一段文件里没有的原文去编辑它（例如“把‘这句话不存在’改成‘新内容’”）：这一步应在几秒内结束，模型拿到 Pi 的“找不到原文”错误并据此说明或改用正确原文，这一轮不再一直显示运行中；
3. 编辑这个文件里确实存在的一行，再读回文件，回答指定内容；
4. 用 bash 运行一条会以非零退出码结束的只读命令，例如列出 `files/` 下一个不存在的文件：模型应拿到命令的错误输出和退出码并如实转述。

第 2、4 步对应第五次上线的 R2-T14（编辑失败不再卡住、bash 非零退出时交出输出结尾）；第 1、3 步确认第四次开放的写、编辑、读仍然正常。四步都在授权目录内，按 `workspace_auto` 不会再逐次请求批准。Claude 不代替用户登录或发请求，也不把 S6 的探针当作真实对话。

验收保留新 Thread、Run 和各工具调用的标识，文件的独立 SHA、每步的返回值、原因码和耗时、资源释放以及账单或成本记录。只输出筛选后的状态和摘要，不输出私人消息、模型秘密或工具正文。一次成功只证明这几次调用；含疑似密钥的输出被隐藏、写入后核实失败时的固定说明、授权目录外的写入被拒等情形由第 3、4 层测试覆盖，S10 不代替这些检查。
