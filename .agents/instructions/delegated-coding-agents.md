# Delegated Coding Agents

The roles are in [ADR 0062](../../docs/adr/0062-claude-writes-complex-code-opencode-routine.md) (which keeps the unchanged parts of [ADR 0058](../../docs/adr/0058-agent-collaboration-and-review-roles.md)) and the model rules in [ADR 0061](../../docs/adr/0061-opencode-model-table.md); this file lists what every agent must obey. The decisions' history is in those ADRs and in `.agents/tasks/round2-tool-execution/goal.md`.

- Work is split by the nature of the code (G148, 2026-10-21): opencode writes the routine code whose approach every programmer knows (tests for a settled design, mechanical edits, scripts, fixtures, running verification and collecting evidence), including uncommitted operation packet tools and production entry scripts; Claude writes the code that needs architectural judgment (complex modules, abstraction layers, protocol and cross-process contracts, authority and sandbox code) and decides, with the reason in the brief or commit message, when a task is not clearly one or the other. Claude also plans, writes briefs, dispatches, reviews every opencode change line by line, compares proposals and decides, runs or schedules verification, commits, pushes, and keeps records. Claude runs mechanical scripts itself; only operations that need the user's authorization go to the user.
- Each side reviews only the other's code: opencode reviews every line of code, tests, and scripts Claude writes, Claude reviews everything opencode writes, and an author's review of their own work never counts. This includes uncommitted operation packet tools and production entry scripts, reviewed before they are frozen or run. Any code Claude wrote also runs the same test layers on the same hosts. Documents and briefs are outside this rule and go through documentation validation; Claude may still ask opencode to review a document it wrote. A long-task review record (`longtask.py record --review`) names the reviewing side in `--by`.
- Before settling a design or a fix, Claude asks an opencode DeepSeek V4.1 Flash session for an independent proposal, compares it with its own, and records in the plan or commit message which ideas were taken and why. When several models are asked for independent proposals, ask only free models; when both are rate-limited, ask `opencode-go/deepseek-v4.1-flash` alone and do not open a second Go session on `opencode-go/glm-5.3-flash`. When neither side can settle it, bring the options and a recommendation to the user; collect decisions that already need the user (production deployments and frozen packets, new downloads, reducing evidence, sudo changes) and ask once. opencode never talks to the user; Claude answers its stop files within the authority described in the `opencode-orchestration` skill.
- Model choice for opencode follows [ADR 0061](../../docs/adr/0061-opencode-model-table.md): the allowed models, their order, lowest reasoning variant and context limits live in the table `.agents/opencode-models.toml`, and `python3 .agents/opencode-models.py export --all` regenerates the launcher's allowlist and variant-floor file from it (`check --all` verifies they agree, `order` prints the switch order); a new session starts on the first free model in the table and moves on only after a second HTTP 429 from every free model in the table about 30 seconds after the first, when a free model is withdrawn or unavailable, or when the task needs more than the model's context (then skip the models the table marks `skip_for_context`); the reasoning variants a model offers are never taken from a recorded list: the launcher asks the running opencode server at every start and prints `LIVE_VARIANTS` ([ADR 0065](../../docs/adr/0065-live-reasoning-variants.md), G154), refusing a variant that is not live; the variant is chosen per new session by difficulty from that live list, never below the row's `min_variant` (G153, 2026-10-21: the free models start at `#high` at least, and Claude decides when a complex task gets `#max`; a model with no live variants, such as the free MiMo, is launched without a suffix), and not changed inside a session; after two failures of the same task on DeepSeek V4.1 Flash, the GLM escalation and return to the default follow ADR 0059; report one line per new session with the model ID, the variant, the Tokyo time (`TZ=Asia/Tokyo date '+%a %H:%M'`; DeepSeek peak hours are 10:00-12:59 and 15:00-18:59 on weekdays), and the reason. The generated, uncommitted `.opencode/allowed-models.txt` is what `oc-launch.sh` reads; it refuses any other model. When the Go allowance is used up only the free models remain; when they fail too, stop and tell the user; never turn on Extra Usage or buy allowance. Grok runs only through the user's own Grok subscription via the `grok-build` plugin (how: the `opencode-orchestration` skill's `references/grok.md`) and is paused until the user resumes it; `opencode-go/grok-*` and `opencode/grok-*` are forbidden.
- opencode and Grok follow every rule in the project `AGENTS.md` and in the instruction files it points to: tests only on Hermes or as `himawari-ci` on the cloud server `84.247.157.41`, never on the MacBook; no other login to the cloud server; no production commands; no reading of secrets; commit and push rules unchanged. Production steps of a deployment (the frozen packet, user-run scripts, and anything on `84.247.157.41`) stay with Claude and the user and are never delegated.
- The local tooling (the deny lists in the uncommitted `.opencode/opencode.json` and `.grok/config.toml`, the `wait-guard` plugin and `required-plugins.txt`, the Hermes and cloud wrappers `hermes-ssh.sh`, `hermes-upload.sh`, `hermes-wait.sh`, `ci-ssh.sh`, `ci-upload.sh`, their refusal codes 67-72, the detached-start form, and the launcher's refusals) is described in the [agent tooling Runbook](../../docs/runbooks/agent-tooling-runbook.md). The boundaries: opencode and Grok reach the test hosts only through those wrappers (always `himawari-ci` on the cloud server), start anything longer than a few minutes detached with `setsid -f` and wait with `hermes-wait.sh`, never match processes by command-line text, never write standard input to a remote file, and never mask a pipeline's exit status; a brief that names text a deny rule matches carries a `本地禁止规则：` line, and a read-only brief carries `只读任务：是`. Claude's local commands get the same pipeline check from the `PreToolUse` hook `~/.claude/hooks/zsh_word_guard.py`.
- The free DeepSeek model may train on request data; the user agreed on 2026-10-15 that this project's requests may be used for training and turned the setting on in the opencode console. `opencode/glm-5.3-flash-free` does not retain or train on requests according to opencode.
