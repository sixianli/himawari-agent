# 受托编码代理

分工写在 [ADR 0062](../../docs/adr/0062-claude-writes-complex-code-opencode-routine.md)（ADR，架构决策记录；它保留了 [ADR 0058](../../docs/adr/0058-agent-collaboration-and-review-roles.md) 中未改动的部分）里，模型规则写在 [ADR 0068](../../docs/adr/0068-deepseek-only-codebuddy-fallback.md)（它保留了 [ADR 0061](../../docs/adr/0061-opencode-model-table.md) 的模型表机制）里；本文件列出每个代理都必须遵守的规则。这些决定的历史见那几份 ADR。

- 工作按代码的性质分配（G148，2026-10-21）：opencode（一个本地命令行编码代理）写每个程序员都知道怎么写的常规代码（为已定设计写测试、机械性修改、脚本、测试夹具、运行验证并收集证据），包括未提交的运维上线包工具和生产入口脚本；Claude 写需要架构判断的代码（复杂模块、抽象层、协议和跨进程约定、权限和沙箱代码），当一项任务不明确属于哪一类时由 Claude 决定，并把理由写进简报或提交说明。Claude 还负责做计划、写简报、派发任务、逐行审查 opencode 的每一处改动、比较方案并做决定、运行或安排验证、提交、推送和保存记录。机械性脚本由 Claude 自己运行；只有需要用户授权的操作才交给用户。
- 每一方只审查对方的代码：opencode 审查 Claude 写的每一行代码、测试和脚本，Claude 审查 opencode 写的一切，作者审查自己的作品一律不算数。这包括未提交的运维上线包工具和生产入口脚本，它们在冻结或运行之前接受审查。Claude 写的任何代码也要在相同的主机上跑相同的测试层。文档和简报不受这条规则约束，走文档校验；Claude 仍然可以请 opencode 审查它写的文档。长任务的审查记录（`longtask.py record --review`）在 `--by` 里写明审查方。
- 在确定一个设计或一个修复方案之前，Claude 要请一个 opencode DeepSeek V4.1 Flash 会话给出独立方案，与自己的方案比较，并在计划或提交说明里记录采纳了哪些想法、为什么。独立方案只能来自 DeepSeek V4.1 Flash，通过 opencode 获取，或在其免费 DeepSeek 不可用时通过 CodeBuddy（另一个本地命令行编码代理）获取。双方都无法定夺时，把各个选项和一条推荐带给用户；把本来就需要用户决定的事（生产上线和冻结的上线包、新的下载、减少证据、sudo 变更）攒在一起，只问一次。opencode 从不与用户对话；Claude 在 `opencode-orchestration` 技能所述的权限范围内答复它的停止文件。
- 模型选择遵守 [ADR 0068](../../docs/adr/0068-deepseek-only-codebuddy-fallback.md)（G169，2026-10-23）：受托编码、审查和独立方案只用 DeepSeek V4.1 Flash。先用 opencode 的 `opencode/deepseek-v4.1-flash-free`；当它在第一次 429 之后约 30 秒再次返回 HTTP 429，或者被下架、不可用时，通过 `codebuddy-orchestration` 技能把任务交给 CodeBuddy 的 `deepseek-v4.1-flash`；两者都不可用时，停下来告诉用户。其他所有 opencode 模型在表 `.agents/opencode-models.toml` 中都是 `paused`，所以导出的允许列表里只有免费 DeepSeek，启动器会以 `MODEL_NOT_ALLOWED` 拒绝其余模型；恢复其中任何一个都需要用户决定。同一任务在 DeepSeek 上失败两次后，Claude 收回任务或拆分任务并重写简报；没有升级到 GLM 这一步。这张表仍是模型、最低推理档位和上下文上限的唯一来源，`python3 .agents/opencode-models.py export --all` 从它重新生成启动器的允许列表和档位下限文件（`check --all` 核对两者一致，`order` 打印切换顺序）；一个模型提供哪些推理档位，绝不取自已记录的列表：启动器每次启动时询问正在运行的 opencode 服务并打印 `LIVE_VARIANTS`（[ADR 0065](../../docs/adr/0065-live-reasoning-variants.md)，G154），拒绝不在当前列表里的档位；档位在每个新会话开始时按难度从该当前列表中选取，绝不低于该行的 `min_variant`（G153，2026-10-21：免费 DeepSeek 至少从 `#high` 开始，复杂任务何时用 `#max` 由 Claude 决定），且在会话内不更改；每个新会话报告一行，写明模型 ID、档位、东京时间（`TZ=Asia/Tokyo date '+%a %H:%M'`；DeepSeek 的高峰时段是工作日 10:00-12:59 和 15:00-18:59）和理由。`oc-launch.sh` 读取的是生成出来、未提交的 `.opencode/allowed-models.txt`；它拒绝其他任何模型。绝不开启 Extra Usage（超额用量）或购买额度。Grok 只通过用户自己的 Grok 订阅、经由 `grok-build` 插件运行（方法见 `opencode-orchestration` 技能的 `references/grok.md`），并且在用户恢复它之前处于暂停状态；`opencode-go/grok-*` 和 `opencode/grok-*` 被禁止。
- opencode 和 Grok 遵守项目 `AGENTS.md` 及其指向的指令文件中的每一条规则：测试只在 Hermes 上运行，或在云服务器 `84.247.157.41` 上以 `himawari-ci` 身份运行，绝不在 MacBook 上运行；不以其他身份登录云服务器；不运行生产命令；不读取机密；提交和推送规则不变。上线中的生产步骤（冻结的上线包、用户运行的脚本，以及在 `84.247.157.41` 上的任何操作）由 Claude 和用户负责，绝不委托出去。
- 本地工具（未提交的 `.opencode/opencode.json` 和 `.grok/config.toml` 中的禁止列表、`wait-guard` 插件和 `required-plugins.txt`、Hermes 和云服务器的包装脚本 `hermes-ssh.sh`、`hermes-upload.sh`、`hermes-wait.sh`、`ci-ssh.sh`、`ci-upload.sh`、它们的拒绝退出码 67-72、脱离启动的写法，以及启动器的拒绝情形）在 [代理工具 Runbook（操作手册）](../../docs/runbooks/agent-tooling-runbook.md) 中说明。边界如下：opencode 和 Grok 只能通过这些包装脚本访问测试主机（在云服务器上一律用 `himawari-ci`），任何耗时超过几分钟的任务都用 `setsid -f` 脱离启动并用 `hermes-wait.sh` 等待，绝不按命令行文本匹配进程，绝不把标准输入写入远程文件，绝不掩盖管道的退出状态；简报里出现会被禁止规则匹配的文本时，要带一行 `本地禁止规则：`，只读的简报要带 `只读任务：是`。Claude 的本地命令由 `PreToolUse` 钩子 `~/.claude/hooks/zsh_word_guard.py` 做同样的管道检查。
- 免费 DeepSeek 模型可能用请求数据做训练；用户于 2026-10-15 同意本项目的请求可以用于训练，并在 opencode 控制台中开启了该设置。CodeBuddy 会把它处理的代码发送到腾讯的模型服务；用户允许把任务交给它（G165、G169）。
