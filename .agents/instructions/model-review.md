<a id="plan-discussion"></a>
## 写代码之前：方案讨论

动手写代码之前要出方案的任务都走这三步；项目规则里的大改动（见[修 bug 和做新功能](../../.claude/rules/owner-standing-rules.md#fixing-bugs-and-new-features)）一定要走。修小 bug 不用。

1. 独立出方案（`--mode plan`）：线程先把自己的方案写好存着，不给模型看。材料只写问题、目标、约束、已核对的事实和查到的一手资料，不写线程的方案或倾向。两个模型各自读代码、上网搜索，各出一套方案。
2. 审核线程的方案（`--mode plan-review`）：把线程的方案发给两个模型，请它们找漏掉的场景、判断错的地方、和业界成熟做法不一致的地方。先独立、后审核，是为了不让模型顺着线程的思路走。
3. 线程整合：线程把两个模型的方案、审核意见和自己的方案逐条比较，自己先判断每一条采纳还是不采纳、为什么、最后建议怎么做，线程自己的方案也一样要过这一遍。交给 Andy 的是一份整合后的方案：开头按[方案的前提](../../.claude/rules/proposal-premises.md)列前提和来源，然后是方案，最后只列真正需要他拍板的几项取舍。三方的原始方案和逐条判断作为附件，不要求 Andy 逐条看。Andy 同意后才写代码。

<a id="code-review"></a>
## 合并之前：代码复核

1. 合并前对 PR 的最终提交做一次完整复核（`--mode code-review`，不传 `--previous`）。开 PR 前不另做。
2. 分类由线程做，不由模型做。线程对每一条意见逐条核对，每条都写下判断和依据（文件:行或实际运行结果），先判断它成不成立，再把成立的意见分成两类：
   - 会出错：照现在的代码，只要存在一种输入或使用方式（包括不合规范的、恶意的或不可信的输入）会让功能出错、丢数据、出安全漏洞，或造成其他实质损害（例如资源耗尽、无法撤销的破坏性操作），即使现有测试没有走到那条路径；或者说明、规则、文档与代码或事实不符、或与另一条规则矛盾，会让后来的人照着做错；或者本轮核对中确认的错误（包括本 PR 刚修好的）缺了能证明它的测试用例。这类意见必须修改（改代码、文档、规则或测试，看问题出在哪里）。
   - 可以更好：不改变任何可观察行为，也不改变任何陈述的真假，只是写法、结构、命名、措辞还能更好（判类只看意见指出的是什么问题，不看改起来有多小：指出说明与代码或事实不符的，哪怕只要改一行注释，也是“会出错”）；或者建议补的测试，线程在工作区里临时写出并运行过，用现在的代码也通过（核对用的测试不提交；证明已确认错误的回归测试除外，它属于“会出错”，要提交，提交后按第 3 步被复核；没有实际运行的，按“会出错”）。这类意见不修改，也不因为它再复核一轮。
   - 拿不准它成不成立、或属于哪一类的，都按“会出错”处理；判为不成立或“可以更好”都必须给出能核对的依据，只写“只是写法问题”不算：不成立，要给具体的反例、实际运行结果，或证明没有可达输入的代码引用；可以更好，要写清这处改动如果做了，只会动注释、命名、格式或措辞（不改变事实和行为），并附上核对过程；现有测试改动前后输出一致只能当辅助证据，不能单独作为依据。涉及错误路径、安全、数据、资源耗尽、不可逆操作的意见，没有这样的依据就按“会出错”。
3. 按“会出错”的意见，或第 5 步里 Andy 采纳的意见，做了修改，就对这些修改再复核一轮（传 `--previous <上一轮复核的提交>`，模型先看增量），一直到线程核对后没有“会出错”的意见为止，第 4 步的停止条件除外。
4. 每多跑一轮之前，在汇报里写明已花的累计费用；这一个 PR 的复核累计费用（已花的加上这一轮预计的）会超过 1 美元时，先问 Andy；费用说不准时按会超过处理（Andy 2026-11-03 为 PR 复核定的先问门槛，不是硬上限；其他花钱仍按 0.5 美元先问）。
   - 第 1 步的完整复核算第 1 轮，之后每次复核算一轮，包括第 5 步引起的复核。
   - 一轮里只要有一条意见被判为“会出错”，不管线程是否已经改完、是否在等 Andy 定，这一轮就算没过；线程已经写明理由判为不成立或“可以更好”的意见，后面的轮次再提，不算新的“会出错”意见；但这条意见涉及的代码后来改过，或者后来的改动改变了这条意见的触发条件，或者模型给出了此前没有核对过的新证据（例如具体的失败输入、复现步骤或运行结果，哪怕意见的文字和上次相同），线程要重新判断并把判断和依据写下来，维持原判也一样；改判为“会出错”的照常算。
   - 连续三轮没过，第三轮的“会出错”意见可以先改，但改完不再复核，直接停下报告 Andy，把已改未复核的和还没解决的分开列出，等他决定，不要一直循环；Andy 明确说继续后，连续的轮数从头算，费用仍按上面的先问门槛。
   - Andy 在停下时明确裁定“这条不改”的“会出错”意见，连同他的理由记进报告附件，之后的轮次不再算没过，已经记录的连续失败不追溯；除非这条意见涉及的代码后来改过、触发条件变了，或者有新的证据。
5. 报告 Andy 时，把各轮所有“可以更好”的意见一起列给他：每条写清是什么、线程建议采纳还是不采纳、为什么。判为不成立的意见和理由放在附件里，不要求他逐条看。只有 Andy 说可以采纳的才改；采纳的改动属于这个 PR，改完按第 3 步再复核一轮（算一轮），再报告一次。Andy 说“合并”才合并。

<a id="checklist"></a>
## 每次都要问的问题

1. 这个改动会不会改变模型已经见过的请求开头？包括系统提示、工具定义、历史消息、遮盖结果。要求回答：发给模型的内容是不是仍然只在末尾追加，每轮会变的值是不是都在最后一条消息里。依据：[发给模型的内容只追加](../../.claude/rules/prompt-prefix.md#rules)。
2. 这个改动会不会让同一段文字在不同请求里变成不同的字节（例如依赖前后文的遮盖、带时间的字段、无序的集合）？
3. 改动有没有对应的自动检查，反向用例是否真的会失败？

<a id="how-to-run"></a>
## 怎么跑

用 `node scripts/model-review/opencode-review.mjs` 跑，不要自己拼 `opencode run` 命令。它做这些事（Andy 2026-11-03 定）：

- 模型自己读代码：只开读文件、按内容搜索、按文件名找文件，以及 `git diff`、`git log`、`git show`、`git blame`、`git status`；改文件、别的命令、派子代理、仓库外的路径全部禁止。
  - git 命令里的重定向（`>`、`<`）、制表符、`difftool`（它能执行任意命令）、写文件参数（`--output`、`-o`）、读仓库外文件的参数（`--no-index`、`--contents`）、外部程序参数（`--ext-diff`、`--textconv`）另行禁止。
  - opencode 只按命令文字匹配，引号和反斜杠能绕过（实测 `"--output=文件"` 照样写出文件），所以脚本还在模型用的 `PATH` 最前面放了一个 git 替身：它拿到的是 shell 解析后的真实参数，子命令不在上面五个里、参数是这些禁用参数及其缩写、或是会读文件的 `--ignore-revs-file`、`--pathspec-from-file`、`--mailmap-file`、`--orderfile`、`blame -S`、打开帮助程序的 `--help`，或者短参数连写里藏着 `-o`、`-O`（如 `-pO文件`）就拒绝，否则才交给真的 git；同时用 `GIT_TEST_DISALLOW_ABBREVIATED_OPTIONS` 让 git 自己也拒绝缩写，并不读系统和用户的 git 配置。
  - opencode 的文字规则还漏掉了 `cd 副本 && git log > 文件` 这种写法（实测写出了文件），所以模型的命令改在受限 bash（`bash -r`，bash 自带的模式：不许输出重定向、不许 `cd`、不许改 `PATH`、不许用带斜杠的命令名）里执行。
  - git 替身调用真 git 之前会去掉所有 `GIT_*`、`LD_*` 等环境变量，只留 `PATH`、`HOME`、`LANG` 和固定的 git 设置，所以模型先 `export GIT_EXTERNAL_DIFF=程序` 再跑 `git diff` 也不能让 git 执行别的程序（第五轮复核实测过这种写法）。opencode 本身也只拿到一份白名单里的环境变量（脚本里的 `OPENCODE_KEPT_ENV`：`PATH`、`HOME`、语言和时区、临时目录、XDG 数据目录、代理和证书设置），线程容器里的令牌和密钥（例如 `GITHUB_TOKEN`）不传给它：原先整份环境都传过去，模型写 `git log $GITHUB_TOKEN` 就能从 git 的报错里读到值（2026-11-05 在云端容器实测），而方案讨论能读网页，网页内容可能诱导模型这样做。
  - 这套限制防的是复核模型误操作（顺手改了文件、跑了别的命令、上了网），不防有人故意在 PR 里埋恶意代码：PR 都是本项目自己的线程写的，复核又跑在用完即删的云端容器里。Andy 2026-11-03 定：这是开发协作工具，不是 Himawari 的功能，不用系统级沙箱，也不再为后一种情况加固；复核材料不要再让模型专门去找这类绕过办法。原因：系统的真相在代码里，只读线程给的材料，材料错了复核就跟着错。
- 代码复核（`--mode code-review`）不联网；方案讨论的两个模式（`--mode plan`、`--mode plan-review`）可以用 opencode 自带的搜索和读网页工具（Andy 2026-11-03 定）。搜索走 opencode 内置的 Exa 免费搜索服务，不花 Andy 的钱，只是搜索结果会算进模型的输入 token。
- 必问问题从 `--base` 提交里的本文件读（方案讨论不传 `--base` 时从 `--head` 提交读），不从被复核的改动或工作区读，免得改动自己改掉要问的问题。
- 第一次运行会联网安装 `opencode-ai@1.19.5` 到 `~/.cache/himawari-opencode-1.19.5-<锁文件摘要前 12 位>`，之后复用；也可以用 `HIMAWARI_OPENCODE_BIN` 指定已装好的程序（这时不做下面的核对）。安装用 `npm ci` 按 `scripts/model-review/opencode-lock/` 里提交的锁文件（`package-lock.json`，逐个记了 `opencode-ai` 和 12 个平台包的 sha512 摘要）进行，下载的包摘要不符时 npm 自己就会拒绝；每次使用前，脚本还会核对已装的每个包的摘要和锁文件一致，不一致以 `OPENCODE_INTEGRITY_MISMATCH` 停下。升级 opencode 时，改 `OPENCODE_VERSION` 和 `opencode-lock/package.json`，在该目录运行 `npm install --package-lock-only --ignore-scripts` 重新生成锁文件，一起提交。
- 密钥不写进脚本生成的配置，由 OpenCode 自己找：Mac 上先用这个 1.19.5 执行 `opencode auth login` 选 OpenCode Go 登录，密钥存在 `~/.local/share/opencode/auth.json`（OpenCode 保存登录密钥的文件）；云端不用登录，云端容器的出口代理（所有外发请求经过的那一层）会给发往 opencode.ai 的请求补上密钥。配置里一旦写了 `apiKey`，OpenCode 1.19.5 就不再用 auth.json 里的密钥，真实请求会报 401（[I-76](../../docs/incidents-and-gates.md#incidents)）；只有自检连本机假服务器时才写假密钥。
- 在 PR 最新提交的一次性副本里运行：副本是干净克隆，只有提交过的文件。历史里任何一个提交（包括合并提交）的文件树里出现过 `.env` 一类文件（`.env.example` 这类模板除外）就拒绝复核，因为 git 命令能从历史里读出它。副本删掉了远程地址、引用日志（reflog，记录分支移动的日志，里面有原仓库路径）和 `FETCH_HEAD`，用完即删，脚本收到中断或结束信号（`SIGINT`、`SIGTERM`）时也会删；被强杀（`SIGKILL`）时删不掉。副本里 PR 自带的 `.opencode/`、`opencode.json(c)`、提交进仓库的 `.env*` 文件和指向副本外的符号链接会先删掉，因为 opencode 启动时会执行项目目录里的插件，符号链接能把读文件带出副本；配置改从副本外的文件读。副本里的分支和标签全部删掉，只留 `refs/review/head`、`refs/review/base`、`refs/review/previous` 三个引用；其他提交的对象还在，知道哈希仍能读到。opencode 的全局配置（`~/.config/opencode`）不会被读入，脚本给它一个空的配置目录。
- 把 opencode 默认写死的 32 000 输出上限调高（`OPENCODE_EXPERIMENTAL_OUTPUT_TOKEN_MAX` 设为 200 000），DeepSeek 高推理时不再被截断。opencode 会再按模型目录里的上限往下调：2026-11-03 抓包实测 DeepSeek 请求是 200 000，GLM 是 131 072（GLM 的模型上限）。
- 开跑前先对本机假服务器自检，不花钱：让假模型发出一条正常的 `git log`、十几种写文件的命令（含引号、反斜杠、缩写、`difftool` 等绕过写法），以及用 git、读文件、搜索、找文件四种工具读仓库外文件的尝试。
  - 正常命令必须能跑；写文件命令既写到副本外，也写到副本里（含先 `cd` 再重定向）；每条写文件命令和每条读仓库外的 git 命令都必须被明确拒绝，只认 opencode 的权限拒绝、git 替身的 `REVIEW_GIT_REFUSED` 和受限 bash 的 `restricted` 三种文字，因别的原因失败（如目录不存在）同样算失败；读仓库外的尝试不能拿到内容；探针按内容对号，不按顺序。读文件、搜索、找文件三种工具读仓库外也必须被明确拒绝。
  - 另有几条先 `export` git 环境变量再跑 git 的探针（让 git 去执行 `env`、`touch`），要求看不到父进程里的标记、副本没有任何改动；还有一条探针在脚本自己的环境里放一个标记变量 `REVIEW_PARENT_CANARY`，让假模型运行 `git log $REVIEW_PARENT_CANARY`，输出里出现标记就算失败（环境白名单失效时它会失败），读 `/proc/self/environ` 也必须被明确拒绝；每个模型跑完都检查副本的 `git status`，有改动就算失败。
  - 五个允许的 git 子命令各有一条必须跑通的探针；受限 bash 外壳每次启动都记一笔，记录数少于这五条就说明 opencode 没有用它，算失败；opencode 发给模型的系统提示里不能出现副本里 `AGENTS.md` 的标题（PR 自带的项目指令不能变成复核模型的指令）；读仓库外的探针也包括 `../` 这种相对路径；`max_tokens` 不能低于 10 万，也不能高于该模型能接受的上限。工具表、输出上限、推理强度也要对。
  - `; touch`、`| tee`、`$(...)` 这类复合命令被拒，靠的是 opencode 把命令按片段分别判断权限（opencode 1.19.5 实测如此）；升级 opencode 后自检突然失败，先查这一点。任何一项不对就以 `SELF_CHECK_FAILED` 停下。
- 不限步数：提示里要求模型先想清楚要查什么、直奔目标去读，读到足以下结论就停，不要漫无目的地翻代码或反复调用同类工具（Andy 2026-11-03 定）。兜底靠下面的费用封顶和超时，再加 opencode 自带的「同一工具连续三次相同调用就拒绝」（`doom_loop`）。
- 两个模型并行（`--models` 可以只跑其中一个，例如只重跑失败的那个），每轮的结果写到 `--out` 下的 `round-<序号>/`：模型的答案（`<模型>.md`）、思考内容（`<模型>.thinking.md`，opencode 的 `--thinking` 输出）、原始事件（`<模型>.jsonl`）。每个模型的真实用量（输入、输出、推理、缓存命中 token、费用、轮次、是否追问过）追加到 `--out` 下的 `usage.jsonl`。
  - 一次运行里每个模型账上最多记 0.2 美元（实际花费可能略高：判线时已经在途的那一步，见下文）；花到 0.15 美元、或者用掉超时的八成（最多留 5 分钟）时，脚本先停掉它，再在同一段对话里追问一次「停止调用工具，现在写出结论」；模型正常结束却没写正文（答案只留在思考里）时也追问一次。追问只给一步，工具定义和前面完全一样，只在对话末尾追加这句话，所以前面的内容都能命中缓存（[发给模型的内容只追加](../../.claude/rules/prompt-prefix.md#rules)）；opencode 在这一步会提醒模型不要再调工具（opencode 在只给一步时会自己追加一条「已到最大步数，只能回文字」的提醒，但实测模型仍可以一直调工具）。
  - 所以追问这一步的配置把所有「允许」（`allow`）的工具权限改成「先问」（`ask`），「禁止」的照旧：工具定义不变，但 `opencode run` 没有人回答「先问」，会自动拒绝，而 opencode 在工具被拒后就结束这段对话（opencode 1.19.5 的 [run.ts](https://github.com/anomalyco/opencode/blob/v1.19.5/packages/opencode/src/cli/cmd/run.ts) 自动回复 `reject`；[processor.ts](https://github.com/anomalyco/opencode/blob/v1.19.5/packages/opencode/src/session/processor.ts) 在 `experimental.continue_loop_on_deny` 不为 `true` 时，被拒就返回 `stop`）。模型若仍然调工具，这个工具不会执行，opencode 也不会再发下一次请求；这一步结束、费用入账后，脚本记为 `wrap-up-tool-call`（这一步的费用同时超出剩余额度时记 `cost-limit`）。以前靠脚本看到这一步结束再停进程，可 opencode 在这之间已经执行了工具、发出了下一次请求，这些请求的费用不入账（2026-11-04 复现：把 opencode 输出里每一步结束的那行延后 1 秒，两次各多发了 22、23 次追问请求；`test/tooling/opencode-review.test.mjs` 的追问调工具用例就按这个延后来跑）。
  - 第一次运行也靠 opencode 自己拦：脚本给 opencode 装了一个很小的插件（`scripts/model-review/spend-guard.mjs`，只读，不改任何消息、系统提示和工具定义），每次要发模型请求之前，由插件在 opencode 进程里先判断，到线就抛错，这次请求不会发出去。判断用的是插件自己累计的各步费用（和 `step_finish` 里的 `cost` 同源，压缩历史后也不会漏算）和脚本传给它的几条线：会话总费用上限、收尾费用线（第一次运行）、收尾时刻、总期限；追问运行只带总上限、总期限和脚本已记的首轮费用（插件在追问进程里看到的历史被压缩时也不会漏算首轮），不带收尾线，否则追问的唯一一次请求会被自己拦下。
  - 插件把停下的原因、累计费用和放行次数写进每个运行独有的标记文件，脚本在子进程退出后读它：标记里有停止原因就采用它（插件的拦截一定早于脚本之后才发的杀进程信号），只有脚本自己发现的 `cost-unknown` 和追问时的 `wrap-up-tool-call` 保留脚本的判断；插件也把读不出费用的已完成步当作 `cost-unknown` 拦下；运行的费用取 `step_finish` 累计和标记累计中较大的一个。以前靠脚本读到 `step_finish` 才发停止信号，opencode 在这之间已经执行了工具、发出了下一次请求，这些请求的费用不入账（2026-11-04 复现：把每一步结束的那行延后 1 秒，费用线路径多发请求，实发 130 次、脚本只看到 9 步；时间线路径实发 101 次、只看到 6 步）。
  - 脚本的收尾定时器不再直接杀进程：插件到点后拦下一次请求，在途的那一步正常结束并入账；定时器放到收尾时刻之后再加一小段宽限（取 30 秒和总超时十五分之一中较小的），宽限到了仍有一步在途（标记里的放行次数大于本进程自己的已完成次数，追问运行不把首轮的步数算进去）才杀，并在 `usage.jsonl` 记 `inFlight: true`，累计时和 `costUnknown` 同一个公式（已记的加 0.05 美元和 0.2 美元中较大的），只让账不偏低，不能少花钱。在途的那一步无法避免，所以账上的数仍可能略低于实际；标题那次小请求不受保护。
  - 开跑前的自检会带着插件跑一次：假模型一直返回工具调用，插件限定放行 3 次，假服务器必须恰好收到 3 次主请求，插件没加载或没拦住就以 `SELF_CHECK_FAILED` 停下（`GUARD_NOT_LOADED`、`GUARD_PROBE_*`）；脚本启动 opencode 前会清掉 `OPENCODE_PURE`，它会让 opencode 不加载外部插件。门槛是 `test/tooling/opencode-review.test.mjs` 里名字带 `[I-77]` 的用例，见 [I-77](../../docs/incidents-and-gates.md#incidents)。
  - 本来要追问（花到 0.15 美元、用掉八成超时、或没写正文）但拿不到会话编号、有一步的费用读不出来、剩下的钱不到 0.02 美元或时间不到 15 秒时不追问，`usage.jsonl` 的 `wrapUpSkipped` 分别记 `no-session`、`cost-unknown`、`no-budget`、`no-time`（顺序如此）。第一次运行里费用读不出来本身就会停掉它（`outcome` 记 `cost-unknown`），这种情况不追问，也没有 `wrapUpSkipped`。追问的钱和时间都算在这个模型的 0.2 美元和总超时里。
  - 某一步的费用读不出来就停（标 `cost-unknown`），不当作 0：`usage.jsonl` 里这条记 `costUnknown: true`，累计时按「已记的费用加 0.05 美元」和「0.2 美元」中较大的一个算（那一步花了多少不知道，所以多留一点）；负数费用同样当作读不出来；费用是每一步结束后才知道的，最后一步可能略超。超时先发结束信号，10 秒不退再强杀。追问后仍被截断、超时、超费用、进程出错、被信号杀掉或没出文字时退出码为 4，按 `usage.jsonl` 里的 `outcome` 处理，不要原样重跑。
- 同一件事的所有轮次（同一个 PR 的代码复核，或同一份方案的独立出方案和审核）用同一个 `--out`。轮次序号取 `usage.jsonl` 里记录的轮次和已有的 `round-*` 目录中最大的那个加一，不会覆盖旧结果；没有轮次字段的旧记录按第 1 轮算。只重跑某一轮里失败的那个模型时，加 `--round <那一轮的序号>`，结果记进原来那一轮，不另占一个序号：这一轮里这个模型已经有 `outcome` 为 `ok` 的记录（`ROUND_ALREADY_HAS_RESULT`）、这一轮不存在（`ROUND_NOT_FOUND`）、这一轮记录的提交和这次的 `--head` 不同（`ROUND_HEAD_MISMATCH`），或者这一轮的 `prompt.md` 和这次的提示词不同（`ROUND_PROMPT_MISMATCH`，例如改了 `--brief`）时拒绝，都在花钱之前；失败那次的文件改名为 `<模型>.attempt-<序号>.*` 留在原目录。`usage.jsonl` 有一行读不出来、费用不是非负数字或轮次不是正整数，脚本以 `USAGE_LEDGER_INVALID` 拒绝开跑，不猜已花多少。开跑前脚本把 `usage.jsonl` 里已花的加上这一轮最多会花的（每个模型 0.2 美元）：代码复核超过 1 美元、方案讨论超过 0.5 美元，就以 `BUDGET_NEEDS_APPROVAL` 拒绝开跑，并打印这几个数。线程把数报给 Andy，他同意的总额用 `--approved-usd <美元>` 传入，累计不超过这个数才放行。每次运行结束打印 `REVIEW_SPENT_TOTAL`，线程汇报费用就用这个数。

用法：

```
node scripts/model-review/opencode-review.mjs --mode code-review \
  --base <分叉点提交> --head <PR 最新提交> [--previous <上一轮复核的提交>] \
  --brief <作者说明.md> --out <结果目录>

node scripts/model-review/opencode-review.mjs --mode plan \
  --head <当前提交> --brief <问题、目标、约束.md> --out <结果目录>

node scripts/model-review/opencode-review.mjs --mode plan-review \
  --head <当前提交> --brief <线程的方案.md> --out <结果目录>
```

三种模式都可以加 `--models deepseek-v4.1-flash`（只跑列出的模型，逗号分隔，可写短名或完整名；自检仍对两个模型都跑，不花钱）、`--round <序号>`（把单个模型的重跑补进原来那一轮，见上文）和 `--approved-usd <美元>`（Andy 同意的这件事的总花费）。

`--brief` 只写这次的材料：代码复核写问题、目标、约束和作者的说法；`plan` 只写问题、目标、约束和已核对的事实，不写线程的方案；`plan-review` 写线程的方案。脚本会在前面加上各模式的固定说明（上面的必问问题、项目指令第 16 条原话、该模式的任务和输出格式），代码复核还会让模型自己用 `git diff` 看改动。提交可以写分支名，脚本先在原仓库解析成提交哈希。按意见修改后的复核传 `--previous`，模型先看增量，但可以读任何文件。
