# 方案：降低代码复核的花费

写于 2026-11-06（JST）。Andy 2026-11-06 的出发点（原话）：“我感觉现在做代码复核的费用有点太高了”。方向是 Andy 同意的“1 + 2”（原话：“同意你这个方案”）：

1. 第 2 轮起只让 DeepSeek 复核。
2. 只有中、高严重度的“会出错”才触发下一轮。

**这是方案，还没动代码。**

## 要 Andy 拍板的

1. **严重度的分界线**，见[改法二](#change-2)。我建议：只有自己故意构造的怪输入才能触发、触发了也只是报错拒绝而不会给出错误结果、或者文字漏写但不会误导人做错事的，算“低”；其余都算“中、高”；拿不准的按“中”。
2. **低严重度改完后由谁放行合并。** 我建议由线程用一条新命令记进账本，汇报里逐条列出，由 Andy 抽查，不再每次单独问 Andy。这等于让线程自己给自己放行一类改动；不想这样的话，可以改成和现在的例外一样，必须有 Andy 的原话才能放行。
3. **要不要先让两个 OpenCode 模型讨论这份方案。** 项目规则要求大改动这样做（`AGENTS.md`“和 OpenCode 协作”一节）。分两步：先各自独立出方案，再审本方案。两步最多 0.8 美元，上次实际花了 0.19 美元。超过 0.5 美元的先问线，所以问 Andy。

## 钱花在哪儿

- 花钱最多的不是某一轮，而是**轮数**：只要有一条“会出错”，就要多跑一整轮，每轮约 0.13 美元（[P1](#premises)、[P5](#premises)）。
- 第 2 轮起只看新改的部分，每轮的花费却没少多少，因为模型还会去读相关代码（[P5](#premises)）。
- 第 2 轮起，GLM 的作用主要是挑规则文件的文字问题（[P7](#premises)），而它每轮约 0.06 美元，大头是读代码（[P6](#premises)）。

<a id="change-1"></a>
## 改法一：第 2 轮起只用 DeepSeek

- **规则。** 第 1 轮（不传 `--previous`）仍是两个模型完整复核。之后每一轮（传 `--previous`，包括合并 main 后的那轮）只跑 DeepSeek。Andy 要求时，任何一轮都可以再跑两个模型。
- **脚本。**
  - 传了 `--previous` 而没写 `--models` 时，默认只跑 DeepSeek。不传 `--previous` 时必须两个模型都跑，只给一个就报错，防止跳过第 1 轮的双模型复核。
  - 合并前检查改成：存在一轮两个模型都 `ok` 的完整复核；在那之后，每一轮只看新改动的复核里 DeepSeek 都 `ok`；最后一轮复核过的提交之后只改了记录目录。
- **只跑 DeepSeek 的轮次，提示词补上 GLM 原来侧重的那一项。** 这一轮 DeepSeek 的侧重说明里，加上“规则文件、说明和代码是否一致”。这正是第 2 轮以后 GLM 独自发现的那一类问题（[P7](#premises)）。只改提示词的固定部分，复核是新会话，不影响缓存（[P10](#premises)）。
- **测试。**
  - 传 `--previous` 时默认只用一个模型；不传时只给一个模型就报错。
  - 合并前检查认“第 1 轮双模型 + 之后单模型”的组合；如果从来没有过双模型轮次，就拒绝。
  - 只跑 DeepSeek 的那一轮，提示词里带上补充的侧重。
  - 每条都做反向验证。

<a id="change-2"></a>
## 改法二：低严重度不再触发下一轮

- **分级。** 线程在判为“会出错”的意见上再标一个严重度（[P11](#premises)）。
  - **中、高（照现行规则，改完要再复核一轮）：** 正常使用就会触发的错误结果、丢数据、泄露凭据或令牌，能绕过合并前检查或花钱上限的问题，无法撤销的破坏性操作；还有会让人照着做错这类事的规则或文档错误。
  - **低（改、补测试，但不触发下一轮）：** 只有线程自己故意构造的怪输入才能触发（例如文件名开头带空格、参数里带控制字符），而且触发后是报错拒绝、不会给出错误结果；或者文字漏写、写得不准，但不会误导人做错事。
  - **拿不准的按“中”。** 判为“低”必须写出依据：怎样才能触发，触发后具体发生什么。
- **放行。** 一轮里的“会出错”意见如果全部是“低”，这一轮就算“通过”。线程照常修改、补测试、做反向验证，然后用新命令 `--assert-reviewed --accept-low <轮次>` 记进账本。合并前检查认这条记录的条件是：那一轮的逐条判断 `judgments.md` 已经提交，记录之后只改了本 PR 的记录目录，main 已经合进分支。`--report` 会把这些“低严重度已改、未复核”的条目逐条列出来。
- **规则。** `model-review.md` 第 2、3 步写明分级标准和放行办法；第 4 步“连续三轮没过”的计数，只算有中、高严重度意见的轮次。
- **测试。**
  - 有中、高严重度意见时，`--accept-low` 拒绝放行。
  - 那一轮的 `judgments.md` 没提交时拒绝。
  - 记录之后又改了代码，就不再认这条记录。
  - `--report` 列出这些条目。
  - 每条都做反向验证。

<a id="estimate"></a>
## 预计效果

按 PR #255 的账本推算，没有实测：

| 做法 | PR #255 估算 |
|---|---|
| 现在 | 0.79 美元（6 轮 × 2 个模型） |
| 只上改法一 | 约 0.50 美元：第 1 轮 0.123，加上第 2 到 6 轮 DeepSeek 0.376 |
| 改法一 + 改法二 | 约 0.25 到 0.35 美元：第 3 轮起的意见按上面的标准多数算“低”（[P8](#premises)），估计第 3 轮左右就能收尾 |

普通 PR（例如 #248、#247 这种 2 到 4 轮的），估计每个 0.15 到 0.25 美元。

**代价：**

- 第 2 轮起少了 GLM 这第二双眼睛。#255 里实质性问题大多是 DeepSeek 找到的，或者两个模型都找到了，但样本只有这一个 PR。
- 低严重度的修改不再被复核。改法二靠测试和反向验证兜底，汇报里也逐条列出。

<a id="not-doing"></a>
## 不做的

- **不调推理强度。** 第 2 轮起把 DeepSeek 降到 `low` 也能省钱，但对质量的影响没有实测。等这两条改法跑过几个 PR、有了数据再说。
- **不改“连续没过就停”的轮数。** 改法二之后，这个计数只算中、高严重度，自然会变少。
- **不处理账本对“在途那一步”的保守入账**（PR #255 多记了 0.13 美元）。这笔多记的钱只影响“先问”提醒触发得早一点，不是实际支出，以后单独处理。
