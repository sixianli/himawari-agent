# PR 497 第 2 轮判断（deepseek-v4.1-flash）

- 1（deepseek-v4.1-flash）成立，会出错，中高：### 1. 中：未判定的候选 CI 会无上限重建并重跑完整 CI。读代码证实；状态加 undecided 计数，连续 3 次没结论就停下队列，判出结论或人工恢复时清零，补了用例；触发：候选 CI 持续没有成功或失败的结论（runner 坏了、ci/required 缺失）；后果：队列每次丢掉候选马上重建、重跑完整 CI，无限循环且不给 PR 反馈
- 2（deepseek-v4.1-flash）成立，会出错，低：### 2. 低：复核超时被当作“复核未覆盖”直接移出队列。reviewChecker 区分被杀（status 为 null）和正常失败，前者这一轮跳过不移出，补了用例；触发：复核检查子进程卡住被 5 分钟超时杀掉；后果：PR 被当成没复核移出队列，要人工重新加标签
- 3（deepseek-v4.1-flash）成立，会出错，低：### 3. 低：`addLabel` 把所有 422 当“标签已存在”，会掩盖真正的创建失败。只放过 errors 里是 already_exists 的 422，其余照样报错，补了用例；触发：建标签时 GitHub 因名称不合法等原因返回 422；后果：错误被吞掉，后面加标签的报错更难看懂
- 4（deepseek-v4.1-flash）成立，会出错，低：### 4. 低：ADR 决定段与新的判定规则不一致，“CI 本身出错不怪 PR”范围偏窄。决定段加上 failure+failure 的限定，后果段写明整次运行超时和单个作业超时的区别和代价；触发：读 ADR 第 74 行实现或排查队列；后果：以为任何候选失败都移出 PR；不知道单个作业超时仍算 PR 的错
- 5（deepseek-v4.1-flash）成立，会出错，低：### 5. 低：`start` 无条件删除远端所有 `mq/*`，范围宽且失败静默。清理挪到真正推新候选之前，ADR 写明 mq/ 只归队列用；触发：没有候选、也不打算建候选时，有人在 mq/ 下放了分支；后果：每次队列运行都删掉它
- 6（deepseek-v4.1-flash）成立，会出错，低：### 6. 低：改名反向用例依赖 git 默认 rename 检测开启，环境关掉时旧代码也会通过。两个测试的临时仓库显式设 diff.renames true；触发：跑测试的机器全局关掉了 diff.renames；后果：改名的反向用例在旧代码上也会通过，失去拦截作用
