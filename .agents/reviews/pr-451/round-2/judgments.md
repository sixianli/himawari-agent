# PR 451 第 2 轮复核：逐条判断

复核的提交 5e7c378b5（增量自 1338704f1），只用 DeepSeek，花费 0.12 美元，累计 0.30 美元。这一轮没有中、高的“会出错”意见。

- **R2-1** 会出错（低）：「中：dry-run 导入不执行新增的记忆出处校验」。成立。校验挪到 dry-run 返回之前，dry-run 和正式导入走同一段。测试「import refuses an unregistered memory source type…」加了 dry-run 也被拒的断言。模型给的是中，我判低：正常导出的文件里出处类型只可能是写入时已校验过的两种，只有手工改文件才触发，触发后是报错拒绝、不写数据。

- **R2-2** 会出错（低）：「低：需要确认的设备动作被说成“设备动作不可用”」。成立。新增固定说明 tools.result.device-action.unconfirmed 和错误码 DEVICE_ACTION_CONFIRMATION_REQUIRED：“这个动作要主人确认后才能做，这次没有拿到主人的确认，所以什么都没有做”。测试断言了错误码和说明文字。提示词清单已重新生成。

- **R2-3** 会出错（低）：「低：新增检查的反向用例只覆盖了“记录完全不存在”」。成立。同一条用例加了：感知记录存在但已标成 deleted 时，新记忆引用它被拒；已经记过这条出处的记忆更新时照常保存。另一个主人、另一个 Agent 的记录没有加用例：测试夹具只有一个主人和一个 Agent，造第二个要另搭一套身份数据，改动面比这条检查本身大。

- **R2-4** 会出错（低）：「低：口头指令分批查询没有自动检查」。成立。分批抽成纯函数 commandUtteranceBatches，单元测试「splits distinct ids into sorted batches no larger than the batch size」用 5007 个编号（带重复、倒序）验证去重、排序、每批不超过 1000。

- **R2-5** 会出错（低）：「低：详细设计仍说入口检查覆盖“所有有后果的工具入口”」。成立。详细设计那一行改成“建提醒、取消提醒、改规则、非读取的设备动作（其余入口由权限审批方案接手）”。

- **R2-6** 可以更好：「低（推测）：persistence 侧重复维护 perception 编号正则」。可以更好，已直接改（Andy 的长期做法：可以更好的直接改）。当前两处正则逐字相同，不是现存缺陷；persistence-sqlite 不能从 application 做值导入，所以不能共用常量。集成测试里加了一条断言，比较两处正则的 source 和 flags，以后只改一处会失败。只加测试，不改任何行为。
