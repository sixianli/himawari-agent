## 会出错（已改）

| 来源 | 意见 | 依据 | 改法 |
|---|---|---|---|
| DeepSeek | 代理地址写成 `//user:pass@host`（不带协议名）时漏检 | 正则在可选协议头后要求 `//` 和协议名一起出现 | 协议名和 `//` 各自可有可无 |
| DeepSeek | git 给出的文件名、`--main-ref` 原样打印，文件名带换行能伪造固定行 | `git diff -z` 保留换行，`problems` 原样打印 | 含控制字符的值按 JSON 字符串打印（`printable`）；`--main-ref` 含控制字符时拒绝 |
| DeepSeek、GLM | 单行校验只看顶层字段，例外记录里的 `problems` 列表没查 | `singleLine` 只遍历顶层 | 递归检查所有字符串 |
| DeepSeek、GLM | `prepareRawDir` 不收紧已存在目录的权限；测试只测新建目录，撤掉修复可能照样通过 | 只对根目录 `chmod` | 每轮目录也 `chmod 0700`；测试先把目录建成 0777 再调用 |
| DeepSeek | `--round` 时这一轮的记录缺 `head` 就跳过提交比较 | `filter(Boolean)` 丢掉缺 `head` 的记录 | 缺 `head` 时 `ROUND_CANNOT_VERIFY <轮> head` |
| DeepSeek、GLM | 拒绝例外时只给一种原因，掩盖了另一种 | 三元表达式二选一 | 两种原因都列出 |
| GLM | 规则文件列的环境变量白名单不全 | 对照 `OPENCODE_KEPT_ENV` | 补全 |
| DeepSeek（推测，拿不准按会出错） | `recordText` 不处理回车符；只认 40 位提交哈希，SHA-256 仓库会被拒 | 读代码 | 回车符统一换成换行；接受 40 或 64 位 |

每条代码修改都做了反向验证：撤掉修复时对应测试失败。

| DeepSeek | `npm ci` 继承完整环境、运行安装脚本 | 和第 3 轮判为不成立的是同一意见，没有新证据：包由锁文件的 sha512 固定，防恶意依赖不在 Andy 2026-11-03 定的范围内 |
