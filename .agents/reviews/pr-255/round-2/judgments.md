# 第 2 轮复核：线程逐条判断

复核提交 `8e378395`，增量从 `bb057722` 起。DeepSeek 0.0579 美元，GLM 0.0390 美元；这个 PR 的复核累计 0.2202 美元。

## 会出错（已改）

| 来源 | 意见 | 依据 | 改法 |
|---|---|---|---|
| DeepSeek | 白名单里的代理变量模型也读得到，代理地址带账号密码时同样泄露 | 云端容器的代理地址不带账号密码（核对过，只看了有没有 `@`）；Mac 上没法核实，按规则拿不准算会出错 | 代理地址带 `://用户:密码@` 时拒绝开跑（`PROXY_HAS_CREDENTIALS`），报错里不打印值 |
| DeepSeek | 例外记录提交后，再跑 `--assert-reviewed` 不认它，`--report` 里也显示“没复核” | `assertReviewed` 不读 `mode=override` 的记录 | 认出已提交的例外记录：记录的提交之后只改了记录目录，就打印 `REVIEW_OVERRIDE ... recorded=<提交>` 并通过 |
| DeepSeek | 例外判断读已提交的账本，却写工作区的账本，两者不一致时会写错 | 同上，`appendFileSync` 写工作区文件 | 工作区账本和当前提交的不同时拒绝（`REVIEW_OVERRIDE_REFUSED ledger-differs-from-HEAD`） |
| DeepSeek | `.prompt.md`、`.stderr.txt` 仍可能带行尾空格 | 提示词含 `--brief` 原文；报错原样写 | `--brief` 读入时去掉行尾空格（发给模型的内容因此不带行尾空格）；报错写入时同样处理 |
| DeepSeek | `--round` 在提示词文件和账本摘要都缺失时放行 | `roundForRun` 两者都缺时不比较 | 以 `ROUND_CANNOT_VERIFY` 拒绝 |
| DeepSeek、GLM | `--round` 不分模式，例外记录（没有 `round`）会被算进第 1 轮 | `inRound` 只按轮次过滤 | 先去掉例外记录；这一轮已有别的模式的记录时以 `ROUND_MODE_MISMATCH` 拒绝 |
| DeepSeek | 规则文件里原始事件目录少了仓库摘要那一层 | 第 1 轮改了 `rawDir`，文档没跟上 | 改文档 |
| DeepSeek | 测试无条件断言 `/proc/self/environ` 探针存在，和代码的平台条件不一致 | 第 1 轮改了代码，测试没跟上 | 测试按平台断言 |
| GLM | 存档的结论去掉了行尾空格，不再是模型原样输出，规则文件没写 | `recordText` | 规则文件写明 |

每一条代码修改都做了反向验证：撤掉修复时对应的测试失败。
