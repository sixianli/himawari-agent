## 会出错（已改）

| 来源 | 意见 | 依据 | 改法 |
|---|---|---|---|
| DeepSeek | 已提交的例外记录被认出时不核对“至少三轮”；例外还能盖过 `main-not-merged`，绕开 Andy 定的“合并前 main 必须在分支里” | `assertReviewed` 认例外时只看祖先和之后的改动 | 例外只能盖过“未复核的文件”这一类问题（否则 `REVIEW_OVERRIDE_REFUSED only-unreviewed-files`）；认出已提交的例外同样要求至少三轮 |
| DeepSeek、GLM | 账本字段带换行时，打印出来会伪造固定行；`head` 是任意字符串时直接交给 git | `parseUsage` 只校验非空 | 任何文本字段带换行都拒绝；复核记录的 `head` 必须是 40 位提交哈希；例外记录必须有提交哈希和非空原话 |
| DeepSeek | 未知的 `mode` 跳过字段校验 | `fieldsValid` 只对三种模式校验 | `mode` 只能是三种模式、`override` 或不写（旧记录） |
| DeepSeek | 原始事件目录用默认权限，多用户机器上别人能读 | `mkdirSync` 未指定权限 | `prepareRawDir`：根目录和每轮目录都设 0700 |
| DeepSeek | `--main-ref`、`--questions-ref` 以 `-` 开头时会被 git 当选项 | 直接拼进 git 参数 | 以 `-` 开头时拒绝 |
| DeepSeek | 规则文件三处和代码不符：`--assert-reviewed` 不是总是只读；禁用参数清单漏了 `-a`、`--text`、`--binary`；汇报会列出同一轮的失败尝试 | 对照代码 | 规则文件改准 |

每条代码修改都做了反向验证：撤掉修复时对应测试失败。其中一条测试的旧数据（方案记录的 `head` 写成 `"x"`）按新规则不合格，改成了真实提交号。
