# PR 315 第 1 轮复核：线程逐条判断

复核提交 `63ddef5c`，两个模型一次跑成，累计 0.1227 美元。

结论：有 2 条中、高的“会出错”意见，指向同一类问题——新加的两条宽松规则会把普通句子、网址、路径误遮。已改，需要再复核一轮。

## 会出错

| 意见 | 严重度 | 改法 |
|---|---|---|
| 中文短语、“1Password hunter22”被当密码（DeepSeek 第 1 条） | 中、高 | 宽松规则的值限定为不含空白、逗号、分号、方括号的 ASCII；英文关键词前不能紧挨字母数字；两项都有反向用例 |
| `pwd` 换行后的路径、带数字的网址被遮（GLM 第 1 条） | 中、高 | 关键词和值之间只隔空格、不跨行；网址和以 / 开头的路径不算 |
| ADR 说遮盖只取决于这段文字自己（DeepSeek 第 2 条） | 低 | 改成“自己和前面已点名的值” |
| 日期排除太窄（DeepSeek 第 3 条） | 低 | 扩到 ISO 带时间、美式日期，ADR 写明 |
| 带词规则没有最短长度（GLM 第 2 条） | 低 | 设 4 字符下限，ADR 写明 |
| ADR 0166 没提 ADR 0188（GLM 第 3 条） | 低 | 原处加括注 |

## 可以更好

严格规则不吃日期排除、测试缺口（已补）、ruleId 复用与尾随标点（标点已剥）、占位符吞并（现已不会）、全角数字（漏判方向，ADR 已承认）。
