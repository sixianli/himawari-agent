# PR 557 复核材料

问题：test/integration/product-path-browser.test.ts 的场景 accept-phone-send 在输入框刚可见时立即数 getByText(PLAIN_ANSWER)（普通回答已完成）作为基线，共享会话的历史消息还没渲染完，取到 0；发送后页面共 7 条，期望 baseline+1=1 永远等不到。Hermes 上线验收因此失败，上线包被拒。

做法：发送前循环数这个文本，连续三次（每次间隔 500 毫秒）数量不变后才取基线，之后断言发送后数量为基线+1。

约束：只改这一个场景，断言不变，不涉及模型请求。作者在云端无法跑这个测试，真实验证靠 Hermes 出包重跑。
请特别查：稳定循环是否可能永不结束（数量一直在变）；历史恰好分批渲染、间隔超过 1.5 秒时基线仍可能偏小；基线偏大是否会让断言误失败。
