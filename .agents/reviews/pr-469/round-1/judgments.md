# PR 469 第 1 轮复核：逐条判断

复核对象 5858f0ca，基准 504308d1，模型 deepseek-v4.1-flash。

1. `start_here` 的 `profile.version` 在统一遮盖之前计算：**成立，会出错，中、高。** 某个值只在今日段被点名、在资料段单独出现时，输出里的资料段被遮了，版本哈希却还按原值算，6 位验证码可以离线枚举出来。已改：版本改用整份输出一起遮盖后的资料段和被略去条数计算；新增用例让 482913 在今日段点名、517204 作对照，确认版本不随被遮的值变化；把遮盖改回各段分开后，这条用例会失败。
2. 主人规则过滤依赖出处记忆的分级：**不成立（对本 PR）。** 这个 PR 之前 `rule_book` 和 `start_here` 不论上限一律列出全部主人规则；现在只列出处分级不高于上限的，暴露面只减不增。出处为空的规则：规则写入器每次都写出处记忆（`production-owner-rules.ts:532`），0087 迁移时表里只有内置规则，所以生产上不会有出处为空的 `owner:` 规则；出处找不到就不给，是设计时定的保守做法（边界优先于方便）。规则写入器只按凭据和证件号升 sensitive、健康和财务类规则仍是 private，这是写入端已有的缺口，不是本 PR 带来的；作为后续事项报给设计线程，判断“哪些内容敏感”要交给模型，不在本 PR 用词表补。
3. 工具顺序测试用注册表验注册表：**成立，会出错，低。** 已改：两个测试文件都写死四个工具名和顺序。
4. 登记表不校验工具名：**成立，会出错，低。** 已改：名字必须匹配 `^[a-z][a-z0-9_]{0,56}$`（加上 `_failed` 不超过 64 个字符），不得和写工具重名；补了重名、和写工具撞名、超长、非法字符四条反向用例。
5. ADR 0219 仍写另外三个读工具的上限未做：**成立，会出错，低。** 已在决定 3 和决定 8 后补 2026-11-13 注。
