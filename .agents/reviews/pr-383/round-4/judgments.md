# PR 383 第 4 轮逐条判断

DeepSeek 结论：没有高、中严重度问题。成立的“会出错”全部是低，按 `--accept-low` 记账，不再复核。

- **r4-1**「ADR 0219 合并后内部自相矛盾，且测试说明没跟上写令牌」：成立，低。旧句子在 main 上就有；在背景、决定 3 后面追加「后续：已补上，见决定 7」，测试说明追加写令牌的那条。只改文档。
- **r4-2**「`elicitationSupported` 对畸形能力对象过于宽松」：成立，低。加上 `Array.isArray` 拒绝数组。实测官方 SDK 在握手（server/discover）时就拒绝 `elicitation: []` 的客户端，所以这一步碰不到；新断言记下这一点（这样的客户端连不上），代码改动只是兜底。
- **r4-3**「分类非法时返回的是“正文为空或超长”的错误文字」：成立，低。SDK 的枚举校验会先挡住；结果文字改成同时写明两种原因，提示词清单同步更新。
- **r4-4**「写工具与 P3-6 摘要没有组合用例」：可以更好。按 Andy「可以更好就改」，在写工具测试里补一条：写令牌连接调 `today_context` 正常返回。
- **r4-5**「跨客户端重发时，审计归属是“最初提议者”，不是“实际确认者”」：不成立（模型自己标为信息、非缺陷）。这是 ADR 0225 写明的信任范围，第 3 轮 r3-3 特意改成记确认框里显示的名字。
