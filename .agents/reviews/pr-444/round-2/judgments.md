# PR 444 第 2 轮复核：逐条判断

复核的提交 d0bfe3669（增量自 4bcdddedc），只用 DeepSeek，花费 0.11 美元，累计 0.41 美元。

- **R2-1** 会出错（中、高）：「高：同摘要并发上传时，被上限拒绝的一方会删掉已成功一方的媒体文件」。成立。改法：同一个摘要的放文件、写行、清理在进程内排队，一次只做一个；后到的一方只会得到“重复”，不会删文件。新测试「keeps the file when the same bytes arrive twice at once」。 触发：同样的字节用两张凭据同时上传，其中一张被上限拒绝；后果：被拒的一方删掉另一方刚入库的文件，留下有行没文件；模型给的严重度：高。

- **R2-2** 不成立：「中：判重查询按 owner/agent 收窄，但主键仍是全局的；跨 scope 同值会从“重复”变成主键冲突」。没有可达输入：ADR 0234（docs/adr/0234-one-program-per-person-database-file.md 第 10 行）定了每人一个数据库文件，一个库里只有一个主人；设备接口的 scope 取自认证出的主人和配置里的 Agent（device-api-routes.ts 第 825、867 行），没有任何入口能让第二个主人写进同一个库。第 1 轮加的条件只是让查询和别的查询写法一致。

- **R2-3** 会出错（中、高）：「中：`releaseContent` 放在 `finally`，失败路径和并发同记录请求会互相破坏；准备阶段失败还会漏掉释放」。成立。改法：同一个主人的“存文字、入库、释放”整段在进程内排队，并且释放放在覆盖存文字阶段的 finally 里。入库失败时删掉没被引用的文字是有意的。存文字中途失败这条路径没有单独用例：夹具里造不出“第 N 条存文字失败”而不换掉真实的存储实现，仓库规则不许用假替身。 触发：存文字存到一半出错；或同一条记录被同一台设备同时交两次、其中一次被上限挡下；后果：前一种留下没人引用的文字；后一种可能删掉另一个请求刚存、还没写进记录的文字，那个请求报错；模型给的严重度：中。

- **R2-4** 会出错（低）：「中低：到期清理没有独立定时触发，导出说明的“最多保留到配置的天数”在空闲时可能不成立」。说明文字不准，成立，已改成“超过配置的天数后，在下一次有设备交数据时删除”。不加定时器：没有设备交数据时也没有新的原始材料进来，磁盘不会涨。 触发：读导出说明；主人长期没有任何设备交数据；后果：说明写“最多保留到配置的天数”，实际要等下一次有设备交数据才删；模型给的严重度：中低。

- **R2-5** 不成立：「低：`device.request.body_bytes` 被新用作单行上限，但配置下限和文档语义都不匹配」。两条路径用的是同一个上限：直接交记录的签名请求本来就受 device.request.body_bytes 限制，后台上传的一行就是一条记录，不该比直接交的整个请求还大；把这个键配得很小，两条路径同样受影响，是配置者的选择。pending 改成按字节算（原来按字符，最多多缓冲到 4 倍）属于可以更好，已顺手改。设计文档里这个键的说明由设计线程更新。

- **R2-6** 会出错（低）：「低：媒体“先到位再写行”的非上限错误路径会留下孤儿文件」。成立。改法：写行抛错时，确认没有行指向这个摘要就立刻删文件。没有单独用例，原因同 R2-3：要让真实的 SQLite 在这一步出错只能换掉存储实现。 触发：文件放到位以后写行出错（磁盘余量不足、数据库出错）；后果：留下一个没有行指向的文件，等下一次清理才删；模型给的严重度：低。

- **R2-7** 会出错（低）：「低：consolidation-hold 契约测试把两种新类别从两边都抹掉，无法发现 0095 漏加类别」。成立。加了断言：迁移后 limit_change/changed 和 delivery_timing/deferred 能写入，limit_change/deferred 和不存在的类别被 CHECK 拒绝。 触发：以后有人改迁移时漏掉这两种类别；后果：这条测试照样通过；模型给的严重度：低。

- **R2-8** 会出错（低）：「低：文档/表结构目录与实际行为不一致」。表结构说明那一条成立，已补。设计文档的两条由设计线程更新（已告知零点切段、保留天数、单行上限三处变化），不在这个 PR 的范围。 触发：读表结构说明；后果：perception_media_items 的说明没写到期删除；模型给的严重度：低。

- **R2-9** 可以更好：「低：媒体身份只有摘要，先到者的 kind/device/milliseconds 会覆盖后到者」。同样的字节就是同一份材料，这是有意的；同一份字节先说是音频再说是图片属于不合规范的输入，结果是第二次得到“重复”，不产生错误数据。要不要把种类算进身份，列给设计线程。
