## 成立，会出错，中、高（改了，未复核）

- r3ds1（中高）项目名凭据检查漏掉少写斜杠的写法。线程用 Node 的 `URL` 实测：`https:/user:tok@host/p`、`https:user:tok@host/p`、`https:\user:tok@host\p`（反斜杠换成正斜杠后）都被解析成带用户名和密码、有主机的地址，而上一轮的规则只找 `://` 和 `//` 开头，确实拦不住。成立。改法：不再自己找 `://`，先让标准解析器拆，拆得开并且有主机的就算远程地址；有 `://` 却拆不开的拒绝；开头是 `用户:令牌@主机` 或 `用户@主机:` 写法的拒绝。线程照新规则写了一段脚本，用 28 个样本实测：16 个拒绝（带用户名、令牌、查询参数或 `#` 的各种地址写法，含少写斜杠的、用反斜杠的、不带协议的 `user:tok@host/path`，以及会被错拒的“小王@公司:周报”和带 `://` 却拆不开的一句话）；12 个照常收（“Q3: 计划”“Trip: Tokyo #2”“调研#2”、`C:\Users\me\notes`、`localhost:3000/app`、“meeting: bob@corp.com”这类名字，解析器拆不开或拆开了没有主机；`host/path?token=abc` 也在照常收的里面，这是补注写明的已知边界）。
- r3ds3（DeepSeek：中，线程拿不准按中、高）主人点的筛也会把敏感正文发给模型，而发给哪些模型没有写。成立。改法：筛这个功能（主人点的也算）任务 C 先不做，按分级能发给哪些模型、怎样遮盖在另出的那份 ADR 里定；ADR 0228 的例外补注和 ADR 0242 后果一节的补注都写明“定下之后才做”。
