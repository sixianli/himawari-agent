- r2ds1（高）、r2ds4（中）、r2ds5（中）都出在“内容一到就自动筛”上。核对：ADR 0228 第 63 行“这张表只有 MCP 写工具和记忆页的确认操作读写，没有任何组装发给模型内容的代码读它。依据「用户主权」：确认前 Himawari 不用它。”；ADR 0246 第 89 行“待确认的提议不进任何发给模型的请求”；ADR 0234 第 76 行“Andy 本人默认不设上限”；待确认表（迁移 0093）、导出 v3、`contracts-v2.ts` 的快照字段里都没有放建议的地方。成立。线程上一轮把“不显示预计费用”和“不用主人点”一起改了，前一半是钱的事，后一半动到的是 ADR 0228 依据“用户主权”划的线，不该在一条补注里顺手定。改法：这个 PR 只留“点之前不显示预计费用，点了就筛”；自动筛连同结果存哪里、进不进导出、按分级能发给哪些模型、按接入怎样限频，另出一份 ADR 给 Andy 定，任务 C 里“筛”这一块等那份 ADR。原来就有的“主人点了才筛”也会把待确认的正文发给模型，和 ADR 0228、0246 的原话字面上对不上，这次在三份 ADR 里各加一条带日期的补注写明这处例外。
- r2ds2（高）类别清单不止三处。核对：`packages/gateway-contracts/src/contracts-v2.ts` 第 1198 行的 `MEMORY_EXTERNAL_CATEGORY_NAMES`（第 1588 行校验待确认快照）；线程再搜了一遍，`packages/persistence-sqlite/src/sqlite-external-memory-proposal-operations.ts` 第 54 行还有一份 `CATEGORIES`，模型也没提到。成立。补注不再写“几处”，列出现在找到的五份，检查改成“每一份都相等，表的 CHECK 按建表结果比，动工时全仓库再搜一遍”。
- r2ds3（高）项目名的凭据检查。成立：原来的用例和新加的用例互相矛盾，协议大写、以 `//` 开头、用反斜杠、前后带空白的写法照字面能混过去。改法：先去首尾空白、统一成 NFC、把反斜杠当正斜杠；任何位置有 `://`、以 `//` 开头、开头是 `用户@主机:` 的算远程地址写法，用标准网址解析拆，拆不开或拆出用户名、密码、查询参数、`#` 部分的拒绝；宁可错拒。不带协议的 `主机/路径?token=…` 写明按普通文字收，以及为什么。旧用例加一句只对远程地址写法成立，每种写法补一条反向用例。
