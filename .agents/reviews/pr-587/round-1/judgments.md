# PR 587 第 1 轮判断（deepseek-v4.1-flash）

- 1（deepseek-v4.1-flash）成立，会出错，中高：### 1. 中：推送登记只在 `scenePhase` 变为 active 时触发，冷启动和刚配对完成时不会登记。AppModel.swift activate() 不调用 registerForPush，RootView.swift:58-60 只在 scenePhase 变化时调 becameActive；已在 activate() 末尾补调用，PushTokenSync 去重保证不重复发；触发：刚配对完成或已配对用户冷启动时 scenePhase 不发生变化（.onChange 不回调初始值），registerForPush 只有 becameActive 一个调用点；后果：推送令牌要等用户下一次切后台再回前台才登记，期间收不到锁屏推送
- 2（deepseek-v4.1-flash）成立，会出错，低：### 2. 中：APNs 环境由 `#if DEBUG` 产生，和实际签名里的 `aps-environment` 可能不是同一个值。AppModel.swift:80-91 用 #if DEBUG；README 已补一句不要用 Release 配开发签名；运行时读 entitlements 在 iOS 上没有公开的 SecTask 接口，需解析描述文件，超出本 PR 范围；触发：Release 配置配开发描述文件（或 Debug 配分发描述文件）装到真机，登记的环境与令牌环境相反；后果：服务器按相反环境发 APNs 得到 BadDeviceToken，收不到推送；不丢数据不泄露；判低理由：标准流程（Xcode 运行=Debug+开发签名，Archive/TestFlight=Release+发布签名）两者一致，只有手工混用配置才触发，且只是推送无效
- 3（deepseek-v4.1-flash）成立，可以更好：### 3. 中：新加的 Swift 测试不在任何自动门槛里，403 分支和反向路径没有用例。Swift 只能在 Mac 上编译跑测试，仓库自动检查不含 Swift 是既有约束（不是本 PR 引入）；缺的 403 与 400 反向用例已补（PushRegistrationTests.swift），Mac 上跑 swift test 的证据由主线程或 Andy 补
- 4（deepseek-v4.1-flash）成立，会出错，低：### 4. 中/低：`PushTokenSync` 的 `flush()` 可被重入，同一令牌可能并发发多次；`deviceGone()` 与在途请求竞态会让重新配对后不再登记。PushRegistration.swift flush() 在 await 后无条件写 sent；已加 generation 计数，deviceGone 递增，返回时 generation 变了就不写；补了挂起传输的测试；触发：设备在登记请求在途时被移除，随后立刻重新配对；后果：在途请求返回后把 sent 设回旧值，新配对不再登记，直到令牌变化或重启 App；判低理由：需要移除发生在请求在途的窄时间窗，且重启或回前台后进程重启即恢复；同一令牌并发多发只是重复 upsert，无害
- 5（deepseek-v4.1-flash）不成立：### 5. 低：“同一令牌只发一次”只在同一个进程内成立，每次冷启动都会重发。服务端按 (device, pushType, activityRef) upsert，冷启动重发是幂等的，而且令牌或服务端状态可能已变，重发是想要的行为；代码和测试都只声明“同一次运行内只发一次”（theSameTokenIsOnlySentOnce...），没有持久化去重的要求
- 6（deepseek-v4.1-flash）成立，会出错，低：### 6. 低：`topic` 固定为 Bundle Identifier，但服务端必须把这个值列进配置；改了 Bundle Identifier 后会永久静默 403。device-push.ts:158-162 要求 topics 包含上报值；README 已补“服务器推送 topic 清单必须包含 Bundle Identifier”；触发：付费账号用户改了 Bundle Identifier 而服务器 topics 配置没同步；后果：服务器 403，客户端按设计静默重试，推送一直不登记；README 只写了“不用改任何代码”，没提服务器配置；判低理由：模型自己给的低
- 7（deepseek-v4.1-flash）成立，可以更好：### 7. 低：失败路径几乎全静默，真机登记失败时没有可诊断线索。失败路径静默是为了免费签名等预期失败不打扰；加只记错误类别的 os_log 能让真机验收好诊断，建议采纳但不阻断合并
- 8（deepseek-v4.1-flash）不成立：### 8. 低：免费签名也会弹通知权限，README 的“静默”表述不准确。README 原文是“iPhone 拿不到推送令牌，没有锁屏推送，其余功能不受影响”，没有说“静默”或不弹通知权限；通知权限本来就为本地通知需要（AppModel.registerForPush 之前已有 requestAuthorization 路径），不是误导
