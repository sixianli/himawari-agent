# PR 292 第 1 轮复核逐条判断

复核提交 a9b19331（经 Magpie，两个模型都跑）。DeepSeek 49 次请求都由 CodeBuddy 回答；GLM 32 次由 CodeBuddy、5 次由 OpenDesign 回答。两条记录都被标成“花费未知”，账本按每个模型 0.2 美元计，所以这一轮记了 0.40 美元（见文末）。

“会出错”的中高意见是 D1：API 报错后等待重试的 60 秒里叫停，30 秒后强制退出，第一次运行的花费进不了账本。已修改，需要第 2 轮复核。其余“会出错”的都是低，一并修改。机器可读的版本在 `verdicts.jsonl`。

| 编号 | 意见 | 类别 | 判断 |
|---|---|---|---|
| D1 | 等待重试时叫停会丢第一次运行的花费 | 会出错（中高） | 等待改成叫停时立刻结束、不再重试，第一次运行照常记账；新增真实 API 报错加叫停的用例。 |
| D2、G1 | `--report` 没有列出覆盖记录 | 会出错（低） | 逐条列出 `REVIEW_OVERRIDE_RECORD`。 |
| D3 | 已提交的覆盖记录可以被伪造 | 会出错（低） | 现有取舍（防误操作，不防有意），文档写明。 |
| D4 | `--providers` 没拒控制字符 | 会出错（低） | 拒绝。 |
| D5、D6、D8 | 文档措辞和代码不一致 | 会出错（低） | 改文档。 |
| D7 | 叫停落在追问开始前时 outcome 不是 owner-stopped | 会出错（低） | 改为 owner-stopped；时间窗口没法稳定构造，没加用例。 |
| G2 | 去掉一家后重建组没测，两个模型时可能失败 | 会出错（低） | 用例改成两个模型都跑，证明重复建组可行（Magpie 帮助：同名组会被替换）。 |
| G3 | `gatewayDropped` 校验没测 | 会出错（低） | 新增正反用例。 |
| G4 | 第 95 行没写 owner-stopped | 会出错（低） | 改文档。 |
| G5 | `--providers` 和自检同用被忽略 | 会出错（低） | 拒绝，报 `ARG_PROVIDERS_NOT_FOR_SELF_CHECK`。 |

线程自己发现的问题：这一轮和“控制复核”方案审核那一轮，两个模型的记录都被标成“花费未知”，PR 289 和更早的轮次没有。真实 Magpie 小请求复现不出来，Magpie 的用量记录已经随临时目录删除。现在改成：读不懂的用量行只算到它所属的模型；标“花费未知”时记 `costUnknownWhy`、打印 `GATEWAY_COST_UNKNOWN`，并把 Magpie 用量记录存进原始目录，下一轮就能看到原因。

修改后的验证：分别把等待重试改回不可打断、把读不懂的行改回两个模型一起算、去掉报告里的覆盖记录、去掉 `--providers` 的控制字符检查和自检拒绝，对应用例都失败；两组测试共 196 条通过；`npm run check` 41 步全过。
