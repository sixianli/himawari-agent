# PR 437 第 3 轮复核：逐条判断

复核的提交：14398657（相对 0051b2dc 的修改）。只跑 DeepSeek。没有中、高档的“会出错”意见。

## 会出错

| 编号 | 意见 | 判断 | 档 | 处理 |
| --- | --- | --- | --- | --- |
| d2（模型给中） | 执行进程正常停止时记录不删 | 成立 | 低 | 正常停止时也删掉记录。判低的理由：模型自己写明不算违反现有规格；重新启用只决定能力在不在清单里，执行进程不在时调用仍然失败。这一条没有自动测试（要真实执行进程完整启动），已写进 ADR 已知问题。 |
| d5（模型给低） | “启动绑定行为不变”和新加的大小上限矛盾 | 不成立 | - | 这是复核说明里的一句话，不是代码或文档的问题；ADR 0254 写的是“格式和写入时机都不变”，并写明了 16384 字节上限。 |

## 可以更好

| 编号 | 意见 | 处理 |
| --- | --- | --- |
| d1（模型给中） | 写出记录后启动失败删记录没有测试 | 已加：单元测试让现场检查通过、装配失败，断言检查通过前读不到记录、装配前读得到、失败后被删掉。去掉删除那几行后这条测试失败。归“可以更好”是因为代码本身没错，缺的是测试。 |
| d3 | 集成测试的快照不是加载器能接受的完整格式 | 没改，列给 Andy：核对函数只读 `capabilities[].manifest`，和真实快照同一位置；要用完整格式得把加载器的资格和绑定材料整套造出来。 |
| d4 | “未装配”的反向断言太弱 | 已改成断言错误码 `PORT_OPERATION_NOT_INSTALLED`，去掉拿常量和自己比的断言。 |
| d6 | 夹具停用时把健康状态改成 unknown，和生产不一致 | 没改：停用那一行是任务 2（PR 435）的，不在本 PR 范围。 |
| d7 | ADR 决定编号顺序；新记录字段不对时错误文字写的是 Agent Service boot binding | 编号已改。错误文字没改，列给 Andy：那个函数是启动绑定原有的，改文字会动到启动绑定的报错。 |
