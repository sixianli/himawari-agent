# PR 630 第 3 轮判断（deepseek-v4.1-flash）

- 1（deepseek-v4.1-flash）成立，会出错，低：### 1 低-中 真实 60 个 check 步骤全部失败时，重印区一条都不输出。这是有意的：失败太多时重印放不进诊断窗口，清单仍完整列出，完整日志仍在 check.log；触发：超过 49 个步骤同时失败；后果：不重印任何输出，只列失败清单；判低理由：有意的取舍，失败清单仍完整
- 2（deepseek-v4.1-flash）成立，会出错，低：### 2 低 写入 `process.stdout` 不处理背压，父进程内存可随单个步骤输出无界增长（上一轮引入，本轮未修）。旧实现 inherit 也会把同样多的输出写进日志；CI 侧 execute 有 32MB 上限；触发：某一步输出极大且 stdout 很慢；后果：父进程写缓冲增长
- 3（deepseek-v4.1-flash）成立，会出错，低：### 3 低 `STEP_TAIL_BYTES` 实际按 UTF-16 代码单元截断，不是字节。只影响上限的精确值，不影响有界；触发：输出含多字节字符；后果：上限按 UTF-16 单元计，略偏离 64KB
- 4（deepseek-v4.1-flash）成立，会出错，低：### 4 低 `process.exitCode` 修复没有自动检查。单测覆盖 runStep；main 只有一行；触发：有人改回 process.exit；后果：最后几行可能被截掉
