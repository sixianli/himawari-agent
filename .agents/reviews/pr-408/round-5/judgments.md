# PR 408 第 5 轮逐条判断

- **ds5-1**（deepseek-v4.1-flash）「命中已保存或已拒绝的正文时，固定编号没有改指，同一 key 的旧待确认也不会被替换」：成立，中。已改：命中任何状态的行都改指，原来指着的待确认没人再指就标为被替换；被替换的决策记录不再只在命中待确认时写。补用例，旧代码下失败（已实际运行）。
- **ds5-2**（deepseek-v4.1-flash）「已保存提议的正文永不清理，记忆被彻底删除后这段文字也删不掉」：成立，中。已改：彻底删除记忆时在同一事务里把对应提议改为已拒绝、清掉正文引用，正文随记忆一起删除，只留摘要。补用例（sqlite-governed-deletion），旧代码下失败。
- **ds5-3**（deepseek-v4.1-flash）「撤销批次会把挂到已有记忆的提议重新打开」：成立，中。已改：只重新打开这批新建记忆的条目和拒绝的条目，挂到已有记忆的保持已保存、离开批次。存储层 reopenBatch 改为由写入器给出要重新打开的编号。补断言，旧代码下失败。
- **ds5-4**（deepseek-v4.1-flash）「固定编号的作用域不含客户端，两个客户端用同一个 key 会互相覆盖」：成立，中低。已改：key 表主键加 client，替换只看同一客户端的 key。补用例，旧代码下失败。
- **ds5-5**（deepseek-v4.1-flash）「respond 全部条目都已在别的批次决定时仍返回成功」：成立，低。已改：一条都没决定时报 MCP_PROPOSAL_ALREADY_DECIDED。部分失败逐条返回仍在 PR A2。补用例，旧代码下失败。
- **ds5-6**（deepseek-v4.1-flash）「decide 允许 committed 且 memoryId 为空」：成立，低。已改：存储层拒绝。数据库约束不改，因为记忆被删时外键会把 memory_id 置空。
- **ds5-7**（deepseek-v4.1-flash）「写入器先存 payload 再做存储层校验，坏输入留下无人引用的 payload」：成立，低。已改：写入器在存正文之前先查分类和 client 长度。
- **ds5-8**（deepseek-v4.1-flash）「undoBatch 用 id 后缀判断归属」：成立，低。已改：按提议编号和批次号算出精确的记忆编号比对。
- **ds5-9**（deepseek-v4.1-flash）「敏感提议挂到已有的非敏感记忆时不提升分级」：成立，低。已改：这种情况不挂，另建一条敏感记忆。补用例，旧代码下失败。
