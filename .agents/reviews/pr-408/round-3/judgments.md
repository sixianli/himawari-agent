# PR 408 第 3 轮逐条判断

- **ds3-1**（deepseek-v4.1-flash）「撤销/外部删除后，已有记忆摘要缓存仍把提议挂到已进回收站的记忆上」：成立，中。已改：撤销后写入器的记忆变化计数加一，摘要表重算；挂到已有记忆前再读一次，不是 active 就新建。新用例：撤销后用同一张摘要表保存同文提议，建出新记忆；两处都去掉后用例失败（已实际运行）。
- **ds3-2**（deepseek-v4.1-flash）「`respond` 的部分失败被吞掉，网页只看到“成功”」：同第 1 轮 ds-6，放到 PR A2（要改约定和网页）。
- **ds3-3**（deepseek-v4.1-flash）「同一个 `key` 的新正文若已作为别的待确认行存在，旧 `key` 行不会被替换」：成立，中（与 ADR 决定 2 不符）。已改：命中待确认行时也替换同一 key 的其他待确认行，并给命中行补上这个 key。新用例覆盖；去掉后用例失败（已实际运行）。
- **ds3-4**（deepseek-v4.1-flash）「待确认列表解密与“调高分级时删除旧 payload”存在竞态，可能让记忆页整页读取失败」：成立，低。已改：listPending 也进写入器队列。
- **ds3-5**（deepseek-v4.1-flash）「`propose_memories` 的 `replaced` 不只代表“同一次调用里被后面同 key 条目替换”」：成立，低。已改：submit 返回这一次替换掉的编号，只标这一次调用里被替换的。
- **ds3-6**（deepseek-v4.1-flash）「批量工具说明写“invalid 包括分类不对”，实际分类不对会整次调用被 schema 拒绝」：成立，低。已改工具说明并更新提示词清单。
- **ds3-7**（deepseek-v4.1-flash）「64 字提议编号与决策记录 128 字上限的组合溢出」：成立，低（当前入口不可达）。已改上限为 40 字：前缀 20 加 40 加批次 38 加分隔和 declined 共 108 字。
- **ds3-8**（deepseek-v4.1-flash）「说明文档与代码/其它 ADR 不一致」：部分成立，低。ADR 0228 待确认正文引用的说法已改为带分级。登录身份一条不成立：Access 校验器给的主体本来就是 sha256: 加 64 位摘要。ADR 0226 那句已在第一个提交改成「已做」，模型看的是旧行。
- **ds3-9**（deepseek-v4.1-flash）「关闭/清理之外，提交建议表无保留策略」：可以更好。行只留摘要和状态，每条几百字节；保留期限列给 Andy。
