# PR 408 第 2 轮逐条判断

- **ds2-1**（deepseek-v4.1-flash）「撤销（undo）不在写入器队列里，和保存交错时会让「记忆已保存」与「提议回到待确认」同时成立」：成立，中高。已改：撤销整个挪进写入器的 undoBatch，在同一个队列里查批次、移入回收站、重新打开；控制层只传入移入回收站的函数。新用例里撤销后记忆进回收站、提议回到待确认。
- **ds2-2**（deepseek-v4.1-flash）「MCP 同意/拒绝和网页同时决定时，会报错或报出与事实相反的结论」：成立，中高。已改：decline 返回 false 或 keep 抛 MCP_PROPOSAL_ALREADY_DECIDED 时，按实际状态回「已保存过」或「主人没有同意」。新用例用测试钩子在读完状态后让网页先决定；去掉两处改动分别让用例失败（已实际运行）。
- **ds2-3**（deepseek-v4.1-flash）「`respond` 在队列外计算「已有记忆摘要」，跨批次并发确认同一段文字仍会各建一条」：成立，中。已改：摘要表改在队列内的 keep 里取，写入器记下自己新建记忆的次数，次数变了就重新计算。并发没有写成用例（队列串行后不可再现）。
- **ds2-4**（deepseek-v4.1-flash）「同一正文以更高分级重发时，提议行被调成 sensitive，但待确认 payload 仍是 private」：成立，中。已改：待确认正文的引用里带分级；调高时行改指按敏感加密的那份，旧的没人引用就删掉。用例补断言 payload 分级是敏感、正文可读；去掉引用更新后用例失败（已实际运行）。
- **ds2-5**（deepseek-v4.1-flash）「去重会把新提议挂到 tentative 或「已被更新版本取代」的 active 记忆上」：成立，中。已改：#activeDigests 跳过 tentative 和 supersededBy 不为空的记忆，这时新建一条。
- **ds2-6**（deepseek-v4.1-flash）「读待确认列表时的清理会删 payload，和提交插入存在竞态」：成立，低。已改：清理也进写入器队列（submit 内部用不排队的版本）。
- **ds2-7**（deepseek-v4.1-flash）「`respond` 的部分失败被静默吞掉，网页调用方拿不到失败明细」：同第 1 轮 ds-6，放到 PR A2。
- **ds2-8**（deepseek-v4.1-flash）「`decline` 先落库后写决策记录，记录失败时提议已永久变成 rejected」：不成立。主人确实拒绝了，提议记为已拒绝是事实；决策记录没写上时工具报失败，客户端重发会走 decline 的已拒绝分支补写记录（ADR 0225 已有的修复路径），现有 failDecline 用例覆盖了补写。
- **ds2-9**（deepseek-v4.1-flash）「`propose_memories` 同一批里同 key 的新正文替换旧正文时，结果里旧条仍报 `pending`」：成立，低。已改：返回前复查，被替换的报 replaced，工具说明同步。用例覆盖；改回 pending 后用例失败（已实际运行）。
- **ds2-10**（deepseek-v4.1-flash）「资源与容量没有上限」：可以更好。待确认不设总数上限是 ADR 0228 决定 6 的取舍（上限等于丢数据）；按登录身份限流已有。确认框同意时全量解密已有记忆做比对，记忆量很大时会慢，列给 Andy。
- **ds2-11**（deepseek-v4.1-flash）「ADR 0228 与代码/契约的小出入」：成立，低。已改 ADR（正文或 key、哪些情况整次调用被拒、队列范围）；导出计数排除 committed。
- **ds2-12**（deepseek-v4.1-flash）「表里允许的 proposal id 长度和派生 id 的上限不匹配」：成立，低（当前不可达）。已改：存储层拒收超过 64 字的提议编号。
