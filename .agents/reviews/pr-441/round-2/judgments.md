# PR 441 第 2 轮逐条判断

## DeepSeek

1. 中：指向目录外路径的反向用例是空转的。成立，会出错，低（过滤本身是对的，模型自己也核对过；缺的是保护它的用例，要等以后有人删掉过滤才出事，所以不按中算）。修法：用例改成在目录外放一份带失败用例的 JSON 和一份日志，登记相对路径（`..`）、绝对路径、经符号链接目录、直接符号链接四种写法，断言输出里没有目录外的内容。反向验证：去掉 `realpath` 检查，或同时去掉 `..` 和绝对路径过滤，这条用例都失败。
2. 中低：失败命令的日志排前面，对 build、browser、security 不成立。成立，会出错，低。核对：`details.commands.push` 只出现在 `scripts/ci/run.mjs:183`。触发：这三类作业里某条命令失败、同时日志总量超过上限；后果：失败的那份日志可能排在后面被省略，说明文字会列出它的名字。没有改这三个脚本去记 `details.json`（那是另一件事，会动发布的数据结构），ADR 补充里写明只有 `run.mjs` 直接执行的命令会排前面。
3. 低：说明文字预留 512 字节不够，多字节文件名时会超出上限。成立，会出错，低。修法：预留量改成下一条说明文字的实际字节数。新用例对一段连续的上限值逐个渲染，断言都不超出；反向验证：改回固定 512，用例报出 314 个超出的上限值。
4. 低：ADR 第 4 条“只报数量”、设计文档第 250 行“每个 `.log`”、测试标题过时。成立，会出错，低。三处都已改。
5. 低：用例名、文件名不检查私钥标记。成立，会出错，低。触发：用例名里带遮盖规则不认的私钥；后果：私钥正文打印到公开日志。修法：`cleanLine` 命中标记时整个名字显示成 `?`，加了用例。
6. 低：命令日志不去 ANSI 颜色码。成立，会出错，低（只影响可读性）。修法：`textTail` 也去掉颜色码，原有用例的期望从 `last ?[31mred?` 改成 `last red?`。
7. 低：`result.json`、`details.json` 没有大小上限，失败列表全量留在内存。部分成立，会出错，低。两份文件现在走同一个读取函数（普通文件、不超过 64 MiB、解析符号链接后仍在目录内）。失败列表全量收集这一半不成立：整份报告已经被 `JSON.parse` 读进内存，再存一份引用不增加占用，而“共 N 条”需要完整计数。
8. 低（推测）：中间目录是符号链接时会读到目录外。成立，会出错，低。和第 1 条一起修（`realpath` 检查和用例）。
9. 低：`--failed-logs` 没有专门的反向用例，20/120/30 没有写死的断言。成立，会出错，低。`policy.test.mjs` 加了“去掉 `--failed-logs`”“改错目录”两种变体；`ci-summary.test.mjs` 加了三个数字的断言。
