# PR 441 第 3 轮逐条判断

## DeepSeek

1. 中：ANSI 颜色码在遮盖和私钥标记检查之后才去掉。成立，会出错，中。触发：命令输出或用例名里，颜色码正好夹在密钥或私钥标记中间；后果：遮盖和标记检查都认不出来，颜色码去掉后明文出现在公开的作业日志里。修法：四处（命令日志、文件名、用例名、报错）都改成先去颜色码、再遮盖、再查私钥标记。新用例把颜色码夹在令牌中间和私钥标记中间，断言输出里没有明文；反向验证：改回原来的顺序，这条用例失败。
2. 低：诊断和日志的文件名不查私钥标记，和 ADR 的说法不一致。成立，会出错，低。修法：`safeName` 加同样的检查，加了用例。
3. 低：第一份文件就放不下时，说明文字可能超出上限。成立，会出错，低。触发：调用方传入不到约 700 字节的上限（现有调用最小约 32 KiB，实际不会发生）。修法：说明文字放不下时不写；加了小上限的用例，反向验证：改回无条件写入，用例失败。
4. 低：ADR 主句仍写“只报数量”。成立，会出错，低。主句直接改成列出前 5 个名字，并注明 2026-11-12 之前只报数量。

推测部分（硬链接、检查和读取之间的竞态、聚合内存上限）：模型自己说明不是本轮必须修、也不是这个 PR 引入的；不成立为本 PR 的问题，不改。
