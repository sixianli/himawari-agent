# PR 441 第 4 轮逐条判断

## DeepSeek

1. 中：`execute.mjs` 写日志、`publish.mjs` 发布时仍不先去颜色码。不成立为本 PR 的问题。这两处是 main 上原有的代码，本 PR 没有改；它们产出的文件留在 CI 服务器的共享目录里，汇总作业结束时删除，[ADR 0243](../../../../docs/adr/0243-ci-uses-no-github-artifacts.md) 之后不再上传到 GitHub。本 PR 新增的对外出口只有 `ci-summary.mjs` 打印的内容，那里已经先去转义序列再遮盖。要让发布环节也先去转义序列，得改 `redactText` 和发布校验（`assertClean` 用 `redactText(text) === text` 判断，直接改会把所有带颜色的日志判成含密钥），是另一件事；已在 ADR 补充里写明这个范围，并报告给 Andy 作为后续项。
2. 中低：正则只认 `[0-9;]*m`，冒号参数的颜色码和 OSC 序列绕得过。成立，会出错，低（main 上原本完全不去转义序列，这不是退步；补上更稳）。修法：改成去掉完整的 CSI 和 OSC 序列，加了冒号参数和超链接序列夹在密钥、文件名私钥标记中间的用例；反向验证：改回只认 `[0-9;]*m`，这条用例失败。
3. 低：ADR 说 security 作业自己记日志，实际它不写命令日志。成立，会出错，低。核对：`scripts/ci/check-security.mjs` 里没有 `.log`。ADR 改成“security 作业不写命令日志，失败时这一段没有内容”。
4. 低：ADR 没写说明文字放不下时不写。成立，会出错，低。已补。
5. 低：完整 PEM 私钥的文件名显示成遮盖占位而不是 `?`。成立，会出错，低（密钥本身已遮掉，只是文档说法不准）。ADR 改成“遮盖之后仍留有标记时显示成 `?`”。
6. 低（推测）：检查和读取之间的竞态、报告数量没有上限。不成立，和第 3 轮同一条，理由相同：文件由 CI 自己产生，能改这些文件的进程本来就读得到它们。
