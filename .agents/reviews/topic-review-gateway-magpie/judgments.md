# review-gateway-magpie 逐条判断

线程方案（T）、GLM 第 1 轮独立方案（G1）、GLM 第 2 轮审核（G2-编号）。DeepSeek 两轮都没有结果。

| 编号 | 意见 | 成立 | 采纳 | 理由 |
|---|---|---|---|---|
| G2-1 | 改 `REVIEW_MODELS` 会让旧账本和逐条判断记录校验失败 | 是 | 采纳 | `opencode-review.mjs:918`、`:1007` 按全名比对；改为不改身份、用 `modelID` 映射 |
| G2-2 | 插件改写系统提示违反只追加规则，需要正式例外和透传探针 | 是 | 采纳 | 插件 `index.mjs:976-1008` 的 `systemAsUser` 证实；列为待 Andy 拍板的例外，自检加透传探针 |
| G2-3 | 回环加代理的组合会被 Magpie 拒绝 | 部分 | 采纳加固 | Magpie 只拒绝带转发头的请求；云端 `NO_PROXY` 已含 `127.0.0.1`（`OPENCODE_KEPT_ENV` 也保留它），端到端实测已通过。仍显式设 `NO_PROXY`，防止换机器出问题 |
| G2-4 | 积分没有运行中的上限；容器里直接查积分没有真凭证 | 部分 | 采纳 | 运行中无积分上限属实，写进局限；直接查不是“永远失败”（加 `NODE_USE_ENV_PROXY=1` 能查到，已实测），但改用 `magpie quota --json` 更简单 |
| G2-5 | 只核对版本号挡不住自动更新换程序 | 是 | 采纳 | 改为运行前后核对 SHA-256，程序副本只读 |
| G2-6 | 和 I-76 门槛冲突 | 是 | 采纳 | `test/tooling/opencode-review.test.mjs:153-154`；门槛改写为“`apiKey` 只允许和回环地址一起出现” |
| G2-7 | 自检的模型名和输出下限会误报 | 是 | 采纳 | `opencode-review.mjs:27`、`:1695-1696`；改为按模型的下限，并核对映射后的模型名 |
| G2-8 | 新的 `providers` 字段校验会让旧账本读不了 | 是 | 采纳 | 只对带 `gateway` 的行要求 `providers` |
| G2-9 | Bun 不在锁文件里 | 部分 | 不单独锁 | 实测 Magpie 自己下载 Bun 1.4.2，GLM 引用的文档说 Bun 的校验值写在 Magpie 程序里；锁住 Magpie 即锁住 Bun |
| G2-10 | 要把 `usemagpie.ai` 加进网络白名单 | 否（本环境） | 不采纳 | himawari-cloud 的网络是“unrestricted”（`get_environment` 返回）；写进文档，换受限环境时再加 |
| G2-11 | `stays=auto` 和“留在同一个账号”的说法矛盾 | 是 | 采纳 | 实测里中途切走后又切回来了；建议改为 `session`，列为待拍板 |
| G2-12 | 用量要在清理临时目录前读 | 是 | 采纳 | 读不到时记为未知、按保守公式记账 |
| G1-a | 用 Magpie 网关密钥的 token/美元限额在转发前拦 | 是 | 不采纳 | 现有 `spend-guard.mjs` 配保守单价已能在请求前拦，而且有 I-77 的门槛测试；Magpie 的限额对没有价格的 CodeBuddy 不计费（G1 自己也指出），要另配 token 限额，多一套机制 |
| G1-b | 新增积分的先问线 | 是 | 不采纳 | 积分不是钱；Andy 定的是“剩余低于 20 不用”，按底线执行即可，不另设先问线 |
| G1-c | 用环境变量切换路由 | 是 | 改为命令行开关 | 和现有 `--models` 等参数一致，账本里能记下 |
| G1-d | 双路由提示词逐字节一致的探针 | 是 | 采纳 | 并入透传探针和“开关关闭时配置不变”的测试 |
| T-1 | 启动脚本安装加快照复用 | — | 保留 | G1 主张运行时安装，但没有锁版本（从 `/api/latest` 下载最新版）；锁文件加快照更稳 |
