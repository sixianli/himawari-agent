# PR 289 第 1 轮复核逐条判断

复核提交 338e5ff4（经 Magpie，两个模型都跑，都由 CodeBuddy 回答）。

这一轮没有中高的“会出错”意见。模型标“中”的几条都不会丢数据、泄露凭证或超花：最坏是配置写错时在开跑前停下，或文档描述旧了。低的全部修改，改动在 `--accept-low` 的范围内。D8、G2 属于“可以更好”，列给 Andy；G3 不成立。机器可读的版本在 `verdicts.jsonl`。

| 编号 | 意见 | 类别 | 判断 |
|---|---|---|---|
| D1 | 自检不碰真服务方，文档的验证步骤会误报通过 | 会出错（低） | 自检确实只用假服务方；但开跑前的预检会核对真服务方：实测模型名拼错时 Magpie 的模型清单里没有它，预检停下、不发请求。文档写明。 |
| D2 | 文档仍按两家服务方描述 | 会出错（低） | 改成去掉 CodeBuddy 后先 OpenDesign 再 Go，凭证清单加 `amr-link.open-design.ai`。ADR 正文是当时的决定，不改写，后续一节已记。 |
| D3 | 自定义服务方的模型清单没和成员交叉校验 | 会出错（低） | “预检自己校验自己”不成立（实测见 D1）。仍补读入时的校验和反向用例。 |
| D4 | 不用 workspace 配置跑测试会继承云端变量 | 会出错（低） | 那条子进程用例显式清空变量。 |
| D5 | 顺序测试是同义反复 | 会出错（低） | 成员顺序改成字面量，补“只剩 Go”。 |
| D6、G1 | `main` 读环境变量的接线没测试 | 会出错（低） | 新增子进程用例，变量名改掉时失败。退回直连就是改动前的行为，按低处理。 |
| D7 | 自定义服务方用的假密钥是 `probe` | 会出错（低） | 改用 `proxy-injected`，实测 OpenDesign 3 次都返回 200。 |
| D8 | 任何一家清单取不到整次复核都停 | 可以更好 | 与 PR 281 的 R6-D4 同一取舍；文档写明这时用 `--gateway direct`。 |
| G2 | 三家顺序没有端到端用例 | 可以更好 | 顺序由字面量断言钉住；端到端探针列给 Andy。 |
| G3 | 删掉了无关注释 | 不成立 | 项目规则要求删掉所编辑文件里已有的注释。 |

修改后的验证：分别去掉 `main` 的环境变量接线、自定义服务方的非空检查、成员模型名检查，对应用例都失败；`review-gateway.test.mjs` 和 `opencode-review.test.mjs` 共 187 条通过；`npm run check` 41 步全过。
