# PR 452 第 3 轮逐条判断

## DeepSeek

1. 中：纯日期的记忆按当地日期两端都含来算，不是严格的 7×24 小时。不成立。和第 1 轮第 7 条、第 2 轮第 3 条是同一条。模型说的现象属实：纯日期没有时刻，所以只能按日期比，今天和第 7×24 小时所在的那一天都算进来。这是有意的选择，不是出错：提醒的窗口（现在到 7×24 小时后）本来就会碰到这 8 个当地日期，纯日期的事落在这些日期里就列出；如果改成只列 7 个日期，窗口最后一天有提醒的事会列出、同一天只有日期的事反而不列，两种条目对不上。今天的纯日期也要列（“今天要洗衣服”正是要她知道的）。用例“counts the seven days in the Owner's local dates and includes both ends”把这个口径写明了。
2. 中：记忆页说明写得比代码窄。成立，会出错，低。核对属实：近期安排不分类别，任何带日期的记忆都会进，上一轮补的那句只说了“其中”的敏感记忆和事件。已改三种语言的说明：任何一条记忆只要带日期、日期落在接下来 7 天里（包括这些不放进来的），都会作为近期安排带上。判低的理由：上一轮改完后说明不再和实际相反，只是没说全；不影响发给模型的内容和任何行为。模型另提的“敏感分级的身份、偏好类记忆其实会进档案”是改动前就有的说明和行为，不在这个 PR 里，记给方案线程。
3. 低：历史报告测试自己写死三个场景。成立，会出错，低。修法：加一条用例，记录里带一条“主动提下一步”的用例，断言汇总和报告里有这一场景，未知场景被拒绝。
4. 低：没有“敏感分级的带日期记忆在允许敏感的那一轮会进”的正向用例。成立，会出错，低。修法：加了用例，同一条记忆在允许敏感时进、只允许私密时不进。

## 模型列为推测的

- 纯日期的截止日等于今天时，这条记忆当天就被当成已过期（`currentlyValid` 按字符串比较）：属实，但这是改动前就有的判断，主人档案也用它，改它会改变哪些记忆算有效，不在这个 PR 里做，记给方案线程。
- 同一条记忆开始和截止日期都在 7 天内时列两行：有意的，一行是开始、一行是截止，各自排在自己的日期上。
