# T5 对比实验：事先定好的判据

写于两轮运行之前（2026-11-05 JST）。Andy 2026-11-05 同意跑两轮，预计合计 0.12 到 0.26 美元，最多 0.8 美元。

## 案例

I-73：#207 引入模型清单从 Magpie 动态读取，模型引用变成带斜杠的 `magpie:opencode-go/deepseek-v4.1-flash`，而发送消息、保存偏好等处共用的 `machineString` 校验不允许斜杠，生产上消息发不出去（`docs/incidents-and-gates.md` 的 I-73 行）。出错的校验代码不在 #207 的改动里。

- 对比基准 `7911a7ad`（#207 合并前的 main），被复核的提交 `22ae817b`（#207 的最新提交）。
- 材料：#207 当时的 PR 说明原文，不加“斜杠”“校验”“machineString”之类提示。
- 两轮都用同一个仓库副本、同一份材料，记在同一本账（`--pr 207`）。

## 两轮

1. 基线：T6 提交 `2bfb8ee0` 的脚本，两个模型拿同一份提示词，必答问题 3 条（从 `7911a7ad` 读）。
2. 新做法：T5 提交的脚本，两个模型各有侧重，必答问题 4 条（`--questions-ref` 指向 T5 提交）。

## 判据

- **命中**：某个模型指出“清单生成的模型引用（含斜杠）过不了发送、保存或合约里的校验”这一类问题，并落到具体文件和行。只说“要注意格式”而没有指出两端对不上的，不算。
- 每轮每个模型记：结论里的意见条数、命中与否、两个模型的意见重合条数、线程判为不成立的条数（误报）、花费。
- 结论只按命中与否下：新做法命中而基线没命中，算改进；两轮都命中或都没命中，说明这一次看不出差别。一次个案不能证明普遍更好。

- 重合：基线两模型有 1 条大致重合（价格分档只覆盖新增模型）；新做法两模型按标题看没有重合，各自的发现分别落在 DeepSeek 的侧重（启动失败、坏输入）和 GLM 的侧重（测试缺口、文档、授权资格）上。重合按标题人工判断，不是逐条精确比对。
- 误报：未逐条核实，两轮都没有明显与代码不符的说法；GLM 第 2 轮说“I-73 在本仓库不存在”，在 `22ae817b` 上属实（I-73 是事后才记的）。
- 合计花费 0.3075 美元（`usage.jsonl`）。

## 结论

按事先定的判据：两轮都命中（都靠 DeepSeek），**这一次看不出新做法在命中上的差别**。看得出的变化有两点：两个模型的意见几乎不再重合；新加的第 4 条问题没有让 GLM 找到这个问题，它答了却答错。一次个案不能证明普遍更好或更差。

注意：当年真实复核时两个模型都漏了这个问题，而这次的基线 DeepSeek 就命中了。差别可能来自当年的提示词和脚本版本不同（例如推理强度、输出上限），也可能只是同一个模型每次跑的结果不同，这次实验分不清。
