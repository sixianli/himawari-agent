# 线程方案（供审核）：让模型能用上 sensitive 记忆

## 前提（来源和原话见材料；本方案另外用到的，附来源）

1. 出口遮盖把密码、验证码、机器密钥、银行卡、证件号换成占位符，模型输出里的占位符只在显示给主人和写库前还原。来源：`docs/adr/0183-mask-only-when-data-leaves-and-keep-the-original-inside.md` 决定一至三。
2. 还原只作用在助手回复的文字块，不碰工具调用的参数：`packages/runtime-pi/src/egress-context.ts:30-39`（`restoredMessage` 只处理 `block.type === "text"`）。所以模型即使把占位符写进工具参数，原值也不会被还原出去。
3. 嵌入请求本来就经出口遮盖，发出去的字节已经是遮盖后的文字：`packages/application/src/services/model-egress.ts:488-499`（`redactEmbeddings`）。
4. `recall` 的分级过滤在 `apps/agent-service/src/production-memory-recall.ts:160-163`（取不高于运行分级的）和 217 行附近的 `allowedClassifications` 过滤；档案块和自动上下文各有自己的过滤（`owner-profile-service.ts:17`、`production-run-memory.ts:357`）。
5. 其余前提同材料里的 1-7 条（文件:行已在材料中）。

## 做什么

### 第一步：凭证型 sensitive 记忆（密码、密钥、证件号码、银行卡号）能被 recall 找到，模型只见占位符

**零新增主人确认，不改模型分级门槛，不新增工具、不改工具参数、不改表结构（待核实，见风险 6）。**

1. **索引用“遮盖后的文字”建，不用原文。** 在 `hybrid-memory-provider.ts` 的 `upsert`：对 sensitive 记忆，先判断它是不是“凭证型”（见 2）。是，就用不带 tag 的 `redactForEgress(原文)`（值被换成固定的 `[密码]`、`[证件号]` 这类通用占位，不含由值算出的哈希）得到遮盖文，全文词项用遮盖文分词（“家里 / Wi-Fi / 密码”这些语境词进去，值本身不进）；向量用遮盖文去嵌入，发出去的字节和今天聊天里发的遮盖内容同类（前提 3），不需要改嵌入模型的 `allowedDataClassifications`。实体表仍不写。
2. **“凭证型”的判断（宁可漏判也不误放）：** 记忆的原文经遮盖后有凭证类发现（password、machine-secret、证件号、银行卡，不含验证码），并且 `sensitiveTopic` 是 `other` 或空。健康、财务等主题的 sensitive 记忆一律不是凭证型。判断函数放在 `packages/sensitive-capture`，索引端和 recall 端共用。
3. **recall 放开凭证型：** `ProductionMemoryRecall` 里，即使本次运行是 private，凭证型的 sensitive 记忆也允许进结果；其他 sensitive 仍排除。结果里的 `text` 仍是记忆原文，由出口遮盖在发给模型时换成占位符（前提 1），模型回答里原样写占位符，主人看到原值。自动上下文、主人档案块、后台调用（邮件检查、整理记忆）保持只取 public/private，不放开。
4. **KV 缓存：** 工具集合和 `recall` 的参数结构不变，敏感结果只出现在工具结果里（追加内容）；占位符由稳定的 HMAC 生成，同一个值每次遮成同一个占位符；排序沿用“分数降序、记忆编号升序”。
5. **已有记忆补索引：** 启动时的补投影任务（设计规格“迁移和回滚”一节）按“修订 + 模型 + 维度”判断，已存在的 sensitive 凭证型记忆修订没变，不会被重投影。需要让“投影策略版本”进入判断，或一次性补投影；如果这要加列，就排在改表结构的块之后。

### 第二步（需要 Andy 拍板，先不做）：健康、财务、法律、亲密关系、他人私事、位置这类“话题型” sensitive 记忆

这类文字出口遮盖不动它，要让模型用就得把明文发给外部聊天模型，而生产配置里聊天模型只允许 public/private。三个选项：

- A. 保持现状，模型读不到；
- B. 只给模型签名引用，显示端展开（DeepSeek 方案）：不改分级门槛，但要新增引用格式、校验签名的展开器，所有显示面（聊天、导出、推送）都要走展开器；
- C. Andy 在配置里给聊天模型加上 sensitive，并在设置里加“允许对话用到敏感记忆”的开关（默认关，Claude 的做法），打开一次长期有效，只对 recall 生效，不进自动上下文和档案块。

线程倾向 C，理由：主人自己在聊天里打的健康信息本来就发给这个模型，把明说要记的同类信息按需召回，不比这更暴露；B 的改动面大。但这是改变“什么能发给外部模型”的取舍，必须由 Andy 定。

## 放弃的做法

- 本地扫描所有 sensitive 记忆（DeepSeek 的最小版）：每次 recall 都解密 N 条，没有语义检索，“上网口令”找不到“Wi-Fi 密码”；
- 带密钥哈希的词项索引：值已经不进索引，语境词不是秘密，多一套密钥管理没必要；
- 新增 recall_sensitive 工具或给 recall 加参数：触发按对话换新工具集合；
- 每次召回弹确认：违反“常规判断应预先授权，不逐次确认”。

## 反向验收

1. 存“Wi-Fi 密码是 abc12345”后，recall 命中；抓到的模型请求体（聊天和嵌入）里没有 `abc12345`，有占位符；主人看到的回复里有原值。
2. 全文词项表、向量输入里没有原值（去掉遮盖时测试必须失败）。
3. 健康类 sensitive 记忆、待批准/已拒绝/已删除/已归档/restricted 的记忆，recall 不返回（放宽过滤时测试必须失败）。
4. 自动上下文、档案块、后台调用不返回任何 sensitive。
5. 多轮：第 3 轮 recall、第 10 轮追问，占位符仍能还原（历史里存原文、每次重新遮盖，还原表能重建）；`check:prompt-prefix` 加这个场景，故意改写历史必须失败。
6. 模型把占位符写进工具参数，原值不出现在工具实际收到的参数里。

## 风险

1. 值被占位符取代后，“abc12345 是什么的密码”这类以值查语境的问题查不到。
2. 检测漏判的凭证（全字母口令、全角数字等）会被当话题型，模型读不到——失败方向是保守的。
3. 以前已经存了、旧版本识别不出的密码记忆，topic 可能不是 other，也会被当话题型。
4. 情景摘要（episodes）路径仍只取 private，凭证型对话摘要不放开。
5. 对话中密码会出现在助手回复文字里并存库（原文，private 标签），这是 ADR 0183 既定取舍。
6. 补投影可能需要加列或一次性任务，是否动表结构未核实。
