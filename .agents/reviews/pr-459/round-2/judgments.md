# PR 459 第 2 轮逐条判断

1. linux-x64 的 wheel 规则放行 macOS x86_64 的 wheel（模型：中等）。成立，低：要人为写错锁文件，结果是 pip 安装失败，不会装错。已改：Linux 两个平台只认 manylinux、musllinux 的平台标签和 none-any。
2. wheel 的 `name`、`version` 和文件名没有互相校验（模型：低到中等）。成立，低。已改：文件名的包名和版本两段必须等于这两个字段。
3. 直接调 `run.mjs` 时要做完大量工作才拒绝（模型：低）。成立，低。已改：`runCheck` 在建输出目录之前先拒绝 build、browser、coverage。
4. `run.mjs --input` 在不知道检查类型前就算产物平台（模型：低）。不成立：`--input` 只用于读入构建产物的两项检查，它们在 linux-arm64 上本来就要拒绝。
5. 测试标题仍写“双方平台”（模型：低）。成立，可以更好。已改标题。

没有中、高的“会出错”意见，低的修改记进账本，不再复核。

这一轮之后分支上另有两处不属于复核意见的修改，协调者转来的 CI 故障：`npm run typecheck` 给 tsc 固定 4 GB 堆上限（main 上 tsc 用到约 2.1 到 2.5 GB，超过 Node 默认上限时以 134 退出）；security 检查失败时在作业日志里写出是哪一项扫描、什么错误码。
