## 意见

### 1. 低 — 愿景文件自己的版本行仍写 v2.2，与本次采纳的 v2.4 不一致
文件:行：`docs/product-vision.md:18`（对照 `docs/product-vision.md:5`、`:12`、`:208`）

问题：同一份 `docs/product-vision.md` 的文档头日期已是 2026-11-16，仓库注写“2026-11-16 以 v2.4 整篇替换”，附录也有“### v2.4 相对 v2.3（2026-11-16）”，但正文上方的版本行仍写“版本：v2.2（2026-10-31）”，并且只描述到 v2.2。读者从版本行会以为当前仍是 v2.2。

证据（读代码证实）：

```text
docs/product-vision.md:18: > 版本：v2.2（2026-10-31），基于 v2.1 修订：...
docs/product-vision.md:5:  date: "2026-11-16"
docs/product-vision.md:12: ...2026-11-16 以 v2.4 整篇替换...v2.4 的采纳记录见 [ADR 0284]...
docs/product-vision.md:208: ### v2.4 相对 v2.3（2026-11-16）
```

推测：这会增加读者和后续文档引用者的困惑，但不影响运行时行为。该行在 v2.3 时就已经是旧文案，不是本增量引入；本 PR 采纳 v2.4 后矛盾更明显。

建议：由 Andy 决定是否更新版本行；如果版本行属于“正文照原文保存”、不能由代理修改，至少在仓库注里补一句“版本行保留 v2.2 原文”，或把这一已知不一致记进 ADR 0284。

### 2. 低 — 作者累计说法“改记为已知缺口”与当前 ADR 0284 的字面不一致
文件:行：`docs/adr/0284-adopt-product-vision-v2-4.md:49`

问题：作者说法称 ADR 0284“改记为已知缺口”，但当前文件第 49 行已没有“已知缺口”字样，而是写成“本 ADR 没有逐条重新核对哪些已经解决……也不改动它们”。这是第 3 轮后续改动造成的说法滞后，不是代码或文档行为错误。

证据（读代码证实）：

```text
docs/adr/0284-adopt-product-vision-v2-4.md:49:
0134「后果」里列出的下游冲突，本 ADR 没有逐条重新核对哪些已经解决
（例如其中“邮件检查不读正文”一条已由 ADR 0159 改掉），也不改动它们。
```

建议：更新这一轮的说法核对记录即可；不需要再改 ADR 正文。
