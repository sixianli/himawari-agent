- 1（deepseek-v4.1-flash）成立，会出错，低：### 1. 中：上一轮第 4 条没有改好，旧代码移动或复制到别的路径仍会被当成“当前已不存在”。plan-claims.mjs claimEvidenceProblem 231-240 行：headTexts 以 place.path 为键，只取同路径在 head 的内容；挪走后 atHead 为 null 被跳过，与第 3 轮意见 4 同一缺口；触发：方案讲的代码在 PR 里从 a 路径挪到 b 路径，模型对 a 路径写 文件:行@旧提交；后果：commit-quote-still-in-head 只查同一路径，这条证据不会报错；model-review.md 和 ADR 0270 写“当前提交里已经没有这段原文”，比代码宽；判低理由：沿用第 3 轮意见 4 的原判，这段代码本轮没改（本轮增量只是把单处改成对每个 place 各读各的）：引文确是那个提交里的真实代码，说法仍被对着代码核过，不放行未核对的说法；文字比代码宽但不误导到做错
- 2（deepseek-v4.1-flash）成立，会出错，低：### 2. 中：缓存命中后跳过大部分自检的分支仍没有自动测试，上一轮第 3 条未落实。opencode-review.mjs selfCheck 的 cached 分支在 test/tooling/opencode-review.test.mjs 里没有调用 selfCheck({cached:true}) 的用例，同一缺口；触发：无运行时触发；将来有人改坏 selfCheck 的 cached 分支；后果：现有测试只核 selfCheckCacheKey/Hit/Write，拦不下 cached:true 分支被改坏；判低理由：沿用第 2 轮意见 4、第 3 轮意见 3 的原判，这段代码本轮没改：缺的是测试，代码现在的行为正确；selfCheck 要真实 opencode 和副本，已列给 Andy
- 3（deepseek-v4.1-flash）成立，可以更好：### 3. 低：自检缓存键只指纹了 opencode 入口文件和 Magpie 安装路径，没有覆盖依赖树或插件内容。沿用第 2 轮意见 3、第 3 轮意见 5 的原判：opencode 升级或重装会改入口文件 size 或 mtime，要同大小同 mtime 换内容只能有意构造；缓存命中仍跑第一个模型的探针，正常使用没有触发路径。把依赖树和插件内容也进键算可以更好
- 4（deepseek-v4.1-flash）不成立：### 4. 低：上一轮意见的 id 和原话未转义就插进提示，可以被构造出指令性文字或控制字符。沿用第 1 轮意见 2、第 2 轮意见 1、第 3 轮意见 2 的原判，priorFindingsBlock 本轮没改、模型没给新证据：quote 经 --finish-round 核对逐字出现在上一轮模型自己的答案里，id 由 --judge-skeleton 按答案标题编号写入，只能被同一线程有意改写
- 5（deepseek-v4.1-flash）成立，可以更好：### 5. 低：`low-fix-refusals.jsonl` 直接 append 到 PR 控制的路径，可跟随符号链接写到仓库外；目录不存在时又静默不记录。沿用第 3 轮意见 8 的原判：要触发得有人有意提交指向仓库外的符号链接，同目录 usage.jsonl 的追加早就是同样写法，属“防误操作不防有意”；目录不存在不可达，--accept-low 要先有那个 PR 目录里的轮次记录。lstat 拒绝符号链接算可以更好
- 6（deepseek-v4.1-flash）成立，会出错，低：### 6. 低：沿用判断只取第一条匹配的旧 `model-wrong`，证据过期时会误拒后面仍有效的判断。plan-claims.mjs 414-423 行 carried.find 取第一条同模型同句子的旧判断，只校验这一条；这段代码本轮没改，模型第一次提出；触发：同一模型同一句话在两个以上较早轮次都判过 model-wrong，且排在前面那条的证据在当前提交里已不存在、后面那条仍有效；后果：门禁多报 claims-verdict-evidence，要线程重新判一次；只会拒绝，不会放行未核对的说法；判低理由：没给低以外的理由：只多拒绝、不放行；要同一句话在多轮重复出现且早先证据过期才触发
