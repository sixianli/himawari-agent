# “复核交给云端线程”方案讨论：三方比较和取舍

| 来源 | 意见 | 取舍 |
|---|---|---|
| DeepSeek 方案 | git 引用交接、锁、停止引用、交接脚本 | 只取“结果先核对再采用”“记录只能追加”；其余对一次只有一个交出的情形过重 |
| GLM 方案 | 材料先提交进分支；预算由 Mac 先问；失败不重跑 | 采纳 |
| DeepSeek 审核 1、3（高） | 云端线程直接写 PR 分支，事后检查拦不住强推、账本可伪造 | 部分采纳：`check` 先核对再拉取，核对强推、只改记录目录、账本只追加和字段一致；本地留着交出点可恢复；伪造按“防误操作不防有意”处理 |
| DeepSeek 审核 2、12 | 材料可被改、任务说明和材料是否同处自相矛盾 | 采纳：材料由 Mac 提交、任务说明只写路径 |
| DeepSeek 审核 4 | 提交材料后分支头不是 `--head` | 采纳：引入“交出点”，第 0 步核对交出点，`--head` 仍是代码提交 |
| DeepSeek 审核 5、GLM 审核 5 | 云端会话的花费不进账本、不走先问 | 列给 Andy 定 |
| DeepSeek 审核 6 | 代理只看 HTTPS_PROXY | 采纳：用 PROXY_ENV 名单 |
| DeepSeek 审核 7、GLM 审核 2 | 结果核对没有测试 | 采纳 |
| DeepSeek 审核 8 | 参数未校验 | 采纳 |
| DeepSeek 审核 9 | 没改第 130 行 | 采纳 |
| DeepSeek 审核 10 | 核对时执行了云端改过的脚本 | 采纳：只 fetch 不检出，用本地脚本核对 |
| DeepSeek 审核 11 | 没有开始消息和状态，可能重复交出 | 采纳：开始消息、60 分钟、不再交出第二份 |
| DeepSeek 审核 13 | 没有锁 | 不采纳：`check` 会拒绝冲突结果，写进风险 |
| DeepSeek 审核 14 | 预算和服务方只靠文字约束 | 部分采纳：`check` 核对服务方在允许范围；预算由脚本自己的先问门槛兜住 |
| DeepSeek 审核 16、GLM 审核 3 | 材料路径按当前目录解析 | 采纳：任务说明先 cd 到仓库根 |
| DeepSeek 审核 17、GLM 审核 9 | 消息格式不可机读、转抄的数字不可信 | 采纳：一行 JSON；花费以账本为准 |
| GLM 审核 1（中高） | 交出前没要求提交整个记录目录 | 采纳 |
| GLM 审核 6 | 等待期间不推送和“立即推送”冲突 | 采纳：写成等待期间不做任何提交 |
| GLM 审核 8 | 推送权限没核实 | 已核实：PR 291 那次云端线程推送了 849f495 |
| DeepSeek 建议 | Mac 默认仍直连 Go | 列给 Andy；线程建议一律交出 |
