## 做法

### 1. 什么时候交出去

Mac 线程（没有 `HIMAWARI_REVIEW_GATEWAY=magpie` 的会话）要做方案讨论或代码复核时，一律交给 himawari-cloud 里的云端线程；只有 Andy 说“直连 Go”时才在 Mac 上直连。云端线程自己要复核时照旧直接跑。

### 2. 任务说明由脚本生成，不手写

新增 `node scripts/model-review/delegation-prompt.mjs`，参数和复核脚本一样（`--mode`、`--pr`/`--topic`、`--base`、`--head`、`--previous`、`--models`、`--round`、`--approved-usd`、`--brief`），另加 `--branch <分支>` 和 `--reply-to <Mac 会话编号>`。它打印一份自成一体的任务说明：

- 第 0 步：`git fetch` 后分支头必须正好是 `--head` 那个提交，否则停下回报 `DELEGATION_HEAD_MOVED`。

- 预算：要不要 `--approved-usd`、用不用 `--providers`，由 Mac 线程交出前按现行规则问 Andy、写进命令；云端线程不得自己加参数。
- 第 2 步：运行给定的复核命令，命令里带新参数 `--require-gateway`（见第 3 条）。
- 第 3 步：只提交 `.agents/reviews/<目录>/` 下的文件，推送到同一个分支；推送被拒（分支被人动过）就停下回报，不强推、不合并、不改代码、不发 PR 评论。
- 脚本失败（退出码非 0）时不重跑，照样提交已写出的记录、按第 4 步报告。
- 第 4 步：给 `--reply-to` 那个会话发一条消息：`DELEGATED_REVIEW_DONE <目录> round=<n> commit=<提交>` 加上脚本打印的 `REVIEW_RESULT`、`GATEWAY_USAGE`、`REVIEW_SPENT_TOTAL` 各行；失败时发 `DELEGATED_REVIEW_FAILED <原因>`。
- Andy 叫停、跳过、指定服务方时，云端线程按“Andy 怎样控制复核”一节做。

### 3. 脚本里的硬检查 `--require-gateway`

复核脚本新增参数 `--require-gateway`：最终不走 Magpie（命令行或环境变量没选 magpie），或者没有出口代理（`HTTPS_PROXY` 为空），就在读材料、安装和花钱之前以 `GATEWAY_REQUIRED` 停下。任务说明里的命令一律带它，所以开到 Default 环境时脚本自己拒绝，不靠云端线程自觉。

### 4. 两个线程怎么分工

- Mac 线程：推送要复核的提交和材料 → 生成任务说明 → `start_session`（target cloud，环境 himawari-cloud）→ 等消息。等待期间不往这个分支推送。收到 `DONE` 后拉分支，先用新命令 `node scripts/model-review/delegation-prompt.mjs --check-result --from <交出时的分支头>` 核对：云端推上来的提交只改了这次的记录目录、账本新记录的 `head`、`mode`、`round` 和交出的一致；不对就不采用并告诉 Andy。核对通过后逐条判断、修改、写 `verdicts.jsonl` 和 `judgments.md`，照常提交；下一轮再交出去。
- 云端线程：只跑复核、只提交记录、只回消息，不做判断。

### 5. 出错时

- 开到 Default 或环境列表读不到：脚本 `GATEWAY_REQUIRED` 停下，云端线程回 `FAILED`；Mac 线程告诉 Andy，请他在应用里手动选 himawari-cloud，不重试到 Default。
- 云端线程跑失败：按回来的原因决定用 `--round` 补跑，再交一次。
- 消息没到：Mac 线程交出后 45 分钟还没收到，就 `git fetch` 看分支上有没有这一轮的结果提交；有就照常处理，没有就去看那个云端会话的状态，再告诉 Andy。
- 分支冲突：第 0 步和第 3 步保证云端线程只在预期的提交上追加记录，推送被拒就停。

## 风险

- 桌面应用读不到环境列表时只能落到 Default，靠 `GATEWAY_REQUIRED` 兜住，代价是白开一个会话（约 0.4 美元的 Claude 额度）。
- 云端线程是另一个 Claude，可能不照任务说明做（例如顺手改代码）：只提交记录目录这条靠任务说明约束，Mac 线程拉取后用 `--check-result` 核对，不对就不采用并告诉 Andy。
- 运行中的叫停：Mac 发消息给云端会话能不能中途送到没有核实；Andy 可以直接在应用里对那个云端会话说“停止复核”，单轮损失本来就被每个模型 0.2 美元封顶。

## 比较过、没采用的

- 用独立的 git 引用（任务、结果、锁、停止四类分支）交接，再由 Mac 合并结果（DeepSeek 的方案）：能防重复执行、能不靠消息叫停，但要新建一整套交接脚本和引用清理；现在一次只有一个 Mac 线程交出一个复核，直接推回原分支加“交出期间不推送”就够了。
- 云端线程连逐条判断一起做：它看不到写代码的上下文，判断质量差，规则也要求由写代码的线程判断。
