# PR 312 第 2 轮复核：逐条判断

DeepSeek 说未发现高、中严重度的功能回归，并确认新加的那条门槛在目标回归（把 `resultUnrecoverable` 挪进两个实例共用的参数）上确实会变红、新调用不会给后面的断言带入副作用。四条意见都成立，两条修改、两条列给 Andy。

## 会出错（已修改）

### R2-1 低：归档后的 Backlog 摘要仍用现在时说白名单「现在有两份」

成立。第 1 轮 R1-3 指出的就是这个摘要，我上一轮只改了 frontmatter 的 `record_state` 和 `result`，正文没动。

严重度判低：只会让人去找一份不存在的第二份清单，不影响运行行为。

修改：摘要改成「在这条记录写下时有两份（PR #312 已合成一份，见 `result`）」，保留它作为历史记录的原意，不再断言一个已经不成立的现状。`validate_docs.py --strict` 仍是 main 上原有的 11 条 Runbook 哈希错误。

### R2-2 低：一条反向断言断言的字符串在任何上限下都不可能出现

成立，而且是我自己上一个提交引入的。原来那条反向断言是用 `/ 1_000_000` 重算默认上限字符串；我把它换成写死的「CPU 时间 1 秒、内存 1.0 MB」，但按改后的 1024 换算，fixture 默认的 1000000 字节读作「976.6 KB」，所以这句话任何时候都不会出现。

严重度判低：同一用例的正向断言（`CPU 时间 12.5 秒`、`内存 256 MB`）仍然能挡住「用错上限」，没有功能风险；问题是这条反向断言给人一种有反向覆盖的错觉。

修改没有按 DeepSeek 建议的「改成 976.6 KB」做，因为那样它仍然是死的：这个用例里没有任何代码路径会去用 fixture 默认上限，所以写哪个默认字符串都不会失败。改成断言资源上限那段文案不含输出上限的读数（`not.toContain("1000 字节")`，1000 是这个用例里生效的输出上限）——资源上限的 `limits` 只列 CPU 时间和内存，这是真的可以被改坏的性质。

反向验证（已实测）：把 `、输出 ${limitBytes(ceiling.maxOutputBytes)}` 加进资源上限那段 `limits` 之后，三条资源上限用例都以 `expected ... not to contain '1000 字节'` 失败；还原后 112 条全过。

顺带按 R2-3 指出的不准确处，把事故表 I-84 那一行里「这个只判断的实例」改成「这个不带回调的实例」，并写明它并不是只读：仍会执行 `recoverMissingResult`，不带的只有写不可恢复记录的那个回调。

## 可以更好（不改，列给 Andy）

### R2-3：`inspectToolResultRecovery` 这个名字暗示只读，实际仍会执行 `recoverMissingResult`；把它挂在组合对象上暴露面偏宽

成立。这个实例不带的只是写不可恢复记录的回调，`recoverMissingResult` 仍在它身上，而那条路在条件满足时会 `saveOutput` 并写记录。按项目规则，命名和暴露面属于「可以更好」，不在本轮改。

我建议采纳 DeepSeek 的第一个办法：把它改名成 `recoverToolResultWithoutMarking` 之类，名字说清「不带的是哪一个能力」。不建议改成只给测试的注入口：那样生产代码里要多一条只为测试存在的分支，比一个准确的名字代价大。事故表那一行的措辞已经按这条意见改准，所以文档上不会再有误导。

### R2-4：新断言守的是导出的那个实例，不是调用点实际选了哪个实例

成立。把 `resultUnrecoverable` 挪进共用参数会被新断言抓住，但如果有人把 `authorizeAuthorityChange` 里的调用换成写记录的那个实例，现有用例不会变红。

DeepSeek 自己写了「成本较高，可作为后续补强，不是本 PR 的阻断项」。它提的便宜办法（断言两个实例不是同一个函数）在这里写不出来：写记录的那个实例没有挂在组合对象的返回值上，测试拿不到它。

我建议采纳 GLM 在第 1 轮提过的另一个办法：让 `createProductionToolResultRecovery` 在带和不带 `resultUnrecoverable` 时返回两种不同的类型，`authorizeAuthorityChange` 只接受不带的那一种，调用点被换回去就过不了 `npm run typecheck`。我在工作区试过一版用函数重载实现，被 `exactOptionalPropertyTypes` 挡住（组合里是条件展开，类型是 `resultUnrecoverable?: fn`，两个重载都不匹配），要做得改成两个工厂函数，是一处实质的结构改动，所以按规则等 Andy 说采纳再做。
