# PR 420 第 1 轮复核的逐条判断

被复核的提交：fed6ae9（基准 44a0e33）。两个模型：DeepSeek V4.1 Flash、GLM 5.3 Flash。

## 会出错（中、高）

- **ds-1 被扣留的摘要重复，导入时才失败：成立。**校验只查明文里的摘要，被扣留的摘要要到导入时从封存文件取出。修法：取出后、试导入返回之前，对没被替换的提议再查一次摘要不重复，重复时报 `LINE_INVALID`。测试：两条正文被扣留、摘要相同的提议，试导入和真导入都拒绝，表里没写任何东西。

## 会出错（低）

- **ds-2 已保存但记忆链接被置空的提议，撤销时不恢复：部分成立，判低。**生产库里删掉记忆时 `memory_id` 也会被置空（`ON DELETE SET NULL`），批次号保留，所以这种行本来就会出现，撤销时不恢复是 PR A 的后端行为。但导出、导入自己置空链接时，没理由留着批次号。修法：导出时记忆没导出、导入时记忆被跳过，`batchId` 和 `memoryId` 一起置空。没有按建议在校验里拒绝「已保存、有批次号、没有记忆」的行，因为生产库里真实存在这种行，拒绝会让正常的导出文件导不回去。测试：受限记忆和没口令时被跳过的机密记忆两种情况，导入后 `batch_id` 都是空。
- **ds-3 / glm-1 时间格式：成立。**校验加上库里存的格式（带毫秒、以 Z 结尾）。反向用例：不带毫秒的收到时间被拒绝。
- **ds-4 / glm-2 占位编号扫描范围：成立。**扫描范围加上规则、规则历史、提议、固定编号和不带编号的客户端。测试：库里已有 `[已扣留:1]` 的固定编号，再加一个像机密的固定编号，导出后能导回，三个编号互不相同。
- **ds-5 全部失败后仍显示上一批结果：成立。**每次送出前先清掉上一批的结果。浏览器测试：一批部分成功后，再送一条在别处处理过的，结果行消失。
- **ds-6 正文分级和提议分级不一致：成立。**真实数据里正文按提议自己的分级存（`production-mcp-memory-writer.ts` 提交时用同一个分级存正文），所以校验要求两者相同。反向用例：把正文分级改成 sensitive 被拒绝。

## 不成立

- **glm-3 已保存的条目后来被替换：不成立。**只有待确认的提议会被替换（`sqlite-external-memory-proposal-operations.ts` 的替换语句带 `status = 'pending'`），已保存的不会变成被替换，批次的保存条数不会少。

## 可以更好

- **glm-5 2000 字上限在三处各写一次：已改。**上限只在 `packages/gateway-contracts/src/contracts-v2.ts` 定义一次，网页和后端都从这里取。
- **glm-4 含「拒绝满 30 天、正文已删」条目的批次，撤销不恢复这些条目。**不改，列给 Andy：这是 PR A 的后端行为，要改得先让概况告诉网页一批里有几条已经没有正文，本 PR 只加了按钮，文案没有承诺逐条恢复。

## 反向验证

把四处修改分别改回去后，新加的 4 条导出测试和 1 条浏览器测试都失败；恢复后全部通过。
