# PR 428 第 1 轮判断

两个模型：DeepSeek v4.1 flash、GLM 5.3 flash。费用 0.2228 美元。

## 会出错（已修）

- D2 / G1（中高）：展示字段里的控制字符会让 `approval.detail` 合同校验失败，G1 还指出会连带让待审批列表整体失败。读代码确认：合同拒绝除制表、换行、回车以外的控制字符，生产端只遮盖不清洗。修法：遮盖之后把这些字符换成 U+FFFD，再截断；补单元用例和经网关投影的往返用例。
- D1（中高，按“文档与代码不符”）：现行 Spec 写“原始文件内容、命令不放进公开审批摘要”。需求本身（设计线程）就要预览，所以改 Spec 写明例外：取实际参数一小段、先遮盖后截断、上限可配置。模型顺带说“对话删除后 record_json 残留”：不成立，`approval_requests.run_id` 对 `runs` 是 `ON DELETE CASCADE`（`0001_initial_product_schema.sql:182`），删对话删运行时审批行一起删。
- D3（低）：展示构造之后没重读时钟。触发需要构造耗时超过剩余期限，后果是一条读出来显示为已过期的审批，不授权任何动作。已改成构造后重读时钟并重做期限检查，补用例。
- D4（低）：遮盖用例截断后本来就看不到完整卡号，删掉遮盖也过。已改成秘密放在保留部分并断言出现遮盖标记。
