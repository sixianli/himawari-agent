# PR 545 第 1 轮判断（deepseek-v4.1-flash）

- 1（deepseek-v4.1-flash）成立，会出错，低：### 1、中：分片的一致性只在单台 runner 内自证，跨台没有核对，可能出现漏跑或重跑而检查仍通过。scripts/ci/test.mjs 原来分片也用 git ls-files --cached --others；已改为分片时只用 --cached（已提交文件），test/tooling/pipeline.test.mjs 的分片用例加了一个未提交的 integration 文件，两份合起来仍只等于已提交的五个；触发：两台 runner 检出同一提交但工作树里有不同的、符合 include 的未提交测试文件；后果：两份按位置分到的文件错开，某个文件两台都没跑而各自的文件集核对都通过；判低理由：CI 每台都是同一提交的干净检出，安装步骤不生成 test/integration 下的测试文件，正常运行触发不了
- 2（deepseek-v4.1-flash）成立，会出错，低：### 2、中：`--coverage measure` 报全部项目，和拆分后按成员校验项目集合冲突，且没有“只在一台上跑”的机制。核对 run.mjs:353 measure 时用 check.projects、aggregate 按 member.projects；试过让汇总在 initialization 时按全部项目核对，会让 evidence、gate-lifecycle 里以 initialization 为真的 18 条夹具全部要重写，改动不成比例；ADR 0275 已把它写成已知限制并写明以后的做法；触发：基准上没有 ci/policy.json 的仓库第一次接入；后果：三个 tests 成员都统计全部项目，汇总按成员项目核对而不过；判低理由：resolvePolicySource 只有基准缺 ci/policy.json 时 initialization 才为真，本仓库 main 早有策略，正常使用走不到；手工 --coverage measure 不经汇总
- 3（deepseek-v4.1-flash）成立，会出错，低：### 3、低：全量运行中空分片失败只在 `run.mjs` 兜底，`runTests` 自身对零文件分片返回成功，且没有直接测试。test/tooling/runner-orchestration.test.mjs 新增 [ADR-0275] 用例：integration-2 全量且零文件时 details 里有 CI_INCOMPLETE_EXECUTION、状态不是 passed；相关范围下零文件时 passed；触发：以后有人改动 run.mjs 的 CI_INCOMPLETE_EXECUTION 判定；后果：全量运行里分到零个文件的一份悄悄算通过
- 4（deepseek-v4.1-flash）成立，会出错，低：### 4、低：ADR 的分片公式没说明下标从 0 开始，与代码的实际取法不一致。docs/adr/0275 已改成“从 0 开始数，第 i 个文件归第 i % count + 1 份”，和 test.mjs 的 index % shard.count === shard.index - 1 一致；触发：有人照 ADR 的公式手算哪个文件归哪份；后果：算出的份号和代码差一
