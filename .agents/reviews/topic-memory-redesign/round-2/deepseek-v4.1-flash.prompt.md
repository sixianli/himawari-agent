# Himawari 记忆系统重新设计：整合方案 v1

## 先回答两个问题

**1. ChatGPT、Claude 遇到同样问题怎么做，用户看到什么？**
- Claude App：边聊边由 Claude 自己按“主题”存记忆，用户在设置里按主题查看、编辑、删除；另有“搜索旧聊天”，以工具调用的形式出现在对话里，回答带链接指回原对话（support.claude.com/en/articles/11817273）。
- ChatGPT：两样东西，“保存的记忆”（明确的一条条）和“参考聊天记录”（模型从旧聊天里自己找）；新版是“持续更新的较宽摘要”，用户能看到记忆摘要、点“别再提这个”、删除（help.openai.com/en/articles/8590148）。
- Claude 开发者平台的 memory tool：模型看到 /memories 下的文件，自己 view/create/str_replace/insert/delete/rename；背后存文件还是数据库由应用决定。
- Claude Code：MEMORY.md 索引开局载入，主题文件按需读，一条记忆一个小文件。
- 共同点：**由主模型自己决定记什么、什么时候查；旧对话原话能搜能打开；用户看得到、改得了。** 没有一家是“每轮另起一个小调用替主模型挑 5 条”。

**2. 根因还是表面修补？** 根因。现在的设计让程序和小调用替主模型决定它能看到什么、记什么（见“根因”）。只把 5 条改成 20 条是表面修补；这次改的是“谁决定”。

## 前提（每条附来源）

1. 愿景原则 3：“记忆是所有决策的主要输入，必须有单一权威源，且我可查看、编辑与删除……推断带来源、时间与置信度；遗忘与纠正同样是记忆的功能……规则不是记忆，是硬性设定”（docs/product-vision.md:59）。
2. 每轮自动搜记忆：配置模板 memoryLimit 20、maxSelectedMemories 5（scripts/delivery-mode/packet-template/maintenance/production-shape-config-template.json:14-15）；context-formation-service.ts:281-286 按分数取前 maxSelectedMemories 条，其余记“selection_limit_reached”。
3. 主人资料块上限 2000 字、重要度门槛 600（packages/application/src/services/owner-profile-service.ts:20,24）。规则也从记忆里取（同文件 216-219 行，取 category === "rule"）。
4. 主模型能调的记忆工具只有读工具 memory.recall，最多 10 条 + 5 段对话摘要（apps/agent-service/src/production-memory-recall.ts:24,41,289）；工具说明：“查主人的长期记忆和以前的对话摘要”（packages/prompt-catalog/src/tools.ts:36）。没有写记忆工具，没有打开旧对话原话的工具。
5. 写记忆：每轮结束后另起一次模型调用抽取，原文最多 6000 字、近期 20 条、相关 10 条、最多 8 个候选，另有确认裁判（apps/agent-service/src/production-memory-capture.ts:64-77，MEMORY_CONFIRMATION_JUDGE 第 40 行）。
6. 模型描述里有 contextWindow 字段，可用来动态算预算（packages/application/src/ports/configuration.ts:51）。
7. 发给模型的内容只追加，每轮会变的放最后一条消息，系统提示和工具按对话冻结，工具集合变了换新一次（.agents/instructions/prompt-prefix.md 第 27-28、36、42 行）。
8. 理解用户意思交给模型，程序只做校验（.claude/rules/owner-standing-rules.md “理解用户的意思交给模型”一节）。
9. 业界资料：Anthropic memory tool（platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool）；上下文越长召回越差、建议按需检索（anthropic.com/engineering/effective-context-engineering-for-ai-agents）；按“轮”存原始历史最好、长上下文模型读全部历史掉 30%–60%（arxiv.org/abs/2410.10813）；受控对比下原话检索与全上下文接近，agent 自管记忆 42% 不如基础检索 47%（arxiv.org/abs/2606.29914）；原样保存带日期的对话、写入时不做决定（arxiv.org/abs/2609.36059）；原始片段无损保留、事实带双时间线、失效不删（arxiv.org/abs/2501.13956）；Mem0 论文全上下文基线准确率最高，Mem0 赢在延迟和 token（arxiv.org/abs/2504.19413）；单份资料文档越大越容易出错、一条条集合召回更高（docs.langchain.com/oss/javascript/concepts/memory）；文件系统工具的 agent 在 LoCoMo 74%（letta.com/blog/benchmarking-ai-agent-memory）。

## 根因

1. **读**：主模型每轮只看到检索器挑的 5 条和 2000 字资料，不知道自己还有什么，也没法“再看更多”“打开出处”。
2. **写**：主模型不能写记忆。记不记、记成什么，由每轮之后一个只看 6000 字、30 条旧记忆的单独调用决定，再过一道确认裁判。没被抽中的就丢了，主模型再聪明也找不回。
3. **原话**：旧对话只能搜到每日摘要，摘要漏的细节永远找不回。
4. **规则混在记忆里**：规则靠“模型有没有把它归成 rule 类、有没有被 2000 字挤掉”，是概率性的，违反愿景原则 3（ADR 0134 已记为已知缺口）。

## 方案：三层，主模型自己决定

### 第 1 层：原话（发生过什么，无损）
- 所有对话原文本来就全存着（thread_messages + 加密 payloads），不动。
- 新增按“轮”的检索索引（词 + 向量）。
- 给主模型两个新工具：**搜旧对话**（按意思、词、日期找，返回对话、位置、日期、原文片段）和**打开旧对话**（读某处前后原文，可往前往后翻）。
- 回答用到旧对话时带链接，点开跳回原消息（ADR 0186 已有跳转）。
- 每日摘要保留，降为“目录”：每段带指回原消息的位置，模型随时能打开原话核对。

### 第 2 层：记忆（现在相信什么，数据库唯一正本，模型看到的是 Markdown）
- 正本仍是数据库（出处原话、时间线、版本、分级、加密都保留）。
- 主模型看到一个 /memories 目录：一条记忆一个 Markdown 小文件（像 Claude Code 自动记忆），开头写类别、从什么时候成立、置信度、出处；正文可以写条件、例外。外加一个 MEMORY.md 目录文件，每条一行。
- 怎么分文件、起什么名、要不要合并，模型自己定，不写死类别。
- 工具照搬 Anthropic memory tool 的六个命令（看、建、改一段、插入、删、改名）。程序把文件改动翻译成数据库操作：改=存新版本，旧版本标失效不删；删=进回收站可恢复；建=新记忆。
- 程序只做确定性校验：出处原话必须逐字出自主人（沿用现有校验）、路径安全、版本冲突、分级上限。不再有“确认裁判”模型。
- **边聊边记**：主模型自己决定什么时候写（Claude App、ChatGPT 的做法）。
- **取消每轮之后的单独抽取调用**，改为**回看**：对话告一段落后（和现有每日回看 ADR 0231 合并），让同一个主模型带着完整记忆目录和这段时间的全部原话，补记漏掉的、合并重复、处理冲突，改动成批可撤销。回看用主模型、看全量，不是小判断。
- 纠正传播：记忆之间记“由哪条推出”，一条被改，由它推出的记忆标“待复核”，依赖它的规则标“出处变了”（沿用 ADR 0232）。

### 第 3 层：规则（硬性设定，不再从记忆里取）
- 规则只从规则手册取，必定带进上下文；记忆里只留规则的出处和修改历史。补上 ADR 0134 列的缺口。

### 每轮带进上下文的
- 对话开始时放一次：MEMORY.md 目录 + 关于 Andy 的核心记忆全文 + 规则 + 未来 7 天安排。放在第一条消息里，之后不改，保 KV 缓存。
- 大小按模型 contextWindow 算一个比例，不写死 2000 字；放不下时只放目录，其余模型按需打开。
- 对话中途记忆有变化（模型自己写的、别的设备写的），在下一条消息末尾追加一段“记忆变化”，不回头改开头。
- 每轮“程序自动搜 5 条塞进去”默认去掉，改为模型自己查；评测里作为对照组比一次，数字证明不变差才去掉。
- 所有写死的数量（10 条、5 段、6000 字、2000 字……）换成按上下文窗口动态算，加翻页。

### Andy 这边
- App 记忆页加“文本视图”：就是模型看到的同一套 Markdown，能直接改，改动同样写回数据库留版本。
- 每条记忆能点开出处原话和历史版本。
- 导出：整套 Markdown 文件 + 机器可读数据 + 校验清单，可再导入。

## 分四步做，每步单独可上线、可评测
1. **能翻原话**：搜旧对话、打开旧对话两个工具 + 按轮索引；recall 的写死上限改动态。最快见效。
2. **记忆变成文件视图**：/memories 读工具 + MEMORY.md 目录 + 开局放一次；每轮自动塞 5 条进对照评测。
3. **主模型自己写**：写入工具 + 回看取代每轮抽取和确认裁判 + 纠正传播。
4. **规则搬出记忆** + 记忆页文本视图 + 导出导入。

## 怎么证明更好（评测）
- 同一主模型、同一向量模型，只换记忆做法（论文 MemDelta 的教训）：A 现状；B 只有原话检索；C 新方案；D 新方案 + 每轮自动塞；E 新方案去掉回看；F 新方案 + 小裁判（验证 Andy “删小裁判”的判断）。
- 题目：现有合成集 + 真实记忆周评测（ADR 0239）+ LongMemEval-S 抽 100 题做行业对照；新增“原话/出处”和“纠正后不出旧值”两组题。
- 量：分五种能力的准确率、纠正后不出旧值率、该拒答时拒答、引用原话是否对、该记没记/记错率、每轮 token、延迟、缓存命中率。
- 门槛：C 不能比 B 差（否则记忆层没价值就砍掉），C 比 A 明显好。

## 风险
- 主模型漏记：原话永远在，回看兜底，评测里量漏记率。
- 主模型记错：出处原话逐字校验 + 版本可回滚 + 推断标待确认。
- 工具从 1 个变 9 个左右：工具集合变一次，按冻结规则每个老对话换新一次缓存；一次加齐，之后不改。
- 敏感内容：原话检索和记忆文件都按本次模型服务方允许的分级过滤（沿用 ADR 0193）。
