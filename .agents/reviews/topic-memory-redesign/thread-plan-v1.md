# 线程方案（v1）：记忆系统重新设计

## 根因
现在的设计是“程序和小调用替主模型决定它能看到什么、记什么”：
- 读：每轮程序用本轮消息搜 20 条、最多塞 5 条（production-shape-config-template.json: memoryLimit 20, maxSelectedMemories 5），加 2000 字主人资料块（owner-profile-service.ts:20）。主模型只能看到被挑出的碎片，不知道自己还有什么记忆。
- 写：主模型没有写记忆的工具。每轮结束后另起一次模型调用抽取，只看原文最多 6000 字、近期 20 条、相关 10 条、最多出 8 个候选（production-memory-capture.ts:64-76），再加确认裁判。这正是 Andy 否定的“只看一小块信息的小判断”。
- 翻原话：只有每日摘要可搜，没有打开旧对话原文的工具。摘要漏的就永远丢了。

## 设计：三层
### 1. 原话层（无损，所有记忆的证据）
- 所有对话原文已经在 thread_messages/payloads，保持不变。新增按“轮”的检索索引（词 + 向量），LongMemEval 实验表明按轮最好。
- 两个新工具给主模型：search_conversations（按意思/词/日期找旧对话片段，返回对话 id、消息位置、日期、片段）和 open_conversation（按 id+位置读前后原文，可翻页）。
- 回答引用旧对话时带链接，App 里点开跳回原消息（ADR 0186 已有跳转原话）。

### 2. 记忆层（数据库唯一正本，主模型看到的是 Markdown 文件）
- 正本仍是 memory_records（出处、原话、时间线、版本、分级、加密不变）。
- 主模型看到一个虚拟目录 /memories：按主题分文件（如 关于我.md、人物/妈妈.md、项目/求职.md），每行一条记忆，带短编号和日期。文件怎么分由模型自己决定（新建、改名、合并），不写死分类。
- 工具照搬 Anthropic memory tool 的六个命令 view/create/str_replace/insert/delete/rename，执行端把文本改动翻译成记录操作：改一行=新版本旧的标失效；删一行=失效可恢复；加一行=新建；行里必须能指回证据（原话校验沿用现有“原话逐字出自主人”的程序校验）。
- 边聊边记：主模型自己决定什么时候写（Claude App、ChatGPT 都是这么做的）。
- 每轮结束后的单独抽取调用取消；换成“回看”：每天（或对话闲置后）让同一个主模型带着完整记忆文件 + 当天全部原话，补记漏掉的、合并重复、纠正冲突（Letta 睡眠时 agent、现有 ADR 0231 回看对话）。回看用主模型、看全量，不是小判断。
- 规则不进这里，仍是硬性设定（愿景原则 3）。

### 3. 每轮带进上下文的东西
- 对话开头放一次：记忆目录索引（每个文件一行说明+条数）和“关于我”核心文件全文。放在对话第一条消息里，之后不改（KV 缓存规则）。
- 大小不写死：按模型 contextWindow 的一个比例算；超出时只放索引，其余靠模型按需读。
- 对话中记忆有改动，以工具结果的形式追加，不回头改开头。
- 现在“每轮程序自动搜 5 条塞进去”：保留为对照组，在评测里比；默认倾向去掉，改为模型自己读（见要 Andy 点头的第 2 项）。

### Andy 这边
- App 记忆页加“文本视图”，就是同一份 Markdown，可直接改，改动同样写回数据库留版本。
- 导出：整套 Markdown（含出处链接）+ 现有 JSON 导出。

## 评测
- 比四种：A 现状；B 新设计（文件视图+原话工具+开头索引）；C B 再加每轮自动搜；D 只有原话检索不存记忆（MemDelta 说可能不差）。
- 数据：现有合成集 + 真实记忆周评测（ADR 0239）+ LongMemEval-S 抽 100 题做行业对照。
- 量：回答准确率（分五种能力）、知识更新不出旧值率、拒答正确率、每轮 token 和延迟、写入错误率（误记、漏记、改坏）。
- 花钱：开跑前报费用和用哪个 key。

## 风险
- 主模型边聊边记会漏记 → 每日回看兜底，评测里量漏记率。
- 大文件改坏 → 每行是一条记录，改动粒度是行；版本全留可回滚。
- 敏感记忆：按本次模型服务方允许的分级过滤文件内容（现有逻辑）。
- 工具数增加（+8 个），工具定义冻结规则下只在新对话生效。
