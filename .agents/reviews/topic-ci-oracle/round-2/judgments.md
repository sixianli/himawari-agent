# Oracle 方案第 2 轮（审核）逐条判断

| 编号 | 审核意见 | 判断 | 怎样处理 |
| --- | --- | --- | --- |
| 1 | 固定命令若指向检出目录里的脚本，会被 PR 代码接管 | 成立 | 脚本装在 root 所有的系统目录，不加载检出目录的代码 |
| 2 | 接收账号进了共享组就能删改别的运行 | 成立 | 方向反过来，不再有接收账号 |
| 3 | tar 的攻击面没列全 | 成立 | 不用 tar，改传 JSON |
| 4 | Oracle 上的 PR 代码读得到测试数据 | 成立 | 测试数据目录逐个列为不可见并验证；清单要问 ARM 测试机线程；剩余风险报给 Andy |
| 5 | 长期私钥放在 PR 读得到的地方 | 成立 | 钥匙改放 CI 服务器 3 号 runner 的目录，只读；不做 OIDC |
| 6 | 暂停只去掉一个标签 | 成立 | ADR 0256 的实现已按全部标签处理，Oracle 的脚本沿用 |
| 7 | 新值的使用端没列全 | 成立 | 方案逐项列出；实现时每个值查产生端和使用端 |
| 8 | 平台是全有或全无，ARM 条目没核实 | 部分成立 | 仍用一份锁文件；证据放进工具链 PR |
| 9 | 共用标签让结果不确定 | 成立 | 固定架构，先试跑再切换，日志写架构 |
| 10 | 传输的超时、主机密钥、暂存清理没写 | 成立 | 已写进方案 |
| 11 | 安装脚本只管一台 x64 机器 | 成立 | Oracle 单独一套配置，脚本管两台 |
| 12 | `local.mjs` 不认 linux-arm64 | 成立 | 策略 PR 里改 |
| 13 | 原生依赖在 ARM 上没核实 | 成立 | Oracle 上实跑一遍作为证据 |
| 14 | “每小时清理”说得不准 | 成立 | 改成“每小时扫一次，删 6 小时以前的” |
| 15 | ADR 0256 还没落地，ADR 0238 要修订 | 成立 | 顺序里写明先落地 0256；修订 0238 |
| 16 | 反向用例不够 | 成立 | 验证一节补全 |

模型说“在线但坏掉的 runner 不会自动回退”：成立，已写进“Oracle 不在时”。
