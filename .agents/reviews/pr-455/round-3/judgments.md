# PR 455 第 3 轮代码复核：逐条判断

模型：opencode-go/deepseek-v4.1-flash。复核的提交：4bc381ce5，增量从 74c64574 起（含合入 PR 451 分支的 7 个提交）。第一次运行被后台命令的 10 分钟时限中止，没有答案，账本记为 owner-stopped；用 `--round 3` 重跑得到这份答案。这一轮没有新的中、高严重度的“会出错”意见。

## 会出错，低（已修改）

2. **程序条目的链接不校验协议**（模型：中（潜在），线程判低）。成立。触发：以后登记的由别的程序写入的来源把外来内容当链接传进来；现在没有登记这种来源，模型自己写明“当前没有生产写入方，属于潜在风险”。后果：提醒页出现不是 https 的可点链接。修改：`recordProactiveProgramEntry` 只接受空字符串或 `https:` 链接，其余返回 entry_invalid。测试：`a program entry is not recorded twice...` 加了 `javascript:`、`data:`、`http:`、不是链接的字符串四种被拒，和一条 https 链接被接受。反向验证：把协议判断放宽后这条用例失败。
3. **提议入口一直不答复会让检查多等最长 3 分钟**（模型：低）。成立。修改：`packages/application/src/services/proactive-mail-check-service.ts` 交出去之后不再等提议入口答复，抛错和拒绝照旧不影响检查。测试：`a proposal entry that fails or never answers does not hold up the check` 的检查时限从 50 毫秒改成 10 分钟，一直不答复的接收方也必须立刻返回。反向验证：改回等待后这条用例超时失败。
5. **“存储层在事务里读每天上限”缺一条专门的用例**（模型：低）。部分成立。模型说并发用例在旧实现下也会通过；实测把存储层读上限的判断拿掉，并发用例 `two writers racing...` 会失败，所以它并非区分不了。但“预检之后上限被调低”确实没有专门的用例，已补：预检读完已用量之后把上限调到已用量，写入被存储层以 daily_limit 拒绝。反向验证：拿掉存储层的判断，这条用例失败。
6. **条目不是对象时抛 TypeError，时间字符串没有长度上限**（模型：低）。成立。修改：条目不是对象返回 entry_invalid；dueAt、deliverAt 超过 40 个字符直接拒绝。测试：同一条用例加了 null 条目和带 100 个空格的时间。

## 可以更好（不修改，列给 Andy）

4. **每个来源的开关和上限不导出**。成立，可以更好。设计文档 `docs/execution/specs/2026-11-11-apple-device-body-design.md` “导出导入”一节把“每个来源的设置”列在要导出的一类里；第 7 批的任务说明没有要求这一项，现有的总开关和不打扰时段（`proactive_settings`）现在同样不导出。后果：从导出文件恢复后，每个来源的开关回到开、上限回到登记表的默认值。加进导出要改导出文件的格式，建议和 `proactive_settings` 一起另做。表结构目录里的说明从“never exported”改成了如实的“现在不导出，恢复后用默认值”。

## 不成立

1. **clear_records 清掉全部来源的记录**（模型：中）。维持第 2 轮的判断，不成立。这条在第 1、2 轮都提过，第 2 轮已写明理由；这一轮涉及的代码没有改过，触发条件没有变，模型没有给出新的失败输入或运行结果，只是把同一段代码引得更全。理由不变：`docs/execution/specs/2026-10-29-proactive-loop-v1-gmail-design.md` 第 302 行写的就是“删除全部记录”，网页上这个按钮的含义也是清空全部；登记表里只有 Gmail 一个来源，这个 PR 不登记新来源。同一条里提到的两处（断开来源时只对 Gmail 撤销 OAuth 授权；断开来源时清掉全部降频状态）都是改动前就有的行为，降频表没有来源列，按来源区分要改表。登记第二个来源之前，需要先定“清除记录”和“断开”是按来源还是全部，已列给设计线程。
7. **两处来源登记表要人工保持一致**（模型标为未核实）。不成立。存储层默认的来源清单由 `registeredSqliteProactiveSources()` 从同一个 `PROACTIVE_SOURCES` 生成，导入默认用的 `PROACTIVE_SOURCE_NAMES` 也是它的 `names`；另外传入清单的只有测试里登记假来源的地方。
8. **登记表里只有 Gmail、没有“提示词编号”字段**（模型标为未核实）。不成立。任务说明写明这一批不登记新的真实来源，登记表只放流程上的事实，不放场景名和每个来源的提示词。
