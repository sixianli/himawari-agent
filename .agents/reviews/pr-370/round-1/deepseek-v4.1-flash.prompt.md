# P3-2：聊天找记忆时嵌入失败，退回关键词和实体，不再整轮失败

## 问题
嵌入（把文字变成向量）走外网，会失败（断网、网关不报费用、HTTP 402 额度被拒）。检索层 `packages/memory-engine/src/hybrid-memory-provider.ts` 的 `search` 在嵌入抛错时调用 `onVectorFailure`，然后按关键词和实体继续查；生产在 `apps/agent-service/src/service-main.ts` 把它接到 `retrievalDegradeRecorder`，写一条 `retrieval_degrade` 决策记录。Gmail 检查和回忆工具都照常继续，只有聊天路径整轮失败。

## 目标（验收标准，不能改）
模拟向量失败，聊天 run 带着关键词找到的记忆完成，且有一条检索降级记录（测试）。复用检索层已有的退化和记录，不重写。

## 作者的说法
- 聊天路径失败有两处原因，都在 `apps/agent-service/src/production-run-memory.ts`：一是检索层降级后这一层又抛 `CONTEXT_MEMORY_*`；二是嵌入请求发出后失败记成“结果未知”（markUnknown），整轮预算账户变成 reconcile_required，后面的对话模型调用会被预算拒绝。
- 改法：聊天路径直接返回检索层结果；聊天路径嵌入发出后失败（非主人取消）按预估上限 settle（同文件里 3 秒超时和 Gmail 路径已有先例）；投影路径和取消保持 markUnknown；删掉用不到的失败码、RunCoordinator 分支、执行记录映射和三语文案；进程测试替身补接 onVectorFailure 并导出 retrievalDegradeRecorder。
- 新 ADR 0216 部分取代 ADR 0109 决定 4 的嵌入部分；事故清单 I-11 补一句。
- 测试：`test/integration/production-http-composition-process.test.ts` 的 `[P3-2]` 用例；`apps/agent-service/test/production-model-composition.unit.test.ts` 改为按预估结清。
