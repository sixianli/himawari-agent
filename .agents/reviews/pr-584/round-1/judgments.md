- 2（deepseek-v4.1-flash）成立，会出错，低：### 2. 中：`shadowRunsDone` 数的是模型记录，不是抽样轮次。increment.mjs 旧 298-313 行按 ok 记录计数；已改为按 账本目录+round 去重，测试补了双模型和两次运行；触发：shadow 运行带两个模型（被复核的提交里打印的命令从不带 --models，只有主线程手工加时才会）；后果：抽样次数按模型条数算，实际抽样少于 shadowFullTotal；复核结论和合并检查不受影响；判低理由：被复核提交里 shadowCommand 不传 --models，shadow 只跑默认单模型，正常使用计数正确；后果只是少抽样，不给错结果
- 3（deepseek-v4.1-flash）成立，会出错，中高：### 3. 中：`SHADOW_FULL_SUGGESTED` 的命令没有转义 brief 路径，也漏了模型/服务方/批准额度。increment.mjs 旧 shadowCommand 只拼 pr/base/head/brief/gateway 且 brief 未转义；已加 shellQuote 并带上 models/providers/approvedUsd，测试用 sh 拆参数核对；触发：Andy 指定 --providers（或 --models、--approved-usd）跑增量轮后，主线程照抄 SHADOW_FULL_SUGGESTED 命令；后果：shadow 运行不带 --providers，会经 Andy 排除的服务方调用模型，违反 Andy 控制服务方的规则；brief 路径带空格时命令拆坏
- 4（deepseek-v4.1-flash）成立，会出错，中高：### 4. 中：合并基线算不出时没有退回，main 改动会混进“本轮增量”。increment.mjs 旧 117-123 行 merge-base 为 null 时 mainChanged=[] 且 fallback:null；已改为返回 merge-base-failed，并补无关历史的测试；触发：origin/main 存在但与 previous 或 head 没有合并基线（浅克隆、无关历史）；后果：不退回，unreviewedFiles 退回全部改动文件，main 带进来的改动被当成本轮 PR 增量，提示文字与事实不符；与 ADR 0280 第 5 条不符
- 5（deepseek-v4.1-flash）成立，会出错，中高：### 5. 中：速度报表把退回轮也回算成增量轮分档，污染“改前/改后”对比。review-speed-report.mjs 旧 281 行只看 increment?.lines；已改为 increment 存在就不回算，补了真实 git 用例；触发：有退回原做法（increment.fallback）的增量轮出现在速度报表里；后果：backfillIncrements 给退回轮回算行数，bucketStats 把它算进改后的增量分档，改前改后对比失真
- 6（deepseek-v4.1-flash）成立，会出错，低：### 6. 低：增量块预算按“未加增量的提示”计算，且截断列表导致少放文件；提示总长没有测试。increment.mjs 旧 used 初值含全部截断清单且从不回减；已改为每加一个文件重算 render，main 改用 withIncrement 超限时退回 too-large，均补测试；触发：本轮增量接近字节预算时；或将来改文案使增量轮材料比退回文案长；后果：能放下的文件被列进“已截断”，模型需按列出的命令自取差异；文案变长时直接抛 PROMPT_TOO_LARGE 而不是退回。当前文案增量轮材料比退回文案短 56 字节（已用脚本核对），不会超限
