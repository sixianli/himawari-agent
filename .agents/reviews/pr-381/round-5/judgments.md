# PR 381 第 5 轮逐条判断

这一轮的 r5-1、r5-2、r5-4、r5-5 都来自“记住上次补到哪一条”这个做法本身，所以不再逐条修补，而是换掉这个做法：不记位置，改为给算不出来的那一条记一个“多久之后再试”（1 小时起、加倍、最长 24 小时，记在服务内存里），每次补算都从头翻页，跳过还在等的条目。

| 编号 | 判断 | 严重度 | 处理 |
| --- | --- | --- | --- |
| r5-1 | 成立：3 条坏条目让这次补算停下后，后面的好条目要等下一次 | 中高 | 在等的坏条目直接跳过、不占名额，下一次补算立刻越过它们；用例覆盖 |
| r5-2 | 成立：只剩坏条目时全量补算永远报错、永远重试 | 中高 | 剩下的只有在等的坏条目时补算返回 0、算作完成；用例“只剩坏条目时返回 0、不再试” |
| r5-3 | 成立：写诊断抛错会让重试定时器建不起来 | 中高 | 先排好重试再写诊断，写诊断放进 try；用例让诊断抛错，还原时出现未处理的拒绝并失败 |
| r5-4 | 成立 | 低 | 不再绕回，同一次里同一条最多试一次 |
| r5-5 | 成立 | 低 | 不再有共享位置；同一条正在算时另一次补算跳过它 |
| r5-6 | 成立 | 低 | 新增真实 SQLite 用例：两条不同创建时间的摘要，分别核对按时间和按 id 的比较；只比 id 或只比时间时都失败 |
