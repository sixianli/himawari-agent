# PR 576 第 1 轮判断（deepseek-v4.1-flash）

- 1（deepseek-v4.1-flash）成立，会出错，低：### 1. 中：设备动作读到外部内容后仍是硬拒绝，A' 的“改成问主人”没有覆盖到。属实：production-device-action-authorization.ts:59-60 在 ownerScope.authorize 之前按 untrustedOriginAllowed 和 readUntrustedContent 直接 deny，readUntrustedContent 来自 production-device-actions.ts:92 的运行级外部内容标记；ownerApprovedTask 到不了这一层。错的是效果句 production-task-proposals.ts:256 写了“任何写入也都先问你”，按低修：改效果句写准。；触发：主人同意的任务读过网页后调用 calendar.create、calendar.update、calendar.delete、contact.update 或 home.control 这类 untrustedOriginAllowed:false 的设备动作；后果：动作被直接拒绝而不是弹审批，和提议效果句“任何写入也都先问你”不符；方向是更严，不会有动作绕过主人执行；判低理由：拒绝是更安全的一侧，只是效果句说宽了；这个设备动作层的拒绝对主人自己发起的运行同样生效（production-device-action-authorization.ts:59 只看 intent.untrustedOriginAllowed 和 readUntrustedContent，不看运行来源），是 ADR 0257 起就有的按动作的设计，不是本 PR 引入的缺口；ADR 0278 决定 3 只承诺内置规则 refuseBackgroundAfterExternalContent 让位，没有改设备动作层
- 2（deepseek-v4.1-flash）不成立：### 2. 中低：提议撤销后，已经问过的审批仍按冻结事实判定，与 ADR“回到直接拒绝”不一致。不成立：一条已同意的 task.run 提议离开 accepted 的唯一代码路径是 production-proposals.ts:837-842 的 release（adopt 抛错时 accepted→pending），task.run 的 undo 直接抛 PROPOSAL_NOT_UNDOABLE（production-task-proposals.ts:190-192），reject 只动 pending（production-proposals.ts:868），所以“撤销后已有审批仍按冻结事实批准”没有正常可达的输入。即使状态被改，冻结快照里带 run_source_owner_approved_task 的结果也只是 askAfterExternalContent 让动作等主人点批准（owner-scope-authorization.ts:289-295 重新 decide），不会出现没人批准就执行；新发起的动作在 authorize 里重新读来源（owner-scope-authorization.ts:155），不带标记就回到 refuse。ADR 后果第 2 条措辞过强的部分并入第 6 条按文字问题修。
- 3（deepseek-v4.1-flash）成立，会出错，低：### 3. 低：新增的事实文字没有任何生产界面显示，ADR 承诺的审批卡内容是空的。属实：POLICY_FACT_REGISTRY 的 label 在生产代码里没有消费方（grep 只有 policy-fact-registry.ts 本身），approvalDisplay 只返回 displayTitle、bodyPreview、origin、askedBecause（action-policy-service.ts:545-559），Apple 端只显示 askedBecause.ruleText，事实代码只在控制中心治理页原样列出（governance-control-center.tsx:356-358）。这和既有事实的处理一致，错的是 ADR 后果第 3 条的说法；做卡片上的事实显示是新的界面功能，不在本 PR 范围。修法是改 ADR 0278 后果第 3 条写准现状；ADR 已过 plan-claims，而且这一轮低修改的文件数已到上限 5，这一轮不改 ADR，交主线程决定。；触发：Andy 或后来的线程读 ADR 0278 后果第 3 条，以为审批卡片会显示“这一轮是你同意过的一件任务”和读过的外部来源；后果：以为审批卡有这层上下文来抵挡网页夹带的诱导写入，实际卡片只显示动作标题、正文预览和问你的规则原因；动作仍要主人批准，不会自动执行
- 4（deepseek-v4.1-flash）成立，会出错，低：### 4. 低：控制中心的规则说明没随 revision 2 更新，仍说这条规则“不做也不弹卡片”。属实：apps/control-center/src/i18n/resources/zh-CN.ts:884、en.ts:936、ja.ts:942 的说明没有随 action-rules.ts 第 2 版条件 !("run_source_owner_approved_task" in facts) 更新。按低修：三种语言补“你同意过的任务除外，改为弹卡片问你”。；触发：主人在控制中心看内置规则 action_refuse_background_after_external_content 的说明；后果：说明写“不做，也不弹卡片”，但第 2 版对主人同意过的任务让位，由“先问你”那条弹卡片；主人会以为同意的任务读网页后写操作一定不做
- 5（deepseek-v4.1-flash）成立，会出错，低：### 5. 低：效果句“任何写入也都先问你”超出代码实际，且旧待定提议会继续显示旧文案。属实：action-rules.ts 两条外部内容规则都带 target_type != "managed-task"；设备动作层见第 1 条；effect 在提议创建时写进 owner_proposals.effect，旧提议不会改。旧提议的旧句说的是更严的行为，主人照旧句理解不会做错事，不迁移；按低修效果句措辞，和第 1 条一起改。；触发：主人在提议卡上读到 task.run 的效果句；后果：“任何写入也都先问你”不准：停掉本轮自己开的任务（managed-task）由 preauthorizeOwnTaskCancel 直接做，部分设备动作直接拒绝；旧的待定提议仍显示旧句“会被直接拒绝”，实际行为更宽但仍要主人批准
- 6（deepseek-v4.1-flash）成立，会出错，低：### 6. 低：ADR 0278 没记 `amends`，而它描述的“撤销”在现有代码里没有真实入口。属实：ADR 0278 frontmatter amends 为空（第 7 行），而它把 ADR 0257 决定 3 的内置规则升到第 2 版；task.run undo 抛 PROPOSAL_NOT_UNDOABLE（production-task-proposals.ts:190-192），accepted 只会经 adopt 失败的 release 退回 pending（production-proposals.ts:837-842）。这一轮已把 task-proposals 测试的 'revoked' 改成真实会出现的 'pending'（同时清 decided_at）；ADR 的两处（amends 指向 ADR 0257、后果第 2 条改成“提议不再是已同意，例如开运行失败退回待定”）因 ADR 已过 plan-claims、低修改文件数已到上限 5，这一轮不改，交主线程决定。；触发：读 ADR 0278 的人按 frontmatter 找它改了哪份 ADR，或按后果第 2 条以为产品里有“撤销已同意的任务”这个操作；后果：找不到它对 ADR 0257 决定 3 那条规则的修改关系；以为能撤销已同意的任务来停掉后续写入，实际 task.run 没有撤销入口
