## 二、侧重检查

- **错误路径 / 部分失败【证实】：** ADR 0234 第 6 条要求某个人的文件迁移失败时只有这个人显示“维护中”，回滚要恢复每个文件的快照（`0234:68`）；第 10 条删除步骤可重试（`0234:82`）。设计方向正确，但没有代码实现可核。
- **不合规范 / 不可信输入【证实】：** 名册里没有或已停用的人立即拒绝（`0234:67`）；Gmail 回调按发起授权时的记录找人（`0234:67`）。Access 身份编号是否一致、名单能否自动增删仍列在未核实清单（`0234:52`）。本次没有代码可验证这些路径。
- **安全 / 资源耗尽【证实+推测】：** ADR 0117:114 明确“Magpie 只监听本机时不检查访问密钥”，生产机上任何本地程序都能用 Andy 的套餐额度；ADR 0234 因此把按人上限做在主程序里，并计划用防火墙按系统账号挡住执行账号（`0234:73`）。但“按系统账号的防火墙规则能否覆盖所有执行路径”没有列进未核实清单，也没有代码；如果执行账号能绕过防火墙，按人上限就失效。CPU/内存“硬上限”也与仓库里“采样不能证明硬配额”的现有说明存在张力（ADR 0032、Runbook 263/353 行），需要实现时证明。
- **不可撤销操作【推测】：** 除了第 3 条的体验账号自动永久删除，第 10 条的“删目录、删执行账号、删 Access 邮箱”都是不可撤销的；文档写了顺序和回执，但没写删除前的最终确认或恢复窗口。建议至少对“体验者”和“受邀真人”分开处理。
- **规则文件 / 说明 / 代码一致性【证实】：** `check:adr-numbers` 会校验 ADR 文件名、标题编号、链接和路径（`scripts/check-adr-numbers.mjs:72-97`），`check:prompt-prefix` 会校验追加规则；但没有任何脚本检查“全走 OpenCode Go”这类正文措辞、推断标注或“每人一个实例”的残留表述。因此本轮这些文档矛盾不会让 CI 失败。

## 三、必答问题

### 1. 会不会改变模型已经见过的请求开头？是否仍然只在末尾追加，每轮变化的值是否都在最后一条消息？

**本次改动本身不会。** 这是纯文档 PR，没有改提示词组装、工具定义、历史存储或遮盖代码。
但 ADR 0234 第 11 条对未来迁移提出了正确要求：系统提示、工具定义、模型和服务方、数据密钥、已存历史消息、遮盖后的输出，迁移前后必须逐字节相同（`0234:83`），依据是 `.claude/rules/prompt-prefix.md` 的只追加规则。实现时必须保证：每轮变化的值（时间、本轮记忆、用量等）只放在最后一条用户消息里，不能进系统提示或工具定义。现有 `check:prompt-prefix` 能验证追加规则和反向用例，但“旧库回放”尚未实现。
**结论：文档不改变字节；未来实现有明确要求，但目前只有要求、没有迁移回放检查。**

### 2. 会不会让同一段文字在不同请求里变成不同字节？

**本次改动不会直接引入。** 文档没有新增时间字段、无序集合或依赖后文的遮盖规则。
需要注意的是 ADR 0234 第 2 条给每人“自己的模型配置”、第 7 条又要求所有人走同一条 Magpie 路由（`0234:63、70`）。如果实现把“自己的模型配置”做成同一对话中途可换模型/服务方，会违反 `.claude/rules/prompt-prefix.md` 第 8、9 条，导致缓存失效；这不是“同一文字变不同字节”，但会造成同样的请求开头失效。遮盖仍必须按第 10、11 条保持确定性。
**结论：文档本身不产生这个问题；实现时要防止按人配置导致同一对话换模型/服务方。**

### 3. 有没有对应的自动检查？反向用例真的会失败吗？

**这次没有新增自动检查。** 纯文档改动没有新增测试。
现有检查里：
- `npm run check:prompt-prefix` 存在（`package.json:56`），并带反向用例：改写历史用户消息、系统提示带每轮变化值、关掉冻结、请求中间出现 system 消息，检查都必须失败（`.claude/rules/prompt-prefix.md:74`）。这些反向用例是真的会失败，但它们不覆盖迁移回放。
- `npm run check:adr-numbers` 校验 ADR 编号、标题编号、链接和路径，测试里也有重复编号、错标题、坏链接的反向用例（`test/tooling/adr-numbers.test.mjs`）。
- **没有任何检查会捕获本轮发现的“全走 OpenCode Go”残留、0209 前提未改、案例库“放不下”写成事实、PRD 唯一所有者表述等问题。** 所以这些修正目前只靠人工复核，CI 不会失败。
