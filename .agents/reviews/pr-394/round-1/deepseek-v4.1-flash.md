## 侧重检查

- **提示前缀**：读了 `.claude/rules/prompt-prefix.md`、ADR 0234 决定 11、ADR 0076/0145。当前没有任何请求组装代码被改，所以现有请求字节不受本 PR 影响；但 ADR 0234 对“迁移后 Andy 的请求开头不变”的保证不完整，见发现 8。

**建议**：把 ADR 0234 写成“部分取代 ADR 0076 决定 2”，或在 ADR 0076 加 `amended_by`/后续说明，明确“按人按月额度”是新的例外；同时修正 ADR 0076 第 3 条“预算账本不是费用限制”的表述。不能继续写“0076 不变”。

## 推测与未核实

- **“8 GB 生产机放不下 20 人”**：ADR 0234:27、:96 把它写成事实，但同文件 :52 说“一个人常驻占多少内存……未核实”，:86 说“最多几个人在量完之前不定”。这应标为估算，不应作为已证事实。生产机约 8 GB 有 ADR 0145:41 支持，但“放不下 20 人”没有实测。
- **Andy 原话、OpenCode Go 单人条款、整合方案 P16/W16**：这些来源在仓库外（`/mnt/project-files/multi-user-plan/integrated-plan.md`），无法从仓库核对。ADR 0234:50、:110 把它们作为关键依据，建议把相关原文摘录进仓库或改为可公开核对的来源。
- **未来名册字段、额度配置键、每人标识的校验**：本 PR 没有代码，也没有定义这些字段。无法核对“产生它的地方”和“使用它的地方”是否互相接受。按 I-73 的教训，后续实现必须补：名册 ID 要过名册后端校验、额度配置键要过严格配置校验、每人模型引用要过 `modelRefString`，并加反向用例。
- **ADR 0234 承诺的“代码里出现写死额度数字就失败”反向用例**：本 PR 没有新增这个检查；`package.json:27` 的检查清单里也没有对应项。不能声称它已经会失败。
- **沙箱和系统账号能否真正阻止跨用户读取**：没有代码改动可验证。ADR 0234 已承认内核漏洞和主程序被攻破的剩余风险，但“每个执行账号独立、数据库和密钥归主程序账号”的隔离还需要实现和测试证明。

## 必答问题

1. **会不会改变模型已经见过的请求开头？**
   本 PR 只改文档，不改请求组装代码，所以当前发给模型的内容不受影响，仍然只由现有代码决定“只在末尾追加”，每轮变化的值仍应只在最后一条消息里。
   但 ADR 0234 为未来迁移写的保证不完整：决定 11 只列系统提示、工具定义、模型/服务方和数据密钥，没有列历史消息和遮盖结果；迁移测试也只是承诺，尚未实现。未来改动是否仍只在末尾追加、每轮值是否都在最后一条消息，**未核实**。

2. **会不会让同一段文字在不同请求里变成不同字节？**
   本 PR 不产生新的序列化。计划中的“每人一把数据密钥”只会让不同人的密文不同，模型看到的是解密后的明文，且不同人属于不同对话，不违反“同一对话字节稳定”。真正的风险是未来把每人的额度、用量、名册状态或时间放进系统提示：ADR 0234 没有明确要求这些每轮变化的值只能放最后一条消息。若这样实现，会让同一段文字在不同请求中变字节。现有 `check:prompt-prefix` 覆盖不了尚未实现的迁移。

3. **有没有对应的自动检查，反向用例是否真的会失败？**
   只有文档层面的机械检查：`check:adr-numbers`（检查 ADR 编号重复、文件名与标题编号一致）和 `check:docs-links`（检查链接和锚点存在）。按脚本逻辑，新 ADR 的编号、标题和链接应能通过；我没有运行检查。
   没有任何检查能发现本次的高/中级问题（ADR 0076 与 0234 冲突、PRD 第 33 行与第 36 行矛盾、ADR 0145/0032 的“决定不变”不成立、0209/0086 漏改）。ADR 0234 承诺的“写死额度数字必须失败”反向用例在本次提交中不存在，因此**不能确认反向用例会失败**。

4. **每个产生或修改的值，使用它的地方都能接受吗？**
   文档标识层面基本可以：ADR 0234 编号没有重复，标题编号与文件名一致；`superseded_by` 和 `supersedes` 路径互相对应；指向 0083、0076、0069、0117#routing-order、0200、0032、0145、0106、0003、0020、0027、0082、0089 的链接和 `#case-multi-user` 锚点都存在；Backlog 和 PRD 的路径也存在。
   问题在于：Backlog 的 `updated`/`reason` 仍是旧值；ADR 0076 和 0145 的既有决定/测试预期与新增说明冲突；未来名册字段、额度配置键、每人标识没有代码产生者和消费者，**无法核对两端校验**，属于未核实。
