# PR 300 第 2 轮复核逐条判断

复核提交 e6fd4f5d（经 Magpie，只用 DeepSeek，由 OpenDesign 回答）：34 次请求，按 Go 单价折算 0.1271 美元，没有标“花费未知”。

这一轮没有中高的“会出错”意见。模型标“中”的 R2-D1、R2-D2 都只是把合法结果误拒，不丢数据、不超花，按低处理。低的全部修改；改动涉及 `delegate.mjs`、测试和文档，超过 `--accept-low` 的单文件 30 行上限，所以再复核一轮。R2-D9 不成立。机器可读的版本在 `verdicts.jsonl`。

| 编号 | 意见 | 类别 | 判断 |
|---|---|---|---|
| R2-D1 | `unknown` 服务方被误拒，没写 `--providers` 时不校验 | 会出错（低） | 放行 `none`、`unknown`；没写时以 `gateway.json` 为准。 |
| R2-D2 | 预期轮次没看磁盘上已有的目录 | 会出错（低） | 同时看交出点里的 `round-N/` 目录。 |
| R2-D3 | 远端字段能带控制字符进终端 | 会出错（低） | 新记录里任何字段或键带控制字符就拒绝。 |
| R2-D4 | 读文件失败被当成文件不存在 | 会出错（低） | 先 `ls-tree` 判断在不在，在却读不出就当 git 出错；没加专门用例。 |
| R2-D5 | 合法补跑删除旧报错文件被拒 | 会出错（低） | 改名成 `.attempt-N.stderr.txt` 时放行。 |
| R2-D6 | `wait` 间隔大于总时长立刻超时 | 会出错（低） | 间隔不能大于总时长。 |
| R2-D7 | `--apply` 合并的是可变引用 | 会出错（低） | 合并刚核对过的提交号。 |
| R2-D8 | 费用未知的记录被当成正常 | 会出错（低） | 用复核脚本自己的口径算花费，汇总行加 `estimated=true`。 |
| R2-D9 | 替补记录满足不了 `absent=` | 不成立 | 原模型自己的记录先写进账本，不会误报。 |

修改后的验证：分别去掉 `unknown` 放行、没写 `--providers` 时的默认名单、控制字符检查、磁盘目录轮次、补跑改名放行、花费口径、合并提交号、间隔不超过总时长，对应用例都失败；三个测试文件共 223 条通过；`npm run check` 41 步全过。
