# PR 300 第 1 轮复核逐条判断

复核提交 51dd5b2d（经 Magpie，两个模型都跑，CodeBuddy 积分已低于底线，全部由 OpenDesign 回答）。GLM 第一次没跑完（第一个请求没回应，0 步就到了收尾时间，记为 `wrap-up-time`），按规则用 `--round 1 --models glm-5.3-flash` 补跑了一次，第二次正常；第一次的答案和提示词留作 `glm-5.3-flash.attempt-1.*`。

“会出错”的中高意见是 D1（G1 是同一条）：`check` 只看路径前缀，云端线程可以改写记录目录里的旧文件（例如逐条判断）或放符号链接，合并前核对就会读到伪造的内容。已修改，需要第 2 轮复核。其余“会出错”的都是低，一并修改。D6 属于“可以更好”，G6 不成立，不改。机器可读的版本在 `verdicts.jsonl`。

| 编号 | 意见 | 类别 | 判断 |
|---|---|---|---|
| D1、G1 | `check` 的目录检查太松，旧文件能被改，符号链接能混进来 | 会出错（中高） | 精确白名单：只能新增或改动预期那一轮、新记录对应模型的答案、提示词、报错文件和 `usage.jsonl`；拒绝删除和非普通文件；提示词哈希对账本。 |
| D2、G2 | 不查轮次、模型是否齐全、`outcome` | 会出错（低） | 轮次必须是预期的下一轮（补跑等于 `--round`），预期模型每个都要有记录；`outcome` 不是 `ok` 时仍接受记录，但打印 `DELEGATION_RESULT_INCOMPLETE` 并以 4 退出。 |
| D3、G5 | `--require-gateway` 只看代理变量，Mac 上有公司代理也会放行 | 会出错（低） | 同时要求 `HIMAWARI_REVIEW_GATEWAY` 是 `magpie`，否则 `GATEWAY_REQUIRED not-cloud`。 |
| D4、G4 | `wait` 的参数没校验 | 会出错（低） | 校验分钟数和间隔。 |
| D5、G3 | git 失败被当成“没变化”或“被强推” | 会出错（低） | `wait` 连续 3 次失败报错；`check` 只有 `merge-base` 返回 1 才算被强推。 |
| D6 | gitleaks 脚本来自被复核分支 | 可以更好 | 项目一贯的前提（PR 都是自己的线程写的，只防误操作），文档写明。 |
| D7 | “90 分钟”实际 88 分钟 | 会出错（低） | 多轮询一次。 |
| D8 | “改了又还原”的提交能混过去 | 会出错（低） | 逐提交检查，拒绝合并提交。 |
| D9 | 几处小的输入校验和输出顺序问题 | 会出错（低） | 都已改。 |
| G6 | `none` 服务方的豁免 | 不成立 | 真实账本里请求没到任何服务方时就有 `none`，去掉会误拒。 |
| G7 | 命令行接线、fetch 失败等没测试 | 会出错（低） | 新增用例。 |

修改后的验证：分别把拒绝非普通文件和删除、拒绝合并提交、逐提交检查、轮次、模型齐全、提示词哈希、文件白名单、`wait` 间隔校验、git 失败计数、`not-cloud` 检查各改成不生效，对应用例都失败（`merge-base` 报错那一处，后面的 git 命令会出同样的错，两种写法效果相同，没法分开测）；三个测试文件共 218 条通过；`npm run check` 41 步全过。
