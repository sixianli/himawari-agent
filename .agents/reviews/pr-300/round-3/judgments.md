# PR 300 第 3 轮复核逐条判断

复核提交 348c847d（经 Magpie，只用 DeepSeek，由 OpenDesign 回答）：25 次请求，按 Go 单价折算 0.1063 美元，没有标“花费未知”。DeepSeek 的结论是没有发现能让 `check` 接受代码改动、强推、删除旧文件或非普通文件的高危漏洞。

这一轮没有中高意见。“会出错”的都是低，改动在 `--accept-low` 的范围内（3 个文件、每个文件增删不超过 30 行、有测试改动），记账后不再复核。R3-D3、D5、D6、D7、D9 属于“可以更好”，列给 Andy；R3-D8 是文档已承认的设计取舍（云端能伪造账本），不是新问题。机器可读的版本在 `verdicts.jsonl`。

| 编号 | 意见 | 类别 | 判断 |
|---|---|---|---|
| R3-D1 | 替补成功时 `check` 仍报不完整 | 会出错（低） | 和复核脚本口径一致：有成功的替补记录覆盖该模型时不算不完整。 |
| R3-D2 | `check` 不收 `--reply-to`，和文档“同一组参数”不符 | 会出错（低） | `check` 也收。 |
| R3-D3 | 非法模型名会走到 git 出错 | 可以更好 | 复现不出来（`ls-tree` 不把 `*` 当通配）；加了防御和一条用例，但用例去掉防御也通过，没有证明力。 |
| R3-D4 | 文档“没有删除文件”与改名删除不一致 | 会出错（低） | 改文档。 |
| R3-D5 | 允许名单读工作区的 `gateway.json` | 可以更好 | 交出期间 Mac 不提交，工作区就在交出点。 |
| R3-D6 | `apply` 不校验当前分支名 | 可以更好 | 既有行为；Mac 本地分支名可能和远端不同，强行要求相同会误拒。 |
| R3-D7 | 控制字符整条拒绝可能误拒 | 可以更好 | 推测，概率很低。 |
| R3-D9 | 分支被删时空等、超大账本 git 出错 | 可以更好 | 推测，极少见。 |

修改后的验证：把替补覆盖判断、`check` 收 `--reply-to` 各改回去，对应用例都失败；三个测试文件共 224 条通过；`npm run check` 41 步全过。
