# PR 377 第 3 轮复核判断

成立的“会出错”有 2 条中（R3-1 用同一份结果再存会漏掉“取代旧记忆”、R3-2 ADR 说法），已改为存失败不重试、直接写放弃。三轮已满，按规则先问 Andy 是否再跑一轮。

- R3-1：### 中高：`#commit` 不是整体事务，第二次保存失败后仍删队列并记“放弃”，可能把“部分已存”说成“没记成”
  - 会出错，中。触发：新记忆已建好、取代旧记忆那一步失败，再用同一份结果存一次。后果与处理：第二次在编号相同、内容相同的分支直接返回，旧记忆没被取代却算成功；部分已存时界面说“没记成”。已改为存失败不重试、不排队，直接写 capture_gave_up，标签改“这轮没记全”，说明写明可能已存下一部分。
- R3-2：### 中：ADR 说“更新类再次应用会因版本号对不上被拒”，代码实际会再次更新成功
  - 会出错，中。触发：读 ADR 0222 决定 4。后果与处理：说法与代码不符；存失败不再重试后这段已删，ADR 改写为不重试的理由。
- R3-3：### 中低：失败记账本身抛错会挡住第二次保存，或导致 `capture_gave_up` 丢失
  - 会出错，低。触发：删队列行或写决策记录时抛错。后果与处理：已改为删行、写记录各自失败只上报，不互相挡住。
- R3-4：### 低：新测试只覆盖 checkpoint 请求失败，没有覆盖“部分写入后重跑”
  - 会出错，低。触发：部分写入后重跑。后果与处理：存失败不再重跑，这条路径不存在了；测试改为断言存失败时只调一次模型、不排队、写放弃。
- R3-5：### 低：中文/日文部分标签仍写“抽取失败”，与新增的“保存失败”语义不一致
  - 会出错，低。触发：存失败显示在每日评价。后果与处理：存失败只产生 capture_gave_up，它的标签已改为“这轮没记全”；“已重试”“下一轮补做”两种只来自模型调用失败，标签准确。
