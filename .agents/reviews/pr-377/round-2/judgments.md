# PR 377 第 2 轮复核判断

成立的“会出错”有 3 条中（R2-1 存失败后重新问模型会重复写、R2-2 文档说法、R2-3 网页说明归因），均已修改，需要第 3 轮复核。

- R2-1：## 1. 高（机制已证实；触发场景为推断）— 部分提交后重跑 `#attempt` 会重新抽取并重跑整个 `#commit`，写入不幂等
  - 会出错，中。触发：第一次存记忆时 processCommittedRun 写进一部分后失败，同轮重试或补做重新问模型再存。后果与处理：新结果条目不同会重复写、重复更新、重复安排提醒，或少存；已改为存失败只用同一份已解析结果再存一次，不再问模型，再失败写 capture_gave_up 并删队列行；补测试。
- R2-2：## 2. 中 — ADR/说明文档与代码不一致
  - 会出错，中。触发：读 ADR 0222 决定 4、案例库、schema-catalog。后果与处理：说法与代码不符；已按新做法改写 ADR（新增决定 4、放弃的做法）、案例库和 schema-catalog 描述。
- R2-3：## 3. 中 — 网页文案把“存记忆失败”说成“模型调用/抽取失败”
  - 会出错，中。触发：存记忆失败写出 capture_retrying 或 capture_gave_up 后打开每日评价或周报说明。后果与处理：说明写成模型调用失败，归因错；已把三种语言的说明改成“抽取或保存失败”。
- R2-4：## 4. 低（结构已证实，后果为推测）— `#replayOne` 的“读取最旧行 → 检查 `#busy`”不是原子领取
  - 不成立。不成立：oldest 返回后到 has/add 之间只隔一个 await 的恢复点，has/add 同步执行；另一轮补做成功删行后，本轮拿着旧 entry 走 #plan 和 #extract，最后 remove 和 save 对已删行是空操作，记忆 id 按生成编号去重；服务是单进程、单写者
- R2-5：## 5. 低 — 测试门禁有缺口
  - 会出错，低。触发：存记忆部分成功后失败的路径。后果与处理：缺测试；已补“存失败用同一份结果再存一次、不再问模型”和“补做时两次存失败就放弃”两条，改回前一版实现时第一条失败。周报、每日评价测试在第 0 层和完整测试里跑，不重复放进这个检查。
