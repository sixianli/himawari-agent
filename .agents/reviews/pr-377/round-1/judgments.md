# PR 377 第 1 轮复核判断

成立的“会出错”里有 4 条中（D1/G1 存记忆失败和删行顺序、D2 进程内重复补做、D7/G2 周报评价文案），均已修改并补测试，需要第 2 轮复核。

- D1（deepseek-v4.1-flash）：### 高：提交阶段的失败既不重试也不入队，而且队列在提交前就被删了
  - 会出错，中。触发：模型回答成功，但存记忆时 generations.request 或 processCommittedRun 抛 PORT_CONFLICT，或进程在删队列行和存记忆之间重启。后果与处理：已改：一次尝试=调用模型+存记忆，存失败按同一套重试/补做处理，队列行只在存成功后删除；补 2 条测试。
- D2（deepseek-v4.1-flash）：### 高：待补队列没有原子领取，同轮重试与补做会抢同一条
  - 会出错，中。触发：同一进程里 A 轮正在同轮重试，B 轮（另一个对话）开始并补做 A 那一条。后果与处理：同一条被调两次模型、可能重复存；已改：同轮重试期间把这一条放进进程内的占用集合，补做跳过；补测试。跨进程部分不成立：服务是单进程、单写者。
- D3（deepseek-v4.1-flash）：### 中：补做重建的提示词不是原轮提示词的复刻
  - 会出错，低。触发：读 ADR 0222 决定 4。后果与处理：ADR 原文没说补做提示词用当前状态、相关记忆为空，也把记忆 id 幂等说得过满；已在 ADR 写明这些和“存成功后、删行前重启”的重复窗口。
- D4（deepseek-v4.1-flash）：### 中低：同轮第二次失败后，队列里的 `last_error_code` 仍是第一次的错误
  - 会出错，低。触发：同轮两次失败、错误码不同。后果与处理：队列行错误码不是最近一次，和 ADR 不符；已改为第二次失败时更新，并改测试断言。
- D5（deepseek-v4.1-flash）：### 中低：决策记录 id 的键不含错误码，重复写入被静默吞掉
  - 不成立。不成立：同一条只有 turn:1、turn:2 两次同轮尝试，补做的 backlog:N 用 recordAttempt 原子加一后的次数，各次 id 不同；进程重启后同一轮不会再跑同轮捕获，只走补做
- D6（deepseek-v4.1-flash）：### 低：回收站里的对话会留下永久队列行
  - 会出错，低。触发：对话进回收站后一直不永久删除。后果与处理：队列行只含 id 和错误码，留着；从回收站恢复后还能补。ADR 原先没写这个保留方式，已补写。
- D7（deepseek-v4.1-flash）：### 低：周报网页对新分组的评价标签仍是通用文案
  - 会出错，中。触发：打开网页周报，记忆抽取失败这组有足够评价。后果与处理：显示“做对了/该做没做”，与 ADR 写的“没漏掉什么/漏了该记的”不符；已给三语 weekly.rate 加键并补测试。
- G1（glm-5.3-flash）：### 1.【中】补做成功后“先删队列行、后提交”留下静默丢记忆的窗口
  - 会出错，中。触发：同 D1。后果与处理：同 D1，已改。
- G2（glm-5.3-flash）：### 2.【中】周报评分按钮文案与 ADR/校准包不一致，回落到通用文案
  - 会出错，中。触发：同 D7。后果与处理：同 D7，已改。
- G3（glm-5.3-flash）：### 3.【低】队列行 `last_error_code` 停留在第一次错误，第二次失败不更新
  - 会出错，低。触发：同 D4。后果与处理：同 D4，已改。
- G4（glm-5.3-flash）：### 4.【低】数据导出/导入不含 `memory_capture_backlog`
  - 会出错，低。触发：导出再导入到新实例。后果与处理：待补的轮次不带过去；队列只是待办不是主人数据，决定不导出，ADR 写明。
- G5（glm-5.3-flash）：### 5.【低】补做重建的提示词里“相关记忆”永远为空
  - 会出错，低。触发：同 D3。后果与处理：同 D3，ADR 已写明。
- G6（glm-5.3-flash）：### 6.【信息·推测】`#replaying` 去重只在单进程内有效
  - 不成立。服务按单进程、单写者运行，没有两个进程共用一个库的部署形态；进程内的部分已按 D2 修
