# PR 433 第 1 轮代码复核：逐条判断

复核的提交是 `9fa963c4`，对比基准 `3086f38b`。两个模型各看了一遍，这一轮花了 0.2173 美元。编号 D 开头的是 DeepSeek 的意见，G 开头的是 GLM 的意见。

## 会出错，中或高（已改，要再复核）

- **D1 服务在两步之间重启会漏记文件。** 成立。命令的改动对比结果存下以后、文件登记做完之前重启，恢复时整段登记被跳过，也不写不完整标记。改法：登记做完后另存一次 `workspace-artifacts`（里面记有没有登记被丢掉）；恢复时发现没有这一条，就按存下的对比结果把登记补做一遍。登记按命令和路径去重，重做不会多记。测试：`[WC-7] a restart after the change record was saved…`。
- **D2、G4 到期时间写法不合契约会让整个文件夹清单失败。** 成立。`admin-cli` 建授权目录时只要求到期时间能被解析，契约要求毫秒精度的 UTC 写法。改法：返回前统一转成 `toISOString()` 的写法；每条记录单独按契约的 `workspaceFolderSchema` 校验，不合格的只跳过这一条并写一行日志。测试：`[WC-9] one bad stored folder is skipped…`（秒级精度、带时区偏移的两条被转成规范写法后列出；不是日期、id 和键对不上、路径不是字符串的三条被跳过，各有一行日志）。
- **D3 删除没登记上却说完整。** 成立。`recordDeleted` 现在返回“有没有没登记上的”：写库失败，或多条命令同时跑时查不出文件是否还在，都返回是，调用处据此写不完整标记。测试：`[WC-7] a deletion that could not be recorded…`，以及 `[WC-6]` 末尾两条断言。

## 会出错，低（已改）

- **D4 授权目录撤销或过期后含义不清。** 成立，判低：返回的仍是主人自己这个 agent 的改动记录，没有越权也没有错数。定的含义是“以前记录到的改动照常返回”，新加 `grantActive` 字段说明目录现在是否有效。测试：`[WC-3]` 末尾。
- **D5 先取 200 条再过滤会漏掉有效目录。** 成立，判低：要先有 200 多条失效记录。`listScopedState` 加了“从哪个键之后开始”的参数，接口一页页读、先过滤，凑够 201 条有效的或读完为止，`truncated` 按有效目录数算。测试：`[WC-9] one bad stored folder…`（201 条失效记录排在前面，有效目录仍然全部列出）和 `[WC-9] more than 200 live folders…`。
- **D6、G2 两个标记键不是一次写入。** “两个键可能一个有一个没有”成立，判低。改成只写一个对话级键，按整个目录查时看这个授权目录的键前缀下有没有任何标记，所以不会再不一致。D6 的另一半“写标记失败就让这次工具调用报失败，模型可能重试”不改：同一段代码里保存改动对比结果失败本来就同样报失败；设计线程明确要求写标记失败不能当作完整；写标记失败只剩数据库写不进去这一种原因，那时这一轮运行本来也继续不了。
- **D7 两个对话同时写目录级标记会冲突。** 成立，判低。共享的目录级键已去掉；同一对话的几条命令同时写时，后写的发现标记已在就算成功；已有标记时不再重写。测试：`[WC-4] ids that contain colons…` 后半段（三条命令同时写）。
- **D8 键用冒号拼接会撞。** 成立。键改成 `workspace-ledger-incomplete:<授权目录号长度>:<授权目录>:<对话>`。测试：`[WC-4] ids that contain colons…` 前半段。
- **D9 存储里的坏 id 让整个清单失败。** 成立，和 D2 一起改。
- **D10 查询随记录数平方变慢。** 成立，判低：只影响速度。改成窗口函数，只扫一遍。表上没有按路径的索引，加索引要改表，已写进架构文档。
- **D11 文档前后矛盾。** 成立。架构文档和运行手册两处已改。
- **D12 契约测试的名字让人以为存储也支持新工具。** 成立。测试改名，架构文档写明存储的 CHECK 约束只认四种来源，新增工具要先改表。
- **D13 `[WC-6]` 的上限用例测不到上限。** 成立。改成文件读得出来：正好 50 个不标记，51 个标记一次。
- **G1 换授权目录后旧改动算到新目录名下。** 成立，判低，代码不改：现在生产只配一个授权目录，同一目录重新授权后旧改动接着显示正是想要的；要按目录分开必须给 `thread_artifacts` 加列，本 PR 定了不改表。已写进架构文档，并告诉设计线程。
- **G3 write、edit 这一支的标记没有测试。** 成立。新加 `[WC-7] write and edit mark the thread incomplete only when…`。

## 可以更好（没改，列给 Andy）

- **G5 经 HTTP 入口、目录匹配且库里有数据的用例。** 成立。现有 HTTP 用例证明了两个操作已装进正式入口并能返回合契约的响应；目录匹配且有数据的路径由真实 SQLite 的 `[WC-1]` 到 `[WC-6]` 覆盖。要在 HTTP 组合测试里补这一条，得给那份测试配上写代码路由和授权目录，改动不小。线程建议：等 Mac 端调用方接上时，和它的端到端验收一起补。
