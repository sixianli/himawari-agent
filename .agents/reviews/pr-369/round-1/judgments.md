# PR 369 第 1 轮复核判断

成立的“会出错”全部判为低；D1 模型判中，线程判低（理由见下）。

- D1（deepseek-v4.1-flash）：### 1. 中：historyId 用 rowid，导出/导入后会换号，且 rowid 可能被复用
  - 会出错，低。触发：导出后导入到一个全新实例（import.ts:56-73 要求目标表为空，只能是新库），旧实例的网页标签页不刷新、连上新实例后直接点恢复。后果：控制中心在连接变化时重新拉取快照（apps/control-center/src/memory.ts 的 useEffect 依赖 connected），旧编号会被替换；rowid 复用只发生在最大行被删后，新行只会加在当前记忆上并让版本号加 1，旧请求被 expectedRevision 挡下。判低理由：两条路径都需要旧页面跨越换库或同时删改，且分别被重新拉取快照和版本号检查拦住，最坏结果是拒绝而非恢复错版本。
- D2（deepseek-v4.1-flash）：### 2. 低：低分级版本复制失败时留下孤儿 payload，ADR 说的“后续清理”在代码里没有对应机制
  - 会出错，低。触发：分级较低的版本另存后，restoreVersion 因并发版本号冲突失败。后果：留下没有引用的加密正文；已改为失败时删掉本次新存的那份，并补测试。
- D3（deepseek-v4.1-flash）：### 3. 低：网页用 singleLine 后的文本判断是否显示按钮，服务端用原始文本判断是否“与当前相同”
  - 会出错，低。触发：两版正文只差首尾空白或控制字符。后果：网页不显示按钮而服务端允许；已改为服务端也用 singleLine 比较并补测试。
- D4（deepseek-v4.1-flash）：### 4. 低：链归属校验与保存不在同一事务，存在链变化的 TOCTOU 窗口
  - 会出错，低。触发：同一主人在恢复某一版的同时，另开页面把链中间的旧记忆换回来。后果：恢复出的文字来自刚脱离这条链的同一主人的旧记忆；分级仍按当前记忆检查，不越权、不降级，可以再恢复别的版本撤回。
- D5（deepseek-v4.1-flash）：### 5. 低（部署兼容）：快照和命令都新增了必填 historyId，版本仍是 gateway.v2
  - 会出错，低。触发：服务端升级后，浏览器里还开着旧版网页不刷新。后果：记忆页的修改操作报契约错误，刷新后恢复；控制中心和服务端同包发布，contentRef 早已是同样的必填键。
- G1（glm-5.3-flash）：**1.（中低，测试缺口）`MEMORY_VERSION_TARGET_NOT_CURRENT` 与多层链恢复没有测试覆盖**
  - 会出错，低。触发：控制层拒绝分支和两层以上的链没有测试。后果：以后改坏不会被发现；已补两层链正向用例和恢复到被取代记忆的反向用例。判低理由：模型自己说代码逐行读过没有缺陷，只缺测试，已补上。
- G2（glm-5.3-flash）：**2.（低，部署耦合）`historyId` 成为 `memory.mutate` 所有动作的必填键，旧网页包对升级后的服务端会全线失败**
  - 会出错，低。触发：同 D5。后果：同 D5。
- G3（glm-5.3-flash）：**3.（低，已文档化但无机制）重新加密另存的正文在保存失败时成为孤儿 payload，目前没有清理机制**
  - 会出错，低。触发：同 D2。后果：同 D2，已修。
- G4（glm-5.3-flash）：**4.（信息，体验）UI 会对分级高于当前记忆的历史版本显示“恢复到这一版”，点击后才被服务端拒绝**
  - 可以更好。服务端拒绝正确；要隐藏按钮得在快照里加分级字段，同一条链分级不同的情况很少，暂不做
- G5（glm-5.3-flash）：**5.（信息）restoreVersion 不像 correct 那样把 `inference` 置 false、`confidencePermille` 置 1000**
  - 可以更好。采纳：主人亲自选了这一版，和手动修改一样记成非推断、把握 1000，有实际意义（召回会参考把握）；已改并补断言，ADR 写明
