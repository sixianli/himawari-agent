# 作者说明：PR 359，D1 第 2 步

## 改了什么
`packages/runtime-pi/src/pi-runtime-adapter.ts`：适配器原先在建好 Pi 会话之后给 `session.agent.streamFunction` 赋值，用来在每次请求模型前后做准入和预算、出口遮盖与还原、审批续跑回放、识别压缩（摘要）请求、拒发。现在改成建会话时传入每次运行专属的 `ModelRuntime` 代理（`governedModelRuntime`），只重写 `streamSimple`，其余成员转给共享的 `binding.modelRuntime`；同步返回一条流（`deferredPiStream`），异步走原来的准入逻辑。测试里的假会话改为调用代理的 `streamSimple`。文档：ADR 0208 增加第 2 步实施记录，Pi 规范 D1 行更新。

## 目标
1. 不再替换 Pi 会话的函数字段，改挂在官方的 `ModelRuntime` 上，请求行为不变。
2. 遮盖、预算准入、审批续跑回放、压缩识别、拒发这些保护一样不少。
3. 发给模型的请求字节不变（项目规则：已发内容只追加；`check:prompt-prefix` 必须过）。

## 已核对的事实
- Pi 1.5.0 `dist/core/sdk.js` 的默认 `streamFn` 最后调用 `modelRuntime.streamSimple(model, context, requestOptions)` 并同步使用返回值（预热器也是）。
- `agent-session.js` 的 `_getSummarizationRequestAuth` 把默认请求函数登记为属于传入的 `ModelRuntime`（身份比较），所以摘要不再预先取凭据；凭据由 `admitPiStream` 每次请求现取。
- `dist` 里没有 `instanceof ModelRuntime`。
- 测试：packages/runtime-pi 的 pi-compat 加 unit 共 442 条通过，含 `d4-golden-requests.json` 黄金请求（真实 Pi 会话）；`check:prompt-prefix` 27 条通过。
- 已知遗留：第 3 步之前缓存预热器（D7，生产关着）重放的是 Pi 自己的开头。
