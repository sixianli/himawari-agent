# PR 638 第 3 轮判断（deepseek-v4.1-flash）

- 1（deepseek-v4.1-flash）成立，会出错，低：### 1. 中 — 叫醒/“等不到了”/改版通知虽带 `external_content`，现有代码却不按这一列打标，生产里也没有消费端。核对 docs/execution/specs/2026-11-24-main-thread-subthreads-inbox-design.md:248 和 :469；apps/agent-service/src/context-external-content.ts:85-90；apps/agent-service/src/production-http-composition.ts:1336；apps/agent-service/src/service-main.ts:3522-3525。顺手把 :248 写成按这一行的 external_content 打、不按运行来源，补一条不带标记的叫醒不误标的反向用例；触发：编码第 3 步投递结果板事件时，把“照外来的事写进对话时的做法打上标记”理解成按运行来源 external_event 打标，而不是按这一行的 external_content；后果：要么所有叫醒都被当成外来内容、多弹同意卡片，要么带标记的事件被忽略、等待者按没读过外来内容走；后一种要兄弟写的名字里夹带指令才有害；判低理由：部分成立：现有代码只按运行来源打标属实（apps/agent-service/src/context-external-content.ts:88），生产没传 delivery 属实（apps/agent-service/src/service-main.ts:3522-3525），但接投递正是这份规格第 3 步要做的事；规格 :469 已另定“外来的事写进对话时就打上标记”的新做法，:248 写了“事件带上那一条的标记”，读下来本意是按事件的标记打；事件文字只有名字和版本，不抄简要正文，文字不够准但不误导
- 2（deepseek-v4.1-flash）成立，会出错，中高：### 2. 中 — 看目录返回简要，却没有要求把条目的数据分级带到工具结果。核对属实：docs/execution/specs/2026-11-24-main-thread-subthreads-inbox-design.md:243 只写“读正文时，工具结果带上这条存下的分级”；:244 目录返回每条的简要，没写分级；contentClassification 是可选项（packages/application/src/ports/intelligence.ts:489），不返回就按 invocation.dataClassification 记（apps/agent-service/src/production-runtime-tools.ts:1008-1014）。简要和正文同样加密存、各带分级，目录每次都返回简要，是正常使用就触发，与第 2 轮第 1 条同类，按中高；触发：子线程只调“看兄弟结果”看目录，目录里有兄弟写的、分级为 sensitive 的简要；后果：目录工具结果按运行原来的分级存盘和处理（apps/agent-service/src/production-runtime-tools.ts:1008-1014 只在工具给了 contentClassification 时才抬高），敏感简要被当成低分级内容导出、删除和处理，绕过第 2 轮第 1 条补上的分级
- 3（deepseek-v4.1-flash）成立，会出错，中高：### 3. 中 — “等结果”在结果已存在时直接返回，没写返回的是不是正文、要不要记已读和打外来标记。核对属实：docs/execution/specs/2026-11-24-main-thread-subthreads-inbox-design.md:246 只写“等的那条结果已经在了，‘等结果’直接返回，不停下”，没说返回什么；:247 记读过、:248 打标记都挂在“读正文”上，规格没把“等结果”算进去。涉及权限边界，拿不准按中高；触发：子线程调“等结果”时那条结果已经写下，实现者照“直接返回”把正文一起返回；后果：这次读正文没走第 5、6 条：不记读过哪一版，之后改版收不到通知；也不打“读过外来内容”的标记，读了外来内容带来的正文还能不经同意卡片改日历
- 4（deepseek-v4.1-flash）成立，会出错，中高：### 4. 中 — 注册等待时不查兄弟已失败/已删，失败事件又没有定义版本，重复“等不到了”可能被唯一键去重后永久挂起。核对属实：docs/execution/specs/2026-11-24-main-thread-subthreads-inbox-design.md:246 只在“等待过程中”兄弟失败、交回没写、被删时叫醒，没写登记时兄弟已经是这几种状态怎么办；:247 只说来源编号带上条目和接收者，没定版本，叫醒和“等不到了”对同一条等待重复出现时会撞唯一键。先交回、后来才被等是正常使用就会出现的顺序。模型说 source_version 可以为空不对（同一迁移 :7 是 NOT NULL），不影响结论；触发：订机票的子线程已经交回结果但没写“落地时间”（或已失败、被叫停、进入“做不下去”、被删）之后，订餐馆的才调“等结果”等它；或同一个子线程按 :246 末尾“可以再等一次”第二次等同一条、又一次等不到；后果：第一种：没有结果、也不会再有事件，等的一方一直停在“等兄弟的结果”；第二种：第二次“等不到了”的来源编号和版本与第一次相同，被 inbox_events 的唯一键（packages/persistence-sqlite/src/migrations/20261124153216_inbox_events.sql:20）当重复挡掉，同样一直挂着
- 5（deepseek-v4.1-flash）成立，会出错，低：### 5. 中低 — 名字的清洗只在写入端，查找端不跟着规范化；`clip` 也不会去掉控制字符。核对属实：apps/agent-service/src/production-inbox.ts:53-56 的 clip 只做 \s+ 折叠和 trim，不去控制字符和格式字符；docs/execution/specs/2026-11-24-main-thread-subthreads-inbox-design.md:243 只写写入端，:244、:246 按名字查找没说同样处理；触发：子线程写名字时带了换行或控制字符，之后用写入前的原字符串去取或等；或名字里带 U+202E 这类格式字符；后果：按原字符串查不到，报“没有这一条”；格式字符留在目录里，显示顺序乱掉；判低理由：查找方通常照目录里看到的（已经折好的）名字去查，只有子线程拿自己写入前的原字符串去查才触发，结果是查不到报错；格式字符没有绕过标记的路，标记按条目整体打（:248）。规格说“照 clip 去掉控制字符”与 clip 实际只折空白（apps/agent-service/src/production-inbox.ts:53-56）不符，文字不准，顺手改
- 6（deepseek-v4.1-flash）成立，可以更好：### 6. 中低 — “被删时叫醒”没写删除路径怎么在级联删除等待记录之前找到等待者。规格 docs/execution/specs/2026-11-24-main-thread-subthreads-inbox-design.md:246 已要求被删时叫醒等待者，:260 已有“被删，等它的订餐馆子线程收到‘等不到了’，等待记录没了”的用例，删除时先查等待者再删、外键要不要级联是编码时的细节，照 :260 的用例写就会暴露级联先吞掉等待记录；采纳只会在测试一行加“经过真实删除命令”几个字，不改设计
- 7（deepseek-v4.1-flash）不成立：### 7. 低 — 单板有上限，但结果板整体永不删除，长期总量仍无上限；版本到顶后也没有回收办法。不成立：总量随大事数增长和聊天记录一样，是规格定的“子线程也是对话，存在聊天记录里，不会到期删掉”（docs/execution/specs/2026-11-24-main-thread-subthreads-inbox-design.md:175），删大事时一起删（:243），不是缺上限；单块的条目数、版本数、长度上限已有（:243）。版本到顶后规格写了“报错拒收，由写的子线程自己决定怎么办”，子线程可以换一个名字写或用“告诉主对话”（:247），不是没有出路。沿用第 2 轮第 5 条的判法
- 8（deepseek-v4.1-flash）不成立：### 8. 低 — ADR 0285 决定 8 仍未改写，规格里的“不冲突”澄清没有落到决策记录。沿用第 2 轮第 9 条原判：这个 PR 只改设计规格、不改 ADR（材料文件的约束），歧义那一半已在 docs/execution/specs/2026-11-24-main-thread-subthreads-inbox-design.md:251 写明“那里说的是子线程交回主对话的结果”；ADR 0285 :42 没有与之相反的说法，模型没给新证据
