# PR 419 第 2 轮判断

被复核的提交：`455774e5`（只看第 1 轮 `670f9507` 之后的修改），只跑了 DeepSeek，这一轮 0.0685 美元，累计 0.2232 美元。

## 成立，会出错，低（改了）

- r2ds4（模型：低，推测）出口遮盖的自检拒绝一个请求时，Pi 把这个拒绝当连接错误重试，每次重试都重新检查并再报一条 withheld 记录。成立：线程用本地探针复现（让 fetch 抛 `ModelEgressRefusedError`、`maxRetries: 2`，pi-ai 调用了 3 次，耗时约 1.3 秒）。线程判低：触发只在自检拒绝时；后果是审计里同一次拒绝记成 3 次、白等约 1.3 秒，不会多发出任何内容或给出错误结果。改法：`model-egress.ts` 也记住被拒绝的那一次，重发直接再抛同一个拒绝，不再检查、不重复上报；`[RETRY-429]` 加了用例（改动前失败）。白等的 1.3 秒没有消除，写进了 ADR 决定 6。

## 成立，可以更好（改了）

- r2ds1（模型：中）端到端的重试用例没有带需要遮盖的内容，删掉复用代码照样通过。成立。`prompt-prefix.compat.test.ts` 加了一条真实 Pi + 真实遮盖的用例：前面的消息里出现一个值，后面的消息把它点名为密码，第一次请求 429 后重发；断言重发字节与第一次相同。用改动前的 `model-egress.ts`（`670f9507`）跑，这条会失败。
- r2ds2（模型：低）只记上一次请求，同一个交换里 A、B、A 交错会失效。当前接线每次模型调用新建一个出口交换（`pi-runtime-adapter.ts` 的 `egress.exchange`，`pi-model-transport.ts` 也是），不可达。改法：比较里加上请求方法；ADR 决定 6 写明约定“一个出口交换服务一次模型调用，只记住上一次请求”。
- r2ds3（模型：低）缓存键把整段请求体拼成新字符串并长期持有。成立。改成分别记地址、方法、请求体的引用，不拼接、不复制；重发命中时直接比较字符串。
- r2ds5（模型：低，推测）连接错误重试在直连服务方时可能让同一个请求被再处理一次。这是请求层重试的固有风险，OpenAI、Anthropic 的官方 SDK 默认也重试连接错误。ADR 后果里写明并接受；走网关时观察器不会真的再发。

## 其他说明

- 模型对增量的必答问题结论：不改变请求开头；不引入新的字节差异；反向用例逐条核过有效。
- 模型提到的 `\u0000` 拼接撞键：已随“不拼接”消失。
