# PR 526 第 2 轮判断（deepseek-v4.1-flash）

- 1（deepseek-v4.1-flash）成立，会出错，低：### 1. 中：`readText` 返回 `undefined`（而不是抛错）时仍会写当前版本，上一轮第 3 条只修了“抛错”这一半。perception-service.ts rebuildSearchIndex treated readText undefined as no text and wrote current version; production readPerceptionText returns undefined only when the payload row is missing or not text/plain, i.e. a record whose contentRef points at lost data. Fixed: undefined for a non-null contentRef throws into the skip path so the record stays stale; test 'leaves a record stale when reading its text undefined during rebuild' fails without the fix and passes with it；触发：a record whose contentRef payload row is missing or not text/plain at rebuild time (corrupted store, not normal use)；后果：record is marked current with only evidence terms and is never rebuilt once the payload is restored；判低理由：only reachable when the payload store has lost or corrupted the payload of an active record; the result is a missing index entry, no wrong answer or data loss
- 2（deepseek-v4.1-flash）成立，可以更好：### 2. 中：答案修补和失败重试都没有能真正回退的测试。Added tests through the real service path: first search auto-rebuild, term cap on ingest and rebuild via PerceptionService termLimit (cap moved from composition into the service so it is covered), rebuild skip on readText throw and on undefined, each verified to fail when the fix is removed. The control() answer mapping in the test is still a copy of the production one; extracting it is optional
- 3（deepseek-v4.1-flash）不成立：### 3. 中：作者的说法与代码相反——“失败写空词表并记当前版本”已经不是现在的行为。The author's note describing 'write empty terms and record current version' is the round-1 behaviour; perception-service.ts catch now only pushes the id to failed and replaceSearchTerms runs only on the success path. The note being stale is not a defect in code or docs of the repo
- 4（deepseek-v4.1-flash）不成立：### 4. 低：软删除只清词表，不清索引版本状态；记录若被恢复为 active 会永久搜不到。Same as round 1 item 6: grep of non-test code shows setRecordStatus is called only to set deleted (durable-adapters.ts wrapper, no restore path), so a deleted record never returns to active and the stale-state sequence is unreachable
- 5（deepseek-v4.1-flash）不成立：### 5. 低：失败列表无上限、每轮重扫全表，首搜还可能一次重建整库，可能放大延迟/资源。failed only grows when a record's read or tokenization throws and is bounded by the active record count; each pass is one indexed query of batch size. replaceSearchTerms returns false only when the record is no longer active (sqlite-perception-operations.ts:705-706), and such a record is not listed again, so the loop cannot repeat. One rebuild per process per scope is the brief's design (goal 2), same per-record cost as ingest
