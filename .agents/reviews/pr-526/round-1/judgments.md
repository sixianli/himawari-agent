- 1（deepseek-v4.1-flash）不成立：### 1. 高：`indexTermLimit` 在分词后按数组前缀截断，长中文记录的双字词会被整段丢掉。canonicalTokens (browser-thread-search.ts:33-41) emits terms per segment in text order (chars then bigrams per segment), so the cap keeps a prefix of the text with both chars and bigrams; truncating beyond indexTermLimit is the requested cap behaviour (brief goal 1). - 3（deepseek-v4.1-flash）成立，会出错，中高：### 3. 中：重建时读文本或分词失败会写空词表并记当前版本，记录从此永久不再重建。perception-service.ts rebuildSearchIndex swallowed errors then called replaceSearchTerms; now a failed record is skipped, stays stale, and is excluded from the rest of this run via listStaleSearchRecords excludeRecordIds so the loop terminates; store test added；触发：readText or tokenizer throws during rebuild (transient decrypt/IO, oversized NFKC expansion)；后果：record gets empty terms at current version and is never rebuilt, silently unsearchable

Ingest tokenization failures write no state row so the record stays stale and is rebuilt on next process start (perception-service.ts ingest path), not permanently lost. Search errors being swallowed upstream is pre-existing PR 522 behaviour.
