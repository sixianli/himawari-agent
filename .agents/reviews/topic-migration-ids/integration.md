# 整合记录：DeepSeek 独立方案（第 1 轮）和方案审核（第 2 轮）逐条判断

## 第 1 轮：独立方案

| 意见 | 判断 | 理由 |
|---|---|---|
| 编号用 ULID | 不采纳 | 撞号只会让后合的 PR 检查失败、换号，不进 main；时间戳好读、与 Rails/GitLab 一致；生成器对照 origin/main 顺延 |
| 旧行不改写，读时按 sequence 推出编号 | 采纳 | 历史字节不动，少一次写 |
| sequence 变成“第几个被跑”，另存集合指纹 | 采纳（与线程方案一致） | |
| 禁止迁移里的非确定值 | 部分采纳 | 不禁止（已有迁移在用），比较数据时排除这类列 |
| 两种顺序回放 + 数据摘要 + integrity/foreign_key_check | 采纳 | |
| 要求分支先并入最新 main | 不采纳 | 等于重新排队 |
| decision_ledger 加 kind、outcome 两张参照表 | 采纳 | 已核对 0095 第 67 行起的 kind→outcome CHECK |
| 列全整数版本的使用方（导出、管理命令、raw-copy、沙箱管理） | 采纳 | 已核对 production-data-export.ts:321 等 |
