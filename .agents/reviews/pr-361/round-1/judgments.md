# PR 361 第 1 轮复核处理

没有已证实的高严重度意见。A1 与 B1 是同一件事（中，已改）。

## 会出错
- A1、B1（中）：最坏的设置会让生成的表达式超过长度上限。把上限从 262144 提到 524288，最坏情况约 30 万字节，现在能编译；补了 200 个各 254 个控制字符发件人的用例。网关正则本来就挡住控制字符，所以用户入口原本不可达。
- A2（低）：“最大设置”用例的 200 个发件人被截成同一串。改成序号放前面，并断言 200 个互不相同。
- B3（低）：开始等于结束的静默时段，裁判改为永不静默，和旧实现一致，补了用例。

## 不成立
- B2：旧正则 `/\b(?:...)\b/iu` 对 `ſbill`、`billſ`、`Kbill`、`statementK` 实测都返回 false，新旧一致，没有分歧。

## 可以更好（不改，列给 Andy）
- A3：网关允许发件人 320 字符、存储只收 254，是改动前就有的不一致。
- A4：docs/product-vision.md 附录和 ADR 0184 仍提 `proactive_settings.important_senders`，属历史记述。
- A5：第 4 步前要补求值次数上限，已写进 ADR 0209 后果。
- A6：`writeRule` 更新时没有把 status 设回 active，目前没有停用路径。
- A7：缺“迁移后的数据读出设置”的组合用例。
