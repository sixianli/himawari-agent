# PR 371 第 4 轮复核（只跑 DeepSeek，合并 main 并加体检表之后）：逐条判断

DeepSeek `ok`，0.0967 美元；累计 0.4681 美元。

## 会出错 · 中、高（已修改，未再复核）

- R4-1：一个以上矛盾对时，第二对以后的新条（待确认、置信度低）会先被“系统把握不大”队列占掉，这一对就不再作为矛盾出现。改为矛盾对里的两条不再因其他原因单独进清单。回归测试：`memory-checkup.test.ts`“新条同时把握不大时，每个 hold 对都作为矛盾列出”（旧代码失败，已运行）。
- R4-2：周清单生成后新条在别处被确认，这一对仍能删除或合并。改为新条已不是待确认时以 `MEMORY_CHECKUP_STALE` 拒绝。回归测试：`memory-checkup.test.ts`“[negative] 清单生成后新条被确认，拒绝处理这一对”（旧代码失败，已运行）。
- R4-3：`listHeldPairs` 读出所有历史 `hold`，包括已撤销的。加 `openOnly`，只读没撤销的、新的在前。回归测试：`memory-consolidation.test.ts` 的 `[P3-8]` 用例撤销后断言（已运行）。
- R4-4：接上体检后所有 `hold` 决策记录都不进“整理记忆”组，清单生成失败或这一对没排进清单时就看不到了。改为只隐藏本周清单里已有的矛盾对。回归测试：`daily-review.unit.test.ts` 的 hold 用例两种情况（已运行）。

## 会出错 · 低（已修改）

- R4-5：ADR 说“两个错误一起报出”，代码只报 `MEMORY_CHECKUP_RESTORE_FAILED`；改 ADR 文字。
- R4-6：迁移加 `CHECK (kept_memory_id IS NULL OR action = 'merge')`，迁移测试加反向插入（没有这条约束时失败，已运行）。
- R4-7：体检处理过的新条修订号已变，P3-8 撤销 `hold` 会被拒绝。体检自己的撤销能退回，这一限制写进 ADR 0218 的已知限制。
