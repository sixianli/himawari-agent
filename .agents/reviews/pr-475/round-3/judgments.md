# PR 475 第 3 轮逐条判断

费用 0.1805 美元，三轮合计 0.6328 美元。

## r3-1：重放已执行过的调用时，标记“写”失败仍会返回 `not_sent`

判断：会出错，严重度 low（模型给中）。成立，但要先有“上次已执行，这次的来源却不在状态里”（来源名随新版本改了，或状态丢了），再碰上写失败，模型自己也标为推测。后果是对一次已执行的调用说“没发出”，不放行任何动作。已修：返回“没发出”之前查这次调用有没有执行意图记录，有就照常报错；补用例（清掉标记、让写失败后重放），去掉这项检查后用例确实失败。

## r3-2：标记队列没有超时，单个“挂住不返回”的写会永久阻塞同一对话后续所有标记

判断：不成立。状态读写走同一个数据库端口，那里挂住时同一进程所有状态读写都会挂住，排队没有带来新的出错方式；失败不会卡住后面的写，模型也确认了。不改。

## r3-3：缺少“第一次写失败后，下一次写仍然成功”的自动检查

判断：会出错，严重度 low（模型给低）。成立，覆盖缺口。已补：第一次写失败后，同一对话的下一次写正常完成。

## r3-4：来源名/记录编号截断可能把不同的来源或记录变成同一字节，削弱“按记录编号区分”的保证

判断：会出错，严重度 low（模型给低）。成立。已修：超长时截短再接原文哈希前 16 位，补用例（尾部不同的两条超长记录得到不同的标记）。

## r3-5：ADR 写“最多 512/256 个字符”，代码实际按 UTF-16 code unit 计算，可能截断代理对

判断：会出错，严重度 low（模型给低）。成立，文档说法不准。已改 ADR 为 UTF-16 码元，和网关校验同一算法。

## r3-6：捕获测试的运行来源桩与生产 `runExecutionSource` 语义不完全一致

判断：不成立。模型自己确认捕获先读运行来源，读不到直接返回；只剩对话恰好在两次读之间归档的窄竞态，那时退回按运行读标记，偏松但对话已归档、不会再有新动作。不改。

## r3-7：旧的拒绝审计行与新 `targetRef` 不兼容

判断：不成立。后台拒绝规则 `action_refuse_background_after_external_content` 是本 PR 新加的，生产库里不可能有这条规则编号的旧拒绝审计。

## r3-8：`preauthorizeOwnTaskCancel` 的表达式比“取消”更宽

判断：可以更好。现在登记表里只有取消命中；以后加别的托管任务写操作时要收紧。列给 Andy，不改。

## r3-9：拒绝记录状态只增不删

判断：不成立。每条只在后台真被拒时写一条，很小，和其他审计记录同样只追加。
