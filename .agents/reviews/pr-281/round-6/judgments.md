# PR 281 第 6 轮复核逐条判断

复核提交 a59ff871 加合并 `origin/main`（c6ff30321）后的 25e350c1（经 Magpie，只用 DeepSeek）：39 次请求全部由 CodeBuddy 回答，10.16 积分，OpenCode 按 Go 单价算的费用 0.1074 美元。这一轮是 Andy 说“合并”后，按规则对合并 main 做的复核。

这一轮没有中高的“会出错”意见。模型标“中高”的 R6-D1 和标“中”的 R6-D2、R6-D3 都不能让一次运行突破 0.2 美元上限，按低处理，仍全部改成更保守的做法。低的全部修改，改动在 `--accept-low` 的范围内。R6-D4、R6-D8 属于“可以更好”，不改，列给 Andy。机器可读的版本在 `verdicts.jsonl`。

| 编号 | 意见 | 类别 | 判断 |
|---|---|---|---|
| R6-D1 | 失败请求缺用量时按 0 记，不标 `costUnknown` | 会出错（低） | 非 2xx 的请求一般不计费，回答到一半断开（状态 200）缺用量第 3 轮已记 `costUnknown`。仍改为：Go 这类按美元计价的服务方，失败请求缺 `in` 或 `out` 也记 `costUnknown`。 |
| R6-D2 | 换算比把没到达服务方的 `none` 槽位当成别家 | 会出错（低） | 判断“只用了 CodeBuddy”时忽略 `none`。 |
| R6-D3 | 发过的请求数只按“至少 1 次”算 | 会出错（低） | 每一步就是一次请求，取步数和放行次数中较大的那个。 |
| R6-D4 | 预检失败不退回只用 Go | 可以更好 | 文档写明预检失败就停下；成员缺失说明配置或插件出了问题，停下比悄悄降级容易发现。 |
| R6-D5 | `docs/kv-cache-guide.md` 写“例外三种” | 会出错（低） | 改成四种。 |
| R6-D6 | `npm pack` 失败时报错不带原因 | 会出错（低） | 带上 stderr 或 error.message。 |
| R6-D7 | `gateway.mjs upgrade` 的 curl、npm view 没有超时 | 会出错（低） | 加 300 秒超时。 |
| R6-D8 | 新测试不在 `npm run check` 里 | 可以更好 | 同 R5-D3。 |

修改后的验证：分别去掉 `none` 过滤、把 Go 失败请求的 `in` 和 `out` 退回缺了按 0、把请求数退回“至少 1 次”，对应用例都失败；`test/tooling/review-gateway.test.mjs` 41 条通过；`npm run check` 41 步全过；文档严格校验仍是 11 个原有错误。
