# PR 281 第 1 轮复核逐条判断

复核提交 bcdc3141。“会出错”的中高意见是 D2（用量记录异常时整条账本记录不写）和 D3（gateway.json 没有校验，积分底线可能悄悄失效），已修改，需要第 2 轮复核。低的已一并修改：D1/G2（中断时残留 Magpie 进程）、D4/G7（积分卡片格式）、D5（费用计入没有自动检查）、D6（服务方名原型污染）、D7（直连配置快照）、D9/G3（文档说法）。不成立的是 D8、G5；其余属于“可以更好”，不改，列给 Andy。机器可读的版本在同目录 `verdicts.jsonl`。

| 编号 | 模型原话 | 成立 | 类别 | 判断 |
|---|---|---|---|---|
| D1 | 中断时 Magpie 可能漏停，自检的网关不受 `stopGateway` 管理 | 是 | 会出错（低） | 只残留进程，不影响结果、花费和数据。改为登记每个 Magpie 进程，结束和中断时 `stopAllGateways`；新增用例证明不留句柄也能全部停掉。 |
| D2 | 用量记录处理抛错会让整条账本记录不写 | 是 | 会出错（中高） | 这次已花的钱可能不进账本，先问线少算。汇总改为跳过读不懂的行、非数字不累加，出错时退回 `costUnknown` 并照样写账本。 |
| D3 | `gateway.json` 没有校验，积分底线可能静默失效 | 是 | 会出错（中高） | 改配置时漏字段或拼错服务方名，会在积分低于 20 时照样用 CodeBuddy。读入时逐项校验，报 `GATEWAY_CONFIG_INVALID`；底线遇到非数字一律不用 CodeBuddy。 |
| D4 | `creditsLeft` 假定 remaining 是百分比 | 部分 | 会出错（低） | 按真实输出核对过，现在的解读正确（250×95.488% = 250−11.28）；只在升级改格式时才错。加了百分比和已用积分的一致性检查，对不上按查不到处理。 |
| D5 | 自检没验证经 Magpie 时每步费用非零 | 是 | 会出错（低） | 冒烟账本里确实非零，但没有自动检查。补 `GATEWAY_COST_NOT_COUNTED`，去掉单价后自检确实失败。 |
| D6 | 服务方名未白名单化 | 是 | 会出错（低） | 和 D2 一起修。 |
| D7 | 直连配置测试是自己和自己比 | 是 | 会出错（低） | 新增快照：改动前提交 7b549e3 的六种直连配置，把安装路径换成占位后的 SHA-256 写进测试。真实自检用例要联网，和现有测试一致，不改。 |
| D8 | 只跑一个模型时仍对两个模型建组和预检 | 否 | — | 预检本来只看本次要跑的模型；两个模型都建组是必要的，DeepSeek 失败时 GLM 要顶上。 |
| D9 | 文档有和代码不一致的说法 | 是 | 会出错（低） | 三处都已改，ADR 同步。 |
| G1 | 真跑的主流程没有自动测试 | 是 | 可以更好 | 没指出会出错的地方。修 D1、D3 时顺带补了 `startLiveGateway` 的两条用例。 |
| G2 | 启动期间中断会留下 Magpie 进程 | 是 | 会出错（低） | 同 D1。 |
| G3 | 旧的密钥说明和新功能矛盾 | 是 | 会出错（低） | 同 D9。 |
| G4 | 透传探针只验证 DeepSeek | 是 | 可以更好 | 两个模型走同一段转发代码，多跑要多两次 OpenCode 启动。 |
| G5 | 测试只有 18 条 | 否 | — | vitest 报告 19 条通过。 |
| G6 | 美元折算不计缓存写入 | 是 | 可以更好 | 只影响账本展示，预算用的是 OpenCode 的费用；Go 的单价表没有缓存写入价格。 |
