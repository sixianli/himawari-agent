# PR 281 第 2 轮复核逐条判断

复核提交 f872aaaa（只用 DeepSeek；第一次 40 分钟超时，记为 attempt-1，60 分钟重跑完成）。“会出错”的中高意见是 R2-D4：积分底线写成 0，或积分服务方写成不带登录的服务方，都能通过配置校验，和第 1 轮 D3 同一类。已修改，需要第 3 轮复核。其余“会出错”的都是低，一并修改。R2-D6 属于“可以更好”，不改。机器可读的版本在 `verdicts.jsonl`。

| 编号 | 意见 | 类别 | 判断 |
|---|---|---|---|
| R2-D1 | 缺失的 token 或积分被当成 0 | 会出错（低） | 模型标中高。换算比取历史最大值和默认值 54 中较大的那个，美元上限用 OpenCode 的费用，所以不会让预留或预算偏低，按低处理。改为成功的请求缺字段时记 `costUnknown`。 |
| R2-D2 | 读用量文件抛异常时账本不写 | 会出错（低） | 只在本次临时目录出文件系统错误时发生。读取错误一律返回 null，记 `costUnknown`。 |
| R2-D3 | Magpie 子进程没有 `error` 监听 | 会出错（低） | 程序不能执行时脚本会崩溃。加了监听，报 `GATEWAY_START_FAILED`。 |
| R2-D4 | `creditFloor: 0` 和非插件积分服务方能通过校验 | 会出错（中高） | 积分底线 20 会被绕过。底线必须大于 0，积分服务方必须是带登录的插件。 |
| R2-D5 | 用量文件为空时不记 `costUnknown` | 会出错（低） | OpenCode 发过请求、用量里却没有记录时，记 `costUnknown`。 |
| R2-D6 | 替补模型的成员没被预检 | 可以更好 | 和第 1 轮 D8 相反：预检替补会让只跑 DeepSeek 的运行因为 GLM 不可用而失败；替补真不可用时会记 api-error，不漏记花费。 |
| R2-D7 | 文档写“每步”，代码看的是总费用 | 会出错（低） | 改文档。 |
| R2-D8 | 第一次启动失败没有统一错误码 | 会出错（低） | 统一包成 `GATEWAY_PREFLIGHT_FAILED`。带 CodeBuddy 启动失败时退回只用 Go 是有意的降级，会打印原因。 |
| R2-D9 | 透传探针全局替换模型名 | 会出错（低） | 只在系统消息里还原，用户消息逐字比较。 |
| R2-D10 | 未知服务方被按 Go 单价计价 | 会出错（低） | 不计价，记 `costUnknown`。 |
| R2-D11 | `gatewayDropped` 没有消费方 | 会出错（低） | `GATEWAY_USAGE` 打印 `dropped=`，文档写明。 |
| R2-D12 | 测试缺这些错误路径 | 会出错（低） | 新增五条用例。 |

修改后的验证：`test/tooling/review-gateway.test.mjs` 32 条通过；分别去掉积分服务方的类型检查、成功请求缺字段的检查、空用量的检查、读取错误的捕获、只在系统消息里还原这五处，对应用例都失败；`--self-check-only --gateway magpie` 通过；`npm run check` 41 步全过。
