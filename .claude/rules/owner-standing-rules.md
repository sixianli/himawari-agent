<a id="money-and-models"></a>
## 钱和模型

- 花钱先问（Andy 2026-10-29 11:27 JST 定）：任何评测、测试、实验或批量模型调用，预计要花 Andy 的钱超过 0.5 美元时，先在项目聊天报出预计费用和用途，等 Andy 明确同意再开跑；费用说不准时，按会超过处理。2026-10-31 Andy 删掉了项目指令里“不设任何费用上限”那句，以这条为准。
- 评测用哪个 key（API 密钥），评测之前先问 Andy（Andy 2026-10-31 定）。评测和测试绝不和生产共用预算：2026-10-29 一次评测花光了 Vercel 账号的预算，生产因此中断。
- 禁用贵模型（Andy 2026-10-29 13:31 JST 定，16:09 补充）：任何场景（生产、评测、裁判、测试、实验、后台任务）都不得通过按 token 付费的渠道（例如 Vercel、OpenRouter）调用 Claude、OpenAI 或同价位的模型；按量付费只用 DeepSeek V4.1 Flash 这类低价模型或免费额度。代码和评测脚本里不得写死 `anthropic/`、`openai/` 开头的模型名。
- Andy 已付费套餐里的 token（例如 Claude Max 附带的 API 额度、OpenCode Go）不在禁用之列，而且要优先用。生产经 Magpie（装在生产机上的模型路由程序）调用模型，顺序是套餐内 token、免费额度、最后才是 Vercel 上的低价模型。

<a id="fixing-bugs-and-new-features"></a>
## 修 bug 和做新功能

- 修 bug 先查根因，不许只修表面（Andy 2026-10-30 13:17 JST 定）。修法要先上网查当前的做法（官方文档、成熟开源项目，附一手来源），已有成熟方案就采用，拿不准的拿出来和 Andy 讨论；不得凭记忆或过时的训练数据决定修法。PR 和案例里写清“业界怎么做、我们为什么这样做、放弃了什么”。
- 不熟悉的功能不从零写：先去 GitHub 找开源项目、上网找成熟做法，对比方案、想清楚思路之后再动手。

## 界面上的数字和验收

- 界面上给 Andy 看的每个数字和判断词（例如“找到 3 条相关记忆”“命中”“推荐”“成功 N 条”）都要有可以验证的定义和门槛，没有就不显示（2026-10-29 15:50 JST 定，起因是“找到 3 条相关记忆”永远凑满 3 条；事故 I-13、I-23 是同一类）。
- 线程说一个界面功能“做完了”时，要附上在真实网页上的正向和反向两种验收结果。反向验收是给一个不该命中、不该触发的输入，期望结果为空或不触发。没有反向验收的不算完成。判断类功能的发布验收（`release-walkthrough`）必须有反向用例。
- UI/UX 意见攒批（Andy 2026-10-28 18:42 JST 定）：Andy 在项目聊天一条条提界面问题时，协调者每条只回“记下了”，等 Andy 说“提完了”，再把全部意见打包交给对应线程。Andy 明说“不是 UI 问题”的，不进攒批。

## 授权、上线和合并

- 上线和回滚：Andy 在 Mac 线程里说，或者在项目聊天里对协调者说，都算授权；协调者转给 Mac 线程时要附上他那条原话（Andy 2026-10-31 定，详见[交付模式](../../.agents/instructions/delivery-mode.md#fast-mode)）。
- 上线和回滚以外、会动生产机或 Andy 的 Mac 的操作（例如停服、改配置、删 Mac 上的文件），只认 Andy 在 Mac 线程（通过 Remote Control 在他 MacBook 上运行的那个线程）里亲手打的字；协调者只告诉 Andy“去 Mac 线程打什么”和为什么（Andy 2026-10-29 23:15 JST 定）。云端线程的授权，Andy 在项目聊天说一次即可，由协调者把他那条原话附上转给线程。
- 会删东西的上线，所有要 Andy 选的选项先选完，再上线（2026-10-30 10:30 JST 的教训）。
- 合并 PR 一律由做这个 PR 的线程执行，要等 Andy 说“合并”。他在那个线程里说，或者在项目聊天里对协调者说、由协调者附上他那条原话转给线程，都算（Andy 2026-10-31 定）。不让 Andy 自己去 GitHub 操作。

<a id="prompt-layout-for-the-kv-cache"></a>
## 模型上下文的排列

- KV 缓存最大化是原则（Andy 2026-10-30 16:11 JST：“这是原则性问题！”）。KV 缓存是模型服务方对重复出现的开头内容做的缓存，开头完全一样的部分不用重新计算，更快也更便宜。组装发给模型的上下文时，固定不变的内容放前面，会变的内容（例如时间戳、本轮输入）放后面；不得以“收益小”为由不这样排。
