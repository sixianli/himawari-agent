# 界面与交互设计指南

<a id="contents"></a>

这份指南记录 Himawari 网页（主人用来和 Himawari 对话、管理记忆和设置的网页）在界面和交互上必须遵守的规则，以及踩过的坑。改界面文案、过程区或任何会显示数字和判断的地方之前，先读这里。

- [不良设计](#bad-designs)

<a id="bad-designs"></a>

## 不良设计

这里每一条都是 Andy 实际指出过的问题，写清楚错在哪、正确做法是什么，以及拦住它的自动检查。

<a id="bad-design-claim-without-definition"></a>

### 显示一个判断，却没有核对它背后的定义

**例子（2026-10-29，事故 I-23）：** 过程区写“按这句话找到 3 条相关记忆”，可记忆搜索根本没有“够不够相关”的门槛，只是把最不远的 3 条带上了。Andy 问“写到一个pdf文件”，看到的是前同事的名字。同类的前一次是事故 I-13：记忆页筛选按钮上的数字和点开后看到的条数对不上。

**规则：**

1. 界面上出现“相关”“成功”“已完成”“N 条”这类判断或数字，必须能指出它来自哪条记录、按什么定义算出来；说不清就不显示。
2. 结果为空时，不显示“找到 0 条”这类空结果，整步隐藏。Andy 原话：“没有记忆的话就不要在过程中显示！否则就是此地无银三百两！”
3. 常驻的内容（例如每轮都带的主人档案）不能和“按这句话找出来的”内容用同一种说法，要写明“每轮都带”。

**拦住它的检查：** `npm run check:memory-relevance`；发布走查必过项 `accept-unrelated-no-memory`（详见 [ADR 0115](adr/0115-memory-search-relevance-threshold-and-retrieval-eval.md)）。
