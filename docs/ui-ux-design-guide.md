# Himawari 网页设计规范

<a id="contents"></a>

这份文档记四样东西，供协调者和以后每个做界面设计的线程参考：

- **好的设计规范**：从下面两类例子里总结出的规则，改界面时照着做。
- **优秀设计**：Andy 批准过、而且明确说喜欢的设计。
- **不良设计**：做出来后被 Andy 指出、或被检查拦下的问题，写清原因和改法。
- **自动检查**：规范里已经变成程序检查的部分，每项写明用哪条命令、哪个测试或哪项上线走查来查，拦下什么问题；还要靠人看的部分也列在那里。

这里的“Himawari 网页”指 Andy 日常聊天用的网页，代码在 `apps/control-center`。iPhone、Apple Watch、Mac 上的 App 另有几条自己的规则，在[苹果客户端](#apple-clients)一节；那一节没写到的，照网页的规则。文档由 Andy 在 2026-10-29 提出：“任何我们遇到的 UI 和 UX 的问题，都记入到本项目的 UI UX 设计的‘不良设计’中，而把我们确定下来的、我很喜欢的设计记入本项目的‘优秀设计’中，并维护一个适合本项目的《好的设计规范》”，目的是尽可能做出优秀的设计。

**怎么用。** 改界面之前先读完[好的设计规范](#rules)。交付时，把这次遇到的新问题补进[不良设计](#bad)，把 Andy 新批准的设计补进[优秀设计](#good)；新问题如果能归纳成一条新规则，也补进规范。视觉基线（定稿的原型截图）仍以 [AGENTS.md 的“Approved Web Design Baselines”](../AGENTS.md#approved-web-design-baselines) 列出的版本为准，本文不替代基线。

## 好的设计规范

每条规则后面括号里是它的出处：界面意见编号（第一批 1–22，第二批 23–41）、事故编号（见[事故与门槛清单](incidents-and-gates.md)）或 ADR（架构决策记录，记下一个长期决定和理由的文档）。

<a id="attention-first"></a>

### 总原则：主人的注意力最宝贵

**只在合适的地方，展示合适的、有必要的信息。** 主人的注意力很宝贵，页面上每多一样东西，都会从真正重要的信息那里分走一点注意力。判断一样东西要不要放上页面，不看它“对不对、有没有用”，只看“站在主人的角度，他此刻是不是足够需要它”。下面所有规则都从这一条来；规则没写到的情况，按这一条判断（2026-11-03，Andy：“设计 UI/UX 里面的设计原则就是：只在合适的地方，展示合适的、有必要的信息……用户的注意力是很宝贵的，不要用一些无关的信息去抢占用户的注意力”）。

做设计和交付原型前，对页面上的每一样东西过一遍：

- **他此刻要不要？** 不是主人下一步要用的，不放（第 1 条）。
- **放在这里对不对？** 该在别处出现的，挪到它作用的地方旁边（第 45 条）。
- **已经出现过了吗？** 同一个信息、同一句话、同一个日期只出现一次（第 43、48 条）。
- **是说明还是内容？** 说明文字收进点开才看到的一层，默认不显示（第 36、48 条）。
- **他能直接看懂吗？** 名字自己说清是关于什么的，不要他自己翻译（第 49 条）。
- **他会被打扰吗？** 不抢眼的信息不用醒目的颜色、动画或常驻提示（第 21、35 条）。

### 显示什么

1. **站在主人的角度决定显示什么。** 只放 Andy 下一步要用的信息，不放实现细节。收起时一句话说清做了什么，细节放进点开才看到的第二层。例如“运行命令”展开后只显示“✓ 成功”或“✕ 失败 · 出错代码 1”，命令本身收进“命令详情”；快捷键提示也不常驻在控件旁边，例如编辑框下不写“⌘↵ 保存 · Esc 取消”，快捷键照常可用（第 30、35 条；[ADR 0295](adr/0295-web-chat-interface.md)）。
2. **数字和判断词必须有定义。** 页面上的每个数字都要能说清是怎么算出来的，并且和主人点进去看到的对得上。例如筛选按钮上的数字，必须等于“其他筛选不变、点它之后能看到的条数”（I-13）。“找到 N 条相关记忆”里的“相关”必须有门槛；没有门槛、凑够 3 条就叫“相关”，是不良设计（I-23，记忆召回线程，2026-10-29）。现行定义：相关分（向量相似度，加上关键词和实体命中的少量加分）达到截断线，截断线等于本次检索的向量门槛减去截断余量（[ADR 0300](adr/0300-how-memory-works-now.md)）。
3. **空结果不显示过程。** 什么都没找到时，不要在步骤里写“没有相关记忆”这种话，否则就是此地无银三百两（2026-10-29，记忆召回线程）。
4. **内容优先，元信息放进第二层。** 打开文件先看到内容；类型、大小、第几轮、时间、来自哪个对话，以及网页文件的安全说明，都收进“文件信息”按钮（第 29、38 条）。
5. **不给主人看系统用语和错误码。** 例如空白新对话中间不写“尚无已提交消息”，而是欢迎问候；错误要用一句话说明发生了什么、要不要他做什么（第 27 条自查）。
6. **不写死会变的名字。** 例如联网搜索的说明不写某家厂商的名字，而是列出服务器配置里真正会收到数据的网址，换厂商时页面不用改（第 26 条批注）。
7. **新动作要让人明白后果。** 例如“分出新对话”：提示里写清会开一个新对话、带上到这一轮为止的全部内容、原对话不受影响；新对话顶部写“从「原标题」第 N 轮分出 · 打开原对话”，原内容颜色稍淡地显示在分隔线上方（第 28 条，I-17）。
48. **解释文字收进标题旁的 ⓘ，页面只放标题、数字和简短状态。** “这个数怎么算”“这一行是什么”“两组数字有什么不同”这类说明，默认不显示，放进标题旁边的 ⓘ 图标里，点开才看到：电脑上在图标旁弹出小框，手机上从底部弹出。页面上只保留看懂数字所必需的一句短状态，例如“观察期还没满 7 天”。同一个信息只显示一次，例如统计的日期范围只在标签下方写一次，不在每个区块下面重复。这条比第 36 条更进一步：第 36 条管“写不写”，这条管“写了放哪”（2026-11-03，Andy 看校准周报原型：“整个页面无关的文字提示不要直接显示出来，会让整个用户界面感觉都是字，乱糟糟的”）。

### 布局和对齐

8. **同一组元素对齐到同一条线。** 空状态的图标、标题、说明和底部提示整体居中；同一列里的返回箭头、标题和正文用同一个左边线（第 27 条）。
9. **不让任何东西超出屏幕或被挡住。** 不出现横向滚动条，按钮不被别的元素盖住，文字放不下时换行或用省略号，不被挤成竖排（第 23、36 条；I-14）。
10. **三种语言一起排版。** 同一个意思在中英日里长度不同，按钮和标签不写死宽度，放不下时换行（[ADR 0295](adr/0295-web-chat-interface.md) 第 7 条）。
11. **弹窗固定大小、内部滚动。** 设置弹窗在电脑和手机上都是固定外框，内容多时在框内滚动，关闭按钮始终在框内可见（第 23 条）。
12. **相邻的按钮分开放。** 顶栏每个按钮是单独的圆形按钮（[ADR 0295](adr/0295-web-chat-interface.md)），之间留出空隙，不把两个按钮挤在同一个胶囊里，免得误触（第 33 条批注）。
13. **浮在内容上的按钮要小。** 例如“回到最新消息”是输入框正上方居中的小圆形箭头，不挡聊天内容（第 34 条）。

### 控件

14. **不用浏览器自带的控件外观。** 下拉菜单用页面自己画的，颜色、圆角、阴影和其他组件一致，不出现系统深色菜单（第 25 条）。按钮的提示用页面自己的提示框（`data-tip`），不用浏览器的 `title` 提示（第 28 条）。
15. **编辑控件一个规则。** 没改动时“保存”是灰色不能点，改了才变成实心；“取消”是描边按钮；“编辑”是图标加文字的轻按钮；“删除”是红字，放在最左边和“保存”隔开；输入框和按钮同高、同圆角（第 35 条）。
16. **焦点描边只给键盘用户。** 用 `:focus-visible`，鼠标和手指点击不画描边；弹窗打开时焦点放在弹窗本身，不放在关闭按钮上（第 37 条，I-18）。
17. **能点开的才给箭头。** 没有内容可看的步骤不能点，也不显示箭头（[ADR 0295](adr/0295-web-chat-interface.md) 第 2 条）。
18. **按钮的悬停底色和按钮一样大。** 全站按钮默认有 44px 最小高度；图标按钮要显式取消这个最小高度，否则 28px 的图标外面会出现一个又高又窄的悬停底色（第 28 条自查）。
31. **主人批准后马上有回应，同一步的同类请求只问一次。** 点“允许”后卡片立刻变成“已收到，正在继续…”，之后的进度和回答自己出现，不用主人退出再进来；页面读数据的请求要有时限，一次没回答就重试，不能让整页停在“正在加载…”。模型同一步发起几次同类操作（例如一次搜两个地方）时，合成一张卡片，写明“这一步要搜索 2 次”，一次允许全部放行；不同类的操作仍然分开问（I-29，和 OpenAI Agents SDK 一次返回全部待批项、Claude Code 按工具记住选择的做法一致）。
32. **主人的设置不能被系统悄悄改掉；只读操作不逐次问。** 设置存在服务端，手机和电脑看到同一份；只有主人同意过的前提真的变了（例如联网搜索要发往的地址换了）才可以改，而且要在设置旁边写明原因和现在的情况，不能只把开关变灰或变关。联网搜索、读网页这类只读、没有副作用的工具默认打开、不逐次弹卡，付款、发邮件、改文件这类不好撤回的事才逐次确认（I-34，[ADR 0299](adr/0299-tool-calls-and-command-lifecycle.md)；和 ChatGPT、Claude、Gemini 默认自动搜索的做法一致）。
33. **控件灰着不能点时，必须有原因，且不能依赖一个可能永远不返回的浏览器接口。** 设置里的开关和按钮要等状态读到才可点，但读取不能用不会失败也不会结束的接口（例如 `navigator.serviceWorker.ready`，没有后台程序时一直等）；先查“有没有”，没有就立刻显示可操作的状态。读不到要显示原因和重试，不能静默灰着（I-39）。
34. **出错时只说程序真的知道的原因，不同的原因分开说。** 一句话不能同时盖住几种失败：模型没回答、没答完、答案被截断、答案读不懂，各写各的，主人和我们才知道该查哪一步（I-40）。

36. **能不写的字就不写。** 设置页里的每一行说明，只在“主人不看就会做错”时才留；功能介绍、以后会有什么、操作的后果能从控件本身看出来的，一律不写。长说明收进点开才看到的一层，默认不展开（第 42 条）。
37. **过程区默认收起，不显示后台默默做的事。** 主人来问问题是想要答案：每一轮的过程区在手机和电脑上都默认收起，里面不列“带上了几条记忆”这类后台步骤（第 47、48 条，推翻 PR #39）。
38. **搜索直接在原处做，不另开弹窗。** 对话搜索是侧栏里的搜索框，回车后结果替换下面的列表，清空就回到列表（第 49 条）。
39. **打开一页时，先显示主人此刻要看的内容，不等最慢的一条。** 读多段内容时每段到了就显示，最新的先读，并限制同时读取的条数（第 50 条）。

41. **全站一套“圆润”造型。** 图标是双色的：一层半透明浅色底形，上面一层实心细节或圆头线条；侧栏入口、过程区工具和文件类型的图标用向日葵金色。组件不描边，靠浅灰底色和柔和阴影分层：侧栏、卡片、菜单、弹窗浮起来；按钮一律胶囊形，只有主按钮是实心的文字色；分段选择是浅灰槽里浮起一块；开关是 iOS 式；输入框和搜索框浅灰底、无边框。圆角和阴影用 `rounded.css` 里的变量，不另写数值。全站图标只从 `components/glyphs.tsx` 一个文件取，新图标照这个文件里的画法先画底形再画细节，不在组件里另画，也不用 ×、⋯、⌄、›、✓ 这类文字符号当图标（第 45 条，[ADR 0295](adr/0295-web-chat-interface.md)，`npm run check:layout` 的 `OUTLINED_CONTROL`、`GLYPH_FILL_LOST`、`ICON_OUTSIDE_GLYPH_SET`、`TEXT_GLYPH_ICON`）。
42. **手机侧栏是浮动卡片，点外面就关；弹窗从底部弹出。** 侧栏离屏幕边 8 像素，外面盖半透明遮罩，点遮罩收起；侧栏不占满屏幕，右侧留出能看到对话的一条（第 46 条）。设置等弹窗在手机上从屏幕底部弹出，顶上有拖动条。
43. **一个功能只有一个入口，一句文案只出现一次。** 侧栏已有的重命名、置顶、归档，对话页的 ··· 里不再放；··· 里没有别的东西时不显示 ···。侧栏页（记忆、提醒、文件）只留侧栏和页面里的一个标题，不再加大标题、返回键和数量摘要；“记忆 13”和“记住了 13 条”这类同一个数字只留一处（2026-11-01 第三批第 6、10、13 条）。
44. **侧栏上的操作就地完成，不弹窗。** 重命名直接把这一行变成输入框，回车保存、Esc 取消；删除在这一行里出“取消 / 删除”确认，和 ChatGPT、Claude 的侧栏一样（第三批第 1 条）。
45. **按钮放在它作用的东西旁边，能点的一定像按钮。** “+ 添加”放在记忆搜索框右侧；提醒的“完成”是实心主按钮，“不再提醒”和“为什么提醒我”收进这条提醒的 ···；完整的提醒决策记录放进设置的邮件那一栏，不占提醒页（第三批第 9、11、12 条）。
46. **过程区按秒计时，进行中只说现在在做什么。** 超过 60 秒写“X 分 X 秒”；收起时显示“当前步骤 + 总用时”，例如“正在搜索网页 12 秒”；展开后不画时间条，每步只标自己的耗时。同一段连续的搜索网页和读网页合成一行“搜索网页 · 域名”，并行的不重复列（第三批第 2、5 条）。
51. **过程区“进行中”的图标在图标里面做自己的小动作，不在外面套转圈的框。** 每类步骤用哪个图标，以 `components/tool-icon.tsx` 里的对应表为准（思考、写回答、等你确认这几种不是工具调用的步骤，先经 `execution-process.tsx` 里的 `stepGlyphs` 对到这张表）：思考是大脑（`think`）；搜索网页和读网页共用雷达（`radar`）；自动审查是清单（`checklist`）；记忆是一张记忆网络（`memory`），回答下方的“记下了 N 条新记忆”和侧栏的记忆入口也用它；读文件是一本书（`book`），写文件是笔在书页上写字（`penBook`）；按文件名或内容找文件仍是放大镜（`search`）；命令、浏览器、数据库等其余步骤也各有图标，见那张表。进行中时动的是图标里面的部分，例如雷达的扫描线转一圈、清单的对勾一项项打上；放大镜是例外，整个图标左右轻摆。不给图标套转动的外框，也不让整个图标缩放闪烁。这些动作写在 `rounded.css` 的 `@media (prefers-reduced-motion: no-preference)` 里，按图标名选中，多数再按第几层（`path:nth-of-type`）选中，新图标要动就照这里加；系统开启“减少动态效果”时全部静止，进行中改用更深的图标底色表示。只有真的还在进行的那一行动：思考只动最后一段还没结束的，自动审查只在还没出结果、这一轮也没结束时动（`execution-process.tsx`）（第 35、41 条，[PR #222](https://github.com/sixianli/himawari-agent/pull/222)，原型 <https://claude.ai/artifact/FHsZ8UqiKmrfmTFrKBFK83>，测试 `ICON-MOTION-1` 到 `ICON-MOTION-7`）。
47. **设置按主人的思路分栏。** “个性化”放称呼和“从对话中自动记忆”，“通用”只放语言和外观，和 ChatGPT 的“个性化”页一致（第三批第 9、15 条）。

### 文字、颜色和语言

19. **日期、时间、数字跟着界面语言走。** 所有格式化都传界面语言，中文界面不出现“Thu, October 29”或“11:55 AM”（第 39 条，I-15）。
20. **正文字重 400。** 不用 430 这类中间值，苹方会把它取成 500，整段看起来像加粗（I-12）。
21. **颜色只表达含义。** 红色表示需要主人处理，琥珀色表示看一下或已自行恢复，向日葵金（主题色）只用在能点的东西和当前状态上，用得克制；主题色固定，不让主人选（[ADR 0106](https://github.com/sixianli/himawari-agent/blob/7d0ffcd52cbb69d4941871cf9bf08d93f3843da8/docs/adr/0106-proactive-loop-v1-gmail-read-only.md)；2026-11-01 第三批 UI 意见第 3 条）。

49. **每一行、每一列的名字自己说清它是关于什么的。** 表头不能用一套通用的词套在意思不同的行上；每一行用这一行自己的说法，只列这一行可能出现的情况。例如校准周报不用三个按评价按钮起名的通用比例列（[词表](glossary.md)第 16 条的旧叫法），而是“系统没存下的记忆：不存是对的 / 该存没存”“已存的记忆：存对了 / 不该存”。行名还要让人一眼知道单位和对象：原来的 Gmail 行名（词表第 18 条的旧叫法）看不出检查的是什么，改成“读完邮件没提醒”（单位是一次读邮件）。改名时连同用到同一个名字的其他页面和[词表](glossary.md)一起改（2026-11-03，Andy 看校准周报原型的两条意见；词表第 16、18 条）。

35. **动画只在表达状态时才动，位置在变的动画只开一个共用计时器，并尊重系统“减少动态效果”。** 标志只有首页大图（慢慢长新种子）和正在回答的那一个（快速长）会动；已完成的回答、侧栏、登录页的标志一律静止。逐帧改位置的动画全页只用一个 `requestAnimationFrame` 计时器，没有东西在动时一帧都不跑；系统开启 `prefers-reduced-motion: reduce` 时，所有位置变化的动画都不启动（[ADR 0126](https://github.com/sixianli/himawari-agent/blob/baf02ebc4f376a27aa2a8d2871cc4a897a42c7e2/docs/adr/0126-sunflower-mark-grows-233-seeds.md)、[ADR 0308](adr/0308-sunflower-mark-seed-count-follows-its-size-except-the-chat-puck.md)，MDN 与 WCAG 2.3.3）。

### 手机

22. **手机上的输入框字号至少 16px。** 否则 iPhone 一点输入框整页放大不回弹；弹窗高度要扣掉状态栏和底部安全区（I-14）。
23. **手机上的点按区域够大。** 顶栏按钮在手机上是 40px 的圆形，回答下方的操作按钮是 36px。

40. **手机键盘弹出时页面跟着可视区域走。** iPhone 的键盘不会缩小页面，`100dvh` 不变，输入框会被顶高、留出空隙、顶栏被推到状态栏下。键盘出现时页面高度取 `visualViewport`，并去掉底部横条留白（第 43、44 条）。

52. **一排放不下的按钮只在自己里面换行或左右滑动，不能把外层撑宽。** 手机上设置的标签栏、筛选按钮这类横排，放不下时要么换行，要么只让这一排自己滑动；按钮本身不被压扁。外层容器被撑宽后，内容会被横向推出弹窗，看起来像左边被切掉（2026-11-05，英文界面手机上设置的“工具与权限”“数据”两栏）。`npm run check:layout` 的 `CONTENT_PUSHED_SIDEWAYS` 拦这种情况。

### 原型

50. **原型要同时能看电脑版和手机版，并直接给可点的网页。** 给 Andy 看原型时发 HTML 文件本身，不只发截图；原型顶部的控制条里要有“设备：电脑 / 手机”切换，手机模式在一个 390 宽的框里显示，不依赖浏览器窗口宽度，否则在宽窗口里只能看到电脑版。截图只作补充（2026-11-03，Andy：“刚才我看的原型里面只有电脑端的，没有手机端的”“你不要给我截图啊，你给我 HTML 啊”；校准周报原型 `docs/assets/control-center/2026-11-03-v17/`）。

### 数据

24. **主人的设置在所有设备上一致。** 主人能改的每一项账户设置（称呼、界面语言、主题、对话用的模型和思考深度、自动记忆开关）都存在服务器上，换设备打开看到的一样；另一台设备改了，切回页面就更新；断线时的旧改动不能盖掉别的设备后来改的值。浏览器本地只放这份设置的缓存和设备自己的东西（草稿、通知授权、侧栏收起）。新加设置时先问“换一台设备它该不该一样”，该一样就存服务器（第 24 条，I-16；2026-10-30 Andy 要求所有设置各端同步，[ADR 0122](adr/0122-every-owner-setting-on-the-server-with-revision.md)）。
25. **变化历史要完整，长了就画图加折叠，不用箭头串。** 一件事的每次变化都要能看到；只有两到四种状态来回变时画成几条线，每次变化一个点；列表只显示最近 3 次，更早的收进“展开更早的 N 条”。变化记录页每次变化一行，只写“现在是：……·第 N 次变化”，不写“旧 → 新”（I-20，[ADR 0300](adr/0300-how-memory-works-now.md)）。
26. **来源没了就如实说。** 来源对话被删后写“来源对话已删除”，不能点；不能退回成别的来源名（例如“整理记忆”）。主人的原话摘录照样保留（I-20，Andy 选择卡）。
28. **同一份数据只有一个地方、一种叫法。** 不把从数据里挑出来的一部分做成能单独编辑的另一页，否则主人会以为有两份资料。例如“档案”只是记忆上的“每次对话都带上”标记，放在记忆页顶部的卡片里，改的就是那条记忆本身（[ADR 0300](adr/0300-how-memory-works-now.md)）。
29. **自动决定的事，主人能看到也能改。** 写明自动挑了哪些、用了多少额度、哪些没放下；每一条都给主人一个开关，主人的选择优先。开关不能打开时变灰，并写出原因，例如“敏感记忆不会每次都带上”（[ADR 0300](adr/0300-how-memory-works-now.md)）。
30. **数据从 10 条涨到 1 万条，页面结构不变。** 按主题分组，每组先显示最新几条，再给“看全部 N 条”；一页 30 条，再点“再显示 N 条”。不靠多加几排筛选按钮（[ADR 0300](adr/0300-how-memory-works-now.md)）。

### 文件预览

27. **文件在页面里看起来要像它本来的样子。** PDF、Word、Excel 直接在预览栏里显示，保留分页、颜色、表格边框、数字格式；文档和表格的“纸面”在深色主题下也是白底，外框跟随主题；显示不出来时用一句话说“可以下载后打开”，不显示错误码（第 31 条，[ADR 0295](adr/0295-web-chat-interface.md)）。

### 苹果客户端

这一节管 iPhone、Apple Watch、Mac 上的 App。批准的原型和截图在 `docs/assets/apple-clients/` 下，说明在[详细设计的“界面照哪一版做”](execution/specs/2026-11-11-apple-device-body-design.md#ui-baseline)。

53. **App 的每一页都用原生界面做，按手机的用法重新设计，不把网页嵌进来，也不照搬网页的布局**（Andy 2026-11-12：“你不会要跟我说你是直接把网页迁移到 ios app 吧？”；[ADR 0247](adr/0247-apple-clients-are-fully-native-with-a-capability-table.md)）。
54. **iPhone、Apple Watch、Mac 三个 App 的图标全部用苹果的 SF Symbols，只用这一套，不加底色块。** Andy 2026-11-26：“这些 icon 重新设计，简约，优雅，有设计感，不要配底色”，加上 Apple 规范优先（第 70 条）；取代 2026-11-12 选定的 Tabler 线条图标。默认用线条款（不带 `.fill`），只有三处用实心：输入条右下角深色圆钮里的停止和暂停、系统控件自己就是实心的选中态、小圆点。颜色跟旁边的字走，深色圆钮上的图标用 `onSpeak`；单色渲染（`.monochrome`）。大小随动态字体放大（`Icon` 里用 `@ScaledMetric`，最多放到 xxxLarge，免得撑破固定大小的圆钮）；小箭头、发送和关闭用半粗，其余常规粗细。右下角“和她说话”用系统的 `waveform`。“她的页面”和它下面各页的列表行前面，图标和正文同一个文本样式（`.body`，放大一档），颜色 `glyph`，占一列固定宽度（`her.rowSymbolWidth`），各行文字左边对齐。服务端发来的过程行图标名（`activityIcon`，40 个）不变，由 App 换成对应的 SF Symbol，认不出的名字用 `puzzlepiece`。名字和 SF Symbol 的对照写在 `clients/apple/Sources/HimawariDesign/Icon.swift` 的 `IconName.symbol`。网页仍用第 41 条的圆润图标。依据：Apple《Human Interface Guidelines》的 [SF Symbols](https://developer.apple.com/design/human-interface-guidelines/sf-symbols)。
55. **导航和按钮是浮在内容上的一层玻璃，颜色用得少。** 顶上她的头像、返回钮、输入条都浮在内容上面，内容从下面滚过去；卡片不描边，靠浅灰底和柔和阴影分层；按钮是胶囊形，只有主按钮是实心的文字色；向日葵金只用在能点的字、带动作的选项、“要你同意”、列表行的图标方块（第 54 条）上（Andy 2026-11-12 要求按苹果现行的 iOS 设计规范做，“简洁、优雅、有设计感”；批准“可以，就按照最新版原型做”）。
56. **所有文字都用苹果的系统字：英文 SF Pro，中文苹方，包括她的回答。** 2026-11-26 起不再用宋体之类的衬线字（Andy 原话：“对话的字体换成苹果官方的字体”）。iPhone 上字号用系统文本样式：设计 token 的字号等于某个文本样式的默认大小时（17 是 `.body`、15 是 `.subheadline`、13 是 `.footnote` 等），代码直接用那个文本样式，跟着系统“动态字体”放大缩小；回答和气泡都是 `.body`。`npm run check:apple-design` 会拦下自定义字体和衬线字（`.custom(…size:)`、`design: .serif`、`UIFont(name:)`）。“她的页面”顶上的 himawari 字样是标志图片，不是文字，不受这条约束。依据：Apple《Human Interface Guidelines》的 [Typography](https://developer.apple.com/design/human-interface-guidelines/typography)。
57. **对话里“它正在做什么”只占一行。** 这句话由 Himawari 自己写，说的是事（“正在查周五早上的新干线”），不是工具名；图标由 Himawari 从固定的 40 个动作图标里挑，没有合适的用“别的工具”那一个。换了一件事就在原地换，不往下堆。进行中是字上慢慢扫过一道光，图标不动、不转圈；没成功时用平常的话说出来并接着做下一步，不用红色；要主人同意时，这一行下面出一张同意卡片（第 67 条）；做完后收成一行“做了 N 件事 · 用时”，N 等于点开后列出的步数，点开看每一步；没做成收成“没做成 · 用时”，主人按了停收成“停了 · 用时”。系统开启“减少动态效果”时那道光不动（Andy 2026-11-12：“这四十个图标我很喜欢，设计风格我很喜欢”“同意图标由 himawari 自己从这 40 个里面挑”；图在 `docs/assets/apple-clients/2026-11-12-process-row/`）。
58. **要主人本人在场的操作（改规则、删记忆、改设置、导出、移除设备这些），点下去直接出面容识别，不另弹一个要再点一次的确认框。** 对话里的日常操作（发消息、改名、置顶、归档等）和“往少的方向”的操作（关掉或暂停感知、暂停记忆、暂停提醒、让正在跑的一轮停下）不用面容；哪个操作算哪一种，以详细设计的客户端能力表为准（随 2026-11-12 批准的原型定，[ADR 0247](adr/0247-apple-clients-are-fully-native-with-a-capability-table.md)）。
59. **Andy 说“学某个 App 的设计”，学的是视觉和组件（按钮、输入条、列表、设置页、字体），不动功能和页面结构，除非他明说**（Andy 2026-11-12：“学组件和 ui，不是说功能”）。
60. **图标、配色这类看眼缘的事，拿不准就一次并排给几套让 Andy 选，不一版一版地试**（Andy 2026-11-12：“多做几套出来给我选”）。
61. **触感每一下都有固定的含义，而且看场合。** 主人的手引起的事和 Himawari 的事分开；回答逐字出来时不震；录音和收听时不震；主人正看着时只有“等你点头”震；手表戴着就只在手表上震；设置里能调三档。页面不直接调震动，只报发生了什么事，由共用的一处决定震不震、怎么震（Andy 2026-11-12：“触感要做的智能、体贴一些”；事件表见[详细设计的“触感”](execution/specs/2026-11-11-apple-device-body-design.md#haptics)）。
62. **每一端只做它最擅长的事，不把别的端的页面搬过来。** iPhone 管提醒、随时对话、刷脸点头和各种感官；手表只有一眼看完、一两下做完的事；Mac 常驻菜单栏，管主人眼前的东西和这台 Mac 上的文件，不做聊天窗口和管理页；要看完内容才能定的事，手表上只给“在 iPhone 上看”。一件事只在一处响，哪一端定了，其他端一起收走（Andy 2026-11-12：“每一端都有各自的优势，那就把这个优势做到最好，其他不必要的功能就可以直接拿掉”；[ADR 0258](adr/0258-each-apple-device-plays-to-its-strength.md)）。2026-11-16 起手表和 Mac 暂停，只做 iPhone。
63. **打开就是一个主对话，不放问好、日期这类装点的字。** 灵动岛正下方居中浮着一个毛玻璃小圆（直径 56 点，系统 `.ultraThinMaterial`，里面是 46 点的向日葵），消息从它后面滚过去；没有顶栏的底、himawari 字样和深色圆底。点小圆打开她的页面，记忆和设置都从那一页进；没有底部页签栏、“今天”页、对话列表和“新对话”。她在忙（正在回答，或后台有事在办）时标志从中间一点点伸出小点，没有暖光；平时不动；系统开了“减弱动态效果”时全部静止。页面上的每个数字都要说得出数的是什么（Andy 2026-11-12：“像日期、问好这些完全没有必要”；2026-11-24 20:06：“打开就是一个主对话，没有新建线程这个入口，只有一个主对话”；2026-11-25 00:06 在六种头像样式里选了这一种：“我选这一个”；2026-11-26 02:00 看了毛玻璃小圆的原型后定稿：“可以，就按照这版来做吧”，01:48：“不要背后的一团暖光”）。
64. **一屏只有一个实心的主按钮。** 要主人定的事给两个等宽的按钮，肯定的在右、实心，上面写的是会发生的事（“改到 9:40”“发出去”），不写“好”“确定”“同意”。否定的按钮写不做的那件事（“不发”“不订”）。例外是同意卡片：要做的事已经写在卡片正中，按钮管的是上面选的那个范围，所以写“不要”和“同意”。她那条话下面的选项不算按钮：带动作的选项本身就写会发生的事（“回复 田中：周四 15:00 可以”），最后一个是“不用了”。同一屏有几件事时，只有最要紧的那一件用实心按钮，其余的用浅底按钮。
65. **要再多看一点就在原地展开，不另弹一页把同一句话和同一对按钮再显示一遍。** 展开和收起用朝下、朝上的箭头；› 只用在进下一层（Andy 2026-11-12 看到底部弹层里四个一样的按钮：“好丑啊……好没有设计感”）。
66. **界面不按事情的种类写死。** 主对话的选项、同意卡片和通知上，一件事都按“一句话、明细、肯定按钮、否定按钮、来源、要不要本人在场”这一个样子画；没见过的种类照这个样子显示。服务器多一种事，界面不用跟着改（Andy 2026-11-12：“而不是一套固定死的工作流”；[ADR 0258](adr/0258-each-apple-device-plays-to-its-strength.md)）。
67. **Himawari 自己想到的事就是主对话里她的一句话。** 有可点的下一步时，下面竖排几个选项：只是接着问的白底细边；带具体动作的浅金底、左边一个发送图标，按钮字由服务器按真实收件人和内容生成，点一次就执行；最后一个灰字“不用了”；点过的变成主人的一条话，上面一行小字“选了”；有了更新的消息，旧的选项变灰。要主人同意的是一张同意卡片：“要你同意”和来源、程序写的真实动作和明细、四个范围（只这一次、这件事里、几天内、以后都行，花钱只能只这一次）、“不要”和“同意”。不再有“提议”和“告诉你一声”两种样子（ADR 0285 决定第 5 条；名字见[词表](glossary.md#terms)第 23 到 26 行）。
68. **深色只换颜色，版式、字号、间距和浅色一样。** 颜色只用 `tokens.json` 里批准过的那一套，不为某一屏新造颜色；跟系统的外观走，App 里不另设开关。
69. **画新的一屏之前，先打开已认可的那几屏和 `tokens.json` 对一遍。** 同一个位置的东西（顶上头像、输入条和右下角声波圆钮、按钮高度）在每一屏都一样；补画的屏在基线的说明里标明“设计线程补画”，和 Andy 逐屏看过的分开。
70. **能用系统组件就用系统组件；自绘的组件，点击区域、按下的反馈和无障碍都要和系统组件一样好。**
    - 系统有现成的就用系统的：分段切换用 `Picker` 的 `.segmented` 样式，列表用 `List`，开关用 `Toggle`，菜单用 `Menu` 和 `.contextMenu`，弹层用 `.sheet`，左滑操作用 `.swipeActions`，搜索用 `.searchable`。只能换系统允许换的颜色和字体，不另画一个外观相似的组件。
    - 只有系统组件做不出已经定稿的设计时才自绘，并且在说明里写清楚原因。
    - 字体只用系统字，见第 56 条。
    - “她的页面”往下推进去的每一页都用系统导航栏：系统返回钮、标题、边缘右滑返回；记忆页是大标题，往下拉出现 `.searchable` 搜索栏。不再用自己画的玻璃返回钮加隐藏导航栏，因为隐藏导航栏后边缘右滑返回会失效。
    - 自绘组件要达到下面四条：
      1. 整块都能点，点中区域至少 44×44 点。字小时，把点击区域放大到整块（`contentShape`），不只是文字那一块。代码里按钮一律用 `.buttonStyle(.pressable)`（整块可点、按下变暗），`npm run check:apple-design` 会拦下 `.plain` 和 `.borderless` 这两种只有字能点的样式。
      2. 选中和没选中，不只靠颜色深浅区分，要一眼就能看出来：系统分段切换那样浮起一块的底，或者字重、颜色一起变；浅色和深色下都要看得清。
      3. 按下时有反馈：按下时变暗或缩一点，松手才触发；手指移开就取消。
      4. 无障碍：VoiceOver 读得出名字和状态（例如“记住的事，已选中，第 1 项，共 2 项”）；跟着动态字体放大，字放大后点击区域也跟着变大；“减弱动态效果”打开时不播动画。
    - 没接通、没做完或只是摆设的按钮和入口不放出来，做好了再放。
    - 每份规划稿写明每个能点的东西用哪个系统组件；自绘的写明原因。每次验收在正反向之外再加三条：点边缘、不点在字上也能触发；选中项在浅色和深色截图里都一眼认得出；VoiceOver 读出的名字和状态对。
    - 依据：Apple《Human Interface Guidelines》的 [Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons)（点击区域至少 44×44 点）、[Segmented controls](https://developer.apple.com/design/human-interface-guidelines/segmented-controls)、[Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)。起因是 Andy 2026-11-26 9:32 看了记忆页的切换后说：“这里的写个选中的 tab 按钮不够明显，而且，只有准确的点击在文字上的时候才会触发切换，你必须按照 ios app 的 ui ux 开发最佳实践来开发各种组件 ui 给我极致的 ux 体验”；9:34 看了记忆页右上角的搜索钮：“这里这个按钮有必要存在吗？如果有就做到可用，好用，再放出来给我用！”
