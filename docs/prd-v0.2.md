# Himawari Agent 产品需求 v0.2

## 产品目标

- 交付一个能够长期运行、主动服务于单一所有者的私人通用 Agent，而不是只响应当前消息的聊天工具或只服务 GitHub 的专用机器人。
- 让同一个 Agent 通过长期 Thread、长期记忆、后台任务和受治理能力持续理解所有者的偏好、目标、项目、承诺和近期变化，并在相关情境中主动使用这些信息。
- 让用户消息、计划时间和外部服务事件进入同一套上下文、授权、执行、跟踪和结果投递规则。
- 通过完整的 Web 控制中心提供对话、审批、任务、收件箱、记忆、能力、授权、跟踪、设置和健康状态，并允许所有者从桌面或手机浏览器安全访问。
- 让 Agent 在明确授权内使用 Web、文件、代码工作区、日历、GitHub 以及经过审查的适配器，同时保证模型不能自行批准行动、扩大权限或隐藏外部副作用。
- 使用一个云端主要生成模型和一个固定云端备用生成模型；模型变化或故障降级不得静默扩大数据披露、改变费用边界或绕过授权。
- 让 Mac 和 Hermes Linux 都能承载同一个 Agent，但任意时刻只有一个活动权威；两台机器之间通过所有者主动发起的停机迁移切换，而不是双活或自动故障切换。
- 达到可作为私人生产服务上线的持久性、安全性、可诊断性、可迁移性、兼容性和长期运行质量，而不是以功能不完整的预览版本冒充 v0.2 生产版。

## 目标用户

- v0.2 的唯一正式用户是 Himawari Agent 的单一所有者（Owner）。
- 所有者可以从多个浏览器和设备访问同一个 Agent，但这些客户端共享同一产品身份、长期状态和活动权威。
- 所有者能够理解任务范围、数据披露、费用、外部副作用和授权期限，并对敏感信息、关键行动、能力和模型变化作最终决定。
- 本版本不面向不受信任公众开放注册，也不承诺多租户、团队共享空间或多个所有者共同管理同一私人 Agent。

## 产品范围

### 本版本包含

- Mac 与 Hermes Linux 两个同等受支持的生产平台，以及相同的产品行为和验收标准。
- 单一活动权威、跨正常重启的持久状态、所有者主动发起的停机迁移和迁移后的短期回切边界。
- 面向公共互联网但受外部身份网关和多因素认证保护的响应式 Web 控制中心。
- 长期 Thread、多轮消息、运行记录、审批、授权、完整可观察 Trace、收件箱和后台任务。
- 自动提炼非敏感长期记忆、敏感记忆逐项审批、跨 Thread 相关检索，以及可查看、纠正、归档和删除的记忆生命周期。
- 固定的行动分类、风险等级和 `ALLOW / ASK / DENY` 授权结果，以及不可被模型降低的确定性安全下限。
- 受统一治理的 Tools、Skills、MCP、本地程序和第三方 API，以及公共 Web 研究、受控的认证 Web 操作、按目录授权的文件能力、授权代码工作区、Apple/iCloud Calendar 和经过审查的适配器管理。
- 公开与私有 GitHub 仓库的在线只读监控、模型相关性分析、Web 收件箱投递和可观察的覆盖缺口。
- 一个云端主要生成模型、一个固定云端备用生成模型，以及独立管理的非生成式嵌入模型。
- 受预算约束的周期反思、主动任务建议、临时内部专业 Worker 和隔离环境中的自我改进候选验证。
- 中、英、日三种 Web UI 语言，Thread 级模型回答语言，以及桌面和移动浏览器的无障碍关键流程。
- 数据加密、机器秘密隔离、受控删除、同一权威存储上的逻辑恢复能力、手动核心升级和生产验收。

### 本版本不包含

- 微信、Telegram 或其他即时通信渠道的消息投递；v0.2 的所有提醒只出现在 Web UI。
- 本地生成模型；只保留未来接入本地模型所需的服务商和部署位置中立边界。
- 原生 macOS、iOS、Android、桌面壳、纯语音或带屏硬件客户端。
- 面向公众的自助注册、多租户计费、团队空间或多个所有者共享完整私人状态。
- 双活、多主写入、自动跨机器故障切换、分布式共识、零停机迁移或离线副本合并。
- 主机或存储完全损毁后的异地灾难恢复、跨设备备份承诺、RPO 或 RTO 保证。
- GitHub 写操作、自动提交、自动推送、自动合并、自动发布或高于只读监控所需的仓库权限。
- Calendar 参与人邀请、参与人增删或会代表所有者发送会议通知的更新。
- 任意插件市场、未经审查的能力安装、通用不可信代码执行平台或能力自行扩大权限。
- 人类可读或通用机器可读的数据导出；只提供受控权威迁移所需的机器迁移包。
- 离线期间遗漏的计划任务、一次性任务或外部事件补跑和追赶。
- 隐藏的第三个生成模型、静默扩大数据披露、静默提高费用或核心程序静默自动更新。
- 对模型服务商的数据保留、删除或“不用于训练”作产品保证。
- 把密码、API Key、访问令牌、Cookie、私钥、恢复码或同类机器秘密写入模型上下文、长期记忆或可读 Trace。

微信、Telegram、本地模型和原生客户端只属于未来扩展方向。v0.2 必须避免封死这些方向，但不实现隐藏的半成品，也不把它们计入当前版本验收。

## 核心产品模型

### 单一 Agent 与活动权威

- 一个私人 Agent 只能有一个所有者，也只能有一个允许提交长期状态和执行外部行动的活动权威。
- Mac 与 Hermes 都可以成为活动权威，但不能同时为同一个 Agent 接纳写入或执行行动。
- 浏览器、内部 Worker、模型服务商、记忆后端和外部适配器都不是产品权威。
- 权威状态不确定、已被撤销或发生冲突时，系统必须停止新写入和新行动，并明确展示安全降级状态。
- 关闭浏览器不能停止已经获得授权的后台任务。

### Thread、Run 与内部稳定边界

- Thread 是用户可见、可长期继续的对话或任务上下文，包含多轮消息和多个可识别 Run。
- 用户不需要理解或管理“Thread 内嵌多个 Session”的层级；内部 Session 只能作为 Trace 聚合或稳定处理边界，不能取代 Thread 和 Run 的稳定身份。
- 浏览器关闭、长时间空闲、上下文压缩或重新连接都不能自动结束或替换 Thread。
- 新建、归档和删除 Thread 必须由所有者明确操作。
- 新 Thread 自动共享 Owner Profile、长期记忆、长期目标和仍然有效的授权，但不复制其他 Thread 的全部短期上下文。
- 当前 Thread 可以按相关性检索其他 Thread 的摘要或消息片段，并在 Trace 中记录来源；不得把全部历史无差别发送给模型。

### 后台任务与结果

- 后台任务必须有稳定身份、明确目标、触发方式、范围、授权、预算、时区、超时、重试边界、当前状态和撤销方式。
- 任务结果必须进入统一的持久结果系统，再由固定注意力规则决定静默、收件箱、摘要、普通提醒或紧急提醒。
- 归档 Thread、离开页面或触发上下文压缩不能自动取消已经批准的任务。
- 未解决承诺、反思结果和模型建议只能形成可追溯候选，不能在没有任务授权时自动执行。

## 业务规则

### Web 控制中心、身份与设备

- Web 控制中心必须提供对话、审批、任务、收件箱、长期记忆、能力与授权、Trace、设置和健康状态的完整操作入口。
- 公网人类访问必须经过外部身份网关和多因素认证；Himawari 仍必须独立验证受信身份断言及其与唯一所有者的映射，不能信任可伪造的普通请求头。
- 唯一所有者只能通过活动权威主机上的一次性本地初始化建立并绑定外部身份；初始化完成后，该入口必须关闭。
- Web UI 必须允许所有者查看并撤销产品会话和设备；关键操作需要近期重新认证。
- 活动权威主机必须提供独立、受审计的本地紧急恢复（break-glass）方式，用于修复所有者映射、撤销会话或关闭公网入口。
- 浏览器状态变更必须防止跨站伪造、重放和重复提交；断线重连必须从持久位置恢复已经接受的结果。
- 浏览器离线时只保留尚未发送的本地输入草稿，不得在本地接纳命令、创建任务或批准行动。
- 外部服务事件必须使用与人类登录分离的专用来源认证和限定入口，不能借此访问普通业务能力。

### Web UI 语言、回答语言与无障碍

- Web UI 必须完整支持简体中文、英文和日文切换。
- UI 语言只保存在当前浏览器，不作为所有者级偏好跨浏览器或设备同步；首次打开时可以使用浏览器语言初始化。
- 模型回答语言属于 Thread。每个新 Thread 默认使用简体中文，所有者通过可见选择或明确自然语言指令修改后，在该 Thread 中持续生效，直到再次修改。
- Web UI 语言与模型回答语言相互独立，输入一段外语不能自动永久改变 Thread 回答语言。
- Agent 生成的摘要和解释使用当前 Thread 回答语言；原始引用、代码、日志和专有名词保持原文，需要时再单独翻译。
- 桌面和手机关键流程必须以 WCAG 2.2 AA 为目标，覆盖键盘、屏幕阅读器、对比度、焦点、触摸和非颜色提示。

### Thread 生命周期与上下文压缩

- Thread 可以自动生成标题，并支持重命名、置顶、归档、标题和内容搜索，以及按时间、状态和任务筛选。
- Thread 归档可逆，归档后默认从主列表隐藏，但保留全部内容、来源关系和恢复能力，也不取消关联任务。
- 所有者可以从任意历史轮次 Fork 新 Thread；新 Thread 保留来源关系和该轮上下文快照，但不复制原 Thread 的任务、审批或长期记忆对象。
- 上下文压缩必须产生带来源范围、处理水位线和策略版本的可恢复摘要；摘要在 Trace 中可见，不创建新 Thread，也不删除原始历史。
- 内部稳定边界可以触发摘要、长期记忆、可复用经验和未解决承诺候选的提炼，但不会自动结束 Thread。
- 待审批行动保留到各自有效期结束；审批过期后必须重新形成提案，不能沿用旧结果。

### Memory 与私人上下文

- 稳定偏好、个人事实、长期目标、持续项目、重要决定、经常性习惯、承诺和明确纠正等具有长期价值的非敏感信息可以自动进入长期记忆。
- 短暂寒暄、一次性细节和只服务当前一步的信息不应默认保存为长期记忆。
- 高置信度、非敏感的推断可以自动保存，但必须明确标记为推断，并保留来源和置信度。
- 敏感个人信息必须逐项获得所有者批准后才能进入长期记忆。所有者明确说“请记住”只构成对该项内容的批准，不自动批准同一消息中的其他敏感信息。
- 在交互式对话中发现敏感候选时，必须在当前 Thread 同步询问；不能先保存正文，也不能静默转入异步候选队列。
- 同一次产生多个敏感候选时，Web UI 必须允许逐项批准、编辑或拒绝。
- 后台任务发现敏感信息时，不保存提取后的敏感候选正文；只保存指向原始加密来源的最小引用，等所有者在线后重新提取或询问。
- 第三方个人信息只有在合理服务于所有者时才能保存，并标记信息主体和来源；敏感第三方信息继续执行逐项审批。
- 每次 Run 后的增量提取和稳定边界的全局提炼必须互相补充，并具有稳定、可重试、不会重复产出同一结果的产品身份。
- 自动记忆失败不能使已完成对话丢失；失败必须可观察并且只进行有限重试。
- Web UI 应以不打断对话的方式显示“已保存若干条记忆”，并允许展开查看；完整变更同时进入活动记录。
- 所有者必须能够查看、搜索、纠正、归档和删除长期记忆，并看到来源、版本、推断状态和最近使用情况。
- 记忆不按固定时间自动硬删除。低价值记忆可以降低检索权重并进入可恢复归档。
- 记忆后端只能提出新增、更新、合并或不变等候选操作；产品权威状态决定稳定的活动版本。后端内部合并、去重和召回算法不属于所有者需要配置的产品策略。
- 记忆后端必须可替换，其索引、缓存或供应商对象不得成为产品事实的唯一来源。
- 所有配置模型只能接收当前任务相关的最小记忆上下文；跨 Thread 和跨来源检索必须在 Trace 中记录引用。

### 机器秘密、敏感数据与可观察 Trace

- 密码、API Key、访问令牌、Cookie、私钥、恢复码和同类机器秘密必须在调用模型、记忆提取和记忆后端之前被排除。
- 机器秘密不得作为普通产品数据保存，也不得进入长期记忆、迁移包、模型可见上下文或可读 Trace；Trace 只记录非秘密引用、用途和结果。
- 私人正文在持久保存时必须受到生产级加密保护，访问和解密必须遵循已批准的能力与上下文范围。
- Trace 必须展示系统可观察到的上下文选择、Memory 引用、模型输入输出、工具参数和结果、内部委派、授权判断、错误、重试、状态变化和外部副作用。
- Trace 不要求也不得伪造模型服务商内部不可观察的隐藏思维过程。

### 行动风险与授权

- 每个拟执行行动都必须先由模型在固定行动分类和固定安全等级内做语义分类，再由固定规则结合可观察事实决定最终风险和授权结果。
- 风险等级固定为 `LOW / MEDIUM / HIGH / CRITICAL`；确定性事实可以设置不可降低的风险下限，模型只能提高风险，不能降低。
- 授权结果固定为 `ALLOW / ASK / DENY`，模型不能创建新的结果类型，也不能批准自己的越权行动。
- 一条足够明确的自然语言任务指令本身可以构成该任务的授权，但必须包含足以确定目标、范围、工具、频率、费用或收件人的必要信息。
- 只有能力已启用、目标已批准、范围有界、操作只读、没有新收件人、没有敏感披露、没有凭据或权限变化且费用在上限内的行动，才能作为低风险读取自动执行。
- 真实资金和购买、不可逆删除、凭据和访问控制、生产部署或回滚、公开发布、法律签署以及可能影响人身安全的物理行动属于关键行动，必须逐次确认。
- 低风险只读长期授权可以持续到所有者撤销；带外部副作用、付费、敏感数据或高权限的授权必须有明确有效期。
- 缩小任务范围可以沿用原授权；扩大目标、工具、频率、费用、数据范围、权限或收件人必须重新审批。
- 能力被撤销或授权过期后，相关任务必须暂停并显示明确原因，不能静默改用其他能力绕过限制。
- 每个待审批行动都有明确有效期；过期后状态为 `EXPIRED`，重新执行必须形成新的行动提案。

### 模型、降级与数据披露

- 正式配置只启用一个云端主要生成模型和一个固定云端备用生成模型；嵌入模型作为独立的非生成式能力管理。
- 每次模型调用必须记录准确的服务商、模型身份或快照、数据披露等级、用量、费用和结果。
- 模型身份应尽可能固定到准确版本；身份、服务商、披露范围或费用变化都视为模型变化。
- 只有所有者预先批准白名单内的主要模型变化可以静默发生；新增模型、服务商、披露范围或费用必须重新批准。
- 非 GitHub 任务只有在备用模型已经批准、能力满足、费用在预算内且不扩大数据披露时，才可以自动降级。
- GitHub 仓库默认只授权给当前主要模型；每一次把仓库内容发送给备用模型都必须单独询问。
- 主要模型的策略拒绝、授权失败或数据披露不兼容不能通过备用模型绕过。
- 模型在尚未产生外部副作用前失败时，可以丢弃不完整步骤并从持久检查点重新开始；已经产生副作用时必须先对账，再恢复或询问所有者。
- 两个生成模型都不可用时，交互式 Run 必须明确失败或等待手动重试；后台 Run 只进行有限重试，然后进入可观察的 `MODEL_BLOCKED`。
- 产品不要求向所有者展示或审批模型服务商的数据保留和训练政策，也不能据此承诺服务商会删除数据或不用于训练。
- v0.2 不实现本地生成模型，但模型接入边界必须允许未来新增本地模型，而不改变授权、Trace 和数据分类语义。

### 正式能力与授权边界

- Tools、Skills、MCP、本地程序和第三方 API 都属于可治理能力，必须使用相同的来源审查、数据范围、授权、预算、撤销、健康状态和 Trace 规则。
- 公共 Web 搜索、页面打开和基于来源的研究属于正式内置能力。
- 公共 Web 默认无需登录；需要登录的站点可以按域管理受控会话。提交表单、发送消息、发帖、购买或修改账户仍经过正常行动分类和授权。
- 文件能力按主机和目录分别授予持久、可撤销的读写权限，不默认覆盖整个用户目录；迁移到另一台主机后必须重新授权。
- 本地删除默认进入可恢复 Trash；永久删除必须逐次确认。覆盖重要文件前必须展示差异或可恢复版本。
- 在已授权代码工作区中，可以读取、编辑并运行已知的构建、检查和测试命令。
- 进入代码工作区后必须先识别已有未提交修改，保留所有与当前任务无关的用户改动；不得擅自重置、暂存或提交这些改动。当前任务与已有修改重叠时必须询问所有者。
- 新命令、联网操作、安装依赖、系统级操作和执行不可信脚本必须重新询问。
- 本地 Git commit 只有在所有者逐次查看完整 diff、验证结果和提交信息并批准后才能执行；v0.2 不执行 Git push。
- Apple/iCloud Calendar 是首个正式日历适配器。
- Calendar 可以读取所有者可见的日程，并对所有者个人事件执行经过授权的创建、修改或删除；包含其他参与人的事件只能读取，不能增删参与人或执行会发送通知的更新。
- Web UI 必须管理经过审查的适配器，并展示其来源、权限、数据范围、配置、启停、撤销和健康状态；不提供任意插件市场。
- 同一可信来源、签名有效、没有权限扩张且保持兼容的适配器更新可以自动应用；来源、主要版本、权限或可验证性变化必须审批，并且必须能够回退。

### 主动建议、周期反思与内部 Worker

- Agent 可以从对话、长期记忆、重复行为和任务结果中提出新的后台任务建议，但只有所有者明确批准后才能创建任务。
- 系统必须包含受周期、上下文、费用和建议数量限制的全局反思，用于回顾长期目标、未解决承诺、近期变化和任务结果；反思不能自动产生外部行动。
- 周期反思和其他主动建议默认进入 Web 收件箱，并进行语义去重。
- 主动建议默认每天最多产生 3 条；所有者可以修改上限，已经确认的紧急事件不占建议额度。
- 主 Agent 可以把复杂研究、编程或规划子任务委派给临时内部专业 Worker。
- Worker 必须归属于同一个主 Agent、Run 和 Trace，只获得完成子任务所需的最小消息、记忆、文件和能力；扩大范围必须重新经过授权和记录。
- Worker 不能形成独立的私人 Agent 身份、绕过主 Agent 直接交付结果，或默认拥有独立长期私人记忆。
- Agent 可以在隔离工作区中生成并验证自己的代码、配置或能力候选改动，但不能自行提交、推送、部署、重启生效或放宽身份、授权、秘密、审计和升级信任根。

### 后台任务、计划与恢复

- 正式触发方式包括人工触发、一次性计划、周期计划和外部服务事件。
- 同一个任务默认只允许一个活动 Run；新触发应合并，只有明确证明安全并经过配置时才允许并行。
- 每个计划使用明确的 IANA 时区；主机或所有者时区变化不能重写既有计划。
- 夏令时不存在的计划时刻跳过，重复出现的计划时刻只执行一次。
- 主机离线期间错过的周期任务直接跳过；错过的一次性任务标记为 `MISSED`，只允许所有者手动重新运行。
- 外部事件在离线期间同样不追赶、不对账补齐；每个集成必须展示覆盖缺口的开始和结束，并说明期间可能遗漏事件。
- 已经在线接受的工作不得静默丢失。受预算阻塞的工作进入有界 `BUDGET_BLOCKED` 队列，受容量阻塞的新低优先级工作必须显示 `CAPACITY_BLOCKED`。
- 系统使用有界的全局和分类并发，并为前台交互保留容量。
- 重试必须按错误类别进行有限退避；凭据、授权、策略拒绝和确定性错误不得自动重试，必须暂停或失败并显示原因。
- 取消和超时采用协作式停止；已经发生的外部副作用保持可见，不能被伪装成回滚。任何补偿行动都是新的独立行动并重新授权。
- 系统必须提供单次 Run、任务周期和全局周期的硬预算；达到上限后转入询问或暂停。
- 每类任务有可调整的默认超时和全局硬上限，但不设置“最晚还有用时间”等隐藏执行期限。

### 注意力与 Web 投递

- 注意力等级固定为 `SILENT / INBOX / DIGEST / NOTIFY / INTERRUPT`，模型只能在这些等级中分类。
- 普通过程记录默认使用 `SILENT`；周期汇总使用 `DIGEST`；普通完成结果和主动建议使用 `INBOX`；需要处理的失败使用 `NOTIFY`；已确认的紧急安全或时效事件使用 `INTERRUPT`。
- 浏览器在线时，`NOTIFY` 和 `INTERRUPT` 通过实时横幅或紧急面板展示。
- 浏览器离线时，所有提醒持久保存，并在重新打开 Web UI 后按优先级展示；v0.2 不向站外渠道发送消息。
- 系统每天按所有者设置的时间和任务时区生成一次可配置的持久 Digest；Digest 只汇总已有结果，不重新执行任务。
- 所有者可以降低普通任务的期望提醒等级，但不能低于确定性安全规则规定的最低等级；重大凭据失效、安全事件或关键行动失败仍可提高等级。

### GitHub 在线只读监控

- GitHub 是首个正式外部事件提供商，必须支持公开仓库和所有者明确选择的私有仓库。
- 私有仓库凭据必须限于所选仓库和只读监控所需权限，并作为机器秘密处理。
- 每个仓库可以独立配置监控事件；默认覆盖默认分支推送、Pull Request 创建、更新或合并、Release 和 GitHub Actions 失败。
- 系统只接纳签名有效且属于已批准仓库范围的在线事件，并对重复投递去重。
- 所有通过基础来源和范围验证的在线事件都交给模型判断相关性和注意力等级，不使用确定性语义预过滤替代模型判断。
- GitHub 结果必须包含事件摘要、与所有者目标的相关性、风险和建议下一步，不执行任何 GitHub 写操作。
- 连接仓库时，Web UI 必须展示当前主要模型、服务商，以及排除机器秘密后整个仓库内容可以发送给该主要模型；一次明确确认同时启用仓库并授权这一披露范围。
- 已批准仓库可以随主要模型切换到预批准白名单内的模型；白名单外模型、服务商、披露或费用变化必须重新批准。
- 每个仓库保留受保护的本地只读镜像，用于当前监控与分析。
- 撤销仓库权限后必须立即停止读取并删除完整镜像和缓存；历史摘要、Trace 和任务历史默认保留，所有者也可以选择全部删除。
- 主机离线期间的 GitHub 事件不追赶、不进行恢复对账，Web UI 必须明确显示可能遗漏事件的覆盖缺口。
- 已在线接受但受预算阻塞的 GitHub 事件必须进入有界持久队列，不能静默丢弃。
- GitHub 凭据不得进入模型上下文、长期记忆、可读 Trace 或迁移包。

### 数据保留、归档与删除

- 对话和长期记忆默认一直保留，直到所有者删除；不设置时间驱动的自动硬删除。
- Thread 的完整 Trace 与 Thread 同寿命。
- 任务定义、结果、重试、检查点和调试记录默认长期保留，直到任务被删除。
- 普通删除先进入 7 天 Trash，并立即退出上下文、检索和执行；同时提供立即永久删除。
- 删除 Thread 前必须列出关联活动任务，由所有者取消、暂停或重新绑定后再完成删除。
- Thread 永久删除必须级联删除其消息、内部 Session、Run、Trace、私人正文、审批和 Thread 专属收件箱，但不自动删除已经形成的长期记忆。
- 保留的长期记忆如果来源 Thread 已删除，只能显示非正文来源标识和“来源已删除”，不得保留原始来源正文。
- 删除任务必须级联删除任务、Run、检查点、Trace 和任务收件箱；已经发生的外部副作用只保留不含原始内容的最小审计墓碑。
- 删除长期记忆必须清除产品活动记录、记忆后端索引和缓存，并建立防止旧副本重新激活的删除墓碑。
- 永久删除的数据必须在 30 天内退出所有可恢复的本地备份和恢复点。
- 未删除的逻辑恢复历史可以长期保留并进行经过验证的去重、压缩和合并，但不能静默破坏已经承诺的恢复点。
- 存储空间接近上限时必须警告；严重不足时停止新的高容量写入，同时保留只读访问、机器迁移导出和人工清理，不能擅自删除所有者内容。

### Mac、Hermes 与权威迁移

- Mac 和 Hermes Linux 都是 v0.2 正式生产平台，必须使用同一产品行为、数据格式和验收规则。
- 权威迁移只能由所有者明确发起，不能由模型、性能判断或故障检测自动触发。
- 迁移不设完成时限，只要求全过程状态真实、可验证，并在目标激活前阻止双活。
- 迁移开始后，源权威必须停止接纳新工作，持久化或明确处理正在执行的 Run，并形成受完整性保护的加密迁移包。
- 主机绑定的机器秘密不能进入迁移包；目标主机必须重新配置和授权这些能力。
- 目标只有在迁移包、私人正文、记忆、身份、任务和就绪状态全部验证通过后才能激活；失败不能留下部分生效的活动权威。
- 迁移前后保持同一个公共访问 URL，但路由变化不能使源部署继续接纳写入。
- 目标激活后，源部署保持不可启动状态并保留加密副本 7 天；到期删除。回切必须执行新的受控反向迁移，不能直接启动旧副本。
- v0.2 不提供主机或存储完全损毁后的异机恢复保证；所有者明确接受权威主机与其存储同时损毁时全部产品数据丢失。

### 核心升级与适配器演进

- Himawari 核心程序升级必须由所有者或运维人员主动发起，不允许静默自动更新。
- 升级前必须完成兼容性检查和本地恢复点，升级过程必须可观察、可验证并提供失败回退边界。
- 未来新增 IM、本地模型或原生客户端时，必须通过新的产品范围、权限和验收确认；v0.2 的扩展边界不能自动成为未来能力的授权。

## 兼容性、规模与可靠性目标

### 浏览器兼容性

- 桌面正式支持 Safari、Chrome、Edge 和 Firefox，移动端正式支持 iOS Safari 和 Android Chrome。
- 对上述浏览器滚动支持发布时最新两个稳定大版本；PRD 不固定会过期的具体版本号。

### 长期规模

- 产品设计和生产验收至少覆盖 5 年使用周期、20 万条消息、1 万个 Thread、50 万个 Run、100 个启用任务和 50 个 GitHub 仓库。
- 达到上述规模时，所有者仍必须能够使用核心对话、搜索、审批、任务、Memory、Trace、删除和迁移流程。

### 可感知性能

- 普通 Web 命令必须在 2 秒内明确确认接纳或拒绝，并返回可持续查询的稳定标识。
- 在线 GitHub 事件必须在 2 秒内完成持久接纳或明确拒绝。
- 在主机在线、预算未耗尽、模型和外部服务可用的前提下，普通 GitHub 事件的分析与注意力投递目标为 10 分钟内完成。
- 正常重启后，Web 查询和新消息必须在 2 分钟内恢复；任务必须在 5 分钟内恢复执行或展示明确阻塞原因。

### 长期运行

- v0.2 不承诺百分比可用性 SLA，但必须提供自动重启、健康状态、停机记录和明确的阻塞原因。
- 正式上线前必须通过连续 7 天运行验收，并验证对话、计划任务、外部事件、模型故障、重启和存储压力等关键路径。

## 验收边界

### 所有者初始化与公共访问

- 活动权威首次启动时，所有者从主机本地完成一次性初始化并绑定唯一外部身份；随后初始化入口关闭，所有公网人类访问都必须经过外部身份网关和多因素认证。
- 请求绕过身份网关、身份断言无效或映射到非所有者身份时，系统必须在请求进入私人控制面之前拒绝，并且不能调用模型或能力。
- 所有者丢失普通 Web 会话但仍具有主机访问和独立恢复凭据时，必须能够通过本地紧急恢复流程撤销产品会话、修复身份映射或关闭公网入口，并留下审计记录。

### 持久 Thread 与 Web 恢复

- 所有者通过 Web 发送消息且权威接受命令时，只能创建一个稳定 Run，并通过可恢复结果流返回增量内容和最终状态。
- Agent 服务、执行进程或整台活动主机正常重启后，所有者重新打开 Thread 时必须看到一致的历史消息、Run、Trace、审批、任务和收件箱；未完成工作从持久检查点恢复或展示明确失败状态。
- 浏览器离线时，Web UI 只保留未发送草稿，不得在本地接纳命令或审批；重连后恢复已经由权威接受的结果。
- Thread 被归档、压缩或稍后继续时，其身份、原始历史、可恢复摘要和仍有效任务必须保持一致。

### 自动与敏感 Memory

- 所有者说“我喜欢吃牛肉”，且该偏好被分类为高置信度非敏感长期信息时，当前 Run 完成后系统自动保存带来源、分类和版本的长期记忆，并以不打断对话的方式提示。
- 消息包含具有长期价值的敏感个人信息时，系统必须逐项展示候选并等待所有者批准、编辑或拒绝，不能自动保存正文。
- 所有者对某项敏感内容明确说“请记住”时，系统只把这一项视为已批准，其他敏感候选仍分别询问。
- 后台任务在所有者不在线时发现敏感信息，系统只保存最小加密来源引用，不保存提取后的敏感候选正文。
- 消息包含 API Key 或访问令牌时，机器秘密原值必须在记忆提取、模型调用和 Trace 写入之前被排除。
- 所有者在新 Thread 中提出与旧偏好相关的问题时，系统只检索相关的长期记忆或来源片段，并在 Trace 中记录引用。
- 所有者纠正或删除记忆后，产品活动版本、记忆后端、缓存和本地可恢复副本必须在既定期限内达到一致状态，旧内容不能重新激活。

### 风险与行动授权

- 一个行动满足低风险读取全部条件，且模型分类和确定性规则都允许时，系统可以在已有授权内执行并记录 Trace。
- 模型把包含不可逆删除、资金、凭据、生产、公开发布、法律或人身安全影响的行动评为较低风险时，只要确定性事实命中关键类别，最终风险就不得低于 `CRITICAL`，并且必须逐次确认。
- 已批准任务后来扩大目标、工具、费用、权限、数据范围或收件人时，新 Run 必须重新询问，不能沿用旧授权。
- 授权过期或能力被撤销后，后台任务再次触发时必须暂停并显示阻塞原因，不得自动改用其他能力。

### 正式能力

- Agent 读取或修改文件时，只能访问该主机上获批的目录和读写范围；永久删除和重要覆盖继续执行更高保护。
- Agent 在授权代码工作区运行已知构建、检查或测试命令，且命令保持在批准范围内时，可以自动执行；新命令、联网、依赖安装、系统操作或不可信脚本必须询问。
- Agent 进入存在未提交修改的代码工作区时，必须先展示现有修改并保留与任务无关的内容；任务与现有修改重叠时必须询问，不能擅自重置、暂存或提交用户改动。
- Agent 准备创建本地 Git commit 时，如果尚未展示完整 diff、验证结果和提交信息，就不得提交；即使本地提交获批，也不得自动 push。
- Calendar 事件包含其他参与人时，v0.2 必须拒绝修改参与人或执行会发送通知的更新。
- 受控认证 Web 会话准备提交表单、发消息、发帖、购买或修改账户时，相关行动必须进入正常风险分类和授权，不能因为已经登录而自动允许。

### 后台任务、离线与预算

- 同一任务已有活动 Run 并再次收到触发时，新触发必须合并，除非该任务明确获准安全并行。
- 主机离线时错过的周期计划保持跳过；错过的一次性任务显示 `MISSED`，主机恢复后不自动补跑。
- GitHub 或其他外部服务在主机离线期间产生事件时，集成恢复后不进行追赶或恢复对账，并在 Web UI 展示可能漏事件的覆盖缺口。
- 在线工作已经接受但预算耗尽且 Run 尚未执行时，工作进入有界 `BUDGET_BLOCKED` 队列或暂停询问，不能静默丢失。
- 任务被取消或超时且此前已经产生外部副作用时，Trace 必须保留真实副作用；任何补偿都作为新的独立行动重新授权。

### GitHub 在线监控

- 所有者连接私有仓库并启用监控前，Web UI 必须展示当前主要模型、服务商，以及排除机器秘密后整个仓库内容可以发送给该主要模型，并取得一次明确确认。
- 已配置仓库在线产生的有效事件通过来源和范围验证后，系统必须在 2 秒内持久接纳或明确拒绝，去除重复投递，并由模型判断相关性和注意力等级。
- 分析结果普通且不紧急时，Run 完成后结果进入 Web 收件箱，并保留仓库、事件、模型、授权和 Trace 来源，不产生 GitHub 写操作。
- 处理内容包含 GitHub 仓库数据且主要模型失败时，每次使用固定备用模型都必须单独询问，不能沿用非 GitHub 自动降级规则。
- 仓库权限撤销完成后，系统立即停止读取并删除本地镜像和缓存；历史内容按所有者选择保留或全部删除。

### 模型故障与受控降级

- 主要模型发生可重试故障，且固定备用模型已经批准、能力满足并且不会扩大当前非 GitHub 任务的数据披露时，系统可以切换并记录原因、身份、用量和费用。
- 备用模型扩大数据披露、缺少能力或不在批准边界时，主要模型失败后当前 Run 必须等待、失败或询问所有者，不能选择第三个模型。
- 模型失败前已经执行外部行动时，Run 恢复前必须先对账真实外部状态，再决定继续、补偿或询问。
- 两个生成模型都不可用且后台任务达到有限重试边界时，状态变为 `MODEL_BLOCKED` 并进入 Web 可见结果。

### 注意力与提醒

- 普通过程、周期汇总、一般结果、需处理失败和紧急事件必须分别使用 `SILENT`、`DIGEST`、`INBOX`、`NOTIFY` 和 `INTERRUPT` 的固定语义。
- 所有者把高频任务设为静默后，如果发生确定性安全事件、重大凭据失效或关键行动失败，系统仍可提升到安全下限要求的提醒等级。
- 浏览器离线时产生的 `NOTIFY` 或 `INTERRUPT` 必须持久保存，并在下次打开 Web UI 时优先展示，但不发送站外消息。
- 周期反思产生大量重复建议时，进入结果系统前必须进行语义去重，并遵守默认每日 3 条新建议上限。

### 删除、存储压力与整机灭失

- 所有者普通删除 Thread、任务或记忆后，内容立即退出上下文、检索和执行并进入 7 天 Trash，除非所有者选择立即永久删除。
- Thread 存在活动任务时，Web UI 必须在删除前列出任务并要求取消、暂停或重新绑定。
- 永久删除完成后，原始内容立即在产品状态、后端索引和缓存中失活，并在 30 天内退出所有本地可恢复副本。
- 存储空间严重不足、系统无法安全接纳高容量写入时，必须停止新的高容量工作并保留只读、机器迁移和人工清理能力，不自动删除所有者数据。
- 活动权威主机及其存储完全损毁且没有可用本地数据时，v0.2 不承诺恢复；该风险是本版本明确接受的产品边界。

### Mac 与 Hermes 迁移

- 所有者从当前活动的 Mac 或 Hermes 发起迁移时，源权威必须停止接纳新工作并形成经过验证的加密迁移包，目标在所有检查通过前不得激活。
- 目标主机缺少源主机机器秘密和主机绑定目录授权时，导入完成后系统必须列出需要重新配置的能力，不能从迁移包恢复秘密原值。
- 目标验证通过并激活、公共入口完成切换后，Agent、所有者、Thread、Run、Memory、任务和授权的产品身份必须保持一致，源部署保持不可启动。
- 目标激活后 7 天内需要回切时，所有者必须执行新的反向迁移，不能直接启动源副本；7 天到期后源产品数据删除。

### 生产上线

- v0.2 可以分阶段开发和内部试用，但只有本 PRD 中所有“本版本包含”的能力、安全规则、数据保护、兼容性目标和关键验收路径全部通过后，才能标记为 v0.2 生产版。
- Mac 与 Hermes 必须分别通过完整验收；只在一个平台通过不能视为 v0.2 完成。
- 发布时正式浏览器矩阵必须覆盖最新两个稳定大版本，关键流程必须达到 WCAG 2.2 AA 目标。
- 上线前必须在目标长期规模下验证核心流程，并完成连续 7 天运行验收。
