# 如实显示前台 Bash 脱离后仍运行的后台程序

## 期望结果

前台 Bash 自行脱离进程组的后台程序仍然存活时，控制中心应如实表达可知的运行状态，避免向用户断言“没有程序在运行”。

## 来源与现象

[ADR 0040 决定第 4 条](../adr/0040-background-output-closed-after-bash-returns.md#decision) 和 [ADR 0033 决定第 5 条](../adr/0033-process-sandbox-default-and-optional-containers.md#decision) 要求用户看清后台程序，同时将当前列表缺口列为已知限制。[SOURCE: docs/adr/0040-background-output-closed-after-bash-returns.md] [SOURCE: docs/adr/0033-process-sandbox-default-and-optional-containers.md]

[stop-22 只读核查](../../.ci-output/handoff/2026-09-28-codex-round2-stop-22.md#页面能力与待完成验收) 与当前 SQL 一致：`packages/persistence-sqlite/src/sqlite-sandbox-execution-operations.ts:387` 的 `listRunningPrograms` 仅查询 `background/service`、已经启动且未释放的登记作业。`packages/application/src/services/thread-execution-environment.ts` 据此生成状态；`apps/control-center/src/i18n/resources/zh-CN.ts:174` 的空列表文字是“没有程序在运行”。前台 Bash 自行脱离的后代没有单独登记，因此列表为空不能证明操作系统中没有程序存活。

## 实测证据与影响

在 `59880a5` 的 B3 Mac 验收中，[释放后截图](../../.ci-output/tool-execution-audit/2026-09-28/round2/b3-r27-layer4-mac-2/33-detached-output-after-release.png) 显示上述空列表文字，但[独立读回摘要](../../.ci-output/tool-execution-audit/2026-09-28/round2/b3-r27-layer4-mac-2-summary.json) 同时记录 `childAliveBeforeFixtureCleanup: true`。原进程组已经释放、脱离的 Perl 仍存活，夹具之后才清理它。用户可能因此误以为后台没有程序，也无法从列表查看这个程序。

## 可能方向与约束

可研究由 Worker 报告脱离的进程，或调整状态行文字，明确只描述已经登记的程序而不对主机全部程序作断言。这里只记录方向，不选择进程发现、管理或 UI 设计方案。后续验收需同时核对真实进程存活和页面状态，不能以列表为空或夹具清理成功代替产品能力。
