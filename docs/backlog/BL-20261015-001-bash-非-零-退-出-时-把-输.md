# bash 非零退出时把输出连同未核实提醒交给模型

## Summary

用户 G109（2026-10-15）同意：bash 命令以非零退出码结束时，模型现在只看到“命令执行失败…请先检查工作区”，看不到标准输出和标准错误，测试失败等情况无法排错。改为把有界的输出连同“效果未核实”的提醒一起交给模型。现行设计见 [SRT 统一执行设计](https://github.com/sixianli/himawari-agent/blob/208007462f99e16c5c8cd4daac2acc10fa9f5f36/docs/execution/specs/2026-09-07-srt-unified-execution-design.md)（第 423 行附近），需先修订该规格。按 G109 第 1 项，不进第四次生产变更，排在第五次。

- 2026-10-15 第 29 批补充：命令运行中超过命令输出上限（`maxOutputBytes × 64`，生产 3 MiB）而被产品结束的命令，退出码同样非零，届时一起处理——把 Pi 已经保留的结尾（`packages/runtime-pi` 复用 Pi 的截断与说明）连同“效果未核实”的提醒交给模型；非前台模式（`apps/agent-service/src/capability-programs/pi-coding-main.ts` 的累计缓冲与每段全文机密扫描）也在那时一起改。第 29 批只做“提高结束命令的门槛”，见 [ADR 0054 的 `#model-output-limit` 补充](../adr/0054-readonly-tools-in-host-and-reused-task-sandbox.md#model-output-limit)。
- 2026-10-16 R2-T14 实现前台部分：非零退出、超时、超过命令输出上限都把 Pi 保留的输出结尾交给模型（前台 runner 目前不把取消信号传给 Pi，取消不走这条路径），Agent 先核对 runner 写出的结果，再在最前面加 `effectNotice` 提醒；输出含机器秘密时交出一份不含正文的结果，并保留命令真实的退出码；2026-10-17（G127）起只剩开头行或结尾行的私钥片段也按命中处理。规则见 [SRT 统一执行设计的 R5 实现说明](https://github.com/sixianli/himawari-agent/blob/208007462f99e16c5c8cd4daac2acc10fa9f5f36/docs/execution/specs/2026-09-07-srt-unified-execution-design.md#r5-实现说明2026-09-09) 和 [ADR 0054 的 2026-10-16 补充](../adr/0054-readonly-tools-in-host-and-reused-task-sandbox.md#failed-command-output)。上一条说的“非前台模式也一起改”没有做：现行生产绑定下模型调不到后台和服务模式，改记在 [BL-20261016-003](BL-20261016-003-后-台-和-服-务-模-式-的.md)。
