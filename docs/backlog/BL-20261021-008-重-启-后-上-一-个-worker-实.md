# 重启后上一个 Worker 实例留下的常驻进程是否主动结束

## Summary

D-53 修复后，服务重启时任务环境里已绑定调用的停止未确认会按 1/2/4/8/16/30 秒退避重试，等旧的常驻任务宿主（Job Host）因 Worker 心跳中断自己退出后再释放。旧进程被冻结或卡死时，重试一直按 30 秒进行、工作区一直被占用，只能管理员处置。要决定是否让新 Worker 实例按记录的进程号和启动时间核对身份后主动结束上一个实例留下的 Job Host、常驻进程组和命令进程组（ADR 0054 第 146 行目前只要求确认它们消失），以及是否给重试设总时长上限后转人工。

- Captured directly.

## Notes

- Add evidence, constraints, and decisions here as the item is reviewed.
- 2026-10-22 opencode 审核 D-53 时提出的相关问题：任务环境的已绑定记录只在原因是 `SANDBOX_TASK_ENVIRONMENT_STOP_UNCONFIRMED` 时重试；如果某次重试换成别的暂时原因（例如整个核查到期 `SANDBOX_RECONCILIATION_TIMED_OUT`），记录仍暂停等人工。这是 D-53 有意的取舍（[ADR 0054 的 2026-10-21 补充](../adr/0298-where-tools-run.md)），与本条一起决定是否扩大。
- 2026-10-22 D-56：上一次核查因服务关闭或派发循环失败被中止（`SANDBOX_RECONCILIATION_INTERRUPTED`）的已绑定记录，现在下次启动后再核查一次，不论后端（[ADR 0054 的 2026-10-22 补充](../adr/0298-where-tools-run.md)）；整个核查到期 `SANDBOX_RECONCILIATION_TIMED_OUT` 等其他暂时原因仍暂停，仍按本条决定。
- 同一审核的另一条：资源恢复调度用 `sandboxBackendKind` 判断后端，`srt` 以外的后端标识一律算任务环境；以后增加第三种后端时，要复核它的已绑定记录是否也该按这条规则重试。
