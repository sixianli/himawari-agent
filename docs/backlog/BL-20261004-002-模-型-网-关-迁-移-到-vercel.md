# 模型网关迁移到 Vercel AI Gateway

## Summary

按 ADR 0048 把生成模型和 Memory 嵌入模型从 OpenRouter 迁到 Vercel AI Gateway：改描述符和配置、删掉 OpenRouter 专有字段、核对用量和费用回读、更新测试、Runbook 和架构文档；用户G34–G38已决定在上线前迁移；文本模型只用`deepseek/deepseek-v4.1-flash`，去掉GLM备用，嵌入模型用`alibaba/qwen3-embedding-8b`，服务商路由按下文均衡方案执行。

## Origin

- 2026-10-04 用户原话：“之后这个项目不在使用openrouter ,而是使用vercel作为 ai gateway”。决定见 [SOURCE: docs/adr/0048-vercel-ai-gateway-replaces-openrouter.md]。

## Notes

- 历史记录（2026-10-04，见ADR 0048；不作为本次迁移验收）：Pi 0.84.2 的 `openai-completions` 接口指向 `https://ai-gateway.vercel.sh/v1`，用 `openai/gpt-6-astra` 流式输出成功（细节见 ADR 0048 的“已验证的事实”）。开发密钥在 Mac 钥匙串，服务名 `himawari.ai-gateway.dev`。
- 要改的地方（2026-10-04 用 `git grep -il openrouter` 找到）：
  - `packages/runtime-pi/src/configured-model-binding.ts`：描述符里写死的 `provider: "openrouter"`、OpenRouter 地址和 `providerRouting` 字段；
  - `packages/runtime-pi/src/pi-model-transport.ts`：`openrouter_metadata` 的旁路读取和 `OPENROUTER_*` 错误码；
  - `apps/agent-service/src/production-model-composition.ts`、`production-memory-composition.ts` 和 `packages/memory-mem0/src/index.ts`：生成模型和嵌入模型的组合；
  - 相关单元测试、集成测试、`test/fixtures/product-path-harness.ts`、`ci/policy.json`、`scripts/operations/` 下的比较脚本；
  - 架构文档、`install-start-stop` 和 `hermes-control-center-upgrade` 两份 Runbook，以及 README。
- 用户 2026-10-04 已决定（见 ADR 0048 补充决定）：排在上线前；禁止使用 OpenAI 模型，文本模型只用 `deepseek/deepseek-v4.1-flash`，去掉现有的 GLM 备用。嵌入模型沿用 Qwen3 Embedding 8B（网关编号 `alibaba/qwen3-embedding-8b`）。长任务里对应条目 R2-L5。
- `deepseek/deepseek-v4.1-flash` 单次最多输出 32768 token，比现在的 DeepSeek V4 Flash（384000）小，迁移时要核对产品的 `maxTokens` 和输出截断处理。
- 生产密钥的创建和写入生产服务器，需要用户为那次部署单独授权。

## 路由方案分析（2026-10-04）

用户 2026-10-04 已选择：方案 2（均衡），并且不限制训练数据条款（不发送 `disallowPromptTraining`）。决定见 ADR 0048 的“服务商路由”补充决定。下面保留选择前的分析。

用户要求：“我希望vercel能进行合理路由，目的是达到性价比最高”。同一个模型 `deepseek/deepseek-v4.1-flash` 在网关上有 18 家服务商（实际运行模型的公司），价格、速度、隐私条款各不相同；路由就是决定每次请求先交给哪一家、失败时换哪一家。

### 网关提供的能力（Vercel 官方文档，2026-10-04 读）

- `providerOptions.gateway` 里的 `order`（先试哪几家）、`only`（只许用哪几家）、`sort`（按 `cost` 估算费用、`ttft` 首字延迟或 `tps` 每秒输出 token 数排序）。`order` 和 `sort` 同时给时，`order` 里的服务商排最前，其余按 `sort` 排；健康状况变差的服务商会被往后排，宕机的排最后。
- `disallowPromptTraining: true`：只交给承诺不拿请求内容训练模型的服务商，所有套餐免费可用。`zeroDataRetention: true`（服务商不保留数据）要 Pro 及以上套餐，团队 `andy-home` 现在是免费的 Hobby 套餐，用不了。
- 非流式响应里，路由结果在 `choices[0].message.provider_metadata.gateway`（`routing.finalProvider`、`routing.sort.executionOrder`、`cost` 等），`usage.cost` 是这次请求的实际费用。

### 实测（2026-10-04，在 Mac 上发了一次请求，未跑 Himawari 测试）

- 请求带 `disallowPromptTraining: true` 和 `sort: "cost"`：网关从 18 家筛到 12 家，按 relace → morph → wafer → deepinfra → alibaba → runware … 的顺序尝试，由 relace 返回，实际费用 0.0000045 美元。
- 这个顺序和各家的输入单价顺序完全一致，而 `metrics` 里每家的估算值都显示为 0。推断（未经文档证实）：网关的“按费用排序”主要看输入单价，没有按 Agent 实际用法（长提示词、大部分命中缓存）计算，所以它选的 relace 不是我们用法下最便宜的。
- Pi 0.84.2 的 `openai-completions` 自带的 `vercelGatewayRouting` 只会发送 `only` 和 `order`；`sort` 和 `disallowPromptTraining` 可以通过 Pi 已有的 `onPayload` 钩子（发请求前改请求体的回调）加进 `providerOptions.gateway`，不需要改 Pi 或另写请求协议。Pi 在开启会话亲和时会带 `x-session-affinity` 请求头，让同一个 Run 的请求尽量落在同一台机器上、提高缓存命中。

### 按 Agent 用法估算的每轮费用和速度

假设一轮的提示词 3 万 token，其中 85% 命中缓存，输出 800 token；价格、首字延迟和输出速度取自 2026-10-04 网关清单（速度是最近一小时的中位数，会变化）。只列不训练数据、且价格靠前的几家：

| 服务商 | 每轮费用（美元） | 生成 800 token 约需 | 说明 |
| --- | --- | --- | --- |
| morph | 0.00061 | 16 秒 | 最便宜，但输出慢（约 51 token/秒）；单价远低于同行，可能是促销价 |
| deepinfra | 0.00107 | 10 秒 | fp8 量化（用较低精度运行，可能略影响质量） |
| relace | 0.00108 | 15 秒 | 网关 `sort: "cost"` 实际选中的那家 |
| runware | 0.00141 | 4.4 秒 | 费用约为 morph 的 2.3 倍，速度约快 3.7 倍 |
| parasail | 0.00246 | 5.5 秒 | |
| togetherai | 0.00246 | 3.5 秒 | fp8 量化 |

另外两点：alibaba 在 UTC 0:00–14:00（北京时间 8:00–22:00）价格翻倍；DeepSeek 官方不在“不训练数据”名单里，开启 `disallowPromptTraining` 后不会用到它。

### 可选方案

1. 最省钱：`disallowPromptTraining: true`，`order: [morph, relace, deepinfra]`，其余按 `sort: "cost"` 兜底。每轮约 0.0006 美元，但每轮要多等十几秒。
2. 均衡（Claude 推荐）：`disallowPromptTraining: true`，`order: [runware, deepinfra, morph]`，其余按 `sort: "cost"` 兜底。每轮约 0.0014 美元，速度快 3 倍以上；按每天 1000 轮算，一天约 1.4 美元，比方案 1 多 0.8 美元。
3. 全交给网关：`disallowPromptTraining: true` 加 `sort: "cost"`。不用维护名单，价格变化时会自动调整；但按实测，它选的服务商又慢、也不是最省钱。

不管选哪个方案：服务商名单写在产品配置里，不写死在代码中；迁移那一批要用一个小规模的工具调用测试比较首选的几家，确认量化和低价服务商的工具调用质量；预算准入按名单里最贵那家的单价估算，结算以 `usage.cost` 为准。

## 2026-10-06迁移准备

前序Linux资格批次的结果见[工具执行审计计划](../execution/plans/2026-09-28-tool-execution-audit-plan.md#linux-qualification-final-20261006)。本项沿用用户已经选定的模型和路由，不重新选择模型。先通过既有Pi `ModelRuntime`的流式接口和Mem0 `OpenAIEmbedder`检查可重复的模拟响应；随后准备在Hermes核对真实流式费用和服务商工具调用质量。离线检查只能证明探测输入、解析和停止条件，不能证明真实费用字段或服务商质量。把Mac开发密钥传到Hermes内存以及真实付费调用，须按[交接文件第五节](../../.ci-output/handoff/2026-10-04-claude-to-codex-handoff.md#ask-user)单独取得用户授权。

迁移实现须保留原模型请求身份、预算预约和未知结果保护，禁止隐藏重试及业务工具重放；文本和嵌入结算都核对网关实际费用。R2-L5最终验收仍用原标签测试及自审，并在迁移最终版本执行规定完整测试和Linux资格；容器停止、tooling及归档用例的独立当前版本检查一起执行。

## 迁移边界自审发现（2026-10-06）

嵌入响应返回后仍要等待权威检查：等待期间取消或原期限到达时，原代码没有在结算前再次核对，仍返回成功。两项自动测试在Hermes均复现。文本请求另有配置上限被调用选项覆盖的问题：配置32 token时发送32768，参数化测试复现。方案在迁移设计及长任务决定中记录；按原信号、期限和配置上限修复，不增加重试、预算或时限。最终验收以同一组测试与公开入口读回为准。
