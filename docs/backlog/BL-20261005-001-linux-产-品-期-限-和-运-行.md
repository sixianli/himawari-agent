# Linux 产品期限和运行中重启夹具按外层进程组查找任务

## 问题与目标

Linux 产品期限和运行中重启场景按外层进程组编号（PGID）查找实际工具，未识别进入独立 PID 命名空间的任务。目标是使用原 Host 子孙、原命名空间及准确命令参数识别任务，并在清理后独立核对原进程号加启动时间身份消失、命名空间为空；不能只以外层进程组消失代替实际任务退出。

## 依据与范围

S3 的原 Worker 期限场景在原 60000 毫秒查找 `/bin/sleep 600` 时失败，期限与认证清理断言尚未进入。同版本的执行中重启场景也在查找 `/bin/sleep 120` 时失败。Hermes 的独立 `/proc` 读回确认原 Host 为 `223047`，记录的外层 PGID 为 `223407`，实际任务 `223652 / 745242818` 的 PGID 为 `223415`，且任务是原 Host 子孙并位于原 PID 命名空间中。旧匹配清单为空。

失败报告、日志、trace、冻结期限、状态归档与进程读回保留于 `.ci-output/tool-execution-audit/2026-09-28/round2/hermes-r64/independent-product-01/`，Hermes 同名目录位于 `/data/hermes/himawari/tool-audit-round2/r30/evidence/r64/`。这是测试平台查找缺陷，红报告不能证明产品期限终止失败。目标属于既有 R2-S2、R2-S3，不新增用户行为或产品功能。

## 修正方案与检查

复用 S1 的现有 `readLinuxJobProcesses()`，以原 Host 身份、原命名空间、准确 argv 和进程启动时间识别实际任务。Linux 期限与执行中重启场景保留原 60000 毫秒等待，并增加原任务身份消失、命名空间 init 身份消失、命名空间成员为空、状态为 released 和 Host 自身组为空的独立断言。macOS 的原进程组路径保持，Mac 验证仍无限期推迟。

原期限、预约释放证明、结果一次交付、无重放和冻结计划相等断言保留。没有产品代码、依赖、协议或迁移改动。S2 原离线恢复和执行中重启使用 `[R2-S2]`；S3 的 Worker、恢复、Run 三种期限场景使用 `[R2-S3]`。精确命令、运行结果与证据 ID 由 longtask.py 记录；在定向场景和不筛选资格实际通过前不写完成结果。

首次修后五项串行运行有三项通过、两项失败。恢复场景汇总到 `[1,1]` 而非 `[1]`，Run 期限场景汇总到先前的两次工具回复而非空清单。原因是三种期限使用同一提示词，`observedToolMessages()` 从整个安装的历史模型请求里按提示词查找，混入了先前场景。数据库读回分别只有一次期限结果或 Run 失败，不支持产品重复交付结论。修正让原提示词带上当前 mode，保留所有历史请求和原数量断言；两项尚未到达的新进程退出断言必须重新实际执行。失败报告为 `E20261005T152954-d91bc6`，现场保留在上述同名目录。

第二次同五项运行的S3三期限和S2离线恢复通过，运行中重启在确认进程退出后收到一次LOST，旧“没有回复、点击停止、零交付”断言失败。独立SQLite确认只有一次启动、一个确定结果、一条释放回执和一次交付，最终Run为completed；这符合既有成对恢复合同，旧测试与自动恢复竞争。用户G41批准替换这部分断言：重启前无结果与交付；重启后唯一规定LOST正文、Run完成、operation和intent各一条、原输出结束块仍为零；二次成对重启不重复。进程退出、认证释放和原40秒/30秒等待保持。失败证据E20261005T155521-d762d6和rejected自审E20261005T155716-4a8df6保留；替换后的通过结果仍须实际执行。
