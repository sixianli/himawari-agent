# P5账号录入未在输入时校验用户名和密码

## 期望结果

使 P5 账号录入按产品合同检查用户名和密码，并在录入阶段给出不包含输入值的具体错误，避免用户直到 account create 才收到笼统的 IDENTITY_LOGIN_REJECTED。

## 来源与证据

来源为 Claude 在生产服务器上读回后编写的[生产沙箱修复简报](../../.ci-output/handoff/2026-10-08-codex-prod-sandbox-brief.md)“记录但本批不修”部分。Codex 本次只在 Mac 上登记文档，没有连接生产服务器、读取生产秘密或重跑生产命令。

Claude 报告生产 P5 脚本未做上述输入检查，用户实际失败两次。静态代码确认 packages/platform-node/src/built-in-identity.ts 的用户名会 trim 并转为小写，随后要求匹配 ^[a-z0-9][a-z0-9._-]{2,63}$；密码要求 12–128 个字符且 UTF-8 字节数不超过 1024。

## 后续范围与约束

后续输入检查应与产品规则一致，覆盖长度边界、用户名首字符和字符集、Unicode 密码字符数及字节数。检查不得把用户名、密码或第二因素输出到日志或对话。
