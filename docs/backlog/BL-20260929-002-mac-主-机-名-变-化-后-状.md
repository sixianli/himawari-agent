# Mac 主机名变化后状态目录旧锁阻止自动恢复

## 期望结果

Mac 常驻服务异常退出后，即使系统主机名发生变化，也能在核实属于同一台机器、原进程已退出且没有其他实例持有状态目录后，安全恢复服务。无法证明这些事实时继续拒绝接管。

## 现象与影响

工具执行审计的真实 Mac 产品测试在 Agent 与 Worker 同时退出后重启。新 Agent 以 `SQLITE_STATE_ROOT_LOCKED` 退出，尚未进入工具结果恢复。锁记录主机名为 `MacBookAir`，当前 Node 主机名为 `Li-MacAir.local`，原 PID 已不存在。现行锁条件对主机名不一致直接拒绝，与 PID 是否退出无关。

Claude 在 reply-8 接受其为环境导致的启动阻塞，并要求登记为 Mac 常驻服务风险：异常退出留下旧锁后，主机名变化可能使自动重启持续失败，需要人工处理。HostName 未设置时网络变化是需要考虑的触发条件；本次没有保存主机名变化的系统事件，不能声称已证明网络切换是历史变化的原因。

## 可能方向与边界

考虑用稳定的本机标识替代主机名进行同机判断，并结合可核验的进程身份，区别原进程、PID 复用、其他实例和其他机器。具体身份来源、旧格式处理、异常关停与并发接管规则需要独立设计和审阅；不能仅因 PID 不存在而接管其他主机的状态。

本轮只记录风险，保持现有锁检查，不实现旧锁接管，不改锁数据形状。方案 B 的结果耐久性验证与此项未来工作分别提交和报告。
