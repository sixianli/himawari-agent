# 能力目录的完整性摘要在换 runner 后与实际不符，需要经主人审核的能力升级入口

## Summary

第四次生产变更（R2-L10，候选 4c705133）有意改了 Pi 和搜索两个 runner（runner：在沙箱里执行工具的程序），新 runner 的 SHA 与数据库能力目录里登记的不同。产品没有能力升级命令：capabilities register 把任何声明变化都当作需要重新审核（apps/admin-cli/src/capabilities-command.ts:41–51），所以用户按 G121、G122 批准不重新登记，只在操作包里放宽“runner 必须等于登记值”这一条：新声明的 integrity 和 artifact.digest 必须指向新 runner 的真实 SHA 并由主机资格密钥签名，除这两个制品摘要外的声明字段必须与登记一致，数据库登记记录和 integrity 列保持 S0 时的值（见第四次变更操作包 signing/catalog-binding-report.md）。结果是上线后数据库和管理界面显示的能力完整性摘要仍是旧 runner 的值，与实际运行的不一致；运行时的记录和绑定来自签名快照，不读这个旧值，所以不影响执行，但会误导查看管理界面的人，下一次换 runner 的部署也要重复这套放宽。要做的是给产品补一个能力升级入口：主人审核新旧声明差异（应只有制品摘要变化）后，原子地更新登记记录和 integrity 列，保留审计记录；之后部署包恢复“runner 等于登记值”的严格检查。
