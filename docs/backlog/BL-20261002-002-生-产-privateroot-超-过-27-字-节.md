# 生产 privateRoot 超过 27 字节时沙箱工具调用必然失败，但启动时不检查

## 期望结果

Linux 生产配置中的 `privateRoot`（存放每个沙箱任务私有数据的目录）一旦长到会让产品自己的 Unix 套接字（同一台机器上进程间通信用的特殊文件）超出长度上限，产品在读配置或启动时就明确拒绝，并说明上限；首次生产部署选用的 `privateRoot` 满足这个上限。

## 来源与现象

第二轮在云服务器上运行产品路径测试时，测试夹具发现临时根过长（见 [ADR 0045 的背景](../adr/0045-short-test-temp-root.md#context)）。Claude 按同样的算法核对生产路径，得到以下结果：

- 产品给每个任务设置 `TMPDIR=privateRoot/<任务编号>`：`apps/execution-worker/src/production-sandbox-execution-v2.ts:963`、`packages/runtime-sandbox/src/job-host.ts:94`。
- 任务编号是 `j` 加 SHA-256 的 base64url 编码，共 44 字节：`apps/agent-service/src/production-sandbox-services.ts:97`。
- 沙箱运行时 SRT（`@anthropic-ai/sandbox-runtime`，负责隔离网络）在 `tmpdir()` 下建 `claude-socks-<16 位十六进制>.sock`：`node_modules/@anthropic-ai/sandbox-runtime/dist/sandbox/linux-sandbox-utils.js:435-440`。
- 合计比 `privateRoot` 多 80 字节。Linux 套接字路径最多 107 字节，所以 `privateRoot` 不能超过 **27 字节**。产品自己的控制套接字（`privateRoot/control-<20 位>/control.sock`，上限 100）只要求不超过 58 字节，SRT 这一条更紧。

## 已知与未知

- **已确认（代码）**：上面的路径组成和长度；在 `packages/` 和 `apps/` 的生产代码中，没有找到在配置或启动阶段检查 `privateRoot` 长度的代码。
- **推断，未验证**：配置了超过 27 字节的 `privateRoot` 时，Linux 上每次沙箱工具调用都会在 SRT 建立网络桥时失败；失败时的具体报错和是否被产品正确归类为沙箱错误，没有实际运行验证。
- **未知**：首次生产部署将选用的 `privateRoot`。部署计划目前暂缓，没有选定路径；例如 `/var/lib/himawari/jobs` 为 22 字节，满足上限。
- macOS 的套接字上限更小（103 字节），对应的 `privateRoot` 上限是 23 字节；Mac 验证已无限期推迟，未核对 Mac 上 SRT 的套接字位置。

## 方向

在产品读取能力安装声明中的 binding 时，按产品已知的最长套接字路径核算 `privateRoot`，超出就以明确错误拒绝配置；先写复现测试（用超长 `privateRoot` 的配置），证明它目前要到工具调用时才失败。首次生产部署计划写明 `privateRoot` 的选择和这条上限。

## 排期

第二轮“已发现缺陷全部修完”范围内（排查编号 D18），排在当前批次之后；首次生产部署之前必须完成。
