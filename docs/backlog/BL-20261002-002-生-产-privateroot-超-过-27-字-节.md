# 生产 privateRoot 超过 27 字节时沙箱工具调用必然失败，但启动时不检查

## 期望结果

Linux 生产配置中的 `privateRoot`（存放每个沙箱任务私有数据的目录）一旦长到会让产品自己的 Unix 套接字（同一台机器上进程间通信用的特殊文件）超出长度上限，产品在读配置或启动时就明确拒绝，并说明上限；首次生产部署选用的 `privateRoot` 满足这个上限。

## 来源与现象

第二轮在云服务器上运行产品路径测试时，测试夹具发现临时根过长（见 [ADR 0045 的背景](../adr/0045-short-test-temp-root.md#context)）。Claude 按同样的算法核对生产路径，得到以下结果：

- 产品给每个任务设置 `TMPDIR=privateRoot/<任务编号>`：`apps/execution-worker/src/production-sandbox-execution-v2.ts:963`、`packages/runtime-sandbox/src/job-host.ts:94`。
- 任务编号是 `j` 加 SHA-256 的 base64url 编码，共 44 字节：`apps/agent-service/src/production-sandbox-services.ts:97`。
- 沙箱运行时 SRT（`@anthropic-ai/sandbox-runtime`，负责隔离网络）在 `tmpdir()` 下建 `claude-socks-<16 位十六进制>.sock`：`node_modules/@anthropic-ai/sandbox-runtime/dist/sandbox/linux-sandbox-utils.js:435-440`。
- 合计比 `privateRoot` 多 80 字节。Linux 套接字路径最多 107 字节，所以 `privateRoot` 不能超过 **27 字节**。产品自己的控制套接字（`privateRoot/control-<20 位>/control.sock`，上限 100）只要求不超过 58 字节，SRT 这一条更紧。

<a id="socket-budget"></a>
## 按平台核算套接字预算

以固定依赖 SRT 0.0.75 为准，Job Host 设置 `TMPDIR=privateRoot/<44 字节任务编号>`。`policy.ts` 生成的网络配置没有外部 `httpProxyPort` / `socksProxyPort` 或 `tlsTerminate`；`job-host-main.ts` 只追加上游 `parentProxy`，并调用 `manager.initialize(configuration, undefined, false)`。

`parentProxy` 是本地代理的上游地址，并不等同于外部代理端口。SRT 的 `sandbox-manager.js` 只有两个外部端口同时存在才跳过本地 mux；Linux 的 HTTP/SOCKS 桥由 Linux 分支创建，Mac 不创建这两条路径。TLS 终止代理需要显式 `tlsTerminate`，日志监视套接字需要 Linux 且 `enableLogMonitor=true`，本产品都未启用。

| 套接字路径（R 代表 privateRoot，J 代表 44 字节任务编号） | 实际启用平台 | R 之后的最长字节数 | 套接字上限 | R 预算 |
| --- | --- | --- | --- | --- |
| `R/J/claude-http-<16 位十六进制>.sock` | Linux | 79 | 107 | 28 |
| `R/J/claude-socks-<16 位十六进制>.sock` | Linux | 80 | 107 | **27** |
| `R/J/srt-mux-<pid>-<36 进制序号>.sock` | Linux / Mac | 68 / 66 | 107 / 103 | 39 / **37** |
| `R/control-<20 位十六进制>/control.sock` | Linux / Mac | 42 | 100 | 58 |

以下 SRT 路径已核对创建条件，但不参与本产品当前预算：`R/J/srt-tt-<pid>-<36 进制序号>.sock` 在启用 TLS 终止时创建，最长偏移 Linux 77 / Mac 75 字节；`R/J/srt-obs-XXXXXX/s<8 位十六进制>.sock` 仅在启用 Linux 日志监视时创建，偏移 75 字节，其中 `XXXXXX` 为 `mkdtempSync` 的 6 位后缀。配置条件变化时必须重新复核此表。

可变字段依据：

- J 为 `j` 加 32 字节 SHA-256 的 base64url 编码，共 44 字节；桥的标识由 `randomBytes(8).toString("hex")` 产生 16 位，控制目录由 10 字节随机数产生 20 位，监视套接字由 4 字节随机数产生 8 位。
- Linux PID 按理论上限 4194304 预留 7 位；Mac 按 `PID_MAX=99999` 且分配时排除上界，最大 99998，预留 5 位。依据分别为 [Linux 的 PID_MAX_LIMIT](https://raw.githubusercontent.com/torvalds/linux/master/include/linux/threads.h)、[XNU 的 PID_MAX](https://raw.githubusercontent.com/apple-oss-distributions/xnu/main/bsd/sys/proc_internal.h) 和 [XNU PID 分配分支](https://raw.githubusercontent.com/apple-oss-distributions/xnu/main/bsd/kern/kern_fork.c)，核对日期 2026-10-02。
- mux 的 `backendSeq` 在每个新进程从 0 开始。产品每次 `prepareSandboxJobHost` 都新建进程；`job-host-main.ts` 的 `JOB_HOST_SESSION_REPLACED` 校验拒绝第二次 prepare，唯一的 `manager.initialize` 只执行一次。SRT 的 `initializationPromise` 防止重复初始化，`startMuxProxyServer` 只调用一次 `listenHttpBackend`。因此本产品的 mux 序号固定为 `0`，最长 **1 字节**；Mac 路径偏移为 `1 + 44 + 1 + 8 + 5 + 1 + 1 + 5 = 66`，根目录预算 `103 - 66 = 37`。此预算依赖现有的一任务一进程、一次初始化约束；该约束改变时必须同时复核。
- TLS 的 `sockSeq` 按连接增加，本产品未启用该路径；表外的 TLS 长度分析保守预留 `Number.MAX_SAFE_INTEGER.toString(36)` 的 11 位，覆盖 Number 从 0 逐次加一至 `2**53` 后不再增长的长度，不把此未启用路径用于当前预算。

源码入口：`mux-proxy.js:19–22`、`tls-terminate-proxy.js:493–496`、`linux-violation-monitor.js:34–35`、`linux-sandbox-utils.js:435–440`，启用条件见 `sandbox-manager.js:437–482, 683–716`；产品配置见 `packages/runtime-sandbox/src/policy.ts` 与 `job-host-main.ts:287–311`，控制接口限制见 `job-host-control.ts:78`。

## 已知与未知

- **已确认（源码和配置加载复现）**：Linux 的最紧路径及 27 字节结论成立。初版 `7ce0b57` 把仅 Linux 存在的桥套接字用于 Mac，错误拒绝 Mac 的 24–37 字节配置。返工按 Mac 实际 mux 路径及当前一次初始化的约束计算，Mac 上限为 37 字节。
- **推断，未验证**：Linux 超过 27 字节时，SRT 建网络桥会超出路径限制。具体工具调用报错及产品归类没有用真实超长套接字运行验证。
- **未知**：首次生产部署选用的 `privateRoot`，部署计划暂缓；例如 `/var/lib/himawari/jobs` 为 22 字节，满足 Linux 上限。
- Mac 结论来自 SRT 0.0.75 和产品源码阅读；配置边界测试在 Hermes 模拟平台参数，**未在 Mac 上验证**套接字创建和沙箱行为。

## 方向

能力安装声明读取器在返回 sandbox binding 前，由路径组成部分计算实际启用套接字的预算，取最紧一项。超过上限以 `CAPABILITY_DEPLOYMENT_INVALID_VALUE` 拒绝，消息写明 privateRoot 实际字节数、允许上限、决定预算的套接字及其长度。UTF-8 字节数用于核算，配置格式不变，不写死 27 字节结论。测试覆盖两平台的 ASCII / 中文边界通过、加一字节拒绝，以及多个套接字同时超长时仍报告最紧预算。
