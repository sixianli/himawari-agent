# 服务重连资格场景没有建立要恢复的读取结果

## 问题与目标

不筛选 Linux 产品路径资格的最后重连场景已恢复连接，但原 notes.txt 内容断言失败；失败页面是前一写入场景的 hello.txt 结果。目标是在本场景新对话中建立并确认原 notes 读取结果，再保留原重启、内容恢复和继续发送断言及原时限。

## 失败证据与原因

2026-10-05 不筛选资格最后的服务重连场景通过了离线显示和连接恢复检查，随后在原5000毫秒等待中找不到 `notes.txt` 的规定内容。失败页面仍显示前一个交付崩溃写入场景的 `hello.txt` 结果；当前场景没有读取notes，也没有保证其结果在当前对话出现。完整报告为 `E20261005T182246-c9b804`，命令退出1记录为 `E20261005T182246-d2d959`；页面和前一场景的记录同时保留。这是未建立初始状态的测试缺陷，失败不支持连接恢复失败的结论。

## 修正与验收

场景先通过既有公开浏览器入口新建对话，再用原 `sendToolRequest()` 读取 `notes.txt`，确认结果内容为NOTE并保存重启前页面。随后执行原停机、离线显示、重新启动、连接恢复、原NOTE可见和继续发送成功的全部断言。没有替换原恢复断言，没有改任何原时限，没有改产品或清空历史证据。

旧失败现场位于 `.ci-output/tool-execution-audit/2026-09-28/round2/hermes-r64/independent-product-01/`，Hermes原件位于 `/data/hermes/himawari/tool-audit-round2/r30/evidence/r64/independent-product-01/`。后续同场景定向和最终不筛选资格使用新目录；原R2-A2完成条件保持，实际通过前不写完成结果。

修正后的同场景在两项定向运行中通过全部原断言，证据 `E20261005T183624-970349`。独立读回重启前后页面，均有本场景读取请求和规定NOTE；重启后还有继续发送的请求和“普通回答已完成”。该定向结果不替代最终不筛选资格，记录在整套通过前保持in_progress。
