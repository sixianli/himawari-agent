# 守护进程测试等夹具就绪只用默认 1 秒

## Summary

test/integration/linux-host-guardian.test.ts 的 [R2-S4] reclaims a dead Host group before its parent reaps the zombie 用 expect.poll 等夹具写出 ready.json，没有指定超时，用的是 Vitest 默认的 1 秒。夹具要先起 Python 监管进程，再起 Node 子进程加载守护模块并启动守护进程；Hermes 上单独运行每次约 0.6 秒（夹具内部启动约 110-180 毫秒），2026-10-22 第 1、2 层 d55-l12-03 里 8 个集成文件并行、主机繁忙时超过 1 秒而失败，监管进程标准错误为空，失败时用例总耗时 1382 毫秒；同一最终代码单独连跑 5 次全部通过（d55-guardian-repeat-01）。这条用例不经过 job-host-main.ts，与 D-55 无关。修法要在“给就绪等待一个与夹具启动预算一致的明确上限”和“缩短夹具启动”之间选择，前者属于放宽测试时限，需按 AGENTS.md 的测试时限规则判断；如在候选的第 3 层或第 4 层再次出现，按缺陷立即处理。
