# 首次部署清单的bwrap路径要求与SRT实际选择不同

## 当前结论与期望结果

`partially confirmed`：原 P6 要求指向 `/usr/local/libexec/bubblewrap-0.11.2/bwrap`，但真实 JobHost 的 SRT 没有从配置取得 bwrap 路径，仍从固定 PATH 查找系统 `/usr/bin/bwrap`。这已由源码确认。它不证明产品缺陷：安装 Runbook 明确区分 SRT 系统路径与要求 `>=0.11.2` 的 program/stdio 隔离后端。当前没有连接云端，不能把历史系统 0.9 当作当前实测身份。

## 证据与合同

| 来源 | 已确认行为 |
| --- | --- |
| `packages/runtime-sandbox/src/job-host.ts:86–96` | 子 JobHost PATH 固定为 `/usr/bin:/bin:/usr/sbin:/sbin:/opt/homebrew/bin`，不继承父服务 PATH |
| `policy.ts:168–201`、`job-host-main.ts:315–316` | 生成 SRT config 没有 bwrapPath，交给原 manager.initialize |
| 锁定 `@anthropic-ai/sandbox-runtime 0.0.75` 的 `dist/sandbox/linux-sandbox-utils.js:1555` | 实际命令采用 `bwrapPath ?? bwrap`；未指定时按 PATH 查找 |
| `packages/platform-node/src/capabilities/isolation.ts:508–525` | program/stdio 后端另外读取 host binding，要求 bwrap 版本 `>=0.11.2` |
| [安装 Runbook](../runbooks/install-start-stop-runbook.md#ubuntu-2404-bwrap)401–406行 | 已批准两个路径，实际采用哪个就检查哪个；没有要求两处版本相同 |

路径核查草稿见[bwrap合同差异](../../.ci-output/production/2026-10-07-first-deploy-packet-01/acceptance/cloud/bwrap-path-findings.md)。P0与签署草稿目前要求系统二进制也等于libexec0.11.2；这是本次新增的严格前提，不是产品原合同。它会对历史系统0.9停止，未修改系统程序、链接、PATH或产品配置。

## 待裁定选择

建议 Claude 明确是否允许分别固定签署 SRT 实际系统 bwrap 与 program/stdio 的 libexec 0.11.2，分别保留真实版本、摘要、AppArmor、完整验收和原版本门槛。这与 Runbook 的两个既有路径一致。另一选择是另批使 SRT 实际选择 libexec 路径；它需要具体设计或系统/产品改动，当前没有授权。不能虚填不存在的 bwrapPath 顶层配置，也不能只签一个未被实际执行的路径。

本条保持open；先完成独立准备，最终随stop-09交Claude裁定。
