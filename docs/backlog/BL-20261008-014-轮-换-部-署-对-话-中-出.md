# 轮换部署对话中出现的TOTP密钥和恢复码

## 期望结果

上线后通过已批准的 account recover 管理流程轮换此次部署对话中出现的 TOTP 密钥与恢复码，并确认旧第二因素及旧会话失效。TOTP 是验证器生成一次性验证码时使用的秘密。

## 来源与证据

来源为 Claude 在生产服务器上读回后编写的[生产沙箱修复简报](../../.ci-output/handoff/2026-10-08-codex-prod-sandbox-brief.md)“记录但本批不修”部分。Codex 本次只在 Mac 上登记文档，没有连接生产服务器、读取生产秘密或重跑生产命令。

Claude 报告 account-enrollment.json 的 TOTP 密钥与恢复码在部署期间显示进对话记录。此条仅登记该报告，不复制秘密内容、不读取该文件，也不声称已完成轮换。

## 后续范围与约束

这是后续运维动作，不属于本批代码修复。account recover 会重置密码和第二因素，撤销旧会话、设备与未完成验证请求；执行前必须取得具体生产账号与影响范围的授权，并按当前 Runbook 的停机、受保护输入和核查要求操作。不得把新凭据放入聊天、Git 或公开证据。
