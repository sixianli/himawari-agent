# 产品路径追踪压缩超时使服务清理未执行

## 当前结论与期望结果

confirmed：r73完整第2层自然退出1。主afterAll先压缩完整浏览器追踪，120000ms hook超时；输出434848590字节ZIP仍不可读，主report.json缺失，installation.close尚未到达，两个已登记自有服务遗留。这是验收控制层证据保存和清理顺序的问题，现无产品停机缺陷证据。期望在原断言、完整追踪信息及所有原期限保持时可靠保存证据并执行安装夹具清理。辅助测试首跑因启动和newPage耗时使正文在30秒后完成，原源码定向诊断12.889秒通过，原因仍uncertain，不撤销失败或放宽期限。

## 来源与失败证据

实际失败来自[完整第2层原件](../../.ci-output/tool-execution-audit/2026-09-28/round2/hermes-r73/layer2-failure-metadata-01/layer2-01/retained-output/vitest.json)，记录 `E20261008T060209-2e9301`，运行前指纹 `b67eb56ca58a1fe625399252aac402ad8837165e290b4919398dd66f603d61a0`。50项中48通过、1失败、1项原有比较基线跳过；两项R2-L6和独立已安装摘要检查均通过，但整文件和结束hook失败。

辅助测试的行为断言在进程计时约36.507秒结束。主trace输出434848590B却没有ZIP中央目录，后续主报告不存在，第39代服务日志没有draining/stopped。源码的结束hook先导出追踪，再关闭浏览器、写报告、调用安装夹具的close。这些证据确定服务清理没有执行，不能据此归因产品停机。

两个原登记服务的PID/stat22分别为Agent `1558488/767943725`、Worker `1558490/767943727`。后续仅对这两个稳定pidfd依次发出SIGTERM，均在原15秒等待内退出，没有SIGKILL。原registry未改写；晚于scratch创建的不可读进程仍阻断旧现场删除。全部原件留在Hermes，未撤销红色报告。
