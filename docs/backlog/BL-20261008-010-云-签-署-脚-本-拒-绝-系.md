# 云签署脚本拒绝系统工具的合法符号链接路径

## 期望结果

使云签署检查能在核对最终规范路径、文件身份及摘要的同时处理已批准的系统工具符号链接，避免 Ubuntu 24.04 上的合法 socat 路径阻止签署。

## 来源与证据

来源为 Claude 在生产服务器上读回后编写的[生产沙箱修复简报](../../.ci-output/handoff/2026-10-08-codex-prod-sandbox-brief.md)“记录但本批不修”部分。[stop-04 裁决](../../.ci-output/handoff/2026-10-08-codex-prod-sandbox-reply-04.md)第 4 项随后批准先修正式工具，再用新来源准备第二次签署。

静态代码已确认第一次 signing/cloud-seal.mjs 对 bwrap、socat、bash、rg 都先求 realpath，再断言结果与输入路径相等。Claude 报告生产 /usr/bin/socat 指向 socat1，原断言失败；Claude 使用去掉该断言的副本签署，回执记录 /usr/bin/socat1。第一次原件及其来源保留；该副本不充当这次正式修复。

## 正式修复合同

[正式 verifier](../../scripts/operations/cloud-system-tool-bindings.mjs)同时记录输入路径、最终规范路径、目标 device/inode/UID/GID/mode、完整链接链的文本与身份、目标 SHA。合法 alias 只有与批准观察结果完全相同时才通过。最终目标必须是不可组写或公开写的普通可执行文件。生产 collector 和 signer 另要求目标及每条链接均为 root 所有。

verifier 使用 O_NOFOLLOW 打开最终文件，并比较读取前后同一文件描述符的身份和元数据。它还独立重新解析完整路径和链接链。目标变化、同字节 inode 替换、内容改变、链接文本或链接 inode 改变、UID/GID/mode 不同、悬空链接、非普通可执行文件、缺失或多余观察字段均拒绝。观察过程不执行系统工具。

第二次签署包保留原 systemTools[realpath] 摘要字段，并增加 systemToolBindings。签署前和每次服务启动都重新检查冻结绑定。S0 专门只读 collector 提供 socat/bash/rg 等实际生产身份；未取得实际观察时停止，不能用 Hermes 或第一次摘要填写。

## 验证与交付边界

[回归测试](../../test/tooling/cloud-system-tool-bindings.test.mjs)覆盖 17 条合同和失败边界。Hermes seal-red-02 真实执行合法 alias 用例，旧断言因 realpath 为 socat1 而输入为 socat 失败；其余 16 条过滤。seal-green-01 同一文件 17/17 通过。seal-red-01 因留证 wrapper 的输出范围配置失败，没有进入用例，不能列作缺陷复现。

最终 Hermes [seal-focused-02](../../.ci-output/handoff/prod-second-evidence-05/reports/seal-focused-02/console.log) 为 17/17；[seal-tooling-03](../../.ci-output/handoff/prod-second-evidence-05/reports/seal-tooling-03/output/vitest.json) 为 45 文件、1219/1219；[seal-check-06](../../.ci-output/handoff/prod-second-evidence-05/reports/seal-check-06/console.log) 的 npm run check 退出 0，包含格式、lint、类型与项目合同检查。修复工具及其测试在后两次运行间没有改变；其他兼容性场景测试的断言另行处理。

上述证据支持关闭工具缺陷。Mac 只编辑和审查，没有运行测试。Codex 没有连接生产、访问签名私钥、签署或启动生产服务。第二次工具是独立操作来源，不进入 clean 7748b0a runtime 安装包；生产资格和签名仍由冻结部署包及 G65/G66 的执行授权控制。
