# 工具效果未知时恢复流程不停重放同一次调用

## Summary

一次前台的、要核实效果的工具调用（操作合同为 `verified_effect`，例如写文件、编辑文件）在沙箱里以非零退出结束，而失败原因既不是有界失败（原因码在 `isSandboxBoundedToolFailure` 列表里，例如超过期限），也不是已核实的失败（例如 `FILE_VERSION_CONFLICT`）时，这次调用的效果停在“未知”，结果不交给模型。运行于是进入“核对外部结果”阶段（`reconciling_external_result`），恢复流程拿检查点里同一条模型输出重放同一次工具调用，不发新的模型请求，大约每秒一次，直到运行截止时间才停。用户看到的是这一轮一直在运行、执行记录显示“部分执行记录暂不可读取”。R2-T14 只修了合同版本 1 的 `write`/`edit` 这一类输入（改为 `FILE_WRITE_NOT_STARTED` 或 `SANDBOX_WRITE_EFFECT_UNVERIFIED`），重放本身仍然没有次数或时间上限，其他输入仍会触发。

## Origin

- 来自第二轮长任务条目 R2-T14 的诊断（2026-10-17）。Hermes 证据 `/data/hermes/himawari/tool-audit-round2/r2t14/evidence/r2t14-key-diag-01/product-path/`：5 分钟里 `trace_events` 有 284 组 `runtime.tool_intent` → `runtime.tool_result` → `runtime.result_unknown`，每组里 `runtime.model_started` 到 `runtime.model_output` 只隔约 1 毫秒；测试的假模型（按固定规则回复的模型）只收到 6 个请求。
- DeepSeek 独立咨询（`.ci-output/handoff/2026-10-17-r2t14-edit-loop-consult-stop.md` 第 4 节）给出判定链：`apps/agent-service/src/production-sandbox-services.ts` 的效果核实 → `packages/application/src/services/sandbox-execution-projection.ts` 的 `needsReconciliation`、`deliverToolResult` → `apps/agent-service/src/production-sandbox-tool-result.ts` 不生成结果意图 → `apps/agent-service/src/production-runtime-tools.ts` 返回 `unknownResult()`。修好的那一类见 [SRT 统一执行设计的 R5 实现说明](https://github.com/sixianli/himawari-agent/blob/208007462f99e16c5c8cd4daac2acc10fa9f5f36/docs/execution/specs/2026-09-07-srt-unified-execution-design.md#r5-实现说明2026-09-09)。

## Notes

- 咨询列出的其他可能触发输入：结果信封超过输出上限（`packages/platform-node/src/files/pi-host-publication.ts` 的 `fitBody`/`bounded` 抛错）、合同版本 3 的准备内容在核对时变化、runner 被系统杀死或崩溃。R2-T14 之后，沙箱路线上 `write`/`edit` 的这些失败都归为 `SANDBOX_WRITE_EFFECT_UNVERIFIED`（`packages/execution-contracts/src/pi-runner-v1.ts` 的 `sandboxFileOperationFailureReason`，经 `@himawari-agent/execution-contracts` 包入口导出，只看核实器和操作名，不看合同版本），不再重放；仍会重放的是其他要核实效果的操作（`save_copy`、`move_directory`）以非零退出失败，以及容器路线（见 [BL-20261017-004](BL-20261017-004-容-器-执-行-路-线-的-写.md)）。runner 被杀和崩溃没有运行记录，处理时先在测试主机上复现。
- 处理方向：给“效果未知后重放”设上限（例如同一次工具调用的重放次数，或不前进的时间），超过后按有界失败告诉模型“效果未核实，请先检查工作区”，并让这一轮能正常结束；同时保留“进程中途被杀、效果真不知道”时不交付结果的保护。
- 真实模型在“结果未知”时会不会自己反复重试，没有核实。
