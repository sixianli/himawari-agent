# 生产部署包里只能在生产主机运行的步骤要用前一步的真实输出做演练

## Summary

第四次生产变更（R2-L10）的 S9 清理步骤（install/S9-clean-transport.py，删除生产上的临时上传目录并归档证据）核对 S8 读回文件时用的是第三次部署的文件名 s8-original-target-readback.json，而第四次的 S8（maintenance/run-maintenance.mjs）已改写为 s8-database-readback.json，生产上 S9 预检因此失败。演练没有发现，是因为 S9 只允许在生产主机运行（主机名检查），Hermes 演练跑不到它，它的夹具 install/verify-s9-clean-transport-fixtures.py 又不含 S8 的结果文件。同一脚本的错误码正则 FOURTH_TRANSPORT_[A-Z_]+ 不认数字，把真正的错误码 FOURTH_TRANSPORT_S8_READBACK_CHANGED 换成了笼统的 FOURTH_TRANSPORT_UNEXPECTED_FAILURE，多花了一轮生产只读诊断。第四次已用第二次修订（G123）修好并完成。要做的是：下一次部署包起，给只能在生产运行的步骤加一项本地检查，核对它读取的每个证据文件名和属主都由包内某个前序步骤写出（读的文件名必须在写的文件名集合里），并让 S9 夹具用 S8 实际写出的文件；错误码过滤统一允许数字。
