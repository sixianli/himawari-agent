# Ubuntu 24.04 默认禁止 bwrap 使用用户命名空间，产品沙箱很可能无法启动

## 期望结果

在默认安装的 Ubuntu 24.04 上，产品要么能正常启动 Linux 工具沙箱，要么在启动前就清楚告诉管理员缺少什么前提、怎样补上，不能等到运行工具时才出现难以理解的失败。

## 来源与现象

2026-10-01 测试改到云服务器 `84.247.157.41`（Ubuntu 24.04.5）上运行，见 [ADR 0045 的沙箱前提一节](../adr/0045-short-test-temp-root.md#apparmor)。[SOURCE: docs/adr/0045-short-test-temp-root.md]

这台机器默认 `kernel.apparmor_restrict_unprivileged_userns = 1`。在这个设置下，AppArmor（Ubuntu 自带的安全模块）只允许带专门规则的程序创建用户命名空间（Linux 让普通用户在隔离环境里运行程序的机制）。以普通用户 `himawari-test` 直接运行 bubblewrap（`/usr/bin/bwrap`，Linux 上的沙箱程序）时：

- `bwrap --unshare-user --unshare-pid --ro-bind / / --dev /dev --proc /proc true` 报 `setting up uid map: Permission denied`；
- 加上 `--unshare-net`（断网隔离）时报 `loopback: Failed RTM_NEWADDR: Operation not permitted`。

用户随后以 root 执行脚本，只给 `/usr/bin/bwrap` 加了允许创建用户命名空间的 AppArmor 规则，全局开关保持 1；之后测试用户运行 bwrap 成功。规则原文和撤销方法见 ADR 0045 的同一节。

## 已知与未知

- **已确认**：默认的 Ubuntu 24.04 上，普通用户直接运行 bwrap 会失败。
- **推断，未验证**：产品的 Linux 沙箱通过 SRT（`@anthropic-ai/sandbox-runtime`，产品使用的沙箱运行库）调用 bwrap，并使用 `--unshare-net`，所以没有这条规则时产品沙箱应当无法启动。还没有在未加规则的机器上实际运行产品验证，也没有确认产品此时给出的错误提示。
- **未知**：产品安装说明目前没有提到这项前提；生产部署时由谁、以什么方式添加这条规则，还没有决定。

## 可能方向与约束

- 在安装 Runbook（操作手册）中写明 Ubuntu 23.10 及以后版本的前提，以及只针对 bwrap 的 AppArmor 规则和撤销方法。
- 研究产品启动或健康检查时能否检测到这项限制，并给出明确提示。
- 项目的 SRT 集成指南要求：不得让编程代理自动关闭全局 AppArmor 限制、使用 `--privileged` 或以 root 启动来“修复”沙箱。[SOURCE: docs/assets/others/Anthropic_SRT_AI_Agent_Integration_Guide_2026-09-07.md]
- 这里只记录方向，不选择检测或安装方案。

## 用户决定（2026-10-01）

用户选择“第二轮只补文档”：第二轮只在安装和部署说明里写清楚 Ubuntu 23.10 及以后版本的这项前提，以及只针对 bwrap 的 AppArmor 规则和撤销方法；“产品启动时自动检测并提示”留到第二轮以后，本条在那之前保持未关闭。

同日在云服务器上从官方源码（SHA-256 `69abc30005d2186baf7737feacd8da35633b93cf5af38838ecff17c5f8e924f6`）编译了 bubblewrap 0.11.2，供产品的 program/stdio MCP 隔离后端使用（ADR 0021 要求 `>=0.11.2`）。它的路径不是 `/usr/bin/bwrap`，同样需要一条只针对该路径的 AppArmor 规则，部署说明要一并写明。

同日用户以 root 运行安装脚本：程序装到 `/usr/local/libexec/bubblewrap-0.11.2/bwrap`（root 所有，0755，SHA-256 `20a3bdb6c1147f62a043a9d4d9c7873db233df40f11a0cc48731a16b97e008f3`），规则文件为 `/etc/apparmor.d/bwrap-0.11.2`，内容与 `/usr/bin/bwrap` 的规则相同、只是路径不同。以测试用户 `himawari-test` 运行 `--unshare-all --unshare-net` 验证成功。部署说明仍需写明这两条规则；本条状态不变。
