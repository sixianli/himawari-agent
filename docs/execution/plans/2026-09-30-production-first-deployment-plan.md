# 生产服务器首次部署计划

**依据：** [SOURCE: docs/adr/0044-tests-on-cloud-server.md#hosts]（2026-10-01 起测试也在这台服务器上运行，测试用户和目录与生产分开）

**目标：** 把 Himawari 部署到生产云服务器 `84.247.157.41`，让用户通过 SSH 隧道（把服务器本机端口转发到用户自己电脑的 SSH 功能）打开控制中心（Himawari 的网页界面）亲自体验。

**做法：** 在 Hermes（局域网里的 Linux 测试服务器）上用锁定的工具链构建 Linux 安装包，复制到生产服务器，按现有安装 Runbook（操作手册）安装到专用普通用户可写的目录，服务只监听服务器本机地址，不向公网开放端口。Claude 用 SSH 密钥以 root 登录，完成建用户、注册系统服务等需要 root 的步骤。

<a id="decisions"></a>

## 用户决定（2026-09-30）

- **版本：** 立即部署当前版本，不等工具执行排查第二轮的修复。部署的是分支 `claude/isolated-tool-execution` 上当时已推送的最新提交，具体提交号在部署时记录。之后修复完成，再按同样步骤升级一次。
- **访问方式：** SSH 隧道。控制中心只监听服务器本机地址，公网上不暴露任何新端口。
- **权限：** 用户最初选择“普通用户登录，root 步骤写成脚本由用户运行”，随后在同一天改为**给 Claude root 权限，但不提供密码**：用户把 Mac 上的 SSH 公钥加入服务器 root 账号，Claude 用密钥登录。Claude 不接触任何密码。执行需要 root 的步骤前，先说明要做什么；Himawari 服务本身运行在专用的普通用户下，不用 root 运行。
- 每一次部署或改动都是生产操作，本计划记录的授权只覆盖这一次首次部署；以后的升级仍要用户逐次授权。
- **2026-09-30 用户决定暂缓部署：** 在用户下次明确要求部署之前，不做任何步骤，也不登录或检查生产服务器。届时重新确认要部署的版本和上面的访问、权限安排，再按下面的步骤执行。

<a id="limits"></a>

## 已知限制

- 这个版本的 Hermes 完整测试（构建加完整 `npm test`）有 3 项失败：Job Host（在沙箱里启动工具任务的子进程）启动时加载沙箱库较慢，会偶尔被判失联，导致工具执行偶发失败；另两项是测试环境的启动超时，仍在排查。详情见 [工具执行排查计划](2026-09-28-tool-execution-audit-plan.md)。
- 这个版本没有跑过 Linux 无筛选产品路径资格。
- 模型服务的 API 密钥由用户自己在服务器上填写，Claude 不经手密钥。

<a id="steps"></a>

## 步骤

1. 用户把 Mac 的 SSH 公钥加入服务器 root 的 `~/.ssh/authorized_keys`，并告知 SSH 端口。
2. 只读核对服务器：操作系统和 CPU 架构、磁盘空间、内存、已开放端口、是否已有 Node.js 或其他服务。与 Hermes 的环境不一致时先停下说明。
3. 在 Hermes 上从记录的提交构建 Linux 安装包，记录提交号和安装包 SHA-256。
4. 复制安装包到服务器，按 [安装 Runbook](../../runbooks/install-start-stop-runbook.md) 安装到用户目录，初始化数据目录和内置账号。
5. 以 root 建专用运行用户、注册常驻系统服务（Agent Service 与 Execution Worker 成对启动和重启），确认防火墙不开放控制中心端口。每一步执行前先说明。
6. 用户在服务器上填写模型服务密钥，启动服务。
7. 用户在自己电脑上建 SSH 隧道，打开控制中心，完成一次真实对话和一次工具调用。

<a id="verification"></a>

## 验收

- 服务状态、Agent 与 Worker 的就绪事件、`doctor` 与 `db status` 的只读输出。
- 从服务器外部确认控制中心端口没有对公网开放。
- 用户通过隧道完成一次对话；数据库里能读回这一轮的 Run 记录。
- 部署记录（提交号、安装包摘要、服务器环境、执行过的命令和结果）保存在 `.ci-output/production/` 下。
