**目标：** 建立 PRD v0.2 到 S0–S9、领域 Plan、实现 revision、测试和平台证据的可机器检查链路，并在必需领域能力完成后验证核心跨切片用户旅程、共同安全不变量和排除项；S7 Calendar 仅在候选启用时进入条件式旅程与资格。

**架构：** S0 不重复实现 S1–S9 的领域语义。它提供稳定 requirement/acceptance/journey 标识、共享集成 fixture、跨切片 conformance 和证据 manifest；发现缺口时回到唯一主责 Spec 与 Plan 修复，不能在集成层另建第二套身份、状态、授权或删除规则。

本 Plan 的早期追踪与测试脚手架可以和领域实现并行；J01–J15 的通过判定必须等待对应领域 Plan 产生真实实现和 fresh evidence。创建本 Plan 不授权执行领域实现、外部账户操作、付费调用、主机迁移或生产资格签署。

## 执行顺序与停止点

- 先冻结 S0 当前绑定的 PRD digest、256 个条款、S0–S9 主责关系和每份 Plan 的 acceptance IDs；PRD 或任一 Spec 语义改变时重新生成并人工复核受影响映射。
- S1 提供持久身份、权威、HTTP/SSE、Task、Memory、Model、GitHub、删除和迁移基础；S2–S4 可以在对应 S1 contracts 冻结后推进。
- S5–S7 必须消费 S4 授权与能力语义；S8 必须消费 S1、S4 和 S6；不得用 integration fixture 伪造缺失的正式 adapter。S7 未实施时保持可选未配置，不阻塞其他领域。
- S9 只在 S1–S6、S8 的实现、平台证据和全部核心 journey 均可追溯后执行 production qualification；候选启用 Calendar 时再要求 S7 与 J07。
- 发现主责缺失、两个 Spec 定义冲突、PRD digest 变化、平台硬要求无法满足或排除能力存在 hidden route 时，阻止相关 journey 和资格收口，先治理来源文档。
- 集成测试失败只能在唯一主责代码或契约中修复；若修复需要新产品语义，停止并修订 Spec/ADR，不能把决定藏在本 Plan。

### Task 4：验证 J01–J04 身份、Thread、Memory 与治理旅程

- [ ] J01 覆盖初始化、MFA 登录、对话、SSE 恢复、正常重启和同一 Thread/Run/Trace/Inbox。
- [ ] J02 覆盖 UI locale 与回答语言独立、搜索、Fork、压缩来源、水位和原文保留。
- [ ] J03 覆盖自动/敏感 Memory、逐项审批、跨 Thread 最小检索、纠正、删除和不复活。
- [ ] J04 覆盖 capability review、Grant、范围扩大重新 ASK、撤销、Handle 失效和任务 blocked。
- [ ] 每条 journey 在关键 commit 前后 kill/restart，并证明浏览器 optimistic state 不是 committed fact。

### Task 5：验证 J05–J07 正式能力旅程

- [ ] J05 覆盖公共 Web 来源、认证 session、Prepare→Approve→Execute→Reconcile 和不重复副作用。

- [ ] 统一验证 capability manifest、ActionIntent hash、execution Handle、Trace、secret exclusion 和最终 Result。

### Task 6：验证 J08–J09 主动性、Worker 与改进候选

- [ ] J08 覆盖每日建议额度、语义去重、Owner 批准后创建普通 Task、最小 Worker 委派和主 Agent 交付。
- [ ] J09 覆盖隔离候选 workspace、base/diff/eval、生产 secret/副作用阻断、protected-root 标记和不可自激活。

### Task 7：验证 J10–J12 在线事件、模型与后台任务

- [ ] J10 覆盖 GitHub event 两秒持久接纳/拒绝、去重、repo 披露、备用模型逐次 ASK、Inbox 和 revoke 清理。
- [ ] J11 覆盖主备模型故障、披露/预算约束、外部副作用先对账、无第三模型和 MODEL_BLOCKED。

### Task 8：验证 J13 删除与保留传播

- [ ] 建立 Thread、Task、Memory、Payload、Trace、Inbox、search/cache、Web/Calendar session 和 Worker artifact 的关联图。

- [ ] 在每个级联 checkpoint 注入中断并验证可恢复、无悬空可解析内容。

### Task 9：验证 J14 双向权威迁移

### Task 10：验证 J15 手动升级与资格边界
