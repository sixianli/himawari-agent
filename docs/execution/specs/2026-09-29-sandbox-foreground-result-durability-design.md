## 审阅决定与理由

Claude 的 [reply-2](../../../.ci-output/handoff/2026-09-28-round2-claude-reply-2.md) 明确不批准宿主保存完整输出：

1. 工具输出可能包含私密内容。现有前台输出以受保护 Payload 落盘，原建议增加控制目录明文路径；必须先设计宿主侧加密和密钥分发。
2. 新签名结果文件、核验器和导入流程增加安全相关合同，超出本轮允许范围。
3. Claude 判断收益集中在宿主输出到 Worker 保存之间的短窗口，且需要 Worker 在该窗口退出；本轮优先解决对话无法结束的问题。该收益判断不是本轮测量得到的故障概率。

未来完整输出耐久保存已通过治理脚本登记为 [BL-20260929-001](../../backlog/BL-20260929-001-前-台-工-具-输-出-的-宿.md) [SOURCE: docs/backlog/BL-20260929-001-前-台-工-具-输-出-的-宿.md]，前提是先审阅宿主侧加密方案。

## 本轮批准的合同

“已知结果”仅指 Agent 已经持久接纳的结果。Worker 内存中的输出可能在重启时丢失，这是明确保留的保证边界。不能因此重新执行原工具或让对话无限停留在结果未确认。

已有被接受的释放证明、签名结束记录确认任务已启动并退出、operation 没有确定结果，并且原 Worker 尝试已确定不能再提交时，以现有 operation revision 比较写入保存确定错误 `SANDBOX_TOOL_RESULT_LOST`。已经持久接纳的结果优先，旧 Worker 迟到提交不能覆盖该错误。仍保留效果未知，不能推断工具未修改工作区。

保存后沿用原 Pi 批次唯一交付路径，给模型一次有界错误：“工具已运行并结束，但输出和退出结果在服务重启时丢失；没有重新执行。它可能已经产生了效果，是否重做请先确认。”继续核验当前 Run、租约、取消、期限、披露权限及预算；取消或过期后不能复活或补交，已接受释放不能撤销。

允许该错误码及既有交付路径所需的内部类型和解析；不新增表、迁移、状态、队列，不延长期限、不下载依赖。下文完整输出保存建议不属于批准范围。本轮先记录原期限到达和页面停止的真实行为，再用测试验证上述合同及竞争边界。

## 目标与来源

以下目标是原未批准方案的目标；本轮范围以[批准合同](#本轮批准的合同)为准。

前台工具已经产生完整输出并结束后，即使 Worker 或 Agent 在宿主收尾阶段退出，仍能在资源释放和原结果核验完成后交付原结果，不重新执行工具。

沿用[隔离工具执行设计](2026-09-24-isolated-tool-execution-design.md) [SOURCE: docs/execution/specs/2026-09-24-isolated-tool-execution-design.md]、[ADR 0033 的进程释放边界](../../adr/0033-process-sandbox-default-and-optional-containers.md) [SOURCE: docs/adr/0033-process-sandbox-default-and-optional-containers.md] 和[已核验工具结果续接合同](2026-09-28-sandbox-tool-result-resumption-design.md) [SOURCE: docs/execution/specs/2026-09-28-sandbox-tool-result-resumption-design.md]。审计执行状态见[缺陷清单](../plans/2026-09-28-tool-execution-audit-plan.md#缺陷和待验证项)。

## 已确认的问题

2026-09-29 在提交 `f1519e7` 的真实 Mac 隔离安装中，自动测试在真实 SRT reset 完成后、Job Host 写结束控制记录之前挂起。Pi read 已输出完整的 `pi-result.v1`，测试从真实宿主 IPC 观察到“项目代号：向日葵”。之后终止本任务的 Agent 和 Worker，解除挂起，再等待原权威租约失效并重启服务。

- 不重启对照：Run completed、result=result、released=1、tool_result intent=1，模型收到一次原读取结果。
- 重启场景：Job Host 最终签名记录显示任务退出、stdio 关闭、SRT 复位和原进程组消失；资源释放成功，但 result=null、intent=0，Run 为 reconciling_external_result，模型没有收到结果。90 秒断言等待失败。
- 没有重新执行原工具；已接受的释放也没有被撤销。缺口是执行输出只在已退出 Worker 的内存中，资源释放证明不含恢复输出所需的信息。

这里的“已产生输出”不等于“Agent 已认证并持久接纳成功结果”。测试观察到的原始字节不能直接升级为产品结果；若要恢复原字节，需要另外的可靠保存和认证过程。本轮未获准实现该过程，改为交付经上述条件确认的结果丢失错误。

证据：[本轮说明](../../../.ci-output/tool-execution-audit/2026-09-28/round2/README.md)、`restart-1-command.json`、`restart-1.patch`、`restart-1-vitest.json`、`restart-1/15-restart-cleanup-{false,true}-{before,after}.json`、`restart-1/trace.zip` 与 `te08-red-readback.json`。全部位于 `.ci-output/tool-execution-audit/2026-09-28/round2/`；失败安装为 `/private/tmp/hma-pp-Vp0WPJ`。

代码证据：`packages/runtime-sandbox/src/job-host.ts` 把 stdout/stderr 收集在 Worker 内存，等宿主 close 后才提供最终结果；`apps/execution-worker/src/production-sandbox-execution-v2.ts` 等待该结果后才保存前台 Payload 和 operation 事实。签名控制终态没有输出引用、摘要和命令退出结果。现有文件恢复仅处理指定的 verified_effect 文件发布，不能重新读取任意 read/bash 的原输出。TE-04 的发现条件需要 result/error 已存在，不能从 result=null 生成缺失内容。

## 范围与责任

以下为未批准原方案的范围与责任，不能据此扩大本轮合同。

建议先支持当前本机 SRT 前台工具。后台输出沿用其既有连续输出机制；Docker、远端服务和安装器工具链包装不在本提案内。不改变 Mac `process_group_gone` 的有限保证，也不增加任何执行、网络或披露权限。

Pi 的工具实现、Bash Operations、结果格式和工具批次 capture/restore 继续复用现有固定版本。Himawari 负责宿主结果耐久保存、原调用身份核验、受保护 Payload、资源释放和最多一次交付。无需在 Pi 上实现第二套工具协议，也不改只读参考仓库。

## 建议设计（未批准）

1. **Job Host 保存可恢复的完整输出。** 在宿主自己的受保护控制目录内，以原 job/attempt 为唯一归属保存有界输出文件。该目录不能成为任务可写的私有工作目录或模型指定路径。输出继续受现有 maxOutputBytes 上限约束。任务结束且管道关闭后，完成输出同步与原子封存，再签名保存包含输出摘要、长度和原任务退出事实的结果记录；不能把仅收到部分 stdout 当作完整结果。
2. **签名结果与资源释放分别成立。** 结果记录绑定原 session、boot、job、attempt、策略及执行身份，并明确退出码、停止原因、完整输出摘要和长度。结果已封存不代表资源已释放。Job Host 在 finish 后半段崩溃时，可以保存操作结果但仍保留目录占用，直到现有原宿主/进程组核验产生释放证明。
3. **Agent 只导入原事实。** 原记录已释放但前台结果缺失或 unknown 时，Agent 在当前权威下核验控制目录身份、原签名、摘要、长度、固定文件类型及完整性，再通过现有 Payload 保护与 journal operation revision 保存原结果。缺少退出事实时保持未知；不能仅解析 stdout 中的 `isError: false` 推断工具成功。已经存在确定结果时只核对一致性，不覆盖它。
4. **沿用既有恢复与交付状态。** 在既有恢复发现流程中补上“已释放但结果尚未导入”的有界核查，成功导入后由 TE-04 现有原工具批次续接及唯一 tool_result intent 交付。不能要求重新派发工具才能触发恢复，不能额外建立常驻结果队列或无限扫描失败记录。发现、导入与 Worker 正常提交的并发仍由现有身份、operation revision 和原结果不可变规则处理。
5. **无新数据库表的目标。** 优先沿用现有执行记录、受保护 artifact、Payload、交付 intent 和恢复状态。新增的是宿主结果文件及其签名合同，以及 Agent 导入所需的证据关联；这些属于持久数据形状变更，不能因为沿用表而免于审批。如实施验证表明需要迁移、新状态或第二个恢复调度器，另行提案，不在本次批准中推定允许。

不采用：重新执行只读工具取得“同样结果”（文件可能已变）；从测试日志或 UI 拼回输出；把清理成功视为命令成功；把未知退出码改为零；直接扩大前台等待时间；仅让 Worker 更早开始异步保存但不处理其保存前崩溃窗口。

## 失败和兼容边界

- 旧作业没有新的结果记录时保持原未知状态，不补造历史输出，不修改旧 final.json。
- 新记录只能通过匹配的新写者和核验器导入；旧读者最多继续认为结果未知，不能错误接纳新合同。具体版本字段和拒绝路径须在实现前明确到类型与解析器。
- 输出文件缺失、截断、超限、摘要不符、签名不符、目录/文件身份变化、符号链接、跨 job 或 attempt 替换均拒绝导入并保存有界诊断。
- 磁盘写入或同步失败不能宣布结果已耐久保存；保留明确失败/未知与资源清理证据，不能删除唯一结果现场以获得通过。
- 用户取消、执行权或披露权限失效后，可以保存已发生事实，但不能复活 Run、恢复执行权限或向模型补交。仍使用原期限，不重置业务和恢复时钟。
- 原 Worker 与 Agent 同时提交同一个确定结果时必须幂等；若两个来源矛盾，保留原确定事实并报告冲突。
- 输出结果文件及签名记录是恢复证据，必须进入保留、备份与诊断边界；不得直接在公共日志打印正文，也不能把现有密钥发给任务。

## 验收与验证策略

原完整输出保存方案的验证草案保留如下，不作为本轮实现要求。本轮按 reply-2 改为验证一次结果丢失错误、无重放、释放不撤销、正常对照及取消/期限/披露拒绝。原失败报告保持不变，修改 restart=true 预期是已批准的合同变化。

已有先失败证据为 `preserves known output when restarting during host cleanup: restart=true`；同一挂起点不重启的对照通过。该测试使用实际浏览器、HTTP、Pi read、SRT、Agent/Worker 和 SQLite；仅模型/身份边界为本机夹具，挂起点用于安排真实进程退出顺序。

原方案若日后另获批准，以下是其测试草案；当前不执行原结果保存设计：

- 完整输出已经封存，分别在 Worker 结果保存前、宿主 reset 后、control.finish 前后和结果 IPC 前后退出；恢复只交付一次原结果。
- 输出未封存、保存失败或只有部分内容时不能交付；资源释放不制造操作成功。
- 原结果与文件内容后来变化时，恢复交付封存的原字节，不能重新读文件或运行原命令。
- 取消、过期、权限撤回、原身份变化及旧记录缺字段均保持拒绝；迟到导入不能复活 Run。
- 真实 SQLite 中的正常 Worker 保存与恢复导入竞争；保持已接受释放不撤销、输出不可变、intent 唯一。
- 首先复跑当前对照与失败测试，再补上交接要求的其余重启、期限、finish 崩溃和交错场景。完成相关检查、完整 npm test、最终无筛选 Mac 产品资格与 Runbook 核对封存。Linux 实测仍交 Claude 决定，本机不连接 Hermes。
