# 记忆系统重新设计

**审阅状态：已批准。** Andy 2026-11-24 在“重新设计记忆系统”线程逐项定下（给 Andy 看的同一份方案：<https://claude.ai/artifact/CbCGmhUDVSAQXsTBWUgnbm>）。决定和理由见 [ADR 0286](../../adr/0286-the-main-model-reads-and-writes-memory-itself.md)。

## Andy 定的几条
Andy 11-24 下午在线程里定的：
1. **不做 /memories 目录和 MEMORY.md。** 不把记忆包装成文件，也不模仿文件命令。她要知道自己记着什么，靠对话开头一段从数据库拼出来的“记忆清单”；要细看，用普通的记忆工具按编号打开。
2. **聊天时当场存（实时存）。** 不再只靠回答后后台另外整理。她先把回答说完，再在同一条回复末尾存，不拖慢回答。
3. **存没存上都不打扰 Andy。** 对话里不出现“已记下”之类的话或标记；存失败她自己处理。
4. **取消敏感内容审批，去掉“敏感”标记。** 健康、财务、人际关系等一律直接记、原样给模型，锁屏推送也显示全文。理由（Andy 原话）：“它必须全面掌握我的个人情况，才能做好 AI personal agent 这个角色”。
5. **密码、密钥一律不记，他明说“记住”也不记。** 以后接一个类似苹果密码管理器的工具，填表时由工具把值取出来直接填，模型只知道“用哪一项”，看不到值（这一版就做，另开线程）。银行卡号、身份证号当普通信息记，原样给模型。
6. **“记忆变化”收窄。** 只写不是她在这场对话里亲手改的；没有变化就不出现。

## 一句话
让主模型自己翻旧对话原话、知道自己记着什么、聊天时自己存记忆；数据库是唯一正本，不另做文件。分四步做，每步先有自动检查，再用评测证明比现在好，才往下走。

## 先回答两个问题

**ChatGPT、Claude 遇到同样问题怎么做，用户看到什么？**
- Claude App：聊天时 Claude 自己按主题存记忆，用户在设置里按主题看、改、删；还能“搜索旧聊天”，在对话里显示成一次工具调用，回答带链接指回原对话。
- ChatGPT：“保存的记忆”（一条条）加“参考聊天记录”（模型从旧聊天里自己找）；用户能看记忆、点“别再提这个”、删除。
- Claude 开发者平台的记忆工具：模型用看、建、改、删等命令操作一组记忆文件，背后存在哪里由应用自己定。
- Claude Code：开局载入一个记忆目录文件，按需打开每条记忆。
- 共同点：主模型自己决定记什么、什么时候查；旧对话原话能搜能打开；用户看得到、改得了。没有一家是“每轮另起一次调用替主模型挑 5 条”。文件只是其中两家的包装方式，不是关键，所以我们不照搬。

**根因还是表面修补？** 根因。现在是程序和单独的模型调用替主模型决定它能看到什么、记什么。只把 5 条改成 20 条才是表面修补；这次改的是“由谁决定”。

## 根因
1. **读**：主模型每轮自动拿到的只有检索器挑的 5 条和 2000 字资料；想多看只能自己调 recall，一次最多 10 条加 5 段摘要。她不知道自己记着什么的全貌，也打不开出处原话。
2. **写**：主模型不能写记忆。记不记、记成什么，由每轮之后一个只看 6000 字、30 条旧记忆的单独调用决定，没抽中的就再也找不回；她自己也看不到存了什么。
3. **原话**：旧对话只能搜到每日摘要，摘要漏的细节找不回。
4. **规则混在记忆里**：规则会不会带上，取决于有没有被归成规则类、有没有被 2000 字挤掉，是碰运气的（ADR 0134 已列为已知缺口）。

## 方案：四步

### 第 1 步：能翻旧对话原话
- 对话原文本来全存着，不动。新增按“轮”（你说一句、她答一句为一轮）的检索索引，按词和按意思都能搜。
- 她多一个**对话工具**：搜旧对话（按意思、词、日期找，返回哪场对话、哪个位置、日期和原文片段）；打开旧对话（读那一处前后的原文，可往前往后翻）。
- 发给模型前，原文里的密码、密钥、验证码照旧遮盖，同一条旧消息每次遮出的结果相同（保缓存）。
- 对话删除时，索引同时删掉，搜不到也打不开；恢复时再建。
- 上线前的旧对话随统一收件箱第 1 步全部删除（Andy 11-24 22:03 定），索引只为之后的对话建，不做补建和兼容。
- 不再生成每日摘要，改由“做梦”（见第 3 步）整理成按主题的记忆和主题页。回答用到旧对话时带链接，点开跳到那条消息。

### 第 2 步：她知道自己记着什么（只读）
- 数据库是唯一正本，保存出处原话、时间线、历史版本。没有任何记忆文件。
- **记忆清单**：每条记忆一行。写法按实测定（Andy 11-24 22:08 拍板）：类别名单独一行，下面每条写“编号紧贴内容”，比如“37喝咖啡不加糖；11月下旬起喜欢加果汁”，内容以数字开头时才在编号后加一个空格（如“8 1998年出生”）。编号用每条记忆固定不变的短数字（新加一列），不用库里现在的长随机编号。不写日期和符号，跟时间有关的由她存的时候写进内容里；要看日期、原话、旧版本就按编号打开。程序当场从数据库拼出，顺序固定，用完就扔。所有当前有效的记忆都放进去；万一多到放不下，常提到、最近用过的照样一条一行，其余每类写“另有 N 条，可搜索”。
- **写法实测**（生产模型 DeepSeek V4.1 Flash，经 OpenCode Go 套餐；token 数是接口返回的实际计费数；1000 条记忆的清单，40 道题，不开思考各跑 2 遍；脚本和原始数据见 [.agents/evidence/memory-list-format/](../../../.agents/evidence/memory-list-format/README.md)）：

  | 写法 | 每条 token | 全对 |
  |---|---|---|
  | 一条一行 JSON | 30.4 | 80/80 |
  | Markdown 标题加列表 | 17.3 | 80/80 |
  | 表格式（tab 隔开编号、类别、内容） | 17.6 | 80/80 |
  | 类别一行 + “编号 空格 内容” | 15.3 | 80/80 |
  | 不写类别 | 15.2 | 77/80 |
  | **类别一行 + 编号紧贴内容（数字开头才空格）** | **14.7** | **80/80** |
  | 编号一律紧贴（不管数字开头） | 14.5 | 80/80 |
  | 只放内容（对照） | 12.9 | 无 |

  读懂率各写法打平，所以按 token 选。类别不能省：不写类别时“哪些还没经主人确认”答不出来，因为“待确认”只写在类别里。编号一律紧贴只再省 0.16，但“8”加“1998年出生”会变成“81998年出生”，不用。编号写法另测：库里现在的长随机编号原样放每条 38.2 token，稳定短数字 15.3，每份清单从 1 重编 14.6；不重编，因为压缩重建清单后，对话里提过的旧编号会指向别的记忆。100 条清单上各写法也都是 119～120/120（开思考 40/40）。全部调用标价约 0.36 美元，走套餐额度，实际扣费 0。
- **开头快照**：新对话开头放一次“记忆清单 + 关于 Andy 的核心记忆”，之后不改（保缓存）。主对话长期不结束时，每次压缩长对话时用最新记忆重新生成一次；后台子线程每次新开都放最新快照。
- **每轮最后一条消息**：你这句话、当前时间、未来 7 天安排、程序按你这句话搜到的相关记忆（最新版本），再加上“记忆变化”。
- **记忆变化**：只写别处的改动，也就是后台整理、子线程、别的设备、你在记忆页改或删的、纠正一条后连带改的。她在这场对话里亲手改的，工具结果里已经有，不再重复；没有变化就不出现。它是必须的：开头快照为保缓存不改，你删掉的记忆还留在快照里，程序搜相关记忆只会“不再搜出”它，不会告诉她它已作废，只有这一段能告诉她。
- **记忆工具**（只读）：搜记忆、按编号打开（含出处原话）、看历史版本。
- 读法是“先递一部分 + 她自己查”：开头清单和末尾相关记忆是程序先递的资料，觉得不够她自己搜、自己打开。程序不替她做决定。没递给她的部分必须告诉她都有什么（Andy 11-24 文档批注）：快照开头有一段“你还能查到的”，写明① 清单里每条只有一句话，日期、原话、旧版本没放，按编号打开；② 主题页有哪些（列名字）；③ 旧对话从哪天到哪天、共有多少天有对话、每月多少天，都能搜；④ 万一清单放不下，每类还有几条没列。这些都是程序数出来的事实，不替她判断。另在系统提示里加一条固定规矩（照 Anthropic 记忆工具自带的“ALWAYS VIEW YOUR MEMORY DIRECTORY BEFORE DOING ANYTHING ELSE”，https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool）：答案取决于主人过去说过的细节时，先打开或搜原话再答，不凭清单里的一句话猜。她该查时有没有查，放进评测量（Anthropic 自己也说“Loading a note also doesn't guarantee that Claude acts on it”，https://www.anthropic.com/research/components-of-agent-memory）。依据：Anthropic 上下文工程文章“maintain lightweight identifiers”“Folder hierarchies, naming conventions, and timestamps all provide important signals”；Claude Code 的 MEMORY.md “serves as an index, which shows Claude what it knows and where to find it”。

### 第 3 步：聊天时她自己存（实时存）
- 记忆工具加三个写命令：存（新记忆）、改（存新版本，旧版本标失效，不删）、作废（进回收站，可恢复）。
- **不拖慢回答**：她先把回答写完，你立刻看到；然后在同一条回复末尾调用存记忆。工具里只有程序检查，几毫秒返回；她接着在同一条回复里补一小段（通常什么都不说）。开头部分已缓存，只多一小段输出。
- **不打扰 Andy**：存成功不说；存失败她自己处理（换个说法重存，或交给回看补），不在对话里提。失败记进日志，评测时算漏记率。存了什么，记忆页随时可查。
- **什么都能记，不用审批**：取消敏感内容审批，去掉“敏感”标记；健康、财务、人际关系、银行卡号、身份证号都直接记、原样给模型；锁屏推送显示全文。
- **唯一的硬拦截：密码、密钥不记**，你明说记住也不记（程序用现有的密钥、密码识别拦下，不只靠模型自觉）。以后接密码管理器时，填表由工具从密码管理器取值直接填，模型看不到值（这一版就做，另开线程）。
- 写入沿用现有后台整理那条路上的检查：出处原话确实是你说的、密钥扫描、人物、提醒、审计。抽成共用代码，不重写。另加：同一次调用重放不重复存；版本冲突时让她重读再改。
- 存记忆的工具说明里写明：内容一句话、尽量短、跟时间有关的把时间写进去（记忆清单的 token 主要花在内容上）。
- 读过网页、邮件等外部内容后存的记忆，只能是“待确认”；规则永远不能由外部内容直接生效（ADR 0278）。
- 手机上认过声纹的语音，现在整段按“主人说的”存（packages/application/src/services/perception-extraction.ts:363-366），做“出处必须是你说的”检查时一并核对，改之前先告诉收件箱线程。
- **后台整理和确认裁判**：第 3 步上线时直接关掉（Andy 11-24 定：“它能自己存就直接关”）。漏记由每晚做梦补，原话永远能搜；评测照样量漏记和记错。
- **回看**（ADR 0231）变成“做梦”（照 Anthropic 的 dreaming，取代每日摘要；Andy 11-24 在文档批注里要求）：每晚一次，加上新对话攒够时再做一次。主模型带着全部记忆和这段时间的全部原话，做四件事：合并重复；被新说法推翻的改成最新的，旧版本留历史；补上聊天时漏存的；把同一件事散落的记忆整理成一页“主题页”（比如“Mika”“求职”“鼻炎”），页里每句话指回原话。每条结论先对着原话核对再写。改动整批生效、整批可撤销，不打扰 Andy（和 Anthropic 不同：它输出新库等人审，我们直接生效靠撤销兜底；它的页面不指回原文，我们指回）。主题页是数据库里的文字，不是文件；记忆清单末尾列出所有主题页的名字，她按名字打开。依据：Anthropic 实测每份合同单独一页记住 57/57 条事实、一张总表 41/57；搜索加主题页 61%，只搜索 53%。现有回看的安全设计（原话校验、整批可撤销）保留。
- **纠正传播**（ADR 0232）：沿用，扩到她自己存的记忆。

### 第 4 步：规则搬出记忆 + 记忆页 + 导出
- 能由程序执行的规则（通知、静默时段等）走规则手册，程序执行，每条有回归测试，必定带进上下文；记忆只留规则的出处和修改历史。软偏好仍是记忆。
- 记忆页每条能点开出处原话和历史版本。不加“把全部记忆排成一整段文字、直接在里面改”的页面。
- 导出复用 ADR 0200 的格式；Markdown 只出现在导出里。

## 数量上限怎么处理
现在写死的数字逐个改成下面这样。生产对话模型 DeepSeek V4.1 Flash 的上下文窗口是 100 万 token（上线配置模板 `"contextWindow": 1000000`，scripts/delivery-mode/packet-template/maintenance/production-shape-config-template.json:87）。比例是初始值，写在配置里，换模型自动跟着变，评测后再调。不是窗口越大就塞越多：上下文越长模型召回越差（LongMemEval 实测掉 30%–60%），所以每类只占窗口的一小部分，其余靠她按需查。

| 现在写死的 | 改成怎么做 | 按 100 万窗口算 |
|---|---|---|
| 主人资料块 2000 字（重要度 ≥600 才进） | 去掉，由开头快照（记忆清单 + 核心记忆 + “你还能查到的”）取代；快照不超过窗口 10% | 10 万 token，按实测每条 14.7 token 约 6800 条记忆全放得下 |
| 每轮自动带记忆：搜 20 条、最多带 5 条 | 不限条数：按相关度从高到低放全文（含日期和原话），低于相关门槛的不放，总量不超过窗口 1% | 最多 1 万 token |
| 记忆工具一次最多 10 条 + 5 段摘要 | 一次返回不超过窗口 2%，放不下给“下一页”，她自己决定翻不翻；每日摘要取消，换成主题页 | 每页最多 2 万 token |
| （新）搜旧对话、打开旧对话 | 同上，一次不超过窗口 2%，可往前往后翻 | 每页最多 2 万 token |
| 做梦（新，取代回看） | 一次读入全部记忆 + 上次做梦以来的全部原话，不超过窗口 50%；超了按对话分批做 | 50 万 token |

防失控的上限单独定，不跟窗口变，也不是用来省钱的：
- 单条记忆内容 ≤ 300 字：超了说明该拆成几条，或者该写进主题页；工具拒收并告诉她原因。
- 一轮里存、改、作废合计 ≤ 50 次：防止她陷入来回改的循环；正常一轮远用不到。
- 单个主题页 ≤ 5000 字：超了做梦时拆成子页。

工具参数的上限（比如“每页几条”）由上面的 token 预算倒推，写在工具定义里，有契约测试。没有“因为 Andy 看不过来”而定的上限，也不为省模型调用而设上限。

## 每一步先上的自动检查
- 请求只追加：快照只在新对话或压缩时写，记忆变化只在末尾；中途重写快照会让检查失败。
- 同样内容同样字节：记忆清单、搜索结果顺序固定。
- 她能写出的每个值，后端和每个使用方都接得住（I-73 的教训）。
- 删除跟随：对话、记忆删掉后，索引、打开原话、快照、导出都拿不到。
- 密码、密钥：任何路径都存不进记忆（含她明说要存、外部内容里带的）。
- 注入：网页里写“记住主人喜欢 X”，不会产生已确认记忆或生效规则。
- 重放：同一次工具调用重放不产生两条。

## 评测：一次只换一样
同一主模型、同一向量模型、同样的提示词布局，只换记忆做法：
- A 现在的做法
- B A + 翻旧对话原话
- C B + 记忆清单和只读记忆工具
- D C + 实时存
题目：现有合成集、真实记忆周评测（ADR 0239）、LongMemEval-S 抽题；新增“引用原话”和“纠正后不说旧值”两组。
量：该查原话时有没有查、分能力的准确率、纠正后不说旧值、该说不知道时说不知道、引用原话对不对、漏记、记错、密码密钥是否漏存、每轮 token、延迟、缓存命中率。
门槛：B 比 A 好；C 不比 B 差；D 不比 C 差。后台整理和裁判在实时存上线时直接关，不等这个数字（Andy 定）。评测一律用 OpenCode Go 套餐里的模型，不用 Vercel（Andy 定）。

## 风险
- 论文里“模型自己管记忆”不一定更好（MemDelta 42% 对 47%）：所以靠每晚做梦补漏、原话永远能搜，评测盯住漏记和记错。
- 漏记：原话永远在，能搜到；每晚做梦补；评测量漏记率。
- 记错：出处校验、历史版本可回滚、外部内容只能存待确认。
- 不再分敏感：所有记忆都会原样发给生产用的模型服务商，锁屏推送显示全文（Andy 已明确接受）。
- 工具变化：只加两个工具（对话、记忆），一次加齐；进行中的对话换新工具时缓存重建一次。
