# 控制中心侧栏与导航修订

## 目标与来源

用户于 2026-09-13 指出现有侧栏把按钮、筛选、对话和未启用功能堆在一起，要求参考其提供的 Codex 与 ChatGPT 网页版截图改善界面与交互。此次调整导航层级、列表滚动和标题栏，保留既有向日葵品牌、明暗主题、聊天与工具记录。

- 控制中心功能和无障碍要求：[2026-08-26-control-center-experience-design.md（已删除，链接指向删除前的版本）](https://github.com/sixianli/himawari-agent/blob/34de855ff109a53391cfc0d59706bcf44ba7f4a5/docs/execution/specs/2026-08-26-control-center-experience-design.md)

原始 v1 原型与效果图保持原样。本说明记录后续修订，不代表 Codex 或 ChatGPT 的内部实现，也不引入演示项目、虚构账号或未实现的能力。

## 设计

- 桌面侧栏宽 272 像素，中等窗口收窄至 240 像素；支持收起和重新展开。手机继续使用已有抽屉入口。
- 品牌下方依次提供新建、搜索和审批。搜索表单按需展开，保留原有标题及授权内容搜索。
- 活跃、已归档和全部合并为一个有明确无障碍名称的筛选框；刷新使用有标签的图标按钮。
- 对话按置顶、最近对话分组。置顶遵循 `pinOrder`，最近列表保留服务端顺序，两个组都可折叠。标题占满行宽，过长时省略并保留完整标题提示；选中行使用中性色背景。
- 顶部入口和底部管理、语言固定，只有历史列表滚动。管理菜单按需打开，可用页面直接列出，未启用页面集中在可展开区域，仍可进入查看部署说明。
- 顶栏显示当前对话标题与连接、外观、详情入口。路由切换继续将读屏焦点移至标题，但不为非交互标题绘制输入框式描边。交互控件保留键盘焦点提示。
- 未选择对话时展示开始工作的提示及新建入口。创建对话、搜索、审批、模型和数据权限沿用原有产品合同。

## 验收

1. 新建、搜索、选择对话与归档筛选可操作；置顶项不会在最近列表重复出现。
2. 管理菜单可以进入已安装页面，未安装功能仍保留说明入口；导航后菜单关闭，Escape 可关闭菜单并回到菜单按钮。
3. 桌面收起后可恢复侧栏；长列表不挤掉顶部和底部入口；手机宽度无横向溢出。
4. 中、英、日三种界面语言可用；正常键盘焦点可见，程序聚焦标题不出现整行边框。
5. 原始设计文件不被覆盖；本地界面测试不作为 Hermes 发布成功的证据。

## 验证方式

使用侧栏组件测试检查分组、排序、链接与空列表入口，运行浏览器测试、类型检查、构建及边界检查。使用隔离的浏览器测试服务实际操作桌面和手机视口；该服务提供固定对话与模型边界，不调用真实模型或读写生产数据。Hermes 部署及公网验收单独报告。

## 加载与异常反馈

用户于 2026-09-13 确认：首次加载只在对话列表显示占位条，后台刷新保留现有内容，较慢或失败时才显示具体提示和重试入口。

- 对话首页不显示“正在加载权威状态”等全局加载文案。列表首次请求完成前显示静态占位条，并为读屏提供明确的加载说明。
- 已加载的列表（包括成功返回的空列表）在后台刷新时保留现状。当前对话的消息和未发送草稿继续可见。
- 请求超过 3 秒时，在受影响区域提示加载较慢并提供重试；失败时立即提示无法加载列表、会话或搜索结果。三种界面语言均使用面向用户的描述。
- 当前对话的消息已经显示后，后台刷新（包括执行记录和执行状态的附带读取）不显示“较慢”提示，失败时也先不提示：保留上次确认的内容，按 1、2、4、8 秒（最长 8 秒）的间隔自动重读；连续失败 3 次才显示失败提示和重试入口，提示在下一次成功读取前保持不变，不随每次重读闪烁。用户于 2026-10-12 指出失败提示反复弹出、挤占聊天内容（G74，记录在 `.agents/tasks/round2-tool-execution/goal.md`），此条修订上一条中“失败时立即提示”对已显示对话的适用范围；首次加载和对话列表页不变。
- 首次打开或切换到一段对话时，消息一显示出来，这次读取剩下的部分（执行记录、执行状态）就按上一条的后台刷新处理，不再计入“较慢”的 3 秒。对话区域里的较慢或失败提示浮在聊天内容上方居中显示，不占版面、不把对话往下推；侧栏列表里的提示仍在原位置显示。用户于 2026-10-24 截图指出，对话已经显示时顶部仍出现“这段对话加载较慢”并把整个界面往下顶。
- 运行中的一轮会持续改变，因此执行状态的附带读取有两种正常情形：读取到的执行状态 revision 高于详情里 Run 摘要的 revision 时，按更新的权威事实直接采用并显示（不丢弃整轮刷新后重读，界面显示最近一次读到的、revision 不低于该 Run 摘要的执行状态）；服务端在一次读取中发现 Run revision 或资源清单在读取途中变化时，丢弃本次结果并从头重读，最多 3 次（含第一次），前后仍不一致才返回拒绝（HTTP 403 `PORT_NOT_AUTHORITATIVE`，错误码不变）。客户端的执行状态读取失败一律走已显示对话的原有规则，即按 1、2、4、8 秒重读、连续失败 3 次才提示（见上一条），不再对某个 HTTP 403 静默保留旧状态。早于详情 revision 的执行状态、作用域不符以及真正的读取错误仍按失败处理。用户在 2026-10-13 的真实运行中看到已结束的工具一直显示“正在准备 · 暂无时长”并弹出“暂时无法加载这段对话，请重试。”（G86，条目 R2-U3，记录在 `.agents/tasks/round2-tool-execution/items.json`）。
- 已显示的对话不再定时整页重读。对话事件按所属对话增量处理：只更新侧栏列表，事件属于当前对话时再从最后一条消息往后读；执行进度由按对话订阅的执行变化流推送，页面只读变化的那一个 Run。首次打开、切换、筛选、写入之后和服务端要求重新快照时仍完整读取。用户于 2026-10-24 选择方案 C（复盘第 8.4 项），见 [对话执行状态改为服务端推送](2026-10-25-thread-execution-push-design.md)。
- 重试替换尚未完成的读取请求，并消费已排队的重复刷新；不重试写入操作。切换对话或筛选时取消旧读取，忽略其迟到的结果和错误。
- 直接打开对话链接时先显示会话占位，不能展示新对话欢迎页；手机侧栏关闭时，首次读取失败仍在主区域提供重试。
- 冲突和操作反馈显示在当前打开的面板；模态确认框挂载在页面根部，避免手机布局隐藏内容区域时一并隐藏确认框。
- 浏览器断网时，对话与管理页面均立即更新连接状态并禁用依赖联网的操作；恢复联网后重新连接。

加载专项验收入口为 `node scripts/test-thread-loading-browser.mjs chrome` 和相同入口的 `webkit` 参数。它使用隔离 HTTP 测试服务，覆盖三种语言与 1280/390 像素视口，实际延迟、拒绝查询并通过页面操作重试。完整流程沿用 `scripts/qualify-control-center-browser.mjs`，涵盖导航、对话操作、审批、断网恢复、无障碍与 320 像素重排。浏览器报告记录实际通过项；手机视口模拟不等同于实体手机验收。
