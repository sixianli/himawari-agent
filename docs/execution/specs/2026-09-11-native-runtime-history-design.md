# Thread 原生运行历史修复

## 目标与来源

修复跨 Run 仅恢复问答正文而丢失工具记录的问题。取消旧任务后，新用户消息必须按新请求进入模型；旧任务的实际执行结果保留，不自动重放工具。

用户已确认本方案的结构调整。参考 [SOURCE: docs/adr/0029-protected-native-runtime-history.md] 与 [SOURCE: docs/architecture-v0.1.md]。

## 范围

包含原生历史持久化、固定上下文快照、Pi 恢复、取消和 Fork 边界，以及旧数据核验和真实模型验收。不修改模型 provider 协议，不更换 Pi 版本，不改变业务工具授权。

## 数据与流程

1. `RuntimeHistoryService` 保存每条原生消息为受保护 artifact，并保存 `pi-history.v1` 引用清单，包含 `coveredRunIds`。清单具有新身份和 Run 内递增顺序；即使时钟相同也可选择最新版本。
2. Context Formation 在 SQLite 事务中选择当前触发消息之前的历史，冻结快照引用、分类与源 Run 状态。较晚 Run 的历史不能进入当前请求。Fork 创建时另存确切源快照。
3. Context Projection 验证 artifact 身份与摘要，读取授权消息，跳过已覆盖的重复正文。当前用户消息保持独立，并在 Pi prompt 时最后追加。
4. Pi 适配层验证原生数据，恢复时保留 SessionManager 支持的原生自定义消息类型；不将取消事件提前转换为普通用户消息再存回历史。Pi 在实际模型输入阶段负责转换。新的产品材料替换旧材料；工具结果、拒绝、错误、摘要与模型来源保留。
5. 消息结束及压缩完成时保存快照。持久化失败阻止后续模型或工具执行。停止等待最后一次保存；审批等待保留真实调用，忽略本地退出错误。

Pi 适配层保留固定版本自带的工具说明与使用规则，再通过 `appendSystemPromptOverride` 追加产品策略。不能使用替换式 `systemPrompt` 丢弃 Pi 生成的 `promptSnippet` 和 `promptGuidelines`。`systemPrompt` 与 `appendSystemPrompt` 的文件来源显式设为空，禁止自动发现工作目录中的 `SYSTEM.md`、`APPEND_SYSTEM.md`，也不能把产品策略文本解释成本地文件路径。这与 Cindy 保留 Pi 默认提示并追加产品规则的组合方式一致；工具授权、审批和受保护历史仍由 Himawari 管理。

## 通用工具进度与本轮状态

循环检测借鉴 Cindy 的结果指纹与滑动窗口：四次连续相同的工具、参数、结果；最近十二次仅两种调用；最近十六次仅四种调用。检测不按模型或提供商启停。它是有限窗口的循环启发式，不是语义上的任务完成证明。命中后阻止继续进入产品工具，在同一 Run 内最多申请一次受既有费用、租约及取消控制约束的汇总请求。该请求复用 Pi 的空活动工具列表，完整保留历史与已确认结果，并明确运行已因重复调用停止，要求说明结果与未完成部分。汇总仍请求工具时不执行，也不再次付费重试。产品终态保留 `PI_TOOL_LOOP_DETECTED`，不能把汇总文字记为成功答案。此行为只用于循环退出，不在每个正常工具批次后关闭工具；审批暂停和结果未知仍先走原有处理。

检测状态只保留摘要和计数，随受保护的审批 continuation 保存；新 Run 重新开始，审批恢复时已披露结果的本地重放不重复计数。仅对产品选择的内置工具，识别与工具名匹配、具有字符串阶段编号的 `pi-result.v1` 包装，在指纹计算时去除 `source.toolCallId`，避免每次执行的新编号掩盖相同结果；保留输出、错误、其他来源字段和元数据。该字段是 Worker 内部 `file-phase` 执行编号，与模型调用编号不同；执行身份绑定由受保护的工具执行端口验证，不能在进度比较中要求两层编号相等。原始结果与模型输入不变，普通文本、不匹配的包装及自定义工具结果不做此处理。结果未知仍优先进入原有对账路径，取消仍保留用户终止语义。Cindy 面向其工具的字符串错误分类和 `TaskOutput` 豁免没有直接移入本产品；后续接入真正的状态轮询工具时须明确其进度语义并验证豁免，不能把任意工具名当作放行依据。



## 旧数据与错误处理

没有快照的旧会话继续使用已有正文路径，不能因此宣称工具历史完整。旧日志仅可用于一次有归属、顺序、终态和内容完整性证据的核验导入；经过脱敏的签名、缺失结果或片段必须报告，不能猜测成功、拒绝或取消。原始记录不覆盖。一次性 `qualifyLegacyPiHistory()` 只去重完全相同的终态观察；对 Pi 0.84.2 `openai-completions` 的 `usage.totalTokens` 误脱敏，只有四个组成计数均完整时才按原公式计算合计，其余脱敏内容拒绝导入。被取消且没有助手终态的旧 Run 仅增加取消说明，不补造助手正文。

其他 Owner/Agent、越级分类、缺失 Payload、错误摘要及非法消息形状拒绝加载。取消不保证工具没有产生副作用；未知结果继续按既有对账机制处理。

## 验收

- 持久化重启后，旧调用与结果成对，新问题最后且只有一次；取消标记在连续恢复后仍保留原生事件类型、来源和时间。
- 拒绝写入后换任务，不执行旧工具；工具取消后保存真实结果。
- 历史保存失败时，模型及工具不继续执行。
- Fork 不受原 Thread 后续写入影响；冻结 envelope 不随最新快照改变。
- Schema 31 的 artifact 与密文在升级到 32 后不丢失。
- 原有审批恢复、压缩、模型切换和授权检查继续通过。
- 实际发给 provider 的系统提示同时包含 Pi 工具规则与产品策略；未授权的本地提示文件内容不能进入请求。
- 循环检测覆盖连续重复、交替循环、四工具轮转、正常批次及审批恢复；重放不重复执行或计数。循环退出汇总最多一次、必须经过费用准入；汇总中的额外工具不能执行，用户取消优先，普通多步任务保持工具可用。
- 生产验收分别检查最终模型请求、实际回答与工具行为；本地替身 provider 测试不代替真实模型质量或 Hermes 性能。

## 验证边界

本 Spec 保持打开，直到旧会话核验、真实模型对照和部署验收完成。代码测试与构建结果记录在 `test/qualification/evidence/runtime-history/`，不将其当作线上修复结论。
