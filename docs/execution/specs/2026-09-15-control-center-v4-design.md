# 控制中心 v4 已批准交互与视觉基准

## 目标与确认

用户于 2026-09-15 明确批准本任务的 v4 原型，并授权按最新版重构正式页面，要求功能、UI 和 UX 与原型一致。本 Spec 保存该批准事实与此前多轮批示。原型中的“待审核”属于冻结时的原文，批准状态以本段为准。

## 来源与范围

- 原有品牌和历史基准：[SOURCE: docs/execution/specs/2026-09-10-control-center-visual-baseline-design.md]
- Thread 与 Run 合同：[SOURCE: docs/execution/specs/2026-08-26-owner-thread-conversation-design.md]
- [批准的原型](../../assets/control-center/2026-09-15-v4/index.html)、[原始片段](../../assets/control-center/2026-09-15-v4/source.html)、[校验清单](../../assets/control-center/2026-09-15-v4/SHA256SUMS)。旧 v1 冻结资源继续保留。发生冲突时，本次批准的布局与交互优先。
- 本次是产品实现授权，不包含生产部署或推送。原型审核工具栏、模拟恢复、图标对照和演示计时不是产品控件，不进入正式页面。

## 验收要求

1. 新建立即进入可输入并聚焦的本地草稿。首次发送才持久创建会话；重复点击不创建空记录。旧刷新不能阻塞跳转或覆盖新页面；分会话保存草稿。发送失败保留内容，未知结果使用原幂等身份核对，不重复执行。
2. 左侧仅品牌、新建、搜索及单一历史滚动区。未归档会话按置顶与最近活动组织；没有活跃筛选、常驻刷新和管理菜单。失败提供重试。标题右键和省略号菜单包含重命名、置顶/取消置顶、归档；禁止删除、回收站及删除影响入口。
3. 右上角齿轮打开统一设置，分通用、工具与权限、会话与数据。语言、明暗/跟随系统主题和主题色集中管理；语言只影响界面。归档记录可查看及取消归档。无高级诊断、同步、摘要、修订、Thread ID、布局滑块或可见测试标记。
4. 全部输入字段采用中性、克制的焦点状态，输入与工具栏为一个容器；不出现紫色粗内框。保留键盘和高对比度可见焦点。
5. 联网搜索授权在工具与权限管理，保留原服务、范围与撤销合同；首次实际调用需要审批时在当前会话处理；“记住我的选择”默认选中，取消勾选只批准本次，拒绝不会开启持久权限。不再显示仅用于搜索授权的执行菜单。
6. 审批属于对应轮次；侧栏对应会话显示红点及可访问说明，无单独审批入口或汇总。批准前不执行，允许一次只执行一次，拒绝不执行。系统级授权留在相应设置。
7. 正常连接不显示绿点；短暂恢复安静处理，持续断开说明用户影响并保留草稿。无法确认执行进度不等于执行失败，恢复读取真实状态。
8. 模型列表只显示真实配置名称；单模型不提供多余子菜单。强度滑块只含真实支持档位，不显示重复强度标题和重置箭头。无可调档位时不伪造滑块。修改从下一次发送生效，不改变已发送或正在执行的配置。
9. 每轮保留可折叠过程、统一语义工具图标、用途、输入输出、状态和逐环节时间。时间来自持久化执行事件；等待审批、排队和执行不混算，缺可靠边界显示暂无时长；并行步骤不以相加替代整轮跨度。不得显示原始私密推理或编造摘要。
10. 取消通用详情栏；仅具体文件、引用或产物触发内容预览。不存在内容时不造预览入口。

## 视觉与数据边界

同状态、窗口、主题、字体和内容下逐项比较原型与产品截图；记录差异，不以测试通过替代视觉验收。以原型的中性配色、字号、间距、侧栏、输入框、设置弹窗和滑块为直接参照。模型名称、档位、消息、权限和时长演示值不能作为生产事实。Pi 负责模型能力与事件，Himawari 负责授权、持久化和展示，不新增平行模型协议。

## 验证策略

从打开页面起测试，覆盖配置慢、连接慢、刚出现就点击、旧请求延迟、切换、重复点击、断开恢复及数据归属；独立读回持久状态。复用现有 Vitest 与 Playwright 工具、浏览器测试服务器和真实后端集成测试。保持明暗、320/390/1024 桌面与手机、键盘、菜单、设置和执行过程检查；保留失败截图和 trace。原型与模拟服务器证据须与真实服务证据区分。

## 上下文压缩的实现核实

现有 `packages/runtime-pi/src/pi-runtime-adapter.ts` 已在 Pi 会话配置中启用 `compaction`，将 `compaction_end` 转为受保护的 `runtime.compaction_proposed`，恢复时依据产品保留消息标识调用 SessionManager 的压缩记录能力。此功能已经存在；v4 只移除面向普通用户的内部摘要/检查点面板，不另造上下文压缩器，也不将摘要记录当作用户备份。

## v5 增补：执行环境显示（2026-09-27 批准）

用户于 2026-09-27 在三个效果图方案中选择“输入框上方状态条”，并要求加上侧栏“有程序在运行”的灰色转圈标记。批准的原型保存为新版本：[v5 原型](../../assets/control-center/2026-09-27-v5/index.html)、[原始片段](../../assets/control-center/2026-09-27-v5/source.html)、[校验清单](../../assets/control-center/2026-09-27-v5/SHA256SUMS)。v5 只增加下列内容，其余布局与交互仍以 v4 为准。需求来源：[SOURCE: docs/execution/specs/2026-09-24-isolated-tool-execution-design.md#mode-disclosure]

1. 输入框上方一行小字：当前模式（“默认模式”或“严格模式”）和仍在运行的程序数量，没有时写“没有程序在运行”。点开弹出面板，再点或按 Esc 关闭。
2. 面板分三段：当前模式及含义（默认模式要说明停止只保证工具的进程组已结束）、仍在运行的后台或服务程序（工具名、类型、开始时间和所属对话，点对话名打开该对话）、严格模式下不可用的工具及原因。模式由安装配置决定，页面不提供切换。
3. 侧栏里有程序在运行的会话，名字前显示灰色转圈标记，与“待你确认”红点在同一位置；两者同时存在时显示红点。读屏软件读出“有程序在运行”。
4. 程序只显示工具名，不显示命令内容。原型中的程序、对话和时间是演示数据。
5. 不新增独立页面、设置页或通用详情侧栏。
