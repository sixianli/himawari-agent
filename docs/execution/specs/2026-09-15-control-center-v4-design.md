# 控制中心 v4 已批准交互与视觉基准

## 目标与确认

用户于 2026-09-15 明确批准本任务的 v4 原型，并授权按最新版重构正式页面，要求功能、UI 和 UX 与原型一致。本 Spec 保存该批准事实与此前多轮批示。原型中的“待审核”属于冻结时的原文，批准状态以本段为准。

## 验收要求

1. 新建立即进入可输入并聚焦的本地草稿。首次发送才持久创建会话；重复点击不创建空记录。旧刷新不能阻塞跳转或覆盖新页面；分会话保存草稿。发送失败保留内容，未知结果使用原幂等身份核对，不重复执行。
2. 左侧仅品牌、新建、搜索及单一历史滚动区。未归档会话按置顶与最近活动组织；没有活跃筛选、常驻刷新和管理菜单。失败提供重试。标题右键和省略号菜单包含重命名、置顶/取消置顶、归档；禁止删除、回收站及删除影响入口。
3. 右上角齿轮打开统一设置，分通用、工具与权限、会话与数据。语言、明暗/跟随系统主题和主题色集中管理；语言只影响界面。归档记录可查看及取消归档。无高级诊断、同步、摘要、修订、Thread ID、布局滑块或可见测试标记。
4. 全部输入字段采用中性、克制的焦点状态，输入与工具栏为一个容器；不出现紫色粗内框。保留键盘和高对比度可见焦点。
5. 联网搜索授权在工具与权限管理，保留原服务、范围与撤销合同；首次实际调用需要审批时在当前会话处理；“记住我的选择”默认选中，取消勾选只批准本次，拒绝不会开启持久权限。不再显示仅用于搜索授权的执行菜单。
6. 审批属于对应轮次；侧栏对应会话显示红点及可访问说明，无单独审批入口或汇总。批准前不执行，允许一次只执行一次，拒绝不执行。系统级授权留在相应设置。
7. 正常连接不显示绿点；短暂恢复安静处理，持续断开说明用户影响并保留草稿。无法确认执行进度不等于执行失败，恢复读取真实状态。
8. 模型列表只显示真实配置名称；单模型不提供多余子菜单。强度滑块只含真实支持档位，不显示重复强度标题和重置箭头。无可调档位时不伪造滑块。修改从下一次发送生效，不改变已发送或正在执行的配置。
9. 每轮保留可折叠过程、统一语义工具图标、用途、输入输出、状态和逐环节时间。时间来自持久化执行事件；等待审批、排队和执行不混算，缺可靠边界显示暂无时长；并行步骤不以相加替代整轮跨度。不得显示原始私密推理或编造摘要。2026-10-26 补充（Andy 要求看到“查了记忆、用到了什么”）：每轮开始前带给模型的记忆显示为两种步骤，“按这句话找到 N 条相关记忆”和“带上档案里的 N 条记忆”，展开是每条记忆的原文；只说带上了哪些，不推断模型用了哪一条；已删除或在回收站里的记忆不显示原文。2026-10-29 补充（事故 I-23，[ADR 0115](../../adr/0115-memory-search-relevance-threshold-and-retrieval-eval.md)）：只有相似度达到门槛的记忆才算“相关记忆”；一条都没有时整步不显示，档案为 0 条时同样不显示；档案步骤改名为“常驻档案 N 条（每轮都带）”。
10. 取消通用详情栏；仅具体文件、引用或产物触发内容预览。不存在内容时不造预览入口。

## 视觉与数据边界

同状态、窗口、主题、字体和内容下逐项比较原型与产品截图；记录差异，不以测试通过替代视觉验收。以原型的中性配色、字号、间距、侧栏、输入框、设置弹窗和滑块为直接参照。模型名称、档位、消息、权限和时长演示值不能作为生产事实。Pi 负责模型能力与事件，Himawari 负责授权、持久化和展示，不新增平行模型协议。

## 验证策略

从打开页面起测试，覆盖配置慢、连接慢、刚出现就点击、旧请求延迟、切换、重复点击、断开恢复及数据归属；独立读回持久状态。复用现有 Vitest 与 Playwright 工具、浏览器测试服务器和真实后端集成测试。保持明暗、320/390/1024 桌面与手机、键盘、菜单、设置和执行过程检查；保留失败截图和 trace。原型与模拟服务器证据须与真实服务证据区分。

## 上下文压缩的实现核实

现有 `packages/runtime-pi/src/pi-runtime-adapter.ts` 已在 Pi 会话配置中启用 `compaction`，将 `compaction_end` 转为受保护的 `runtime.compaction_proposed`，恢复时依据产品保留消息标识调用 SessionManager 的压缩记录能力。此功能已经存在；v4 只移除面向普通用户的内部摘要/检查点面板，不另造上下文压缩器，也不将摘要记录当作用户备份。

## v5 增补：执行环境显示（2026-09-27 批准）

用户于 2026-09-27 在三个效果图方案中选择“输入框上方状态条”，并要求加上侧栏“有程序在运行”的灰色转圈标记。批准的原型保存为新版本：[v5 原型](../../assets/control-center/2026-09-27-v5/index.html)、[原始片段](../../assets/control-center/2026-09-27-v5/source.html)、[校验清单](../../assets/control-center/2026-09-27-v5/SHA256SUMS)。v5 只增加下列内容，其余布局与交互仍以 v4 为准。需求来源：[2026-09-24-isolated-tool-execution-design.md「mode-disclosure」（已删除，链接指向删除前的版本）](https://github.com/sixianli/himawari-agent/blob/208007462f99e16c5c8cd4daac2acc10fa9f5f36/docs/execution/specs/2026-09-24-isolated-tool-execution-design.md#mode-disclosure)

1. 输入框上方一行小字：当前模式（“默认模式”或“严格模式”）和仍在运行的程序数量，没有时写“没有程序在运行”。点开弹出面板，再点或按 Esc 关闭。
2. 面板分三段：当前模式及含义（默认模式要说明停止只保证工具的进程组已结束）、仍在运行的后台或服务程序（工具名、类型、开始时间和所属对话，点对话名打开该对话）、严格模式下不可用的工具及原因。模式由安装配置决定，页面不提供切换。
3. 侧栏里有程序在运行的会话，名字前显示灰色转圈标记，与“待你确认”红点在同一位置；两者同时存在时显示红点。读屏软件读出“有程序在运行”。
4. 程序只显示工具名，不显示命令内容。原型中的程序、对话和时间是演示数据。
5. 不新增独立页面、设置页或通用详情侧栏。
   - 2026-10-28 改窄（Andy 同意，见 [ADR 0100](../../adr/0100-conversation-more-panel-files-and-background-commands.md#baseline-rule)）：只禁止堆放内部运行信息的通用栏或页面；有具体用途的新栏、新页面先出原型、经 Andy 批准，作为新版本记进设计基线后可以做。

<a id="v5-g74-wording"></a>

### 2026-10-12 措辞补充（G74）

用户在 2026-10-12（G74）反馈：一轮卡住时页面同时显示“没有程序在运行”和可点的“停止”按钮，看不出卡在哪里、这一轮是否还在进行。为此在 v5 上做两处只改文字、不改布局的补充；用户可以否决，否决时恢复上面第 1、3 条的原措辞：

- 第 1 条和第 3 条里的“程序”只指第 2 条定义的后台或服务程序（不包括本轮正在执行的单次工具），所以状态条改为“没有后台程序在运行”或“N 个后台程序在运行”，侧栏标记的读屏文字改为“有后台程序在运行”。英文、日文同步改。
- 当后端把这一轮显示为“结果未确认”时，这一轮的状态行下方多一行说明，写明卡在哪个工具、这一轮是否还在进行：这一轮还没结束时写“这一轮还在进行：正在等工具 read 的结果。工具已经交给执行环境，但还没确认它已经停下。”；这一轮已经结束时写“这一轮已经结束，但工具 read 的执行环境还没确认已经停下。”（示例中的 read 换成实际工具名）。用户能做什么仍由原有的下一步提示说明。

<a id="v5-quiet-environment-line"></a>

### 2026-10-25 状态条只在有事时出现

用户在 2026-10-25 指出状态条在单用户生产环境里始终显示“默认模式 · 没有后台程序在运行”，点开也只有固定说明，是摆设。为此改为：默认模式下没有后台或服务程序在运行时不显示状态条；有程序时显示“N 个后台程序在运行”，面板先列程序，再说明默认模式下停止只保证进程组结束，不再显示“模式由安装配置决定”和“默认模式下没有因为模式而不可用的工具”；严格模式照旧始终显示，状态条写“严格模式 · …”。读不到执行环境时不显示状态条。这一条替代上面第 1 条中“没有时写‘没有程序在运行’”和第 2 条中面板固定三段的写法。

## v6 增补：过程区时间条与葵盘标志（2026-10-26 批准）

Andy 于 2026-10-26 审 v6 原型时选定过程区“时间条”样式和“葵盘”标志，要求“每一步的时间一定一定要准确”，界面“必须要完美的支持中英日三种语言”，并去掉步骤行上的“最久”标签。决定和原话见 [ADR 0087](../../adr/0087-chat-ui-v6-process-timeline.md)。批准的原型保存为新版本：[v6 原型](../../assets/control-center/2026-10-26-v6/index.html)、[标志候选](../../assets/control-center/2026-10-26-v6/mark-options.html)、[校验清单](../../assets/control-center/2026-10-26-v6/SHA256SUMS)。v6 第一期只批准过程区和标志；原型里的回答框、输入区、侧栏和右侧文件预览属于第二、三期，审核后另行补充（见下面两节增补），在此之前仍以 v4、v5 为准。原型和截图里的消息、模型、耗时都是演示数据。

1. 一轮结束后过程区收成一行：总用时、按“模型 / 工具 / 等你确认 / 准备与衔接”四种颜色叠起来的细条、最久的一步。运行中保持展开，结束后自动收起；用户自己点开或收起过就按用户的选择。
2. 展开后每一步一行：图标、固定步骤文字加真实数据、对齐到同一时间轴的时间条、这一步的用时。步骤文字不由模型生成。同时进行的工具调用标“同时”；模型调用工具前说的话作为引文放在“思考”下面。步骤行上不标“最久”。
3. 展开区底部列出四类各用了多久和合计，并说明各项相加等于合计、同时进行的步骤只算一次。计时规则见 [ADR 0087 的“时间怎么算”](../../adr/0087-chat-ui-v6-process-timeline.md#timing)，它把上面验收要求第 9 条的“逐环节时间”具体化。
4. 标志改为 96 个圆点排成的葵盘，界面用内联 SVG；回答运行时缓慢转动，“减少动态效果”时关掉。品牌素材在 `assets/brand/himawari/v2/`，v1 原样保留。
5. 所有新增文字在 `zh-CN`、`en`、`ja` 三种语言里都有。

## v6 第二期增补：回答下方一行、来源、消息状态、模型选择和输入区（2026-10-26）

Andy 在 v6 原型上对回答框和输入区的批注，在第一期合并后作为第二期开发。决定和原话见 [ADR 0090](../../adr/0090-chat-ui-v6-answer-and-composer.md)。其余 v4、v5 和 v6 第一期要求不变。

1. 回答正文下面紧贴一行：复制（只复制正文）、“⋯”（里面是“从这里开新对话”）、灰色的模型、用时、时刻和 token 数；来源、记忆和文件卡片在这一行之后。
2. 来源默认收在“N 个来源”一行里，点开后每个来源一行。
3. 你的消息右下方显示时刻和状态（已送达、已开始处理），悬停亮出复制。

## v6 增补：附件支持图片（2026-10-27）

## v7 增补：手机对话页（2026-10-27 批准）

Andy 在 iPhone 上看对话页后提了六条意见，原型 <https://claude.ai/artifact/BGa1vxG7DHy9GQKBQLatSS> 于 2026-10-27 13:49（日本时间）审核通过。决定、原因和参考资料见 [ADR 0096](../../adr/0096-phone-chat-page-safe-area-and-quiet-answer-line.md)。下面几条改变了 [v6 第二期增补](#v6-answer-and-composer)里回答下方一行的写法，其余要求不变。

1. 回答下方一行：复制图标、“⋯”、灰色“用时 · 时刻 · N tokens”，不显示模型名，手机和电脑一样。

## v9 增补：品牌字样、侧栏、记忆页与提醒页（2026-10-28 批准）

Andy 在 2026-10-28 18:44–19:27（日本时间）提了 22 条界面意见，可点原型 <https://claude.ai/artifact/KYcGzu8DdXoLNUT8XuD8JL>（中英日三语，演示数据）由他逐条批注选定。下面分四组写，全部已实现，决定和取舍见 [ADR 0105](../../adr/0105-ui-batch-2026-10-28-show-what-the-owner-needs.md)。实现后的截图（中英日三语、电脑 1280 像素和手机 390 像素宽）存为基线 [`docs/assets/control-center/2026-10-28-v9/`](../../assets/control-center/2026-10-28-v9/SHA256SUMS)，其中的消息、记忆和文件都是测试用的演示数据。其余要求不变。

1. 品牌字样：侧栏 logo 旁写两行，上行英文“Himawari”（Outfit 600），下行假名“ひまわり”（Zen Maru Gothic 500）；两种字体只取用到的字形，随网页一起发布，不连外网字体服务。
2. 侧栏导航顺序：新对话、搜索、记忆、提醒、文件。“提醒”有到期的提醒时右侧显示一个小圆点，不写文字。
3. 对话右键菜单：重命名、置顶、归档三项，每项带图标，“归档”前有一条分隔线。
4. 记忆从设置里移出，成为侧栏打开的独立页面，标题栏左侧有返回。从回答下方“查看”打开时直接进入“全部记忆”，这一轮记下的几条在原位置高亮并标“刚记住”。
5. 记忆画像按类别分卡片，每张先显示 3 条，展开最多 8 条，再多时显示“查看全部 N 条”，跳到全部记忆并按该类筛选。
6. 记忆详情是标签和值两列对齐；“怎么变过来的”画成时间线，只显示最新 2 条和最早 1 条，中间折叠，每次展开 10 条；不是今年的时间带年份。
7. 提醒是独立页面，不再是记忆页的一个标签：先列已到期，再按今天、本周、以后分组，没有提醒时写一句空状态，底部链接到通知设置。提醒所挂的记忆如果是从某段对话里记下的，提醒下面显示“来源对话”链接，点开回到那段对话；手动添加、导入的记忆，或来源对话已删除的，不显示这个链接。
8. 所有新文字都有中文、英文、日文三份，按三种语言的不同长度检查过排版。

回答区（第二组）。下面几条改变了 [v6 第二期增补](#v6-answer-and-composer) 和 [v7 增补](#v7-phone-chat-page) 里过程区和回答下方一行的写法：

9. 过程区收起时只写一句话，说做了什么和一共用了多久，例如“搜索了 2 次网页，用时 13.1s”；最多写两类最多的工具步骤，没用工具时只写“用时 X”。不再显示分类时间条和“最久：…”。
10. 展开后每一步一行：小方框图标、步骤名、时间条、这一步的总耗时。耗时直接由这一轮执行记录的时间戳相减得出，不再显示“从第 X 秒到第 Y 秒”和分段明细。只有有内容可看的步骤（工具的参数和结果、记忆原文）能展开，右侧有小箭头；没有内容的步骤不能点。
11. 过程区最下面一行只写 Token 总数和“缓存命中 N%”（大模型 KV 缓存复用的输入占比，悬停有解释），不写费用和说明文字。
12. 回答下方只放操作：复制、“从这里开新对话”图标；时刻在鼠标移到回答上时才显示，触屏设备一直淡淡显示。耗时和 token 只在过程区里。原型里的“⋯”按钮没有做：“从这里开新对话”拿出来后菜单里没有别的操作，空菜单不放。
13. 来源收起时写前两个网站的域名和“+N”，展开后每行是标题、域名和外链小箭头，鼠标停在链接上显示完整网址。域名指可注册的主域名（例如 www3.nhk.or.jp 写成 nhk.or.jp，news.yahoo.co.jp 写成 yahoo.co.jp），按公共后缀列表（Public Suffix List，记录 .co.jp、github.io 这类“后缀”的公开清单）计算，由 `tldts` 库完成；IP 地址和 localhost 照原样显示。悬停时标题出下划线；不用首字母方块，也不从第三方取网站图标。
14. 给模型的回答规则加一条：加粗只用在最值得注意的一两处，不整句、整段加粗。

设置和欢迎页（第三组）：

15. 设置分四页：通用、通知（装了推送才有）、工具与权限、数据。记忆不再放在设置里（见第 4 条）。
16. 通用页：“怎么称呼你”（只存在这个浏览器里，最多 40 个字）、界面语言、外观（浅色 / 深色 / 跟随系统的小三段开关，带小图标）、主题色（一排色块，只有圆点是彩色，色名用正文颜色）。
17. 工具与权限页：“允许联网搜索”开关加一句用途；搜索服务会收到什么收在一个默认折叠的说明里；“先问你再做的操作”写明范围，标“固定开启”。
18. 数据页：已归档的对话，加一句“这个浏览器只保存界面语言、外观、称呼和未发送的草稿；对话和记忆都在你的服务器上”。原型里的“这台设备 · 退出登录”没有做：生产环境由 Cloudflare Access（网页前面的一道邮箱验证码登录）负责登录，网页里没有可以退出的会话。

20. 文件页的分类按钮是“图标 + 文字”（全部、文档、表格、网页、图片、代码）。第一次打开、还没有任何数据时显示骨架占位；之后刷新保留旧列表，拉到新数据再替换，不再闪。
