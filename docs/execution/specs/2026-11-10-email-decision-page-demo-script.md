# 一封邮件的决策一页：演示脚本

任务块 P1-5。面试里用一个画面同时展示三项护城河资产：可导出的个人决策数据、带出处的 Agent 规则手册、带来源可回滚的记忆事实层。功能说明见 [ADR 0197](../../adr/0197-one-page-for-one-email-decision.md)。

## 准备

- 打开控制中心的“提醒”页，切到“校准周报”。
- 现场演示用生产的真实数据：周报里差距案例的每一行有“查看这封邮件”。截至 2026-11-10，生产上最合适的一封是邮件 `1a1ab3c2a4871176`（2026-11-05，判断为 know，命中 1 条规则和 1 条记忆）；它是最近 100 条 Gmail 决策里唯一规则和记忆都有的（来源：Andy 在 Mac 上运行 `bash scripts/operations/prod-read.sh gmail-decisions` 的结果）。
- 注意：这个功能还没上线，生产上要先上线才能现场演示；而且截至 2026-11-10，生产上所有邮件配对的 Muse 条目数都是 0，Muse 对照那一块会如实显示“没有配对的 Muse 条目”，不会有数字。
- 录屏存档用的是演示数据（不是生产数据），画面底部有“演示数据”字幕。

<a id="steps"></a>

## 讲解步骤（约 2 分钟）

1. **起点：周报里的差距案例**（20 秒）。说：“这周 Himawari 和 Muse 在哪几封邮件上判断不一样，周报逐封列出来。”点其中一行的“查看这封邮件”。
2. **判断和评价**（20 秒）。说：“一页里先看这封邮件 Himawari 当时怎么判断的，处理时间，以及我自己后来的评价。”对应资产：**可导出的决策数据**。
3. **依据链：规则**（30 秒）。指着“命中的规则”：“它命中了哪条规则，规则是我设定的还是内置的，依据哪份文档（ADR），这封邮件用到的会标出来。”对应资产：**带出处和测试的规则手册**。
4. **依据链：记忆**（30 秒）。指着“用到的记忆”：“用到了哪条记忆，它的原话和来源对话，现在的状态；如果是推断出来的，还能展开它是从哪几条记忆推出来的。”点“看来源对话”，跳到原始对话。对应资产：**带来源可回滚的记忆**。
5. **那一周的数字和 Muse 对照**（20 秒）。指着右边：“这周的校准数字和 Muse 的逐封对照结论，同一个口径，和周报一致。”
6. **收尾**（10 秒）：“链上每一环都能点到原始记录；没有记录的地方明说‘无记录’，不留空白。”

<a id="limits"></a>

## 这一版的局限

- 页面入口只在周报的差距案例行；每日复盘和审计列表里的条目没有邮件编号，暂时进不去。
- 没有跳转 Gmail 原文的链接；邮件正文不进控制中心。
- 录屏是演示数据；生产真实数据的录屏要等功能上线、Muse 配对有数据后补录。
