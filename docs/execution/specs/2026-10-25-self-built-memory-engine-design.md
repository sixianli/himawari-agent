## 目标

把记忆从“一堆句子加向量”升级为分层、带时间、会整理、能触发行动的结构，全部放在现有 SQLite 主库里。保留 PR #16 和 PR #17 已有的把握分、敏感审批、加密存储、确认卡和记忆页。

不做：图数据库、独立向量服务、每轮第二次模型调用（Cindy 曾在每次回复后再复盘一次，2026-10-23 已停用）。

<a id="data-model"></a>

## 数据模型

迁移 `0052_memory_engine.sql`（expand）。

`memory_records` 新增列：

| 列 | 含义 |
| --- | --- |
| `category` | `identity`、`preference`、`relationship`、`goal`、`project`、`rule`、`health`、`finance`、`event`、`other`；旧记录为 `other` |
| `importance_permille` | 0–1000，提炼时给出；旧记录为 500 |
| `valid_from` / `valid_to` | 事实在现实中何时成立；`valid_to` 非空且早于现在即视为失效 |
| `superseded_by` | 被哪条记忆更正（阶段二启用） |
| `use_count` | 被选进上下文的次数 |
| `evidence_verified` | 写入时是否核对过主人原话 |

新表：

- `memory_entities(memory_id, name)`：记忆里提到的人、地点、项目、物品。只存 `public` 和 `private` 记忆的实体，`sensitive` 以上不存，避免明文关键词落盘。
- `memory_search_index`：每条记忆一行，记录已索引的修订号、嵌入模型、维度和向量（小端 float32 BLOB，已归一化）。删除行时触发器同步删除全文索引行。
- `memory_history_events`：每条记忆的每次变化一行（迁移 `0065_memory_history.sql`，见 [ADR 0113](../../adr/0113-memory-history-events-and-stance.md)）。只追加；删对话时保留原话摘录和文字，只清空来源对话并标记“来源对话已删除”；删记忆时整条历史连同摘录一起删。
- `memory_search_terms`：FTS5 contentless 表（`content=''`、`contentless_delete=1`），只存分词后的倒排索引，不存原文。`sensitive` 以上的记忆不进全文索引。

向量用普通 BLOB 列而不用 `vec0` 虚拟表，原因见 [ADR 0075 的比较](../../adr/0075-self-built-memory-engine.md#options)：没加载扩展的工具也能正常打开和计数主库。

<a id="write-path"></a>

## 写入

在现有提炼调用上改动，不增加调用次数：

1. 同一次调用多要五个字段：`category`、`importance`、`entities`、`validFrom`（按消息发送时间换算的日期，没有就是 null）、`quote`（主人原话里支撑这条记忆的一段，原样摘抄）。
2. 原话核对：`create`、`update`、`merge` 的候选必须带 `quote`，宿主把引文和主人消息都做空白与全半角归一后检查包含关系，且引文至少 8 个字（消息本身不足 8 个字时取整条消息）。核对不过的候选不保存，审计结果记为 `evidence_unverified`。`unchanged` 也要求模型给引文（用于变化历史），但核对不过时不丢弃这条判断，只是不保存引文。
3. 嵌入和全文索引在同一个后台投影任务里写，沿用现有的投影任务、租约和重试。
4. 阶段二起，更正不再覆盖旧文本：旧条写上 `valid_to` 和 `superseded_by`，新增一条。
5. 每次变化（新记住、补充细节、又说了一次、主人手动改、换回）在 `memory_history_events` 追加一行，存当时的文字、立场标签 `stance`、原话摘录和来源对话；“补充细节”不再丢掉旧文字。立场标签由同一次提炼调用给出。决定见 [ADR 0113](../../adr/0113-memory-history-events-and-stance.md)。

<a id="recall"></a>

## 召回

1. 分词：`Intl.Segmenter('zh', { granularity: 'word' })` 取词，转小写；三个字以上的中文词再补二字切片（“杭州市”补“杭州”“州市”），让“杭州”和“杭州市”能互相命中。查询侧去掉“我”“的”“了”“主人”等停用词。
2. 三路并行：
   - 向量：查询嵌入与所有当前有效记忆的余弦相似度，取前 50；相似度低于下限的丢弃。
   - 全文：FTS5 `bm25` 取前 50。
   - 实体：记忆实体名出现在查询原文里的。
3. 融合：`RRF = Σ 1 / (60 + 名次)`，再乘以 `1 + 0.2 × (重要度 − 0.5) + 0.1 × (把握分 − 0.5) + 0.1 × 新近度`，新近度按最近一次使用或更新时间、90 天半衰期计算。系数用评测集调，不凭感觉定。
4. 默认只取当前有效的事实；阶段二起问历史时带上已失效的。
5. 嵌入失败时退回全文和实体两路，并在 Session Trace 里记录退化。
6. 阶段二给智能体加 `recall` 工具，并支持“上周”“去年春节”这类时间范围。

<a id="profile"></a>

## 常驻档案和规矩

每轮上下文形成时，先放规矩，再放主人档案，然后才是检索到的事实。

- 规矩：`category = rule` 的当前有效记忆，按重要度排序。
- 档案：`identity`、`preference`、`relationship`、`goal`、`project` 类、重要度不低于 600 的当前有效记忆，按类别分节、节内按重要度和记忆编号排序，保证内容稳定以命中提示缓存。
- 两者合计上限 2000 字，超出按重要度截断；只收 `public` 和 `private`，且不超过本轮上下文的数据分级。
- 档案文本加密存为 Payload，按内容哈希命名，内容不变就复用同一份。
- 已经常驻的记忆不再重复出现在检索结果里。
- 阶段二在记忆页显示和编辑档案；阶段三夜间重建档案，每句链回来源事实。
- 2026-10-29 起（[ADR 0112](../../adr/0112-memory-page-carried-memories-and-topic-browsing.md)）：主人可以在任意一条记忆上打开或关掉“每次对话都带上”，选择存在 `memory_profile_pins` 表。打开的条目不看重要度，排在自动挑选前面（事件、健康、财务、其他类不能打开；敏感记忆自 [ADR 0193](../../adr/0193-memory-is-visible-to-the-model.md) 起可以打开，也会进档案）；关掉的条目不再进档案。2000 字放不下的条目和已用字数会返回给记忆页。手动添加的记忆重要度改为 500（要求类 800），不再自动进档案。提取时，家人朋友是谁（名字、关系、职业、所在城市）和主人定的做事要求标为 `private`，别人的健康、钱、感情、行踪等私事仍标为 `sensitive`。

<a id="embedding"></a>

## 嵌入

- 继续用 Qwen3-Embedding-8B（Vercel AI Gateway，OpenAI 兼容接口 `POST /v1/embeddings`）。Pi 没有嵌入能力，产品自带一个最小的嵌入客户端，只发 `model`、`input`、`dimensions` 三个字段。
  - 2026-11-11 起默认改为在本机算向量（jina-embeddings-v5-text-small 的 int8 量化版），Qwen3-Embedding-8B 保留为可选，见 [ADR 0224](../../adr/0224-memory-embedding-runs-on-the-host.md)。
- 每次物理请求照旧走模型准入、预算预留、开始标记和结算，网关返回的用量和费用必须齐全。
- 维度由配置的 `modelDescriptors.embedding.dimensions` 和 `memory.dimensions` 决定，允许 1024 或 4096，默认保持 4096。官方没有公布 1024 维的分数，Andy 不希望效果变差：阶段一在评测集上对比 4096 和 1024 两档，并实测网关确实返回 1024 维，确认没有损失才改配置降维。索引行记录模型和维度，配置变了会自动重建索引。

<a id="migration"></a>

## 迁移和回滚

- 启动时，如果有当前有效记忆还没有对应修订、模型和维度的索引行，就为它们重新排投影任务，由后台逐条补齐。补齐前这些记忆只能通过全文和实体两路命中。
- 旧记录的 `provider_record_id` 是 Mem0 的编号，新引擎投影后改为 `memory-index:<记忆编号>`。
- 回滚到旧版本：旧版本仍按 Mem0 文件检索，本版本不动这些文件；数据库新增的列和表旧版本不读。旧 Mem0 文件在确认不再回滚后的下一次上线删除。

<a id="evaluation"></a>

## 评测集和关口

评测数据在 `test/fixtures/memory-evaluation/dataset.json`，评测在 `test/integration/memory-evaluation.test.ts`（要用真实 SQLite 主库，所以放在集成测试里）：

- 一个虚构主人的 155 条记忆（身份、家人、偏好、规矩、目标、事件、成对的新旧事实、已过期的事实和 50 条干扰项），100 道中文问题，按 LongMemEval 的 5 项能力分组：信息提取 30、跨会话推理 20、知识更新 20、时间推理 15、拒答 15。
- 指标：Recall@5 和 MRR，按能力分别报；知识更新和时间推理另报“不被旧事实抢先”的比例（旧事实或已过期事实不排在正确事实前面；没有正确事实的题要求旧事实不进前 3）。
- 拒答：检索层永远返回前 5 条，“该不该拒答”要看回答，阶段一只量检索层能做的部分：能让回答说出“你没提过儿子，只提过女儿”的那条相近记忆有没有召回。回答层的拒答评测随阶段二的回答评测一起做。
- 基线：Mem0 3.3.1 开源版在 `infer: false` 下的行为，即对全部记忆做纯余弦相似度取前 k、阈值 0、不看有效期。
- 嵌入用生产同款模型实际调用一次后缓存成 `embeddings-4096.json` 和 `embeddings-1024.json`（半精度），由 `scripts/memory-evaluation/embed-dataset.mjs` 生成，评测离线可重复运行。没有缓存文件时评测退回词项哈希向量，只作结构回归，不作关口依据。
- 阶段一关口：新引擎每一类的 Recall@5 和“不被旧事实抢先”比例都不低于基线。
- 同一评测分别用 4096 维和 1024 维嵌入跑新引擎；1024 维每一类每项指标都不低于 4096 维才降维。报告写到 `.ci-output/memory-evaluation/report.json`。

<a id="phases"></a>

## 四个阶段

| 阶段 | 内容 | 关口 |
| --- | --- | --- |
| 一 检索换底 | 评测集和 Mem0 基线；三路混合检索；记忆表新字段；常驻档案和规矩；原话核对；迁移现有记忆并去掉 Mem0 | 评测分不低于 Mem0 基线 |
| 二 档案与情景 | 记忆页查看、编辑档案并显示变化；更正改为旧条失效加新增，记忆页显示历史；按天的情景摘要（复用 Pi 压缩摘要）；时间范围查询；`recall` 工具 | 知识更新、时间推理两类题明显提升 |
| 三 后台整理 | 每晚整理：用水位只读新增对话，没有新对话不调模型；合并重复、处理冲突、重建档案；每次运行登记、每条改动存前后内容可逐条撤销，模型思考期间被主人改过的跳过；反思结果标“推测”走确认卡；规矩“观察一次、再出现或主人同意才生效”；低重要度长期不用的降权或归档，不删除 | 一周真实使用没有误改、误归档 |
| 四 主动行动 | 承诺、计划、纪念日写入待办表，到点经 `SchedulerService` 和 `SuggestionService` 生成提醒推到各端；可选评估本地嵌入模型 | — |

<a id="risks"></a>

## 风险

| 风险 | 应对 |
| --- | --- |
| 自研检索不如 Mem0 | 关口卡住：评测不超过基线不上线 |
| 全文索引和向量是明文衍生物 | `sensitive` 以上不进全文和实体索引；全文表不存原文；向量本来就在 Mem0 里存过且 Mem0 还存了明文，新方案不增加暴露 |
| 常驻档案写错一句，每轮都错 | 档案只由当前有效记忆拼成，主人在记忆页改记忆即改档案；阶段二起显示档案变化 |
| sqlite-vec 仍是 1.0 前版本 | 锁定 0.1.9；扩展加载失败退回 JavaScript 计算；索引随时可从正文重建 |
| 更正和失效判断出错 | 失效不删，记忆页可恢复；低把握冲突进“待你确认” |
