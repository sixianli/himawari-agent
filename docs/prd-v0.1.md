# Himawari Agent 产品需求

## Goals

- 构建一个长期存在、持续了解所有者并能代表所有者使用工具的私人通用 Agent。
- 让个人资料、偏好、习惯、备忘录、日程、物理世界信息以及收藏的外部内容在相关情境中主动参与判断，而不是被动存档。
- 让用户消息、定时任务和外部事件作为同一决策循环的不同触发来源。
- 允许网页、桌面、命令行、移动设备、带屏小设备和纯语音终端访问同一个 Agent，而不把产品绑定到某一种 UI。
- 在主动服务、长期自治与所有者控制之间建立明确边界，使 Agent 不能自行扩大权限或隐藏执行过程。
- 让所有者能够查看每个 Session 中系统可观察到的完整执行过程。
- 让部署位置、模型提供商、记忆后端和具体客户端保持可替换。

## Target Users

- 首要用户是 Agent 的单一所有者；所有长期私人状态都归属于该所有者。
- 如果未来提供多用户托管服务，每位用户拥有彼此隔离的私人 Agent。
- 家庭或团队需要共享能力时，使用独立的共享 Agent 或共享空间，不与私人 Agent 的完整记忆混用。

## Scope

### Included

- 一个持续存在的主 Agent 身份，以及多个彼此独立但共享长期私人状态的对话或任务线程。
- 用户消息、定时器和外部事件触发的统一运行模型。
- 可替换长期记忆服务的接入，以及相关记忆对当前决策的主动影响。
- 受控的内部专业工作单元，用于研究、编程、规划等任务。
- 工具、Skills、MCP、本地程序和第三方 API 等能力的发现、审批、启用、更新、停用和审计。
- 本地模型、云端模型和专业模型之间受策略约束的选择与降级。
- 一次性审批、长期授权、费用和频率边界、撤销以及无 UI 时的等待行为。
- 后台持续任务、统一结果收件箱、摘要、普通通知和高优先级打断。
- 每个 Session 的完整可观察时间线、长期保留、归档、查询和所有者控制的删除。
- 用户控制设备、自托管服务器和第三方云之间可迁移的部署方式。
- Agent 对自身代码、配置和能力提出候选改进并在隔离环境验证的能力。

### Excluded

- 自行重新发明长期记忆数据库、召回算法或知识图谱引擎。
- 将产品固定为 Pi 原生终端 UI、某个网页 UI、某个桌面 UI 或某种语音设备。
- 让同一个 Agent 身份以多个互相竞争的权威实例同时执行外部行动。
- 让多个所有者无边界地共享同一个私人 Agent 的全部记忆和权限。
- 让模型直接批准自己的行动、安装任意代码、修改安全信任根或使自身改动自动上线。
- 将产品长期协议、数据模型或权限边界直接等同于某个上游项目的实验性接口。
- 在本版本中锁定具体记忆产品、模型提供商、数据库、事件总线、云厂商或最终 UI 技术。

## Business Rules

### Ownership and identity

- 一个私人 Agent 只能有一个所有者。
- 任意时刻，一个 Agent 身份只能有一个逻辑权威实例。
- 一个 Agent 可以拥有多个线程；每个线程维护自己的短期上下文，但共享所有者资料、长期记忆、目标和授权。
- 一次具体推理和工具执行必须归属于一个可识别的运行记录。

### Memory and context

- 长期记忆必须在当前情境相关时主动影响问题澄清、建议、回答和行动计划。
- 用户消息、定时任务和外部事件必须进入同一种“形成情境、检索相关记忆、判断、响应或行动”的处理模式。
- 具体记忆后端必须可替换；产品行为不能依赖某一供应商专有的数据模型。
- 所有者必须能够纠正或删除长期记忆；记忆来源和使用情况必须可追溯。

### Proactivity and authorization

- Agent 可以主动发现机会并提出持续任务，但不能根据一次模糊偏好静默创建永久任务。
- 持续任务必须经过一次性批准，或命中包含范围、工具、频率、费用、有效期和撤销方式的长期授权。
- 授权范围内的重复执行不需要每次询问；任何越界都必须重新审批。
- 安全且范围明确的操作可以自动执行；需要确认的操作必须暂停；被禁止的操作必须拒绝。
- 没有可用 UI 时，需要确认的操作必须保持等待或进入审批队列，不能自动升级为允许。

### Agent topology and capabilities

- 所有者始终与一个主 Agent 交互。
- 内部专业工作单元默认是临时且受限的，只获得完成任务所需的最小上下文、工具、时间和费用预算。
- 内部工作单元不能绕过主 Agent、授权规则或审计系统，也不默认拥有独立的个人长期记忆。
- Agent 可以发现并推荐新能力；安装、升级、首次授权、来源变化和权限扩大必须经过所有者批准。
- Agent 可以生成和验证自身改动，但不能自行修改或绕过身份、权限、秘密、审计和升级信任根，也不能自行让候选版本生效。

### Models and data protection

- 主 Agent 使用一个主要推理模型保持整体行为一致，受限子任务可以路由到其他专业、本地或备用模型。
- 模型切换不能静默降低隐私等级或扩大数据披露范围。
- 普通记忆可以由授权运行时按需解密；第三方模型只接收当前任务所需的最少上下文。
- 密码、API Key、访问令牌和私钥必须与模型上下文和 Session Trace 分离。
- 第三方云可以托管核心状态，但系统必须明确其真实信任边界，不能在没有可验证机制时宣称绝对零知识。

### Attention and delivery

- 后台结果必须经过统一的注意力规则，被归类为静默记录、收件箱、摘要、普通通知或立即打断。
- 不同客户端只负责交付结果，不能各自对同一事件作出互相矛盾的优先级决定。
- 立即打断只能用于所有者明确授权的高优先级条件。

### Session visibility and lifecycle

- 所有者必须能够按 Session、轮次和运行查看系统可观察到的完整过程。
- 可查看内容包括触发、上下文组装、记忆检索、模型调用、工具调用、内部委派、策略判断、人工审批、状态写入、外部行动、错误、重试和补偿。
- 完整过程不包括模型服务商内部不可观察的计算或隐藏思维过程。
- 凭证明文不得写入 Trace；Trace 只记录所使用秘密的引用、版本、用途和结果。
- Session Trace 默认长期保留，除非所有者主动删除或设置明确的清理策略。
- 老记录可以归档，但必须仍能恢复查看；删除后只允许保留不含原始内容的最小审计墓碑。

### Deployment and engineering quality

- 默认部署在所有者控制的设备或自托管服务器上，同时允许第三方云托管。
- 部署位置变化不能改变 Agent 身份、所有权、授权和审计语义。
- 开发时间和代码生成量不作为选择较弱架构的理由；仍必须控制一致性、安全、迁移、运维和验证风险。
- 本地组合部署与云端拆分部署必须使用同一组产品边界，不能形成两套行为不同的产品。

## Acceptance Boundaries

### Reference journey

- Given 所有者告诉 Agent“我喜欢吃牛肉”，when 该信息被确认需要长期保留，then 它成为可追溯、可纠正和可删除的长期记忆。
- Given 所有者在新线程中说“我今天想出去吃饭”，when Agent 形成当前情境，then 它主动检索并使用“喜欢吃牛肉”和当前位置等相关信息，而不要求所有者重复说明。
- Given Agent 发现持续监控餐厅可能有价值，when 尚无适用长期授权，then 它只能提出任务及边界，不能静默创建。
- Given 所有者批准任务范围、频率、工具和通知方式，when 定时器之后触发，then Agent 可以在授权范围内完成研究而不重复询问。
- Given 研究结果不紧急，when 任务完成，then 结果进入所有者配置的收件箱、摘要或普通通知，而不是擅自打断。
- Given 所有者要求预订餐厅，when 行动会产生外部副作用，then 系统展示具体时间、人数、费用和目标，并在没有覆盖该行动的授权时请求确认。
- Given 工具需要凭证，when 行动执行，then 模型和 Session Trace 都看不到凭证明文。
- Given 所有者从另一个客户端打开同一线程，when 权威服务可用，then 可以继续交互并看到一致状态。
- Given 所有者打开 Session 详情，when 查看任意一轮，then 可以追踪记忆检索、模型调用、工具调用、内部委派、人工审批和外部结果之间的因果关系。

### System-wide boundaries

- 任意客户端不能绕过权威服务直接改变长期状态或授权。
- 任意内部工作单元不能获得超出任务委派范围的私人上下文或工具权限。
- 任意模型或工具故障不能导致需要确认的操作被自动允许。
- 任意模型降级不能静默扩大数据披露范围。
- 任意 Agent 自我修改不能未经所有者批准进入正式运行环境。
- 任意详细 Trace 删除操作必须覆盖主存储、搜索索引、缓存和归档，并报告第三方副本的清理状态。
