# ADR 0032：原目录模式的磁盘保护与敏感文件遮挡范围

## 背景

[ADR 0031](0031-isolated-tool-execution.md) 决定让会产生副作用的工具在任务级隔离环境（每轮对话一个容器）里运行，并要求 CPU、内存、进程数、时长和“磁盘 / workspace 额度”都能强制；做不到时拒绝相应执行模式。它还要求授权目录里的敏感文件（例如 `.env`、私钥）即使位于授权目录下，也不能被任务随意读取。

“原目录模式”是指把用户批准的真实目录直接挂进容器，容器里写的内容会真实写回宿主；另一种“工作副本模式”是在副本里运行，结果按版本比较规则发布回去。

2026-09-25 在 Mac（OrbStack 2.2.3）和 Linux（Hermes，Docker 29.6.1）上实测，结论见 [P0 平台探针记录](../../test/qualification/evidence/isolated-tool-execution/p0-platform-probe-01/README.md#host-mount-gate)：

- 两个平台的容器运行时都没有给挂载目录限额的选项。容器向挂载目录写入 96 MB 没有被拦截；Hermes 上的 `--storage-opt` 选项被接受，却没有生效。macOS 的 APFS 文件系统不能给任意目录设额度。Linux 的 ext4 项目配额（按目录树统计用量）需要改动服务器文件系统设置，本次没有采用。
- 按路径遮挡敏感文件（创建容器时用空文件或空目录盖住它们）对已知路径有效，但有两个漏洞：同一文件在授权目录里的另一个硬链接名（硬链接是指向同一份文件内容的另一个文件名），以及容器启动后才新建的敏感文件。

[Spec 的平台门禁](../execution/specs/2026-09-24-isolated-tool-execution-design.md#host-mount-gate)规定这种情况由用户选择。用户在 2026-09-25 作出了下面两项决定。

<a id="decision"></a>

## 决定

1. **原目录模式的磁盘用量采用非硬性保护，不要求硬性额度。** 做法：由宿主一侧的可信组件，在准入时和运行期间检查工作目录所在磁盘的剩余空间，不低于设定的下限；同时按固定间隔观察增长，剩余空间跌破下限或增长过快时，按原有停止顺序整体停止环境。这种保护允许在两次观察之间超出，超出量取决于观察间隔和写入速度，产品和文档都不能把它说成硬性额度。宿主一侧的观察无法运行或读不到数据时，不启用原目录模式（失败即拒绝）。
2. **其他资源限制保持硬性。** CPU、内存、进程数、硬期限，以及任务私有的临时目录、HOME 和缓存的额度，仍按 ADR 0031 由运行时强制；实测任务私有临时目录（内存文件系统）的额度在两个平台都有效。工作副本模式保持有容量上限。
3. **原目录模式只遮挡创建环境时已存在的敏感文件。** 创建环境前，宿主一侧检查受保护的文件：只要其中有文件的硬链接数大于 1，就拒绝原目录模式，因为按路径遮挡盖不住另一个硬链接名。环境运行期间，用户或宿主上的其他程序在授权目录里新建的敏感文件不会被遮挡，本轮任务能读到。这是已知且被接受的限制，授权目录的审批内容必须向用户明确说明这一点。

<a id="amendments"></a>

## 与 ADR 0031 的关系

本 ADR 只部分修正 ADR 0031，不整份替代；0031 的其余决定继续有效。

| ADR 0031 的原要求 | 继续有效 | 本决定修正的范围 |
| --- | --- | --- |
| [最小权限与失败关闭](0031-isolated-tool-execution.md#security)中 Resources 一行：磁盘 / workspace 额度必须可强制，否则拒绝相应执行模式 | CPU、内存、进程数、时长和任务私有存储的硬性限制；不能把进程采样当作硬资源边界 | 仅对原目录模式下挂进容器的用户工作目录，允许用非硬性磁盘保护代替硬性额度；保护本身不可用时仍拒绝 |
| 同一节 Filesystem 一行：授权目录中的敏感文件仍需保护 | 创建时已存在的敏感文件必须被遮挡；遮挡不住（例如有多个硬链接）就拒绝原目录模式 | 运行期间新建的敏感文件不在遮挡范围内，改为在审批时明确告知 |

<a id="consequences"></a>

## 比较过的方案与后果

| 方案 | 判断 |
| --- | --- |
| 两个平台的普通命令都改用有容量上限的工作副本 | 未采用；安全性更强，还能顺带排除敏感文件，但大仓库要先复制，占用额外时间和磁盘，并改变工作区 Spec 中“普通命令不被强制转入副本”的约定 |
| Linux 开启文件系统项目配额，Mac 用工作副本 | 未采用；需要改动服务器文件系统设置（通常要重新挂载数据盘，影响正在运行的服务），而且本次没有实测 |
| 运行期间监视授权目录，出现新的敏感文件就停止环境 | 未采用；发现之前任务仍可能已读到内容，并不是硬性防护，还要额外实现目录监视 |
| 授权目录只要有或可能出现敏感文件就改用副本 | 未采用；多数项目目录都会走副本，与保留原目录运行的目的相反 |
| 非硬性磁盘保护 + 遮挡创建时已存在的敏感文件 + 审批时告知限制 | 采用 |

**后果**：
- 原目录模式下，失控的写入仍可能在被发现之前写满一部分磁盘，影响宿主上的其他程序。剩余空间下限和观察间隔要足够保守，并在 Spec 中规定具体数值和验收方法。
- 用户在任务运行期间往授权目录里放入的敏感文件会被任务看到。
- 这两项都必须在产品界面和文档中如实说明，不能表述为硬性保证。
