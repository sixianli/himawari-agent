# ADR 0113：每条记忆的每次变化都留一条历史记录，记忆页画出完整变化

<a id="context"></a>

## 背景

2026-10-29 12:12 JST，Andy 在不同对话里来回说了很多次“想出去玩”“不想出去玩”，然后打开记忆页，记忆“主人最近一个月都不想出去玩”的历史只显示 2 版。他希望看到“这一小块记忆这么多年来是怎么变化的”，而且是完整的时间线。

生产库只读查询（[事故 I-20](../incidents-and-gates.md#incidents)）显示这条记忆的替换链其实有 3 版（10:39、12:07、12:10 JST）。代码里找到的原因：

- 记忆页只取“被当前这条直接替换掉的”上一版，不沿着链往前走，所以第三版之前的都看不到。
- 自动记忆（模型从对话里提取记忆）判断为“补充细节”（`update`）时，直接把记忆的正文换成新文字，旧文字没有任何地方保留。
- 判断为“意思没变”（`unchanged`）时什么都不记，所以“又说了一次”在历史里没有痕迹。
- 对话被永久删除时，记忆的来源对话被清空，页面把空来源当成“每日整理”显示，写错了来源。

按 [产品愿景](../product-vision.md) 的顺序，“记忆可靠”排在“主动和效率”前面：中间版本不能丢。

<a id="decision"></a>

## 决定

1. 新增只追加的表 `memory_history_events`（迁移 `0065_memory_history.sql`，#99 先占用了 0063 和 0064）：一条记忆的每次变化写一行，种类是新记住（`created`）、补充细节（`updated`）、又说了一次（`reaffirmed`）、主人手动改（`edited`）、换回（`restored`）。每行存当时的文字、立场标签、主人原话摘录、来源对话和时间。替换（旧记忆被新记忆取代）沿用现有的 `superseded_by` 链，链上每条记忆都有自己的历史行。已有记忆在迁移时各补一行“新记住”；迁移前已被覆盖的旧文字找不回来。
2. 记忆加一个立场标签 `stance`（不超过 16 个字，例如“想出去玩”“不想出去玩”），由提取记忆的模型在同一次调用里给出，不另外调用模型；“意思没变”时沿用原标签。记忆提取策略版本升到 `memory-capture:v4`。
3. 每次判断都要求模型给出主人原话摘录（至少 8 个字、必须真的出现在主人消息里，最多保留 300 字）；敏感记忆不存摘录。
4. 网页按 Andy 2026-10-29 14:07 JST 在原型上选的方案：记忆页点开一条记忆，立场只有 2–4 种时画“两条线图”（每次变化一个点，横轴是时间），下面列最近 3 次变化，更早的折叠在“展开更早的 N 条”里（方案 A）；变化记录页每次变化一行，只写“现在是：……·第 N 次变化”，不再用“旧 → 新”箭头串（方案 C）。
5. 对话被永久删除时，原话摘录和每次变化的文字都保留，来源显示“来源对话已删除”，不能再点开。Andy 2026-10-29 15:46 JST 在选择卡上选了“做，删对话后保留摘录”（卡片推荐的是一起删，他没有采纳）。删除这条记忆本身时，整条历史连同摘录一起删除。
6. 回答时召回记忆仍只用每条链的最新版本，历史只给主人看，不进模型上下文。
7. 记忆提取的日志补两种结果：模型回答“没什么可记”记 `nothing_to_remember`，模型给出的候选因格式不对或指向它没看到的记忆而被丢弃记 `candidate_invalid`。以前这两种情况不留任何日志，所以查不清 Andy 大部分轮次为什么没写入。

<a id="options"></a>

## 比较过的方案

### 方案一：只追加的历史表（采用）

- 好处：每次变化都有完整快照，旧文字不再丢；删除对话、删除记忆时可以精确清掉对应的原话和文字；召回逻辑不变。
- 代价：多一张表和一次迁移；每次“意思没变”也写一行，数据量随对话增长（每行几百字节，未测量实际增长）。

### 方案二：“补充细节”也改成新建记忆再替换旧的

- 好处：不用新表，链上每个节点都是一条记忆。
- 代价：“又说了一次”和“换回”仍然没法记；记忆条数膨胀，召回和去重都要处理更多已替换记录。

### 方案三：只修网页，沿着替换链往前走

- 好处：改动最小。
- 代价：只能找回 Andy 这条的第三版；“补充细节”覆盖掉的文字和“又说了一次”仍然丢失，不满足“完整时间线”。

### 立场标签：模型给出（采用）对比网页端自己归类

网页端用文字相似度自己分组不可靠，同一立场的不同说法会被分成很多组；在已有的提取调用里多要一个短字段，不增加模型调用次数。

<a id="consequences"></a>

## 后果

- 好处：以后每次变化都能看到；来源对话删了也不会写错来源；时间线不会变成一长串箭头。
- 坏处：迁移前已经被覆盖的旧文字找不回来；没有立场标签的旧记忆只显示折叠列表，不画线图。
- 后续：
  - Andy 当天大部分“想/不想”轮次根本没写入记忆（全天只有 5 次提取写入），原因由只读日志诊断继续查；查明后再决定是否给“没写入”的轮次也留节点并写明原因。
