# ADR 0112：“档案”改为“每次对话都会带上的记忆”，由 Andy 决定带不带；记忆页只留“记忆”和“变化记录”两个标签

## 背景

2026-10-29（日本时间），Andy 连着问了几件事，要求把记忆页当作产品的核心功能整体重想，不要一处一处补：

- “档案”到底是什么？它和记忆是什么关系？为什么档案能单独编辑？
- 哪些记忆能进档案，谁来分类，是不是全凭大模型？进档案的应该是和他密切相关的信息。
- 每行后面的“新”标签有什么意义？
- 如果有 100 个类、每类 100 条，页面怎么显示？
- “全部记忆”里大类、小类、状态三行筛选按钮关系不清，用户会困惑。
- 一条记忆改过很多次，用一个箭头连起来不好看。这一条交给记忆历史线程，本 ADR 不涉及。

本线程先调研，再按[产品愿景](../product-vision.md)核对，然后发了可切换的原型 <https://claude.ai/artifact/EY7f1dkgB7zypskUoQ1dzo>。原型有方案 A、B、C，可切电脑和手机、13 条和 1 万条两种数据量、中英日三种语言。Andy 在原型上批注“选方案A”。原型存为基线 [`docs/assets/control-center/2026-10-29-v12/`](../assets/control-center/2026-10-29-v12/SHA256SUMS)。

## 改之前代码里的档案是什么

下面几点是读代码得出的，不是推测：

- 档案不是另存的一份资料。`OwnerProfileService`（`packages/application/src/services/owner-profile-service.ts`）每一轮对话开始前，从当前有效的记忆里现挑一遍，放进给模型的上下文。所以在档案里改一行，改的就是那条记忆本身。
- 挑选规则写死在代码里，有四条：类别是身份、偏好、人际、长期目标、进行中的事之一；重要度不低于 600（满分 1000）；不是敏感记忆；总长不超过 2000 字，超了按重要度从高到低截断。“你对 Himawari 的要求”（类别 `rule`）另放一段，排在最前面。
- 自动记下的记忆，类别和重要度都由模型打分（提示词在 `apps/agent-service/src/production-memory-capture.ts`）。600 这个门槛没有找到当初的测量依据，属于“未测量”。
- 手动添加的记忆有两个问题。第一，类别靠关键词猜，一个都没猜中时默认归“身份”。第二，重要度固定是 600，正好等于门槛。结果是手动添加的每一条都进了档案。例如“我每天必须喝咖啡”被归成“身份”，并且每轮都带给模型。
- “新”标签的意思是“最近 7 天更新过”，和用户上次看没看过无关，所以对用户没有信息量。
- 三行筛选的数字口径不一致：类别按钮数的是当前状态下的条数，状态按钮数的却是全部类别的条数。

## 决定

### 档案的定义

档案不是另一类数据，而是记忆身上的一个标记，意思是“每次对话都会带上”。界面上叫“每次对话都会带上的记忆”（英文 Brought into every conversation，日文「毎回の会話に持っていく記憶」）。Andy 以后想改回“档案”这个名字，只改文案即可。

谁来决定带哪些，规则如下：

1. Andy 的选择优先。每条记忆的详情里有开关“每次对话都带上”。打开后，这条一定排在自动挑选的前面。关掉后，这条不再自动带上，只在和当前对话相关时被检索出来。选择存在新表 `memory_profile_pins`（迁移 0066），按记忆编号一行，记忆删除时一起删除。
2. Andy 没选过的记忆，仍按原来的自动规则挑选（类别、重要度 ≥600、非敏感）。
3. 不能打开的情况：敏感记忆，以及事件、健康、财务、其他四类记忆，开关是灰的，旁边写原因。服务端也会拒绝，返回 `MEMORY_NOT_PINNABLE`。（敏感记忆一项已由 [ADR 0193](0193-memory-is-visible-to-the-model.md) 取消，现在只按类别判断。）
4. 总长仍然是 2000 字。放不下的条目会列出来，同时显示已用字数。

这样做依据的愿景原则是“用户主权”优先于“记忆可靠”：最终由 Andy 说了算，自动挑选只是默认值。

### 家人和主人定的规矩不算敏感（2026-10-29 追加）

合成数据对比发现，提取提示词把“他人隐私”整类标成敏感，结果家人的名字、关系、职业，以及“花钱前先问我”这类规矩，都进不了档案，也打不开开关。Andy 在选择卡上选了“按建议改”：主人身边的人是谁（名字、关系、职业、所在城市）和主人给 Himawari 定的做事要求标为普通信息；别人的健康、钱、感情、行踪等私事仍标为敏感。提取规则版本因此从 `memory-capture:v4`（[ADR 0113](0113-memory-history-events-and-stance.md)）升为 `memory-capture:v5`。数据见[工程案例库 案例 54](../engineering-casebook.md#case-carried-memories)。Jev 判断“该不该带上”的效果不如现行规则（28 句判对 21 句对 24 句），而且只能用于合成数据，所以不采用。

### 手动添加

- 先按关键词猜一个主题，显示在一个可改的下拉框里。一个都没猜中时归“其他”，不再默认归“身份”。
- 手动添加的普通记忆重要度改为 500，要求类（`rule`）为 800。所以手动添加的记忆不会再自动进档案。
- 添加表单里有开关“每次对话都带上”，默认关闭。

用模型来给手动添加的记忆分类，记为 Backlog，这次不做。

### 页面结构（方案 A）

- 只有两个标签：“记忆”和“变化记录”。原来的“待确认”标签改成页面顶部的“需要你确认 · N 条”区块，有待确认的事才出现。原来的“档案”标签改成“记忆”标签顶部的卡片。
- 顶部卡片显示：带上了几条、已用多少字（满 2000 字）、还有几条放不下，以及按类别的条数。点“查看和调整”展开三组：已经带上的（按类别列出，每条一个开关）、放不下的、Andy 关掉的。
- 去掉“新”标签。如果上次打开记忆页以后有新记住的记忆，页面上方显示“自你上次打开后新记住 N 条 · 看看”。打开时间存在 `memory_settings.last_viewed_at`，每次打开页面记一次。
- 浏览方式：电脑上左侧是主题目录，选中一个主题后，在它下面展开小类；手机上是一个“主题：…”按钮，点开是同样的列表。在“全部主题”下，每个主题先显示最新 3 条，后面是“看全部 N 条”。选中一个主题后，每次显示 30 条，再点“再显示 N 条”。主题按钮上的数字等于点了以后能看到（含“再显示”）的条数，这是[事故 I-13](../incidents-and-gates.md) 的口径。
- “已归档”和“最近删除”从筛选按钮里拿出来，改成列表下方的两个链接。
- 点一条记忆，电脑上从右侧滑出详情，手机上从底部弹出。详情里有：开关“每次对话都带上”、主题、重要度（写明是模型打分还是手动添加的默认值）、来源、上次用到、提醒、怎么变过来的，以及编辑、删除、恢复。
- 人物关系图放在“人际”主题下面。

“换主题”这次不做。原因是改类别要走 `saveWithProjection`，可能触发重新嵌入，会花钱。这一项记为 Backlog。

## 比较过的方案

### 方案 A：两个标签，档案改成顶部卡片（采用）

- 好处：档案和记忆是同一批数据，界面也放在一起，不会让人以为是两份资料。数据量从 13 条涨到 1 万条，页面结构都不用变。
- 代价：卡片和列表在同一页上，需要的话可以把卡片收起。

### 方案 B：保留三个标签，只修文案和筛选

- 好处：改动最小。
- 代价：解决不了“档案是什么、为什么能单独编辑”的疑问，三行筛选的问题还在。

### 方案 C：首页是一格一格的主题，点进去看列表

- 好处：一眼能看出各主题有多少条。
- 代价：多一层点击。搜索和“每次都带上”要另找地方放，手机上也更挤。

### 让 Andy 直接编辑档案文本

不采用。档案是从记忆里现挑出来的，单独编辑会出现两份互相矛盾的内容。愿景原则“记忆可靠”要求只有一份事实来源。

<a id="consequences"></a>

## 后果

- 好处：Andy 能看到每轮带给模型的是哪些记忆、占了多少字、哪些没放下，也能自己决定带不带。手动添加的记忆不会再全部进档案。
- 好处：服务端只多了一张表和一个字段，打开开关不会触发嵌入，所以不花模型调用的钱。
- 代价：自动挑选的规则（重要度 600）仍然没有测量依据。是否重新校准，等 Andy 决定。按“花钱先问”的规则，任何评测都要先报费用。
- 后续：用模型给手动添加的记忆分类（[BL-20261029-001](../backlog/BL-20261029-001-manual-memory-model-category.md)）；“换主题”（[BL-20261029-002](../backlog/BL-20261029-002-memory-change-topic.md)）；PR #99 合并后改用它的统一日期格式和空状态组件。现在列表里的日期还跟着浏览器语言走（事故 I-15 的范围）。
