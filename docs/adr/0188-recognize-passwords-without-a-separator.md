# ADR 0188：密码识别补上英文 “is”、没有分隔符的写法和其他语言

<a id="contents"></a>

<a id="context"></a>

## 背景

[ADR 0185](0185-mark-passwords-and-keys-sensitive-instead-of-dropping-them.md) 的“已知缺口”写明：“password is abc12345”和“Wi-Fi 密码 abc12345”认不出。原因在 `packages/sensitive-capture/src/redaction.ts` 的密码规则：关键词后面必须紧跟冒号、等号或“是/为/は”才认作密码，没有英文 “is”，也没有“关键词 + 空格 + 值”的写法。这条规则同时管发给模型和搜索的遮盖，以及存储时的敏感判断（`classificationWithIdentifiers`），所以认不出的值会原样发给模型、含它的提醒推送也会显示正文。Andy 2026-11-08 问起这个缺口，协调者要求修。

<a id="decision"></a>

## 决定

在原来的规则（关键词 + 冒号、等号、“是/为/は” + 值，不变）之外，加两条更窄的规则。为了不误遮普通句子，它们的值有同样的限制：必须是一段不含空白、逗号、分号、方括号的 ASCII 字符（所以中文短语不算值），里面至少有一个数字，值前面的引号、左括号，值后面的句号、冒号、右括号、引号都不算在值里；英文关键词（`password`、`passwd`、`pwd`、`PIN码`）前面不能紧挨字母、数字或下划线（“1Password”“notpassword”不算），中文、日文、韩文关键词前面可以紧挨任何字符（“wifi密码 abc12345”照样认）；关键词和值之间只隔空格或制表符，不跨行（终端里的 `pwd` 命令后面换行的路径不算）。

1. **带词的写法。** 关键词后接英文 `is/are/was`，或中文“改成/改为/设为/换成”，或韩文 `는/은`，再接 4 个字符以上的值（去掉前后标点后再数）。
2. **没有分隔符的写法。** 关键词、空白，再接 6 个字符以上的值（去掉前后标点后再数），如 “Wi-Fi 密码 abc12345”“password 123456”。

值是日期（`2026-11-08`、`2026/11/08`、`11/08/2026`、带时间的 ISO 写法）、版本号（`v2.0.1`）、网址（`http(s)://…`）以 `/` 开头的路径，或以 `>`、`<`、`2>` 开头的重定向（`pwd 2>/dev/null`）时不算密码；值外面包着引号或括号时，先去掉它们再判断。

关键词表不变，仍含日文、韩文，所以日文 “パスワード abc12345”、韩文 “비밀번호는 abc12345” 一并识别。

<a id="options"></a>

## 放弃的做法

- **关键词后面的任何词都当成值**：“password is required”“密码管理器”会被误判，普通提醒被标敏感、推送正文被藏。
- **值不要求有数字、不限字符**：同上，“密码 我已经用了3年”“密码设为8位以上”会被误遮。代价是 “password is hunter” 这种全字母的值认不出；值里夹着非 ASCII 字符时，只遮到第一个非 ASCII 字符之前（“密码设为 abc12345中文” 遮成 “密码设为 [密码]中文”），后面的部分会原样外发。这两种都留作已知缺口。

<a id="consequences"></a>

## 后果

- 正面：常见的口头写法被遮盖，含它们的提醒、记忆、导入行被标敏感。
- 负面：规则仍是启发式，全字母的口令、关键词与值之间隔着别的词（“密码我设成了 abc12345”）的写法仍认不出；少数普通句子（如 “密码 abc123 已过期”、`password is a1b2c3 hex`）会被误标，方向是保守的。
- 发给模型的内容：这是遮盖规则的变化。已经发出过的历史里，如果有刚好符合新写法的文字，这些文字从此会被遮盖，所以这样的对话请求开头会变一次（缓存整段重算一次）；没有这类文字的对话不受影响。遮盖仍只取决于这段文字自己和它前面已经点名的值（不依赖后文），所以追加新消息不会改变旧消息遮出的字节。
