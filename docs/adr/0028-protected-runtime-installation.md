# ADR 0028：分离安装权限与运行权限

## 背景

Hermes 的常驻服务和安装目录同属部署用户。工具链完整核验每次读取约 34451 个文件，多个执行阶段重复承担这个成本。Owner 已明确批准禁止 Himawari 修改安装文件、复用现有沙箱，并在保护经验证后移除工具路径中的全量扫描。本决定补充既有 SRT 隔离方案，不改变 Pi 工具协议或业务授权。

## 决定

Linux 受保护安装使用独立、非 root、不可登录的运行账号，不能拥有部署文件、提权、接触 Docker 控制端口或调用部署管理入口。程序及其依赖由 root 持有且不可被 group/other 写入；祖先目录只允许 root 或明确登记的可信部署用户持有，不能由运行账号替换。部署管理员是可信边界，必须停止服务后升级，禁止原地修改活动版本。

root 在受 root 保护的路径下发布 `protected-runtime.v1` 记录，精确绑定 runtimeRoot、runtimeDigest、runtimeUid 和 deploymentUid。服务以 `HIMAWARI_RUNTIME_PROTECTION_FILE` 选择该记录；环境变量不是证据，必须实际核验所有者、祖先目录、普通文件形状、进程身份、零有效/允许/继承/环境 capability 以及 NoNewPrivs。记录不包含密码或其他秘密。

每个验证进程首次使用一个版本时，审计完整安装树的权限并重新计算完整内容摘要。后续调用只在同一受保护版本身份下复用这个初始审计；每次仍核对可信记录、祖先目录身份和进程保护。记录或目录替换触发新审计；失败不保留为成功；不使用时间过期缓存。可写安装、Mac 和未配置保护记录的部署继续执行原有全量核验。明确配置保护记录但验证失败时拒绝执行，不静默降级。

工具继续使用 Pi 0.84.2 的既有定义和 Operations 适配、SRT 0.0.75 的路径/网络/进程隔离。业务授权、Grant、版本资格、作用域、Worker 身份、CAS、停止、输出披露与结果持久化仍逐次校验。受保护安装不是授权缓存。

## 比较过的方案

- 仅去掉文件写入位：文件所有者仍可恢复权限，且可写父目录允许替换，不能采用。
- 仅增加校验缓存：没有证明安装在调用间不可被运行账号改变，不能采用。
- 独立运行账号、部署方控制安装、复用既有沙箱：符合当前主机信任边界，采用。
- dm-verity 镜像：可增加按需内容完整性验证，但引入镜像、挂载和升级管理；不作为本次性能修复前提。

## 后果

部署流程需要管理员权限，且要保护程序之外的启动入口和版本记录。运行数据、日志、缓存、工作区和必要秘密源须按原私有边界迁移所有者；不改变应用 Owner，不公开文件，不增加工具目录权限。每次启动仍有完整核验成本；模型和网络耗时不由此解决。

本机制不检测可信管理员违反部署流程后的任意运行中修改，也不提供 dm-verity 的磁盘块损坏检测保证。验收必须用真实运行账号尝试覆盖、chmod、删除/替换目录及修改配置，确认拒绝，并验证正常读写工作区、SRT 子进程、停止、重启和升级。受控测试不能代替这份 Linux 主机证据。
