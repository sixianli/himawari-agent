# ADR 0067：未受保护安装的可执行文件和 runner 也按文件元数据复核

## 背景

[ADR 0034](0034-runtime-verification-by-inode-metadata.md) 规定：没有配置保护记录的安装（下面叫“未保护安装”），每个进程第一次核验时读取运行时目录（安装目录里的 Node、Pi 工具和 SRT 等程序文件）的全部字节，之后每次调用只遍历目录、比对每个文件的元数据（设备号、inode 编号、权限、所有者、大小、修改时间和纳秒级状态变更时间 `ctime`）。它的第 4 条另外规定，Node 可执行文件和 runner（沙箱里执行工具命令的程序）仍在每次调用时逐字节校验。

第六次生产变更（R2-L13）的 S6 验收在生产机 `84.247.157.41` 上第二次失败，原因是 `R2_L6_ORIGINAL_START_TIMEOUT`：验收探针提交的第一个任务在 60 秒内没有启动。S6 验收排在运行时保护步骤之前，所以运行时是未保护的。证据（`agent-1.stderr` 里的 `sandbox.admission.timing` 计时日志）：

- 一个任务启动前要依次经过 4–6 轮 `verifySandboxHost`（准入、常驻环境、broker 的 resolve 和 bind 前的 verifyStart），每轮都完整核验宿主。
- 生产机每轮宿主核验 2.3–6.5 秒，6 轮共约 24 秒；Hermes 测试机同一探针每轮约 0.9 秒。

2026-10-23 在 Hermes 上用第六版安装目录（36748 个目录项，Node 可执行文件 124 MB）实测：

- 每轮重新读 Node 可执行文件算摘要要 3.9–9.4 秒（Hermes 的 `/data` 是机械盘）。
- 每轮的元数据遍历（含线程启动）要 871–1420 毫秒；其中对每个子目录各做两次 `realpathSync`（把路径上每一层都再查一遍，求出真实路径）就占了一半以上：去掉后遍历本身从 600–709 毫秒降到 285 毫秒。

ADR 0034 曾取代 [ADR 0028](0028-protected-runtime-installation.md)。文档校验只认一层取代关系，所以 ADR 0028 的取代者改记为本 ADR，ADR 0034 的 `supersedes` 字段清空；两份旧 ADR 的正文不变。

用户在 2026-10-23 选择先改产品（G167）：“按乙做：先改产品，让未保护运行时的核验不重复整目录摘要，再走其余步骤。”

## 决定

Linux 受保护安装的规则（ADR 0028 和 ADR 0034 沿用的部分）不变。

未保护安装改为：

1. 运行时目录：沿用 ADR 0034 的第 1–3 条，即每个进程第一次完整读取字节并记下元数据指纹，之后每次调用只遍历元数据，任何差异都丢弃指纹并重新完整审计。
2. Node 可执行文件和 runner：取代 ADR 0034 第 4 条。每个进程第一次核验某个“路径 + 期望摘要”时，读取全部字节算摘要，并在读取前后各取一次文件元数据（与目录指纹相同的七项）。摘要一致、且前后元数据相同，才在进程内存里记下这份元数据。之后每次调用先取元数据：与记下的相同就不再读内容；不同就删掉记录，重新读全部字节。路径、类型、写权限、所有者和真实路径的检查仍在每次调用时进行。
3. 元数据遍历只对运行时根目录求真实路径（遍历前后各一次）。子目录逐个用 `lstat`（读取文件自身的信息、不跟随符号链接）确认是真目录、不是符号链接，权限和所有者合格，并在列目录前后比对身份；指纹的内容和算法不变。
4. 记录只保存在当前进程内存，不写入磁盘，不设有效期；换一个期望摘要不能沿用另一个摘要的结果。

依据和 ADR 0034 相同：改写内容、改权限、改所有者都会让内核更新 `ctime`；替换文件会改变 inode 编号；普通用户可以用 `utimes` 改回修改时间，但无法设置 `ctime`。这条依据对运行时目录里的文件和对可执行文件、runner 完全一样，ADR 0034 对后两者保留逐字节校验没有额外的安全理由，只是当时它们不是主要耗时。子目录被换成符号链接时，`lstat` 看到的类型不是目录，会直接拒绝；子目录在遍历中途被替换，列目录前后的身份比对会发现。`realpathSync` 同样是按路径检查，对子目录不能多发现任何东西。

## 比较过的方案

### 只改验收探针，等到任务自己的准入期限（甲）

- 好处：最快，不改产品代码。
- 代价：生产上每个任务启动前仍要多花约 20 秒做重复核验，真实用户的第一次工具调用同样要等。用户选了乙。

### 按时间缓存核验结果

- 好处：最快。
- 代价：ADR 0028 和 ADR 0034 都已否决，它不能证明两次调用之间安装没有被改过。

### 让同一个任务的多轮核验共用一次结果

- 好处：可以把每个任务的核验减到一两次。
- 代价：要改准入、常驻环境和 broker 多个调用方之间的约定，改动面大；这些轮次的间隔可达十几秒，共用结果等于按时间缓存。

### 可执行文件和 runner 按元数据复核，遍历去掉子目录的真实路径计算（采用）

- 好处：不放松核验强度；Hermes 上每轮核验从“可执行文件摘要 3.9–9.4 秒、遍历 0.9–1.4 秒并行”降到遍历约 0.55 秒。
- 代价：每轮仍要遍历约 3.7 万个目录项；进程重启后的第一次核验仍要完整读取。

## 后果

- 好处：未保护安装（包括 S6 验收阶段的生产机和 Mac）上，任务启动前的多轮核验不再重复读取 124 MB 的 Node 可执行文件。
- 限制：与 ADR 0034 相同。能改系统时钟、直接改写磁盘块或拥有 root 权限的一方不在防护范围内；通过内存映射写入而时间戳尚未更新的那一小段时间不在检测范围内；检查完成到真正使用之间的变化也无法发现。
- 后续：本决定不改变工具协议、授权、审批、输出披露或停止条件。引用 ADR 0034 的 Runbook 和架构文档已改为引用本 ADR，Runbook 按新代码核对后重新封存。对应的测试带 `[R2-D24]` 标签，在 `packages/platform-node/test/sandbox-host-verifier.unit.test.ts` 和 `packages/platform-node/test/sandbox-runtime-digest-worker.unit.test.ts`。
