## 背景

第一期（[ADR 0087](0087-chat-ui-v6-process-timeline.md)）只做了过程区和标志。v6 原型（`docs/assets/control-center/2026-10-26-v6/index.html`，里面的消息、模型、耗时、token 数都是演示数据）上，Andy 在 2026-10-26 对回答框和输入区还留了下面这些批注。PR #45 合并（他的原话是“合并”）后，这些作为第二期开发。原话保留如下（语音转写的错字按上下文理解，例如“影视的”是“隐式的”）：

- 复制按钮的位置：“这个按钮，我的理解是，是不是要放在来源上面，紧贴着，紧贴着 response，不然会让用户觉得，哎，是不是连来源也一起复制了？”
- token 消耗：“有没有必要加入 token 消耗？因为作为我的话，虽然我和其他普通用户不太一样，可能我比较关注每一次的 token 消耗。”
- 来源：“来源列表这里，呃，要不要做成一个列表，而不是像这样一块一块的，就是让它紧凑一点，就是不要让它占占掉视觉的大部分。视觉的大部分还是要以上面的 response 为主，因为来源这里其实用户没有那么关注，”
- 消息状态和复制：“呃，用户发的消息，嗯，要给一个标识，就是如果如果模型已经收到的话，就要打一个勾，你懂我意思吧？就像是在那个即时通信软件里面，如果我发的消息被对方已经看到。就打一个打一个勾，但是这个勾放的位置，你可以参考一下，就是即时通讯 APP 的最佳时间，还有就是每一条用户发的消息，呃，当鼠标往上移的时候，就把那个 copy 那个按钮亮起来，然后可以供用户 copy。”
- 模型选择：“这里的话要能显示已经可用的所有的模型，最多显示三个优先级最高的模型。然后，如果用户选了某一个模型，那么推理强度那里就要动态的去调整这一个模型当前可用的推理强度。然后，用户选了某一个模型的话，一定要把推理强度，呃，设置为默认强度，就是目前主流的 AI agent 的话，默认强度应该都是 medium。如果没有 medium 的话，就设成 low。反正就是，呃，设为一个比较平衡的，默认是一个比较平衡的推理强度。”
- 输入框提示语：“呃，这个输入输入框里面的这个提示文本的话，我感觉这一句很普通，就是能不能想想一句又贴合我们这一个项目的愿景，然后又贴合我们这个 agent 现在拥有的功能，然后又俏皮可爱一点。”
- 附件：“加附件这个按钮，呃，目前可以支持，就是一，嗯、呃，就是我希望的是添加添加附件这个这个按钮是真的有用，如果没用的话就不要，就把它关掉，懂我意思吗？我希望的是添加附件可以添加图片，然后文件这几种常见的形式、常见的格式的文件。还有就是，我希望在输入框这里直接，如果我已经复制了一个图片在在剪贴板，我可以在这输入框里面直接 Ctrl V 就可以给它粘贴粘贴上来。包括其他文件也一样。”
- 滚动条：“这个滚动条可以做成影视的吗？就是一个大白条放在这里很丑。我说影视的意思是，就是如果用户有滚动意图，才显示出来，而且要细一点，不要抢占整个页面的视觉。 整一个用户用户界面的这个滚动条都要按照这个原则来设计。简洁高级一点，”

<a id="decision"></a>

## 决定

1. **回答下方一行，紧贴正文。** 一轮结束后，回答正文下面先是一行：“复制”、“⋯”更多操作、灰色的“模型 · 用时 · 时刻 · N tokens”。复制只复制回答正文（Markdown 原文），不含来源和文件。“从这里开新对话”（原来常驻的“从此轮 Fork”）收进“⋯”菜单。来源、记忆和文件卡片都排在这一行之后。回答头部不再单独显示模型名。
2. **来源收成一行。** 来源取自这一轮搜索网页工具返回的结果，同一网址只列一次。默认只显示“N 个来源”一行和前几个站点首字母，点开后每个来源一行：首字母、标题、灰色域名，悬停才有底色。
3. **你的消息带状态和复制。** 气泡正下方靠右（参照即时通信软件的通行做法）显示时刻和状态：灰色单勾“已送达”（服务端已保存这条消息），强调色双勾“已开始处理”（这一轮已有模型开始的记录）。鼠标移到消息上才亮出复制按钮，手机上常亮。原型里的“发送中”转圈这次不做，因为消息只在服务端保存后才出现在列表里，发送中的状态由输入框的发送按钮表示。
4. **模型选择。** 模型列表按配置顺序默认只显示前 3 个，其余收在“更多模型（N）”里；当前选中的模型排在第 4 个以后时直接全部展开。换模型后，推理强度设成“标准”（medium）；没有就设“低”（low）；再没有就取第一个不是“关闭”的档位。打开页面时也按这条规则选默认强度，不再默认取第一档。
5. **输入框提示语。** 新对话：“查新闻、记小事、写首诗，都可以丢给我 🌻”；对话中：“接着说吧，前面聊的我都记着呢 🌻”。英文、日文各写一句意思相同的话。“删除文件、联网命令……会先问你”只在新对话下面出现；“Enter 发送 · Shift Enter 换行”挪进发送按钮的悬停说明。
6. **滚动条。** 全界面滚动条平时透明，某个区域正在滚动时才出现一根细的半透明条，停下约 0.9 秒后消失。做法是在页面上监听滚动事件，给正在滚动的区域临时加 `data-scrolling` 属性，样式只在有这个属性时给滚动条上色。
7. **附件真能用**，见[附件](#attachments)。

<a id="tokens"></a>

## token 数从哪里来

- Pi 每次模型调用结束时，`AssistantMessage.usage` 里带有输入、输出、缓存读、缓存写、推理 token 和按价格算出的费用。Himawari 的事件记录本来就保存了整条消息（去掉凭据后），所以执行记录投影在消息结束时多投影一条 `runtime.usage` 状态记录，内容是这几个数字的 JSON。不改执行记录合同，不改 Pi。
- 网页把一轮里所有 `runtime.usage` 相加：显示的输入数包含缓存命中的部分，总数等于输入加输出；悬停说明写“输入（缓存）· 输出 · 约多少美元”。过程区展开后，时间合计下面多一行 token 合计。
- 费用是 Pi 按模型价格表估算的，所以前面写“约”。实际扣费以模型网关和用量账本为准。

<a id="attachments"></a>

## 附件

Andy 要求附件按钮“真的有用”，否则关掉。做法分三段：浏览器把文件转成文字，附件接口加密保存这段文字，发给模型时按引用展开。

- **能加什么：** PDF、Word（.docx）、Excel（.xlsx）、PowerPoint（.pptx），以及文字、Markdown、代码、CSV、JSON、YAML、日志这类 UTF-8（通用的文字编码）文本文件。每个文件原始大小不超过 20 MB，一条消息最多 10 个。
- **怎么加：** 点 +（可多选）、在输入框里 Ctrl+V 粘贴文件、把文件拖进输入框，三种都行。输入框上方每个文件一张小卡片：读取时转圈，读完显示文件名、原始大小和移除按钮；文字太长被截断时卡片上标“已截断”。文字框里只留你打的字。卡片按选择顺序排列。
- **浏览器里转成文字：** PDF 用 Mozilla 的 pdf.js（`pdfjs-dist` 6.4.299，只在第一次加 PDF 时才下载，不进首屏代码），按页输出并标“[第 N 页]”；Word、Excel、PowerPoint 本质是 XML 文件的压缩包，用 `fflate` 0.8.3 解压后取出段落、每个工作表的单元格（表名作小标题，列用制表符隔开）、每张幻灯片的文字。文字超过约 25 万字（256K 字符）时截断，并在末尾写明“后面的内容太长，已截断”。在浏览器里解析，而不是在服务端解析，是因为文件来自用户自己的电脑，解析不受信任的文件格式的风险留在用户自己的浏览器标签页里，服务端不用装任何解析库。
- **附件接口：** 新增 `POST /api/payload/v1/attachment`，登录、防伪造请求（CSRF）和幂等检查与消息正文用的 `/api/payload/v1/text` 完全相同，只是单段文字上限是 256K 字符（请求体上限 2 MiB），保存的内容类型是 `text/x-himawari-attachment`。消息正文接口的 64 KB 上限不变。
- **消息里只带引用：** 发送的消息正文是你打的字，后面每个文件一行 `<file name="名字" ref="附件引用" bytes="原始大小" kind="pdf"/>`。消息合同和数据库都不用改，草稿保存、发送失败重试、刷新恢复照旧可用；文件全文也不再存进浏览器本地的草稿里。标题生成和记忆提取看到的也只是这一行，不会把整份文件写进记忆。
- **发给模型时展开：** 上下文投影（把对话历史整理成发给模型的内容的那一步）读到你的消息里的引用时，取出对应附件并解密，换成 Pi 读文件参数时用的格式 `<file name="名字">\n全文\n</file>`。只展开内容类型是附件的加密内容，所以引用不能被用来读出其他记录；解密时绑定所有者和 agent，读不到别人的数据。附件不存在或读不了时写“[附件无法读取]”，这一轮照常进行。
- **聊天记录：** 你的消息只显示正文和文件卡片（名字和原始大小），复制按钮只复制正文。
- **还读不了的：** 图片、扫描件 PDF（没有文字层）、旧版 .doc/.xls/.ppt 和其他二进制文件会被拒绝，并分别提示原因，不会悄悄丢掉。

图片要等 Andy 决定是否加一个能看图的模型（生产配置目前只允许一个文本模型）。图片、扫描件和旧版 Office 文件记在 [BL-20261026-012](../backlog/BL-20261026-012-attachments-images-pdf-office.md)，选定后在本 ADR 补一条后续。

后续（2026-10-27）：Andy 选了“加一个看图模型”，图片的做法见 [ADR 0093](0093-chat-attachments-images.md)。

<a id="pi-reuse"></a>

## Pi 复用与 Himawari 负责的部分

- 复用 Pi：`AssistantMessage.usage` 的 token 和费用数字；附件展开后沿用 Pi `processFileArguments`（`@earendil-works/pi-coding-agent` 0.84.2 的 `dist/cli/file-processor.js`）给文本文件用的 `<file name="…">` 格式。以后做图片时复用模型的 `input`（是否能看图）声明和用户消息里的 `ImageContent`。
- Himawari 负责：执行记录投影、网页展示、附件的读取、上传接口、加密保存和按引用展开。Pi 的读文件函数读的是本机路径，也不读 PDF 和 Office；网页拿到的是浏览器里的文件，附件还要走 Himawari 的登录、加密和所有者检查，所以只复用格式，不复用函数。

<a id="options"></a>

## 比较过的方案

- **token 数从用量账本读：** 账本里的费用是网关实际报的，更准；但要给对话快照或执行记录另加一条查询路径。第一步用执行记录里已有的 Pi 数字，账本对账留到以后。
- **在执行记录合同里加 `usage` 字段：** 类型更清楚，但要改合同版本和所有读写方；用一条状态记录承载，和第一期“输出开始”的做法一致。
- **来源取自回答里的链接：** 能反映回答真正引用了哪些，但模型不一定写链接；取搜索结果更稳定，代价是列出的来源可能比回答用到的多。
- **附件全文直接放进消息正文（这一期最初的做法）：** 服务端一行不改，当天就能用；但正文上限 64 KB，文件全文还会进入标题生成、记忆提取和浏览器本地草稿。改成“附件接口 + 引用 + 发给模型时展开”后这些问题都没有了。
- **服务端解析 PDF 和 Office：** 和主流产品一样由服务端统一处理，也能支持旧版格式；但要在服务端装解析库、处理不受信任文件的风险，上传原始文件也更大。选了在浏览器里转文字。Anthropic 的 Files API 文档对 `document` 块不支持的 .docx、.xlsx 也是写“convert the files to plain text and include the content directly in your message”。
- **滚动条只用 CSS 悬停显示：** 不用脚本，但鼠标停在长列表上就一直显示，不符合“有滚动意图才出现”。

<a id="consequences"></a>

## 后果

- 好处：回答下方信息集中在一行，复制不会误带来源；每轮 token 和大约费用一眼可见；模型和强度的默认值更平衡。
- 代价：没有 `runtime.usage` 记录的旧对话不显示 token；来源可能多于回答实际引用的；滚动条在键盘滚动以外的“准备拖动”时不会提前出现。
- 附件：每轮都会把这段对话里的附件全文作为上下文再发给模型，长对话里费用会随之增加；单个附件超过约 25 万字会被截断；读取质量取决于文件本身（扫描件没有文字层，复杂表格只保留单元格文字，Excel 日期显示为数字）。
- 后续：图片、扫描件和旧版 Office 文件（[BL-20261026-012](../backlog/BL-20261026-012-attachments-images-pdf-office.md)）；用量账本对账。
