# ADR 0034：未受保护安装按文件元数据复核运行时

## 背景

每次沙箱工具调用前，服务和 Worker（执行工具的后台进程）都要确认"运行时"（安装目录里的 Node、Pi 工具和 SRT 等程序文件）与安装时登记的内容摘要一致。一次调用的准备、预留、绑定和启动等阶段会分别调用 `verifySandboxHost`，每次都重新检查。

[ADR 0028](0028-protected-runtime-installation.md) 为 Linux 受保护安装提供了快速路径：安装目录由 root 持有，运行账号改不了它，因此同一进程只需完整审计一次。Mac 和没有配置保护记录的安装，仍然每次都读取全部文件字节并重新计算摘要。

2026-09-27 的产品路径浏览器 E2E（从浏览器一路走到后台服务的端到端测试）在 macOS arm64 上测得：

- 当前安装包约 3.3 万个文件、353 MB。空闲时完整摘要一次要 4.5～5.3 秒，并行负载下单次 3～17 秒。
- 一次读取文件调用，服务端做了 8 次主机校验，合计约 57 秒，超过了 60 秒工具期限。这次调用因此被记为"结果未确认"，整轮运行停在等待核对的状态。

Owner 在 2026-09-27 要求速度优先，同时兼顾安全，并授权选择最佳方案。

## 决定

Linux 受保护安装继续沿用 ADR 0028 的全部规则：

- 程序由 root 持有；独立的运行账号不能拥有部署文件、不能提权。
- root 发布 `protected-runtime.v1` 记录，服务通过 `HIMAWARI_RUNTIME_PROTECTION_FILE` 选择该记录。
- 每次调用仍核对保护记录、祖先目录、进程身份、capability 和 NoNewPrivs。
- 明确配置了保护记录但验证失败时，直接拒绝，不降级。

未配置保护记录的安装（包括 Mac）改为"一次完整审计，之后按元数据复核"：

1. 每个校验进程第一次遇到某个"安装目录 + 期望摘要"组合时，读取全部字节并计算内容摘要。同一趟遍历里，为每个目录和文件记下元数据：设备号、inode 编号、权限、所有者、大小、修改时间和状态变更时间（`ctime`，纳秒精度）。读取前后元数据任何一项不同，都拒绝。摘要一致后，才在进程内存里保存这份元数据指纹。
2. 之后每次调用都重新遍历整棵目录，只读元数据，不读内容。结果与保存的指纹完全一致才放行。任何差异都会删除旧指纹，并立即重新完整审计。审计不通过就拒绝。
3. 指纹只保存在当前进程内存，不写入磁盘，也不设有效期。换一个期望摘要不能沿用另一个摘要的审计结果。
4. 目录和文件的类型、写权限和所有者检查，以及拒绝符号链接的规则，在两种模式下完全相同。可执行文件和 runner 仍在每次调用时逐字节校验。

依据：改写文件内容、改权限、改所有者，都会让内核更新 `ctime`；替换文件会改变 inode 编号；增删文件会改变所在目录的时间戳。普通用户可以用 `utimes` 把修改时间改回去，但无法设置 `ctime`。因此元数据一致，足以证明内容自完整审计以来没有变化。

## 比较过的方案

### 每次调用都完整摘要（原方案）

- 好处：每次都直接读到当前字节。
- 代价：单次 3～17 秒。一次工具调用就要约 57 秒，普通读文件都会超时。

### 只按时间缓存审计结果

- 好处：最快。
- 代价：[ADR 0028](0028-protected-runtime-installation.md) 已否决。它无法证明两次调用之间安装没有被改过。

### Mac 上也建独立运行账号，并把安装交给 root 持有

- 好处：和 Linux 受保护安装的强度一致。
- 代价：桌面单用户安装需要管理员权限、额外账号和启动入口保护，安装和升级的负担明显增加。可以作为以后更强的选项，但不作为这次提速的前提。

### 每次调用按元数据复核（采用）

- 好处：每次调用仍能证明内容没变，单次约 0.35～0.8 秒。一次读文件调用的校验总耗时从约 57 秒降到约 5.5 秒。
- 代价：每次调用仍要遍历约 3.7 万个目录项。进程重启后的第一次调用仍需完整审计。

## 后果

- 好处：Mac 和未受保护的 Linux 安装上，工具调用不再因为重复的完整摘要超出期限。一旦发现变化，就退回完整审计。
- 限制：这个办法依赖文件系统如实维护 `ctime` 和 inode。能修改系统时钟、直接改写磁盘块或拥有 root 权限的一方，不在它的防护范围内，这一点与 ADR 0028 对可信管理员的假设相同。通过内存映射写入、而文件系统还没更新时间戳的那一小段时间，也不在检测范围内。和完整摘要一样，检查完成后到真正使用之间的变化也无法发现。
- 后续：本决定不改变工具协议、授权、Grant、审批、输出披露或停止条件。受影响的 Runbook（操作手册）说明已同步。它们的静态合同在本次改动之前就已经不一致，需要在下一次部署核对时重新封存。
