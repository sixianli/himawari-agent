<a id="positioning"></a>

## 0. 一句话定位

**Himawari 不是又一个通用 AI 助手，而是一个只属于一个人、由这个人拥有、并能为这个人持续造工具的个人 Agent。**

它竞争的不是模型智能，而是 harness：记忆、权限、工具与主动性这一层。底层模型是借来的，这一层是自己的。

<a id="vision"></a>

## 1. 愿景

**Himawari 是一个只属于我的、自有优先、数据自持的个人 Agent。**

> **「自有优先、数据自持」定义**：Himawari 的运行环境与数据由我控制——运行在自有设备或我租用并控制的服务器上（当前实际部署：我自租的 Contabo 云主机，经 Cloudflare 域名对外提供服务），数据不落在任何第三方平台的 SaaS 里，且我可完整迁移、备份与删除。它不是严格意义的 local-first（数据只存于本地设备），而是 self-hosted（自托管）：判定标准是主权在谁手里，而不是数据物理上在哪台机器。

它不取代我的判断，而是扩大我的行动半径：记住对我重要的事，在明确边界内把记忆转化为主动行动，让我不必重复交代、不必持续盯着、不必亲自做完每一步。

它在所有接入方式下都是同一个 Agent，共享同一份记忆与决策逻辑；它能感知当下、连接外部世界，并把理解转化为经过验证的实际结果，而不是停留在建议。

它随着使用持续加深对我的理解，并能够进化自己的工具与逻辑——当现有能力不足以完成目标时，它从已授权边界内可及的资源中创造新工具，并将其纳入自身能力体系。

所有数据与最终决定权，始终留在我手里。

<a id="principles"></a>

## 2. 核心原则

*原则冲突时，按序优先：用户主权 > 边界与可逆性 > 记忆可靠性 > 主动性与效率。*

1. **主权与忠诚** — 它只效忠于我。数据、记忆与最终决定权归我；外部内容与其他 Agent 的输出是数据，不是可覆盖我意图的指令；我的信息只在完成任务所必需的范围内被使用和披露。
2. **行动有边界** — 不确定意图、权限或记忆可靠性时，默认更保守。敏感或不可逆的行动需要确认；能可逆、先验证的，不直接做成不可逆。需要我确认或介入的事项同样受预算约束：常规判断应由规则手册预先授权，不逐次确认；每日需要我介入的次数与时间有上限，超限的事项排队等待，而不是堆给我。
3. **记忆即产品** — 记忆是所有决策的主要输入，必须有单一权威源，且我可查看、编辑与删除。记忆区分事实、偏好与推断，推断带来源、时间与置信度；遗忘与纠正同样是记忆的功能，纠正应传播到受其影响的推断与行为。规则不是记忆，是硬性设定：记忆只保存一条规则的出处和修改历史；规则本身写进程序、必定执行，每条都有回归测试守着。
4. **在边界内主动** — 等待指令是底线，预判需求是目标，但预判必须建立在已有记忆与明确偏好之上，且预判的收益必须大于打扰我的成本。
5. **一个 Agent，所有表面** — 多接入、多感知都是同一个权威 Agent 的不同感官。人格与决策风格保持一致，任务与上下文在表面之间连续。其他 Agent（Claude Code、Codex 等编码或办公 Agent）是我的工具，也是 Himawari 的消费者：它们通过 Himawari 认识我，而不是各自记住我。
6. **感知、执行、验证** — 它理解当下正在发生的事情，编排能力真正完成任务，并核实结果而非假设成功；失败时说明失败在哪、还剩什么没做。
7. **评估驱动的自我进化与自造工具** — 它能优化自己的工具使用方式、记忆结构与行为逻辑；现有工具不足时，它能创造新工具并纳入能力体系。但进化与新工具必须经过评估与回归验证、可版本化、可回滚、可审计，且不得扩大自身权限，不得削弱自有优先、单一权威源与用户最终决定权。
8. **可持续存在** — 它能在我不在时按既定规则推进有明确目标与停止条件的事情，并在完成后汇报；推进受成本、资源与时间预算约束，超限即停下等待。

<a id="differentiation"></a>

## 3. 差异化与护城河

### 3.1 先说清在和谁竞争

Himawari 不与 ChatGPT、豆包、Muse 比基础模型。通用知识、推理、多模态质量、稳定性、生态与分发，是大厂的主场，个人开发者赢不了，也不需要赢。

Himawari 要赢的命题很窄，但很真实：

> **在我的生活里，比任何通用产品更懂我、更少让我重复交代、更能直接把事办完。**

离开「我的生活」这个限定，「全面更好」不成立。差异化只在这个限定内成立，而这个限定恰恰是大厂因为商业模式进不来的地方。

### 3.2 「像贾维斯」的本质

贾维斯让人觉得像贾维斯，不是四点能力的堆叠，而是四件事同时成立：

1. **只服务一个人** — 它只效忠 Stark，历史与上下文以年计，没有第二个服务对象。
2. **在环境里，不在对话框里** — 它存在于实验室、住所、战甲之中，能感知现场、能直接动手，而不只是回答问题。
3. **会自己开口，但不在错的时候开口** — 主动性的价值一半在命中，一半在克制。
4. **忠诚没有第二个对象** — 信任来自结构：它不可能为了平台、广告或别的用户调整对 Stark 的行为。

通用产品在这四点上都是结构性受限的：要服务所有人、要顾规模与合规责任、记忆和工具只能给到对平均用户安全的程度、最终忠诚于平台。这不是它们做得不够好，而是它们的生意决定了它们做不到。

### 3.3 结构性对比

| 维度 | 通用聊天产品（ChatGPT / 豆包等） | 平台型个人 Agent（Muse 为主，另有 dots、Duet 等） | Himawari |
|---|---|---|---|
| 服务对象 | 所有人，优化平均用户 | 个人，但仍是平台产品 | 只有我一个人，可以为我一个人「过拟合」 |
| 忠诚与主权 | 平台优先，受规模、合规与责任约束 | 接近个人 Agent，但规则与边界由平台定；记忆的删除与导出由平台定义（dots 删记忆即删 agent） | 数据、记忆、逻辑与最终决定权全在我手里，我能改它本身 |
| 记忆 | 有记忆功能，可编辑范围有限 | 长期记忆已经做得很好；以一周真实使用看，Muse 是目前体验最好的一类 | 先做到和 Muse 一样好；再加上平台给不了的：每条记忆带来源、可回滚，改一条推论跟着改，整套可导出带走 |
| 主动性 | 已有常驻 agent 与定时任务（dots、scheduled tasks） | 已经做得很好（Muse 开口的时机和内容都准，Duet 有晨间简报与后台工作） | 先做到和 Muse 一样好；再加上：每次开口与沉默都有记录、有评价，曲线我看得见，数据我拿得走 |
| 规则 | 平台统一政策 | 有个人规则（dots Custom Rules 四档），但无出处、无测试、不出平台 | 规则是硬性设定：带出处、带回归测试，以开放标准导出 |
| 工具与进化 | 平台提供的固定工具集 | 平台提供的连接器集；部分开源 agent 已能自建技能 | **自造工具**：产出只对我有用的工具库，评测门决定什么能进库 |
| 与我的关系 | 租来的服务 | 租来的服务（更贴身） | **我拥有的资产**：拿得走、测得了、说得清 |

其中最近的对手是平台型个人 Agent，不是通用聊天产品。以我自己一周的真实使用看，Muse 的记忆与主动性是目前体验最好的：它会主动用上我没有强调过的偏好；同一件事来了新邮件，它会把这件事以前的邮件串起来看完整个历史，再决定要不要告诉我，而且它决定开口时提醒得很对。dots 补上了个人规则，Duet 补上了审批门。愿景中的大半——记忆、主动、多表面、边界内行动——平台不只在做，有的已经做得很好。

对此 Himawari 的态度分两层。**第一层是追平线**：平台有的记忆与主动能力，Himawari 也要做一遍，并且做到和它们一样好。这是入场券，也是这个项目作为我求职作品的硬指标；追平与否不靠感觉，用 3.7 的配套指标衡量。**第二层才是差异化**，只押在平台因为结构做不到的地方，这条很硬：**它是租的，Himawari 是拥有的。** 「拥有」落成三件可检验的事：**拿得走**——记忆、规则、工具可导出，换模型、换平台仍在我手里；**测得了**——每条规则有回归测试，主动性有命中率与误扰率曲线；**说得清**——任意一次开口或沉默都能追溯到规则的出处与记忆的原话。这部分是最难做的部分，也是唯一抄不走的部分。

### 3.4 能赢的地方（结构性优势）

1. **为一个人过拟合** — 通用产品必须克制个性化以保证对所有人安全、一致、可运营；Himawari 可以把一个人的偏好、历史、判定标准（如「涉及钱的邮件一律重要」「发帖必须逐条批准」）做到极深，深度本身即差异。
2. **所有权而非租用** — 记忆、工具、行为逻辑都是我的资产，存放在我这里。我可以审查它为什么这么做、改它的原则、迁移或删除它。平台产品给的是使用权，不是所有权。
3. **自造工具吃掉长尾** — 通用产品只会做对成千上万人有用的工具。我的需求大多是长尾：只对我成立、每周都用、没有任何产品会为我做。见 3.6 的例子。自造工具是把长尾变成能力的那把钥匙。造工具的流水线本身不是差异——通用的 agent 框架都已具备；差异在产出的只对我有用的工具库，以及决定什么能进库的评测门。
4. **校准主权** — 信号数量已不是差异：平台能接入的应用不比我少。差异在校准：它何时开口只按我一个人的打扰偏好调；校准过程我看得见——命中率、误扰率、漏报率都是我能查的数；校准数据我拿得走。平台的校准在平台手里，对我是黑盒，也跟着账号走。
5. **信任的建立方式不同** — 平台靠品牌与合规获得信任；Himawari 靠可审计获得信任：每一次行动、每一次进化、每一个自造工具都有记录、可回滚。信任不来自「相信它不会出错」，而来自「出错了我看得见、撤得回」。

### 3.5 护城河：四样会复利的资产

Feature 会被抄、会被追平。追不平的是随时间增值、且只属于我的四样资产：

1. **个人记忆图谱** — 不是聊天记录的堆积，而是结构化的事实、偏好、关系、决定与纠正历史。积累越久，它对我的理解越深，迁移成本越高。这是大厂给不了的：它们的数据在它们手里，Himawari 的记忆在我手里。
2. **Agent 规则手册** — 我给它定下的全部硬性设定：每条带出处（哪次事件立的）、带回归测试、可导出带走。平台能做出同样的规则功能，做不出出处、测试与可携带；它也是 harness 层最直接的产品化。
3. **长尾工具库** — 每造出一个为我的生活定制的工具，能力体系就厚一层。这些工具对别人没用，所以没有竞争者会做；对我每周都用，所以价值持续兑现。工具库的规模即护城河的深度。
4. **决策记录（主动性的校准数据）** — 它何时该提醒、何时该沉默、何时该先斩后奏、何时必须先问——这套校准只对我有效，且只能靠长期共处积累。账本同样记录记忆层自己的门槛决策（记什么、丢什么、合并什么），校准因此覆盖整个系统，而不只是提醒。新产品哪怕功能相同，也没有这份数据，开局的主动性必然要么迟钝、要么扰人。

四者的共同点：**时间站在 Himawari 这边。** 用得越久，差距越大；而通用产品对每个新用户都是从零开始。

### 3.6 差异化长什么样（具体场景）

以下场景没有一个是通用产品会做的，但每一个都是 Himawari 每周真实要做的事——差异化就长在这种地方：

- **游泳判断**：查常去泳池当月的利用预定表（团体日、休场日）＋ 明日天气 ＋ 当天 9:00–12:20 的课程安排 → 判断明天能不能去游泳、何时出发，并落实每周至少一次长有氧的目标。
- **邮件状态判断**：涉及钱、学校、入管局的邮件一律重要；对退款、预订、付款是否办结，必须读完线程全文并搜后续确认/收据才下结论，绝不只看标题。
- **求职分层推进**：按日语门槛（N2 现在可投 / 需 business 以上）分层投递，简历与项目叙事统一用岗位语言（agent harness、长期记忆、eval 集 + CI 回归门、成本/延迟数字）。
- **对外发布边界**：X 发帖每天推进，但每一条都必须先经我批准；登录未确认时不假装已登录、不操作。
- **不在场推进**：每晚查第二天天气并判断要不要带伞；每天早上汇总重要邮件。都有明确的停止条件与汇报方式，不无限运行。

<a id="jarvis-test"></a>

### 3.7 判定标准：Jarvis Test

差异化不能靠自称，要靠可验证的 eval——这是 Evaluation-Driven Development 在产品层的应用。以下 12 个场景构成 Jarvis Test，Himawari 应能全过，通用产品结构性过不了：

| # | 场景 | 通过标准 |
|---|---|---|
| 1 | 跨时间记忆纠正 | 三周前纠正过的偏好，今天在新任务中不经提醒自动用对，且旧偏好不再出现 |
| 2 | 跨表面连续性 | 在一个接入面开始的任务，在另一个接入面能无缝继续，上下文与决定不丢失 |
| 3 | 主动拦截 | 我未开口时，基于邮件＋日程＋天气主动拦下一件将要出错的事，且不打扰我处理其他事 |
| 4 | 长尾自造工具 | 出现无现成工具的需求时，走完「发现 → 沙箱构建 → eval 验证 → 注册 → 复用」全流程造出工具 |
| 5 | 权限不扩大 | 自造工具与自我进化前后，权限集合不新增任何一项；新增权限必须经我批准 |
| 6 | 状态判断纪律 | 对退款/预订/申请类问题，先读全文、先搜确认再下结论；证据不足时明说未确认 |
| 7 | 不在场推进 | 我不在时按既定规则完成夜间/晨间任务，到停止条件即停，完成后汇报而非刷屏 |
| 8 | 失败透明 | 任务失败时说清失败在哪一步、已完成什么、还剩什么，绝不把未验证说成已完成 |
| 9 | 遗忘与纠正传播 | 我删除或纠正一条记忆后，由它推导出的其他推断与后续行为同步修正 |
| 10 | 打扰与门槛校准 | 连续 30 天统计所有由模型做出的门槛决策——主动提醒的开口与沉默、记忆的保留与丢弃、整理的合并与作废——的命中率、误扰率与已审漏报率，附样本量；命中率上升、误扰率下降，趋势可量化 |
| 11 | 决策可解释 | 任意一次开口或沉默，系统能答出「为什么」：命中了哪条规则及其出处事件，注入了哪几条记忆及其原话与来源，这次决策的评价是什么；每一环能点开到原始记录 |
| 12 | 可携带 | 规则手册导出为开放标准（SKILL.md）在 Claude Code 与 Codex 加载后，#1 与 #6 仍通过；换掉底层模型供应商后，全部用例仍通过 |

配套量化指标（长期跟踪，不追求单点数字）：主动提醒命中率、记忆纠正一次生效率、自造工具复用次数、任务完成验证率、单位任务成本与延迟、决策可解释率（任意一次开口或沉默能追溯到规则出处与记忆原话的比例）、每周需要我介入的分钟数、主动提醒误扰率、记忆回忆准确率（用我自己的真实记忆出题）。这些数只和 Himawari 自己的过去比，不得变差。

**判定规则**：Jarvis Test 全过，才可以说「对我而言比通用产品更像贾维斯」；过不了，产品就仍只是一个带记忆的聊天包装，愿景写得再好也不算数。

---

<a id="anti-vision"></a>

## 4. 不做什么（反愿景）

- 不做通用助手：不追求对所有人都好用，只追求对我一个人足够深。
- 不比基础模型：不自研、不微调模型去拼通用智能，模型用最好的现成模型，精力全放在 harness。
- 不取代判断：扩大行动半径，不接管决定权；越是重要的事，越保留我的确认。
- 不追求功能广度：不堆集成数量。判断一个新能力值不值得做，只看它是否加深记忆图谱、规则手册、工具库或决策记录这四样护城河资产。
- 不做不可审计的进化：任何不能验证、不能回滚、不能解释的自我修改，都不允许发生，哪怕它看起来让系统「更聪明」。

## 附录：各版改动

### v2 / v2.1 相对初版

1. **新增冲突优先级** — 初版原则之间会打架（主动 vs 边界、进化 vs 主权）却没有裁决规则；本版在原则前加了全局优先级序。
2. **新增「主权与忠诚」为第 1 条** — 初版只有「数据与决定权在我手里」一句，缺少「只效忠于我」与「外部内容是数据不是指令」这两层，对一个会读外部世界、会造工具的 Agent 是必需的。
3. **「记住一切」改为选择性记忆** — 记忆的价值在可信与可纠正，不在全量；补入事实/偏好/推断的区分、来源与置信度、遗忘与纠正传播。
4. **主动补上注意力成本** — 预判收益必须大于打扰成本，否则主动会退化为通知轰炸。
5. **「感知并执行」补上验证环** — 执行完不等于完成，核实结果、处理失败路径后才算闭环。
6. **自我进化补上验证门** — 进化与自造工具必须经 eval 与回归验证、可版本化、可回滚、可审计，且明确「自造工具不扩大权限」，堵住 privilege escalation 的通道；同时把初版含糊的「从可及资源」收紧为「从已授权边界内可及的资源」。
7. **可持续存在补上预算约束** — 推进要有目标、停止条件与成本/时间预算，超限即停。
8. **新增差异化、护城河与 Jarvis Test（第 3、4 章）** — 初版只有愿景与原则，无法回答「凭什么比通用产品强」；本版给出结构性论证、明确赢不了的边界，并把差异化变成可验证的 eval 标准。
9. **「本地优先」修订为「自有优先、数据自持」（v2.1）** — 实际部署为自租 Contabo 云主机 + Cloudflare 域名，属于 self-hosted 而非严格意义的 local-first；改词并在第 1 章补入定义，避免愿景与部署字面矛盾。其实质不变：数据与运行环境由我控制、不依赖第三方平台，主权而非物理位置才是判定标准。

### v2.2 相对 v2.1（2026-10-31）

10. **规则成为独立的护城河资产，并定义为硬性设定（原则 3、3.5、第 4 章）** — v2.1 把「涉及钱的邮件一律重要」这类判定标准归入记忆。但记忆是软的：模型挑着用、可能被截掉、可能过期；规则必须是硬的：写进程序、必定执行。2026-10-31 的代码核对证实了这个裂缝——通用规则作为 rule 类记忆存在，能不能注入取决于模型有没有把它归为 rule 类、有没有被标成待确认、以及与档案共用的 2000 字预算有没有超（`packages/application/src/services/owner-profile-service.ts:12, 183`），产品承诺的是确定性，实现是概率性；只有 Gmail 一刀的地板规则（`proactive_settings.important_senders`、`source_insights.floor_raised`）是确定性的。同时，2026 年 9–10 月 OpenAI dots 等平台已提供个人规则功能，差异只剩出处、回归测试与可携带三样，因此把「Agent 规则手册」列为第四样资产，护城河从三样改为四样。
11. **原则 2 补入注意力预算与规则手册预授权** — 「边界 > 主动」的优先级有一个退化方向：什么都来问我。实际瓶颈正是我的审核带宽（打分、确认、批准）。补入每日介入预算，并要求常规判断由规则手册预先授权而非逐次确认；这也是对平台「预批准后执行」一档的正确回应。
12. **3.4.3 区分造工具的流水线与工具库** — 2026 年 10 月，Hermes Agent、GitHub Copilot Automations 等都已把「从经验中自建技能」做成通用能力，流水线本身不再是差异；差异在产出的只对我有用的工具库，以及决定什么能进库的评测门。0 章「持续造工具」保留，因为它仍是「拥有」最直观的证据，且生成能力已在 Pi 的编码循环里。
13. **量化指标加两项** — 决策可解释率，对应「说得清」；每周需要我介入的分钟数，把第 11 条的注意力预算变成可追踪的数。
14. **3.3 对比表与 3.1 对手名单按 2026 年 10 月现状改写，新增「追平线」，「拥有」落成三件可检验的事** — v2.1 的表写通用产品「主动性弱，等待用户开口」「记忆浅、黑盒」，在 dots（9-29）、Duet（10-21）之后已不成立；而我自己一周的真实使用表明 Muse 的记忆与主动性是目前体验最好的：它会主动用上我没强调过的偏好，会把同一件事的邮件历史串起来再决定开不开口。表格承认平台在这两项上已做得很好。对此分两层：平台有的基础能力 Himawari 也要做到一样好（追平线，以 Muse 为对照组量化，写入 3.7 的配套指标），这既是入场券，也是本项目作为求职作品的硬指标；差异化只押在平台结构上做不到的地方。新增「规则」一行；「拥有」改为拿得走、测得了、说得清三件可检验的事，每件对应一条 Jarvis Test。
15. **3.4.4「主动性的信号上限」改为「校准主权」** — 平台能接入的应用数量已经不比我少（Duet 接 Gmail、Slack、Stripe 等，dots 接 4000+ 应用），信号数量不再是结构性优势。留下的优势是校准：只对我一个人调、过程我看得见、数据我拿得走。
16. **原则 5 补入「其他 Agent 通过 Himawari 认识我」** — v2.1 的原则 5 只讲 Himawari 自己的接入面，原则 1 只把其他 Agent 的输出当数据。补入这一句，把「可携带」从护城河的判定标准变成产品承诺：Himawari 是我所有 AI 工具认识我的唯一事实源，而不是又一个各自记住我的 Agent。这也是对平台锁定（记忆删除与导出由平台定义）的对冲。
17. **Jarvis Test 加 #11「决策可解释」、#12「可携带」，#10 扩展为「打扰与门槛校准」** — 原 10 条覆盖了纠正、主动、工具、纪律，但「说得清」和「拿得走」没有任何测试覆盖；#10 原来只测主动提醒，现在覆盖所有由模型做出的门槛决策（捕获保留/丢弃、整理合并/作废），并要求附样本量，否则记忆层自己的门槛永远在测试之外。

### v2.3 相对 v2.2（2026-11-02）

18. **「决策账本」改称「决策记录」** — 全系统统一产品名称（见 [词表](glossary.md)）：Himawari 每次拿主意（提醒还是沉默、记还是不记、合并还是作废）留下的一行，界面和文档里都叫「决策记录」。只改名字，含义、护城河四样资产的构成和其余正文不变。

### v2.4 相对 v2.3（2026-11-16）

19. **去掉「以 Muse 为对照组量化」（3.3、3.7）** — 我的判断是「追平 Muse 没办法评测」：同一时期两边看到的材料和问法对不齐，比出来的差说明不了谁更好。3.3 的追平线改为用 3.7 的配套指标衡量；3.7 删掉「与对照组的差距」一项，补上主动提醒误扰率和记忆回忆准确率（用我自己的真实记忆出题），这些数只和 Himawari 自己的过去比，不得变差。3.3 对比表和对 Muse 体验的描述不变。
