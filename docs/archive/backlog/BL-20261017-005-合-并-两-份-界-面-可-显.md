# 合并两份界面可显示的工具失败原因码清单

## Summary

界面在工具行显示失败原因前，要先确认这个原因码可以安全地显示（不泄露内部细节）。这份“可显示的原因码”清单 `SAFE_TOOL_REASON_CODES` 现在有两份：`packages/application/src/services/thread-execution-state.ts`（工具行状态）和 `packages/application/src/services/thread-execution-projection.ts`（执行记录投影）。新增原因码要两处都改，漏改一处时界面只在其中一个视图显示原因，另一个视图显示笼统的失败。

## Origin

- 来自第二轮长任务条目 R2-T14（2026-10-17）：新增 `FILE_WRITE_NOT_STARTED` 和 `SANDBOX_WRITE_EFFECT_UNVERIFIED` 时两份清单都要加；DeepSeek 的方案提醒了第二份清单。

## Notes

- 2026-10-17 加入两个新原因码后，两份清单的内容逐行相同（排序后比较）。处理方向：只留一份清单，两处都从同一个导出读取。
- 纯维护改动，不改变界面行为；用现有的两个单元测试文件（`packages/application/test/thread-execution-state.unit.test.ts` 和执行投影的测试）确认行为不变。
