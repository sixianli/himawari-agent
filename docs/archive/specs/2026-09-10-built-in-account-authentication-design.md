# 内置账号与通用 Web 登录

## 来源与已确认方向

用户明确否决仅限本机的登录方案，并选择 Himawari 内置账号登录。实现同一套账号在本机和服务器部署时的电脑、手机访问，不依赖 Cloudflare 或第三方账号。本轮保持唯一 Owner、多设备和既有授权语义，不开放公众注册或团队共享。

## 使用流程

1. 活动主机管理员通过受保护的初始化入口建立唯一 Owner 账号，设置用户名和密码、绑定验证器，保存一次性恢复码。不存在默认密码或公网抢占管理员的注册页面；已有 Owner 不可被覆盖。
2. 浏览器打开 Himawari，输入用户名和密码，然后输入验证器验证码或恢复码。只有第二步完成后才建立可访问私人数据的产品会话。
3. 会话可跨页面使用，并有空闲和绝对有效期限；用户可退出、查看并撤销设备会话。浏览器仅保存 HttpOnly 会话 Cookie，不在 localStorage 保存凭据或访问令牌。
4. 原有敏感审批要求近期认证。过期时进入再次认证流程，成功后继续原页面；登录不自动批准行动，不重放被拒绝或已执行的副作用。
5. 恢复码替代丢失验证器的第二因素，必须和密码共同使用，且每个只能成功消费一次。密码或全部因素丢失时使用活动主机上的受审计恢复入口，撤销旧会话，不能通过普通网页绕过认证。

## 现状与职责

变更前 Cloudflare JWT 验证、身份查询和产品会话创建耦合在 `platform-node/identity-gateway.ts`；HTTP 组合固定选择它。SQLite 已有 Owner 绑定、产品会话、设备及撤销操作，Gateway 已有 Origin/CSRF 和产品自有认证上下文。复用这些事实及业务授权，增加内置身份适配器。

配置明确选择内置账号或现有 Cloudflare 适配器。旧配置继续按原合同解释，不能因为新增登录而接受伪造的代理请求头。新安装使用内置账号；不默认迁移已有外部身份或合并两个 Owner。第三方统一登录本轮不实现。

这里的会话是人类登录会话，不是 Pi 的模型运行 Session。身份与权限属于 Himawari，不新增 Pi 协议或模型工具接口。

## 数据与事务

凭据归唯一 Owner，包括不可逆密码校验值、密码参数版本、受保护的验证器秘密引用、凭据修订号和限流状态。恢复码只保存校验摘要。登录挑战短时有效，只有摘要持久化，限制尝试次数，绑定目标账号与预登录会话。

完成认证必须在同一持久事务中校验凭据修订、消费挑战及验证码时间步或恢复码、建立产品设备/会话和认证时间记录。并发重复请求最多成功一次；失败或中断不能留下已认证半会话。重新认证产生新的会话认证引用，旧引用失效，原设备与 Owner 关系保留。

密码重置、因素重置及设备撤销使对应旧会话失效。SQLite 保存会话真实认证时间、空闲和绝对期限，刷新或服务重启不能重置为“刚登录”。成功认证及经限流预算接纳的密码/因素失败审计只记录事件、引用与结果，不记录密码、验证码、恢复码、Cookie 或验证器秘密。

## 安全与部署

密码使用成熟密码派生实现与随机盐，不保存明文或快速散列；验证码使用维护中的 TOTP 库，不自行建立一次性验证码算法。校验外部输入大小，限制昂贵的密码验证并发，登录和第二因素共同使用持久的账号尝试预算（每 5 分钟至多 20 次），持久保存挑战消费与失败预算。错误提示避免泄露账号存在性。

公网及跨设备使用 HTTPS，第二因素必需。仅回环开发访问允许明确的 HTTP 配置；这只是传输配置，账号、会话、权限和 UI 使用同一实现，不提供绕过认证的本机模式。Cookie 的 Secure 属性按经过校验的 HTTPS/回环配置生成，始终 HttpOnly、SameSite；登录、再次认证及退出同样验证精确 Host/Origin 和跨站请求信息。反向代理必须显式配置，不能信任客户端随意传入的转发头。

CSRF、会话撤销、近期认证、Owner 归属及一次性行动授权继续生效。会话或凭据失效后，新的命令、审批和流式订阅应拒绝；已建立的事件流不得在会话失效后持续披露私人内容。

## 影响与验证

修改配置、身份端口与适配器、SQLite 认证事务、HTTP 组合、账号管理入口及登录/再次认证/设备页面。追加迁移，保留原数据和外部身份适配器；不改原 Logo、主题、聊天流程、工具授权或 SRT 资格。

验证错误密码和验证码、挑战过期与重复消费、恢复码并发消费、会话过期/撤销、凭据修订失效、CSRF/Origin/代理绕过、SQLite 重开、敏感审批再次认证及旧外部身份回归。真实浏览器检查登录、失败提示、退出、刷新、多设备和手机键盘，分别标识受控测试与实际运行证据。

完整检查和本地提交后继续原控制中心的真实服务验收；内置账号成功不代表模型、工具安装资格和服务恢复已通过。未授权推送、创建 PR 或部署到远端。

## 恢复点与权威迁移

恢复旧数据库不能重新启用已撤销会话、旧密码或已消耗恢复码。同机恢复在 data 原子切换前禁用内置绑定并撤销会话、设备与验证请求，要求活动主机随后执行账号恢复。跨主机权威激活保留账号，但撤销复制的会话与设备，要求在新主机完成 MFA 登录。已有外部身份部署的行为不变。

## 实施结果与关闭边界

内置账号合同、追加迁移、配置适配、受保护账号 CLI、登录与设备界面均已实现。完整五项目检查 1,921 项及 tooling 565 项通过，真实浏览器验证密码与 TOTP/恢复码、再次认证、撤销、刷新与键盘提交。桌面与 320 像素视口 axe 扫描零违规；仍不代表实体手机或公网 HTTPS 验收。证据位于 `test/qualification/evidence/built-in-account-2026-09-10/`。

本 Spec 以账号能力实现和受控认证验收关闭。首次产品安装、当前主机工具资格及真实模型/审批流程仍由 [SOURCE: docs/execution/plans/2026-09-10-control-center-local-acceptance-plan.md] 管理；没有创建日常目录、钥匙串项或收费模型调用。
