# P1 只读网络有限重试

本批接在 `d20fcbf` 网络权限修复之后，落实 W23/E09 的只读与非幂等分支。源码仍采用 Pi 0.84.2、MCP 2.0.0；没有替换协议、升级依赖或调用真实模型。

## 行为与证据边界

- 通用 endpoint 只对声明零费用的 GET，在明确暂时状态 408/429/502/503/504 或已识别连接错误时重试一次。总尝试数最多 2，默认退避 250 ms，有效 Retry-After 不能被缩短；原调用期限包含等待和两次尝试。
- 每次 GET 外发前重查当前授权、秘密句柄和取消；凭据解析后再次检查授权。输入只读一次，保持原 invocation/idempotency key，不重新消费批准。有费用接口、任意写入、非幂等未知、证书/未知错误不自动重发。
- 固定公开搜索只重发内容相同的 `tools/call web_search_exa` POST，不重启工具、会话初始化或任意 MCP 方法。重试创建新的 ProxyAgent，重新触发 SRT 出口检查；所有代理在结束时关闭。保留原请求 signal、30 秒调用期限及 15 秒连接加 30 秒调用的总体上限；连接、流恢复与协议解析仍由已安装 SDK 处理。成功响应的流读取错误不由新增策略重发。
- 真实本地 HTTP + 生产 Payload UDS + SQLite 联测：503 后第二次 GET 成功；首次响应后真实撤销 Grant 则无第二次请求；Grant/Handle uses 保持一次，原调用重放读取原回执。输入/输出边界是受控 fixture，不声称完整模型/Worker 路径。
- 实际 MCP SDK + Undici ProxyAgent + 本地 CONNECT/HTTP 联测：503 重发相同 RPC，初始化一次；第二次使用新连接再次准入，出口拒绝新连接后服务端仅收到一次搜索；403 不重发。外部 Exa URL 替换为本地 HTTP，强制 CONNECT 且单连接池使复用可重现；代理凭据和隧道是实际传输，没有声称真实 TLS/Exa 或生产 SRT 撤销联测。

## 完整验证之后发现的遗漏

首次 MCP 联测替换了代理传输，只能证明协议重试，不能证明下一次请求重新进入出口权限检查。之后读取实际连接池实现发现旧 TLS 隧道可能复用。强化测试保留实际 ProxyAgent/CONNECT，先确认 403 正向控制，再复现两处错误：相同 RPC 使用原连接；出口拒绝新连接后重试仍抵达服务。修正为仅在重试前新建代理池，35 项相关检查通过。

过程错误也保留：首轮强化 fixture 使用 HTTP URL，却遗漏 Undici 对 HTTP 默认不用 CONNECT 的行为，导致初始化超时；显式启用 CONNECT 后才得到有效失败前证据。首次源码替换误把代理创建放到初次发送处，定向测试立即发现，再用精确代码补丁移到重试分支。这些失败不被计作额外产品缺陷。

验证复用依据：首轮完整运行结束后，Git diff 逐文件比较确认已有文件只改动搜索实现与其传输测试；另一个变化是新建的 MCP 集成测试由替身代理改为实际 CONNECT。endpoint 重试、权限存储、Worker、共享 fixture、工具链及其他测试未改动。搜索实现的直接调用方只有固定 `web-search-main`，由新标准构建重新验证；搜索 API 与解析合同不变，保留旧的 SDK、依赖和外部接口。未受影响的首轮结果与新构建、相关消费者复验分别报告，不声称对最终源码重新执行了整套测试。
