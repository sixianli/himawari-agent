# 三个生产缺口的本次验收约定

本文件记录本次修复任务的退出条件和继续执行方式，供后续代理核对范围。它不是生产验收结果，也不替代原始命令、测试或主机回读。

## 退出条件

1. 安装后的 Agent Service 接受经真实身份路径认证的请求，形成持久结果，重启后能够回读。未认证请求不能执行业务动作。
2. 生产 Worker 实际执行已获准的工作，并拒绝越权、过期身份和不同调用之间的正文访问。仅有握手或空注册表不算完成。
3. 同一版本在 Mac 与 Hermes 通过真实进程隔离验证。配置中的布尔值、替身测试或历史版本的结果不能替代本轮证据。

Owner 已明确取消连续运行七天作为个人使用的上线前置条件。这不改变 Trash 或迁移副本的七天保留规则，也不取消隔离和恢复验证。

## 执行与等待

本任务在当前 Codex 会话中持续执行，使用原生子代理消息和有界等待推进独立工作。每个可验证单元完成后保存 PStack 检查点，记录实际检查、未完成部分和下一步。活跃等待不超过六十秒，以便及时回应 Owner。

没有创建定时唤醒或无人值守自动化。持久 Goal 和 PStack 检查点保存目标与进度，但不构成后台计时器。会话若结束，必须由真实的新输入或产品支持的唤醒机制恢复，不能宣称会自行继续。

## 权限与证据边界

编码角色使用 Owner 指定的 Luna，请求推理强度 Max。实际模型身份与请求强度分别记录；Host 无法观测的运行时推理强度不能冒充已验证值。主代理负责协调、复核、验证、文档和本地 Git 操作。

本地修复和完成后的本地提交已获授权。系统安装、签名配置、生产服务操作、付费模型调用、账户或访问控制变更、推送和部署仍需精确目标的独立授权。

相关实现与验收范围以 `docs/execution/specs/2026-08-26-portable-durable-web-agent-design.md` 及其 Plan 为准。不得把任一基础单元通过扩大为三个生产缺口全部关闭。
